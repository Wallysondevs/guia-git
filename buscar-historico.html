Git Procurando no Histórico

A Ana tem certeza de que já existiu manteiga na receita de brigadeiro. Hoje não tem mais. Quando ela saiu? E em que arquivos a palavra "manteiga" aparece agora? O Git responde às duas perguntas: o git grep procura um texto dentro dos arquivos (de hoje ou de qualquer commit), e o git log -S procura o commit em que um texto entrou ou saiu.

Você vai aprender
  • A procurar texto nos arquivos do repositório com git grep (e as opções -n, -i e -c).
  • A procurar num commit antigo: git grep manteiga HEAD~2.
  • A achar o commit que acrescentou ou removeu um texto com git log -S, e a ver a mudança com -p.
  • A diferença entre -S, -G e --grep.
  • Por que um git grep sem resultado não mostra nada (e devolve o código 1).

As saídas desta aula saíram do Git 2.53 do Ubuntu 26.04 na máquina da Ana.

A ideia: o Ctrl+F da máquina do tempo

No editor de texto, o Ctrl+F acha uma palavra no arquivo aberto. Agora imagine um Ctrl+F que procura em todos os arquivos do projeto de uma vez, e que também consegue procurar no passado: "em que versão esta palavra apareceu pela primeira vez? E quando sumiu?".

São duas buscas diferentes:

  • "Onde está?": procurar nos arquivos de um momento (de agora, ou de um commit). É o git grep.
  • "Quando mudou?": procurar os commits que puseram ou tiraram o texto. É o git log -S.

O repositório desta aula

$ git log --oneline
54d0fe5 (HEAD -> main) Ajusta o pão de queijo
f3c1f5b Simplifica o brigadeiro
877bf83 Melhora a massa do bolo
7accc6b Adiciona o brigadeiro
3bafa7d Adiciona as primeiras receitas

Repare que nenhuma mensagem fala em "manteiga". Procurar pela mensagem (o --grep da aula git log: Filtros e Formatos) não ajuda:

$ git log --oneline --grep manteiga

Nada. A palavra está dentro dos arquivos, não nas mensagens. Vamos às ferramentas certas.

1. Onde está o texto agora: git grep

$ git grep manteiga
bolo.txt:2 colheres de manteiga
git grep
Procura um texto nos arquivos rastreados pelo Git (os que estão no repositório). O nome vem do grep do terminal, o comando clássico de busca.
manteiga
O texto procurado. Como no grep, pode ser uma expressão regular.
bolo.txt:2 colheres de manteiga
Cada resultado vem como arquivo:linha encontrada. A manteiga, hoje, só está no bolo.

No terminal, o Git pinta o nome do arquivo e destaca a palavra encontrada (as cores não aparecem aqui). Algumas opções úteis:

$ git grep -n manteiga
bolo.txt:4:2 colheres de manteiga
$ git grep -i MANTEIGA
bolo.txt:2 colheres de manteiga
$ git grep -c manteiga
bolo.txt:1
$ git grep polvilho -- pao.txt
pao.txt:400 g de polvilho
-n
Mostra o número da linha: bolo.txt:4: = linha 4 do bolo.txt.
-i
Ignora maiúsculas e minúsculas: MANTEIGA achou manteiga.
-c
Só conta: quantas linhas de cada arquivo têm o texto.
-- pao.txt
Procura só nesse arquivo (ou pasta), depois do --.
E o grep -r comum?

O grep -rn manteiga . do terminal também acha (./bolo.txt:4:2 colheres de manteiga). A diferença é que o git grep só olha os arquivos do repositório: pula a pasta .git, os arquivos ignorados pelo .gitignore (como node_modules/) e os que nunca foram adicionados. Num projeto grande, isso o deixa muito mais rápido e com menos "lixo" no resultado. E ele faz algo que o grep não faz: procurar no passado.

Procurando num commit antigo

Ponha um commit depois do texto, e o git grep procura nos arquivos como estavam naquele commit, sem mexer na sua pasta:

$ git grep manteiga HEAD~2
HEAD~2:bolo.txt:2 colheres de manteiga
HEAD~2:brigadeiro.txt:1 colher de manteiga     «
$ git grep -n manteiga HEAD~4

Dois commits atrás (HEAD~2, o "Melhora a massa do bolo"), o brigadeiro ainda tinha manteiga: a lembrança da Ana estava certa. Cada linha agora começa com o commit (HEAD~2:). Já no primeiro commit (HEAD~4), ninguém tinha manteiga. Dá para usar um hash ou um branch no lugar do HEAD~2.

2. Quando o texto mudou: git log -S

Testar commit por commit com o git grep cansa. O git log -S faz isso por você: mostra só os commits em que o texto apareceu ou sumiu.

$ git log --oneline -S manteiga
f3c1f5b Simplifica o brigadeiro
877bf83 Melhora a massa do bolo
7accc6b Adiciona o brigadeiro
-S manteiga
Só os commits que mudaram o número de vezes que manteiga aparece nos arquivos: commits que acrescentaram ou tiraram a palavra. Os programadores chamam isso de "picareta" (pickaxe): o -S cava o histórico atrás de um texto.

Leia de baixo para cima: o 7accc6b criou o brigadeiro já com manteiga; o 877bf83 pôs manteiga no bolo; o f3c1f5b tirou a manteiga do brigadeiro. Para focar só no brigadeiro, acrescente o arquivo:

$ git log -S manteiga --oneline -- brigadeiro.txt
f3c1f5b Simplifica o brigadeiro
7accc6b Adiciona o brigadeiro

Vendo a mudança: -p

Com -p (de patch, a "diferença"), cada commit vem com a mudança completa, como no git show:

$ git log -S manteiga -p -- brigadeiro.txt
commit f3c1f5b95e46a362b1b163a80a065a7831042c7e
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Simplifica o brigadeiro

diff --git a/brigadeiro.txt b/brigadeiro.txt
index 704d92c..283e3c7 100644
--- a/brigadeiro.txt
+++ b/brigadeiro.txt
@@ -1,3 +1,2 @@
 Brigadeiro
 1 lata de leite condensado
-1 colher de manteiga     «

commit 7accc6b2a7d159d8d271f86d5a2c2b4e4faf4174
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona o brigadeiro

diff --git a/brigadeiro.txt b/brigadeiro.txt
new file mode 100644
index 0000000..704d92c
--- /dev/null
+++ b/brigadeiro.txt
@@ -0,0 +1,3 @@

Mistério resolvido: a manteiga entrou com o brigadeiro (+1 colher de manteiga, a linha com + foi acrescentada) e saiu no commit "Simplifica o brigadeiro" (-1 colher de manteiga, a linha com - foi apagada). Se a Ana quiser a manteiga de volta, ela sabe qual commit olhar (e pode desfazê-lo com o git revert).

Missão: o repositório desta aula já está pronto. Descubra em que commit a manteiga saiu da receita de brigadeiro, até ver na tela a linha -1 colher de manteiga. Use git log -S manteiga -p -- brigadeiro.txt, ou olhe todas as mudanças do arquivo com git log -p -- brigadeiro.txt.

3. -S × -G: a pegadinha da contagem

O -S procura commits que mudaram a quantidade de vezes que o texto aparece. Isso tem uma consequência curiosa. No último commit, a Ana trocou 500 g de polvilho por 400 g de polvilho. Veja:

$ git log --oneline -S '500 g'
54d0fe5 (HEAD -> main) Ajusta o pão de queijo
3bafa7d Adiciona as primeiras receitas
$ git log --oneline -S 'g de polvilho'
3bafa7d Adiciona as primeiras receitas

Com '500 g', o "Ajusta o pão de queijo" aparece: antes havia 1 "500 g", depois, 0. Mas com 'g de polvilho' ele não aparece: a linha mudou, porém o texto "g de polvilho" continuou lá, 1 vez antes e 1 vez depois. Para o -S, nada mudou.

Para achar qualquer commit que mexeu numa linha com o texto, use -G:

$ git log --oneline -G 'g de polvilho'
54d0fe5 (HEAD -> main) Ajusta o pão de queijo
3bafa7d Adiciona as primeiras receitas
-G 'g de polvilho'
Commits cuja mudança (as linhas com + e -) contém o texto. O texto do -G é sempre uma expressão regular; o do -S é um texto comum.

Regra prática: -S para "quando esta palavra entrou ou saiu?"; -G para "quando mexeram numa linha com esta palavra?".

Quando dá errado

As mensagens de erro abaixo saem em inglês mesmo com o sistema em português: a tradução do Git no Ubuntu é parcial (a aula Seu Primeiro Commit explica).

O git grep não mostrou nada 
$ git grep chocolate
$ echo $?
1

O que aconteceu: nenhum arquivo rastreado tem "chocolate". O git grep, como o grep, não escreve nada e sai com o código 1 ("não achei"); com resultado, o código é 0.

Como resolver: confira as maiúsculas (use -i), e lembre que o git grep não olha arquivos que nunca foram adicionados ao Git nem os ignorados. Se o arquivo é novo, faça o git add dele, ou use git grep --untracked chocolate, que inclui os arquivos novos.

fatal: no pattern given 
$ git grep
fatal: no pattern given

O que aconteceu: "nenhum padrão informado": faltou dizer o que procurar.

Como resolver: git grep palavra. Com espaços, use aspas: git grep '1 colher'.

error: switch `S' requires a value 
$ git log -S
error: switch `S' requires a value

O que aconteceu: "a opção S exige um valor": o texto procurado tem de vir logo depois do -S.

Como resolver: git log -S manteiga (ou grudado: -Smanteiga). Com espaços, aspas: git log -S '500 g'.

O -S não achou o commit que eu sei que mexeu na linha

O que aconteceu: é a pegadinha da seção 3: se o texto continuou aparecendo o mesmo número de vezes (a linha mudou em volta dele), o -S não considera mudança.

Como resolver: troque por -G, ou procure um pedaço do texto que de fato entrou ou saiu ('500 g').

5. Um commit trocou 500 g de polvilho por 400 g de polvilho. Por que git log -S 'g de polvilho' não o mostra?

Resumo

  • git grep texto procura nos arquivos rastreados (-n linha, -i sem maiúsculas, -c conta); com um commit no fim, procura no passado.
  • git log -S texto acha os commits em que o texto entrou ou saiu; com -p, mostra a mudança; com -- arquivo, foca num arquivo.
  • -S olha a contagem; -G olha qualquer linha mudada com o texto; --grep olha só as mensagens.
  • Busca sem resultado não é erro: o git grep não mostra nada e devolve o código 1.
