Git GitHub: Criando um Repositório

A Ana já tem a conta no GitHub e, no notebook, o repositório receitas com alguns commits. Falta o lugar no GitHub para onde esses commits vão. Nesta aula ela cria esse lugar, um repositório no GitHub, e envia o projeto para lá.

Você vai aprender
  • Como criar um repositório no site do GitHub e o que significa cada opção (nome, descrição, público/privado, README, .gitignore, licença).
  • Por que, para um projeto que já existe no computador, o repositório no GitHub deve nascer vazio.
  • Como ligar o projeto local ao GitHub com git remote add origin e enviar com git push -u origin main.
  • O outro caminho: criar no GitHub primeiro e fazer git clone.
A parte do site é ilustrativa. O site do GitHub não roda no laboratório do guia: os passos seguem a documentação oficial (Criar um repositório). Já as saídas do terminal são reais, colhidas num servidor de treino que faz o papel do GitHub.

A ideia antes dos cliques

Criar o repositório no GitHub é como reservar uma gaveta com o seu nome num arquivo da biblioteca. A gaveta vem vazia. Depois, você leva seus papéis (os commits) do caderno de casa para lá. São dois passos diferentes:

  1. Reservar a gaveta: no site, criar o repositório (uma vez só).
  2. Levar os papéis: no terminal, git remote add (anotar o endereço da gaveta) e git push (levar os commits).

Passo 1: criar o repositório no site

  1. No canto superior direito de qualquer página do GitHub, clique no ícone + e escolha Novo repositório.
  2. Proprietário: a conta dona do repositório. Para a Ana, ana-souza.
  3. Nome do repositório: receitas. Use o mesmo nome da pasta, para não se confundir. Segundo a documentação, o nome tem até 100 caracteres, com letras sem acento, números, ., - e _.
  4. Descrição (opcional): uma frase, como "Site de receitas da família".
  5. Visibilidade: público (qualquer pessoa vê; só você e quem você convidar alteram) ou privado (só você e quem você convidar veem).
  6. README, .gitignore e licença: deixe tudo desmarcado, porque a Ana já tem o projeto no notebook (veja o aviso abaixo).
  7. Clique em Criar repositório.
Projeto que já existe? Repositório vazio. Se você marcar o README (ou a licença, ou o .gitignore), o GitHub cria um commit lá. Esse commit não existe no seu notebook, e o seu primeiro git push é rejeitado, porque os dois históricos não têm nada em comum. A documentação avisa exatamente isso. Marque essas opções só quando for começar do zero e clonar (o outro caminho, mais abaixo).

Com o repositório vazio, o GitHub mostra uma página de Configuração rápida, com o endereço do repositório e um botão para copiá-lo. Há dois tipos de endereço:

Passo 2: ligar o projeto do computador ao GitHub

Agora é no terminal, dentro da pasta do projeto. Primeiro a Ana confere que o repositório local tem commits e ainda não tem nenhum remoto:

$ git log --oneline
4f68d0e (HEAD -> main) Adiciona receita de bolo          « dois commits, só no notebook
0e8cf93 Adiciona README
$ git remote -v
                                                        « nenhuma linha: nenhum remoto ainda

O git remote -v não respondeu nada: o repositório ainda não sabe que o GitHub existe.

git remote add origin ENDEREÇO

git remote add
"Cadastre um remoto": anote um apelido para um endereço (aula completa em git remote).
origin
O apelido. origin é o nome tradicional do remoto principal.
ENDEREÇO
O endereço copiado da página do GitHub.
$ git remote add origin https://github.com/ana-souza/receitas.git
$ git remote -v
origin  https://github.com/ana-souza/receitas.git (fetch)      « de onde buscar
origin  https://github.com/ana-souza/receitas.git (push)       « para onde enviar

O git remote add não mostra nada quando dá certo, e não envia nada: só anota o endereço. O -v (verbose) mostra o endereço duas vezes, uma para buscar (fetch) e outra para enviar (push); normalmente são iguais.

git push -u origin main

Agora sim, os commits vão para o GitHub. O -u liga o main do notebook ao main do GitHub, para que os próximos envios sejam só git push (detalhes em git push):

$ git push -u origin main
Enumerating objects: 6, done.
Counting objects: 100% (6/6), done.
Delta compression using up to 4 threads
Compressing objects: 100% (3/3), done.
Writing objects: 100% (6/6), 504 bytes | 504.00 KiB/s, done.
Total 6 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
To https://github.com/ana-souza/receitas.git
 * [new branch]      main -> main                          « o main foi criado no GitHub
branch 'main' set up to track 'origin/main'.                « e ligado ao do notebook
$ git status
No ramo main
Your branch is up to date with 'origin/main'.               « em dia com o GitHub

nothing to commit, working tree clean

No GitHub de verdade, antes dessa saída o Git pede para você provar quem é. Com endereço HTTPS, entra o token; com endereço SSH, a chave SSH. (O servidor de treino do guia não pede.)

No site, ao recarregar a página do repositório, a Ana vê os arquivos, o número de commits e, se houver um README.md, o conteúdo dele formatado logo abaixo da lista de arquivos (veja O README e o Markdown).

Experimente

No terminal abaixo, a Ana já tem o repositório receitas com dois commits. Um repositório vazio de treino, na pasta ~/servidor/receitas.git, faz o papel do repositório recém-criado no GitHub: use esse caminho no lugar do endereço https://….

Missão: cadastre o remoto origin apontando para ~/servidor/receitas.git, confira com git remote -v e envie o main já criando o par. Termine com git status.

O outro caminho: criar no GitHub e clonar

Se você ainda não começou o projeto, é mais simples fazer ao contrário: criar o repositório no site com o README marcado e depois cloná-lo. O git clone já traz o remoto origin configurado e o main ligado a ele:

$ git clone https://github.com/ana-souza/tcc.git
Cloning into 'tcc'...                                       « "clonando em tcc"
remote: Enumerating objects: 3, done.
remote: Counting objects: 100% (3/3), done.
remote: Total 3 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
Receiving objects: 100% (3/3), done.
$ cd tcc
$ ls
README.md                                                   « o README que o GitHub criou
$ git log --oneline
6339aaa (HEAD -> main, origin/main, origin/HEAD) Initial commit
$ git branch -vv
* main 6339aaa [origin/main] Initial commit                 « já ligado ao origin/main
$ git remote -v
origin  https://github.com/ana-souza/tcc.git (fetch)
origin  https://github.com/ana-souza/tcc.git (push)

O repositório do TCC da Ana foi criado com o README marcado: o GitHub fez o primeiro commit, com a mensagem Initial commit. O clone trouxe esse commit, cadastrou o origin e ligou o main a ele. A partir daqui é só trabalhar e dar git push (veja git clone).

Quando dá errado

"Repository not found" (endereço errado) 
$ git remote add origin https://github.com/ana-souza/lojnha.git
$ git push -u origin main
remote: Repository not found.
fatal: repository 'https://github.com/ana-souza/lojnha.git/' not found

O que aconteceu: o endereço tem um erro de digitação (lojnha). Repare que o git remote add aceitou sem reclamar: ele não confere se o endereço existe. Só o push descobre. A mesma mensagem aparece se o repositório ainda não foi criado no site, ou se é privado e a sua conta não tem acesso.

Como resolver: copie de novo o endereço na página do repositório e corrija com git remote set-url:

$ git remote set-url origin https://github.com/ana-souza/lojinha.git
$ git remote -v
origin  https://github.com/ana-souza/lojinha.git (fetch)
origin  https://github.com/ana-souza/lojinha.git (push)
$ git push -u origin main
Enumerating objects: 3, done.
Counting objects: 100% (3/3), done.
Writing objects: 100% (3/3), 237 bytes | 237.00 KiB/s, done.
Total 3 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
To https://github.com/ana-souza/lojinha.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
"remote origin already exists" 
$ git remote add origin https://github.com/ana-souza/receitas.git
error: remote origin already exists.

O que aconteceu: "o remoto origin já existe": você já tinha cadastrado (ou o repositório veio de um git clone).

Como resolver: confira com git remote -v. Se o endereço está certo, não precisa fazer nada. Se quer trocar, use git remote set-url origin URL-NOVA (veja git remote).

Push rejeitado logo no primeiro envio (fetch first)

O que aconteceu: o repositório foi criado no site com README (ou licença, ou .gitignore): o GitHub tem um commit que o seu notebook não tem.

Como resolver: traga o commit com git pull --no-rebase --allow-unrelated-histories origin main e envie de novo. O passo a passo, com as saídas, está em Push Rejeitado. Outra saída, se o repositório ainda está vazio de conteúdo seu: apague-o no site e crie de novo, sem marcar nada.

"src refspec main does not match any"

O que aconteceu: o repositório local ainda não tem commit (ou o branch tem outro nome, como master).

Como resolver: faça o primeiro commit; confira o nome com git branch. Veja git push.

O nome do repositório já existe na sua conta

O que aconteceu: a sua conta já tem um repositório com esse nome, e o formulário não deixa criar outro igual: os nomes são únicos dentro de cada conta.

Como resolver: escolha outro nome, ou use o repositório que já existe.

Resumo

  • Criar o repositório no GitHub = reservar o lugar; enviar os commits é outro passo, no terminal.
  • Projeto que já existe no computador: crie o repositório vazio, depois git remote add origin URL e git push -u origin main.
  • Projeto novo: crie com README e faça git clone.
  • Marcou o README sem querer? O push é rejeitado; traga o commit do GitHub com git pull --allow-unrelated-histories (ou recrie o repositório vazio).
  • Errou o endereço? git remote set-url origin URL-CERTA.
