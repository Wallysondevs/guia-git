Git Submódulos

A Ana criou um repositório só com o visual dos sites dela, o estilos (fontes, cores, o arquivo estilo.css). Agora ela quer usar esse visual no site de receitas e, depois, no portfólio, sem copiar e colar o arquivo em cada projeto (e sem ter de atualizar cada cópia à mão). O Git tem um jeito de colocar um repositório dentro de outro, guardando exatamente qual versão está sendo usada: o submódulo (git submodule).

Você vai aprender
  • O que é um submódulo e o que o repositório "de fora" guarda dele: só um ponteiro para um commit.
  • Como acrescentar um com git submodule add, e o que são o .gitmodules e o Subproject commit.
  • Como clonar um projeto com submódulos (a pasta vazia, --recurse-submodules, git submodule update --init).
  • Como atualizar o submódulo (update --remote) e trazer a atualização de outra pessoa.
  • Como remover um submódulo, e os erros reais mais comuns.

Os comandos desta aula rodaram no Git 2.53 do Ubuntu da Ana (usuária ana, computador notebook), com o "GitHub de mentira" do laboratório (o Git conversa com ele como conversaria com o de verdade). As mensagens do git submodule ainda não têm tradução em português nessa versão e saem em inglês; a aula traduz cada uma.

A ideia: a receita que diz "use o molho da página 12"

Num livro de receitas, a lasanha não copia a receita do molho de tomate: ela diz "use o molho da página 12". Se o molho melhorar, quem atualiza é a página 12. O submódulo é essa referência, com um detalhe a mais: a lasanha diz qual edição do molho usar ("o molho da página 12, edição de março"). Mesmo que o molho ganhe uma edição nova, a lasanha continua usando a de março até alguém decidir trocar.

No livroNo Git
A receita da lasanhaO repositório principal (receitas), o superprojeto
A receita do molho, em outra páginaO submódulo (estilos), um repositório completo com o seu próprio histórico
"página 12, edição de março"O endereço do submódulo (no .gitmodules) e o commit exato usado
Trocar para a edição novaAtualizar o submódulo e fazer um commit no superprojeto

1. Acrescentar um submódulo: git submodule add

O repositório estilos já está no GitHub da Ana. Na pasta do site de receitas:

$ git submodule add https://github.com/ana-souza/estilos.git estilos
Cloning into '/home/ana/receitas/estilos'...
git submodule add
"Acrescente um submódulo."
https://github.com/ana-souza/estilos.git
O endereço do repositório que vai entrar, o mesmo que você usaria no git clone.
estilos
A pasta onde ele vai ficar, dentro do receitas. Sem esse argumento, o Git usa o nome do repositório.
Cloning into '/home/ana/receitas/estilos'...
"Clonando em …": o Git fez um clone completo do estilos dentro da pasta.
$ git status
No ramo main
Your branch is up to date with 'origin/main'.

Mudanças a serem submetidas:
  (use "git restore --staged <file>..." to unstage)
	new file:   .gitmodules                  « arquivo novo: a lista de submódulos
	new file:   estilos                      « a pasta aparece como UM item, não como arquivos

$ cat .gitmodules
[submodule "estilos"]
	path = estilos
	url = https://github.com/ana-souza/estilos.git
$ ls estilos
README.md
estilo.css

O git submodule add já deixou duas coisas na área de preparo (Mudanças a serem submetidas):

  • o .gitmodules, um arquivo de texto comum, que diz onde fica cada submódulo (path, a pasta) e de onde ele vem (url). Ele vai junto no commit, para quem clonar saber de onde baixar;
  • a pasta estilos, que o Git trata como um item só. Os arquivos dela (estilo.css, README.md) não entram no histórico do receitas: eles pertencem ao histórico do estilos.

O que o superprojeto guarda: o ponteiro

$ git diff --cached estilos
diff --git a/estilos b/estilos
new file mode 160000
index 0000000..05a34b8
--- /dev/null
+++ b/estilos
@@ -0,0 +1 @@
+Subproject commit 05a34b807cfbac6a88c8e4e8d986086f3bc0f4ef

Esta é a parte mais importante da aula. Para o receitas, a pasta estilos é uma linha só: Subproject commit 05a34b8… ("commit do subprojeto"). É a "edição de março" da receita do molho: o hash do commit do estilos que este site usa. O mode 160000 é o jeito do Git marcar "isto é um submódulo, não um arquivo nem uma pasta comum".

$ git commit -m "Adiciona os estilos como submódulo"
[main b5287c9] Adiciona os estilos como submódulo
 2 files changed, 4 insertions(+)
 create mode 100644 .gitmodules
 create mode 160000 estilos                    « 160000 = submódulo
$ git submodule status
 05a34b807cfbac6a88c8e4e8d986086f3bc0f4ef estilos (heads/main)
$ git push
To https://github.com/ana-souza/receitas.git
   2cbd07a..b5287c9  main -> main

O git submodule status lista cada submódulo: o commit em uso, a pasta e, entre parênteses, um nome para aquele commit (aqui, o branch main do estilos). No GitHub (ilustrativo), a pasta estilos aparece com um ícone diferente e o nome seguido de @ e do começo do hash, e funciona como um link para o repositório estilos naquele commit.

Pratique no seu computador

O terminal simulado do guia não tem o git submodule, então esta prática é no seu terminal de verdade, com dois repositórios seus no GitHub (por exemplo, um de testes e o do seu site):

  1. No repositório principal, rode git submodule add https://github.com/SEU-USUARIO/OUTRO-REPO.git pasta.
  2. Olhe o git status, o cat .gitmodules e o git diff --cached pasta (procure a linha Subproject commit).
  3. Faça o commit e rode git submodule status.

2. Clonar um projeto que tem submódulos

Aqui está a pegadinha mais famosa dos submódulos. Um git clone comum traz o superprojeto, mas deixa a pasta do submódulo vazia:

$ git clone https://github.com/ana-souza/receitas.git copia
Cloning into 'copia'...
$ cd copia
$ ls estilos
$ git submodule status
-05a34b807cfbac6a88c8e4e8d986086f3bc0f4ef estilos     « o "-" no começo: ainda não foi baixado

O ls estilos não mostrou nada: a pasta existe, mas está vazia. O - no começo da linha do git submodule status quer dizer "submódulo não inicializado". O site, aberto agora, estaria sem estilo nenhum. Para baixar:

$ git submodule update --init
Submodule 'estilos' (https://github.com/ana-souza/estilos.git) registered for path 'estilos'
Cloning into '/home/ana/copia/estilos'...
Submodule path 'estilos': checked out '05a34b807cfbac6a88c8e4e8d986086f3bc0f4ef'
$ ls estilos
README.md
estilo.css
$ git submodule status
 05a34b807cfbac6a88c8e4e8d986086f3bc0f4ef estilos (heads/main)
git submodule update
"Deixe cada submódulo no commit que o superprojeto aponta."
--init
Antes, registra os submódulos do .gitmodules que ainda não foram registrados neste clone: Submodule 'estilos' (…) registered for path 'estilos'.
Submodule path 'estilos': checked out '05a34b8…'
"O submódulo da pasta estilos foi colocado no commit 05a34b8…", exatamente o do ponteiro.

Ou, já no clone, tudo de uma vez:

$ git clone --recurse-submodules https://github.com/ana-souza/receitas.git copia2
Cloning into 'copia2'...
Submodule 'estilos' (https://github.com/ana-souza/estilos.git) registered for path 'estilos'
Cloning into '/home/ana/copia2/estilos'...
Submodule path 'estilos': checked out '05a34b807cfbac6a88c8e4e8d986086f3bc0f4ef'

O --recurse-submodules ("recursivamente, com os submódulos") clona o superprojeto e, em seguida, faz o submodule update --init sozinho.

O submódulo fica em HEAD destacado 
$ cd estilos
$ git status
HEAD detached at 05a34b8
nothing to commit, working tree clean

Depois de um submodule update, o submódulo não está em branch nenhum: ele está no commit exato do ponteiro (veja HEAD Destacado). Para só usar o submódulo, isso é perfeito. Para mexer nele, entre na pasta e faça git switch main antes de editar; um commit feito em HEAD destacado fica solto e é fácil de perder.

Pratique no seu computador

Depois de enviar o commit do submódulo (git push), clone o repositório principal numa pasta nova sem --recurse-submodules, confira que a pasta do submódulo está vazia (ls pasta e o - no git submodule status) e baixe-o com git submodule update --init.

3. Atualizar o submódulo

O Bruno melhorou o repositório estilos: os títulos agora são vermelho-escuros. O site de receitas não muda sozinho: ele continua apontando para 05a34b8, a "edição de março". Trocar de edição é uma decisão, e vira um commit.

$ git submodule update --remote
From https://github.com/ana-souza/estilos
   05a34b8..f9b6a7d  main       -> origin/main
Submodule path 'estilos': checked out 'f9b6a7d1394ce388dd9c4b0f8cd62ffbe4fda17a'
$ git status
No ramo main
Your branch is up to date with 'origin/main'.

Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   estilos (novas submissões)

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")
$ git diff
diff --git a/estilos b/estilos
index 05a34b8..f9b6a7d 160000
--- a/estilos
+++ b/estilos
@@ -1 +1 @@
-Subproject commit 05a34b807cfbac6a88c8e4e8d986086f3bc0f4ef
+Subproject commit f9b6a7d1394ce388dd9c4b0f8cd62ffbe4fda17a
--remote
Em vez do commit do ponteiro, busca o commit mais novo do branch do submódulo no GitHub (a main do estilos) e coloca a pasta nele.
modified: estilos (novas submissões)
"Modificado: estilos (commits novos)". A pasta do submódulo está num commit diferente do ponteiro guardado.
-Subproject commit 05a34b8… / +Subproject commit f9b6a7d…
O git diff mostra a mudança como a troca de uma linha: o ponteiro velho sai, o novo entra.

Para o site passar a usar a edição nova, a Ana faz o commit do ponteiro, como de qualquer arquivo:

$ git add estilos
$ git commit -m "Atualiza os estilos"
[main 6864716] Atualiza os estilos
 1 file changed, 1 insertion(+), 1 deletion(-)
$ git push
To https://github.com/ana-souza/receitas.git
   b5287c9..6864716  main -> main

Do outro lado: trazendo a atualização

Na pasta copia, um git pull traz o ponteiro novo, mas não muda a pasta do submódulo:

$ git pull
From https://github.com/ana-souza/receitas
   b5287c9..6864716  main       -> origin/main
Fetching submodule estilos
From https://github.com/ana-souza/estilos
   05a34b8..f9b6a7d  main       -> origin/main
Updating b5287c9..6864716
Fast-forward
 estilos | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
$ git status
No ramo main
Your branch is up to date with 'origin/main'.

Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   estilos (novas submissões)

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

Confuso: o git status diz novas submissões, mas aqui o submódulo está atrasado (ainda em 05a34b8), e o ponteiro que chegou é que é novo. O Git só diz "é diferente". Não faça git add estilos aqui: isso voltaria o ponteiro para a versão velha. O certo é pôr o submódulo no commit do ponteiro:

$ git submodule update
Submodule path 'estilos': checked out 'f9b6a7d1394ce388dd9c4b0f8cd62ffbe4fda17a'
$ git status
No ramo main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
$ cat estilos/estilo.css
body { font-family: sans-serif; }
h1 { color: darkred; }                       « a mudança do Bruno chegou
Para o pull já atualizar os submódulos

Com a configuração submodule.recurse ligada, o git pull (e o git switch, entre outros) faz o submodule update sozinho. Em outra cópia, a copia2:

$ git config submodule.recurse true
$ git pull
From https://github.com/ana-souza/receitas
   b5287c9..6864716  main       -> origin/main
Fetching submodule estilos
From https://github.com/ana-souza/estilos
   05a34b8..f9b6a7d  main       -> origin/main
Updating b5287c9..6864716
Fast-forward
 estilos | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
Submodule path 'estilos': checked out 'f9b6a7d1394ce388dd9c4b0f8cd62ffbe4fda17a'     « o update veio junto
$ git status --short

Sem --global, a configuração vale só para este repositório; com git config --global submodule.recurse true, vale para todos os seus (veja git config).

4. Remover um submódulo

$ git rm estilos
rm 'estilos'
$ git status
No ramo main
Your branch is up to date with 'origin/main'.

Mudanças a serem submetidas:
  (use "git restore --staged <file>..." to unstage)
	modified:   .gitmodules                « a entrada do estilos saiu do .gitmodules
	deleted:    estilos

$ cat .gitmodules
$ ls
README.md
index.html

O git rm (veja git rm) apagou a pasta e já tirou o submódulo do .gitmodules, que ficou vazio. Falta só o commit (git commit -m "Remove o submódulo estilos"). Uma cópia do repositório do submódulo continua guardada dentro de .git/modules/estilos, para o caso de você voltar a um commit antigo que ainda o usa.

Submódulo ou outra coisa?

SituaçãoMelhor opção
Um repositório seu (ou de terceiros) usado por vários projetos, e você quer controlar a versão exataSubmódulo
Uma biblioteca de uma linguagem (JavaScript, Python, PHP…)O gerenciador de pacotes da linguagem (npm, pip, composer…): é feito para isso e mais simples para todos
Um arquivo pequeno que quase nunca mudaCopiar o arquivo mesmo
Dois projetos que sempre mudam juntosTalvez devessem ser um repositório só

Submódulos são poderosos, mas cobram atenção de todo mundo da equipe: cada pessoa precisa lembrar de clonar com --recurse-submodules e de rodar o submodule update. Use quando a vantagem (a versão exata, o repositório separado) compensar.

Quando dá errado

Clonei e a pasta do submódulo está vazia

É o comportamento normal do git clone sem --recurse-submodules (seção 2). O git submodule status mostra um - no começo da linha. Como resolver: git submodule update --init. Se houver submódulos dentro de submódulos, acrescente --recursive.

modified: estilos (novas submissões) e eu não mexi em nada

O submódulo está num commit diferente do ponteiro. Duas causas: (1) você rodou git submodule update --remote ou mexeu no submódulo, e a mudança é sua: se quer usá-la, git add estilos e commit; (2) você deu git pull e o ponteiro mudou: rode git submodule update. Como saber qual é: git diff estilos mostra o ponteiro guardado (-Subproject commit) e o commit da pasta (+Subproject commit); git log -1 --oneline dentro da pasta mostra em que commit ela está.

fatal: 'estilos' already exists in the index 
$ git submodule add https://github.com/ana-souza/estilos.git estilos
fatal: 'estilos' already exists in the index

"estilos já existe no índice": já há algo rastreado com esse caminho (aqui, o próprio submódulo, acrescentado antes). Como resolver: escolha outra pasta ou, se era um diretório comum que você quer trocar por um submódulo, tire-o antes com git rm -r estilos e faça o commit.

Endereço errado: Repository not found 
$ git submodule add https://github.com/ana-souza/estilo.git css
Cloning into '/home/ana/receitas/css'...
remote: Repository not found.
fatal: repository 'https://github.com/ana-souza/estilo.git/' not found
fatal: clone of 'https://github.com/ana-souza/estilo.git' into submodule path '/home/ana/receitas/css' failed

Faltou um s no nome (estilo em vez de estilos). O clone falhou e nada foi acrescentado (o git status continua limpo). Como resolver: confira o endereço no GitHub e rode de novo. Repositórios privados também dão essa mensagem quando falta permissão (veja HTTPS e Token e Chave SSH).

fatal: transport 'file' not allowed 
$ git submodule add /home/ana/t/estilos.git estilos
Cloning into '/home/ana/t/receitas/estilos'...
fatal: transport 'file' not allowed
fatal: clone of '/home/ana/t/estilos.git' into submodule path '/home/ana/t/receitas/estilos' failed

"Transporte 'file' não permitido". O que aconteceu: o endereço era uma pasta do próprio computador. Por segurança, desde a versão 2.38.1 o Git não aceita submódulos vindos de pastas locais, a não ser que você libere. Como resolver: use o endereço do GitHub (o caso normal). Para um teste local, libere só naquele comando: git -c protocol.file.allow=always submodule add /caminho/estilos.git estilos.

Fiz commit dentro do submódulo e ele "sumiu"

Depois de um submodule update, o submódulo fica em HEAD detached. Um commit feito ali não pertence a branch nenhum, e o próximo update tira a pasta dele. Como resolver: o commit ainda está no git reflog do submódulo (rode dentro da pasta estilos); crie um branch nele com git switch -c resgate HASH. Para evitar: antes de editar, cd estilos e git switch main.

Resumo

  • Submódulo é um repositório dentro de outro. O superprojeto guarda só o .gitmodules (pasta e endereço) e um ponteiro para um commit exato (Subproject commit …, modo 160000).
  • git submodule add URL pasta acrescenta; depois, commit.
  • Clonar: git clone --recurse-submodules, ou git submodule update --init depois de um clone comum (pasta vazia, - no status).
  • Atualizar para a versão nova: git submodule update --remote, git add pasta e commit. Trazer a atualização de outra pessoa: git pull e git submodule update (ou submodule.recurse true).
  • O submódulo fica em HEAD destacado: para editar, git switch main dentro dele antes.
  • Remover: git rm pasta e commit.
