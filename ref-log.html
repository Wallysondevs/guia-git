Git Formatos do git log

O git log é o diário do projeto, e dá para lê-lo de muitos jeitos: uma linha por commit, com o desenho dos branches, só os commits do Bruno, só os da última semana, só os que mexeram num arquivo, ou num formato que você mesmo monta. Esta página junta essas opções em tabelas, com a saída real do Git da máquina da Ana.

Como ler esta página
  • Os exemplos usam o repositório receitas da Ana, com o histórico abaixo. As datas são fixas (o laboratório do guia vive em 15/10/2026), e os hashes mudam no seu computador.
  • As opções se combinam à vontade: git log --oneline --graph --all -5.
  • Para aprender com calma: git log, Filtros e Formatos, log --graph e Procurando no Histórico.
  • Saída longa abre no paginador (less): setas para rolar, q para sair.

O histórico de exemplo

O main da Ana tem cinco commits, com a tag v1.0 no quarto. Depois da tag, o Bruno fez um commit num branch bolo, que ainda não foi juntado ao main, e a Ana fez mais um no main. O desenho com --graph --all mostra os dois galhos:

| * 152d79c (HEAD -> main) Atualiza o título do README   « o mais novo do main (onde a Ana está)
|/                                                   « aqui os dois galhos se separam
* c8d0fdc (tag: v1.0) Adiciona receita de pudim
* 8426608 Adiciona cobertura de chocolate ao bolo
* c94a9e3 Adiciona receita de bolo
* fe996fb Primeiro commit                            « o mais antigo fica embaixo

Os nomes entre parênteses

No terminal, o git log mostra sozinho os nomes que apontam para cada commit: HEAD -> main (você está no main), tag: v1.0, bolo, origin/main. Quando a saída vai para um arquivo ou para outro programa (git log --oneline > lista.txt), eles somem; para forçar, use --decorate.

Author: Bruno Lima <bruno@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

$ git log --oneline --grep=bolo                 « "bolo" na mensagem
8426608 Adiciona cobertura de chocolate ao bolo
c94a9e3 Adiciona receita de bolo
$ git log --oneline -S"chocolate"               « "chocolate" entrou ou saiu do conteúdo
8426608 Adiciona cobertura de chocolate ao bolo
$ git log --oneline -- pudim.txt                « só os commits que mexeram no pudim.txt
c8d0fdc (tag: v1.0) Adiciona receita de pudim
$ git log --oneline --until=2026-09-30          « nenhum commit antes de outubro: nada aparece

Um filtro que não encontra nada não dá erro: a lista simplesmente sai vazia. Vários filtros juntos precisam ser todos verdadeiros (--author=Ana --since=2026-10-01 = da Ana e de outubro em diante); a exceção são vários --grep, em que basta um casar (use --all-match para exigir todos).

Missão: o Bruno fez um commit num outro branch. Use o git log para mostrar só os commits dele, procurando em todos os branches.

Intervalos: comparando branches

EscritaMostra os commits…Exemplo
A..BQue estão em B e não em A ("o que B tem a mais").git log main..bolo = o que o bolo traria num merge
A...BQue estão em um dos dois, mas não em ambos (com --left-right, marca < e >).git log --left-right --oneline main...bolo
^A B / B --not AO mesmo que A..B, com outra escrita.git log bolo ^main
origin/main..mainOs seus commits que ainda não foram enviados (o que o push vai mandar).git log --oneline origin/main..main
main..origin/mainO que chegou no fetch e você ainda não juntou.git log --oneline main..origin/main

Formatos de data (--date)

Valem para o formato completo e para os marcadores %ad/%cd. Para deixar um formato como padrão: git config --global log.date iso (veja Configurações). Exemplos com o commit das 10:30 de 15/10/2026, fuso de Brasília (−03:00):

OpçãoResultado
(padrão) ou --date=defaultThu Oct 15 10:30:00 2026 -0300
--date=iso2026-10-15 10:30:00 -0300
--date=iso-strict2026-10-15T10:30:00-03:00 (o formato ISO 8601 "de verdade", bom para programas)
--date=short2026-10-15
--date=rfcThu, 15 Oct 2026 10:30:00 -0300 (o formato dos e-mails)
--date=localThu Oct 15 10:30:00 2026 (convertida para o fuso do seu computador, sem o fuso no fim)
--date=relative0 seconds ago (no laboratório, o relógio está parado no exato momento do commit; num commit de três dias atrás sairia 3 days ago. Neste Git, o texto sai em inglês mesmo com o sistema em português)
--date=humanRelativa para datas recentes, completa (sem o que se repete) para as antigas. Aqui: 0 seconds ago
--date=unix1792071000 (segundos desde 1/1/1970)
--date=format:'%d/%m/%Y %H:%M'15/10/2026 10:30 (os códigos são os do date: %d dia, %m mês, %Y ano, %H:%M hora)
--date=format-local:'%A, %d de %B'quinta, 15 de outubro (nomes de dia e mês no idioma do sistema)

Marcadores do --pretty=format

Monte a linha que quiser: tudo que não é marcador sai como está. Use aspas para o shell não quebrar o texto nos espaços. --pretty=format:"…" separa os commits com quebra de linha; --pretty=tformat:"…" (ou --format="…") põe uma quebra também depois do último.

%T / %tHash da árvore (a "fotografia" das pastas; veja Como o Git Guarda)703ae57

Quando dá errado

fatal: ambiguous argument … unknown revision or path

$ git log --oneline bolos
fatal: ambiguous argument 'bolos': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

O que aconteceu: o Git não achou nem um branch/commit chamado bolos nem um arquivo com esse nome na pasta ("argumento ambíguo: revisão desconhecida ou caminho fora da árvore de trabalho"). Quase sempre é erro de digitação (o branch é bolo) ou um arquivo que já foi apagado.

Como resolver: confira o nome com git branch ou ls. Se for um arquivo que não existe mais na pasta, ponha -- antes do nome, como a dica sugere: git log --oneline -- receita-antiga.txt.

O git log "travou" e não volta ao prompt

O que aconteceu: a lista era maior que a tela e o Git abriu o paginador less. Na última linha aparece : ou (END).

Como resolver: aperte q. Para não paginar uma vez: git --no-pager log; para limitar: git log -10.

A lista saiu vazia

O que aconteceu: nenhum commit passou nos filtros (autor escrito diferente, data fora do intervalo, commit em outro branch). Não é erro.

Como resolver: tire um filtro por vez; acrescente --all para procurar em todos os branches; lembre que --author diferencia maiúsculas (use -i para não diferenciar).
