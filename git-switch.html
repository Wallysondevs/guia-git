Git switch git 2.23+

Criar um branch com git branch só cola uma etiqueta nova: você continua onde estava. Para ir até outro branch e trabalhar nele, o comando é o git switch (em inglês, "trocar", "mudar"). Ele move o HEAD para o branch escolhido e deixa os arquivos da pasta iguais aos daquele ramo.

Você vai aprender
  • Mudar de branch com git switch NOME, e o que acontece com os arquivos da pasta.
  • Criar e mudar de uma vez com git switch -c NOME, inclusive a partir de outro ponto.
  • Voltar para o branch anterior com git switch -.
  • O que acontece com as mudanças que você ainda não commitou: quando elas vão junto e quando o Git se recusa a trocar.

As saídas vieram do Git real do Ubuntu 26.04, na máquina da Ana, com o sistema em português. O git switch existe desde o Git 2.23 (de 2019). Em tutoriais mais antigos você vai ver o git checkout fazendo o mesmo papel: ele tem aula própria, git checkout: o Comando Antigo.

A ideia: trocar de caderno na mesa

A Ana tem vários cadernos (os branches) e uma mesa (a pasta do projeto). Ela só consegue escrever no caderno que está aberto na mesa. O git switch é guardar o caderno aberto e abrir outro: a mesa passa a mostrar as páginas do caderno novo.

E se tiver uma folha solta, rabiscada, em cima da mesa (uma mudança ainda não commitada)? Se ela não atrapalha, continua na mesa depois da troca. Se ela ia ser coberta por uma página diferente do outro caderno, o Git para e avisa, para você não perder o rabisco. Os dois casos estão na seção 5.

1. Mudar para um branch que já existe

A Ana tem o repositório receitas com três commits no main e acabou de criar o branch sobremesas:

$ git branch sobremesas
$ git switch sobremesas
Switched to branch 'sobremesas'
$ git switch sobremesas
Already on 'sobremesas'
$ git status

Só o HEAD mudou de etiqueta. Os arquivos da pasta ficaram iguais, porque os dois branches apontam para o mesmo commit.

2. Os arquivos da pasta mudam junto

A Ana faz um commit com a receita de pudim no sobremesas e depois volta para o main:

$ echo 'Pudim de leite' > pudim.txt
$ git add pudim.txt && git commit -q -m 'Adiciona receita de pudim'
$ git log --oneline --graph --all
* d6f2336 (HEAD -> sobremesas) Adiciona receita de pudim
* 0244251 (main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README
$ ls
README.md  bolo.txt  pao.txt  pudim.txt
$ git switch main
Switched to branch 'main'
$ ls
README.md  bolo.txt  pao.txt              « o pudim.txt sumiu da pasta
$ git log --oneline --graph --all
* d6f2336 (sobremesas) Adiciona receita de pudim
* 0244251 (HEAD -> main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README

O pudim.txt estava na pasta e, depois do git switch main, não está mais. O Git deixou a pasta igual ao commit para onde o main aponta, e lá não existe pudim. O arquivo continua guardado no commit do sobremesas: voltando para lá, ele reaparece.

Antes:   A---B---C   ← main
                  \
                   D   ← sobremesas ← HEAD     pasta: README.md bolo.txt pao.txt pudim.txt

Depois:  A---B---C   ← main ← HEAD             pasta: README.md bolo.txt pao.txt
                  \
                   D   ← sobremesas            (D = d6f2336, o pudim)
Editor aberto?

Se o pudim.txt estiver aberto num editor de texto quando você trocar de branch, o editor pode continuar mostrando o conteúdo antigo, ou avisar que o arquivo foi apagado. Isso é normal: o arquivo mudou no disco. Feche e abra de novo.

3. Voltar para o anterior: git switch -

O - quer dizer "o branch onde eu estava antes", como o cd - do terminal. É ótimo para pular entre dois ramos:

$ git switch -
Switched to branch 'sobremesas'
$ git switch -
Switched to branch 'main'

4. Criar e mudar de uma vez: git switch -c

Na prática, quase sempre você cria um branch para trabalhar nele na hora. A opção -c (de create, "criar") faz as duas coisas:

$ git switch -c salgados
Switched to a new branch 'salgados'
$ git log --oneline --graph --all
* d6f2336 (sobremesas) Adiciona receita de pudim
* 0244251 (HEAD -> salgados, main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README
-c salgados
Cria o branch salgados no commit atual e já muda para ele. É o mesmo que git branch salgados seguido de git switch salgados.
Switched to a new branch 'salgados'
"Mudado para um ramo novo, 'salgados'": o Git avisa que criou o branch.

Criar a partir de outro ponto

Como no git branch, dá para dizer de onde o branch novo parte. A Ana quer um ramo bebidas que comece onde o sobremesas está, sem precisar ir até lá antes:

$ git switch main
Switched to branch 'main'
$ git switch -c bebidas sobremesas
Switched to a new branch 'bebidas'
$ git log --oneline --graph --all
* d6f2336 (HEAD -> bebidas, sobremesas) Adiciona receita de pudim
* 0244251 (salgados, main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README

Antes:   A---B---C   ← main ← HEAD
                  \  ← salgados
                   D   ← sobremesas

Depois:  A---B---C   ← main
                  \  ← salgados
                   D   ← sobremesas
                       ← bebidas ← HEAD

O bebidas nasceu no commit D, onde o sobremesas estava, e o HEAD foi junto para lá. O ponto de partida pode ser um branch, um hash (git switch -c bebidas d6f2336) ou algo como HEAD~1.

5. E as mudanças que ainda não foram commitadas?

Quando não atrapalham, elas vão junto

A Ana mudou o bolo.txt no main e, sem commitar, trocou para o salgados:

$ git switch main
Switched to branch 'main'
$ echo 'Bolo de cenoura com cobertura' > bolo.txt
$ git status --short
 M bolo.txt
$ git switch salgados
M       bolo.txt                           « "levando junto: bolo.txt modificado"
Switched to branch 'salgados'
$ git status --short
 M bolo.txt                                « a mudança continua aqui
$ git switch main
M       bolo.txt
Switched to branch 'main'

O M do git status --short (veja git status) continua lá depois da troca, e o próprio git switch avisou, antes do Switched…, que o bolo.txt está modificado (a linha M bolo.txt). As mudanças não commitadas não pertencem a nenhum branch: elas estão na pasta, e a pasta é uma só. Como o bolo.txt é igual nos dois ramos, o Git pôde trocar sem mexer nele, e a mudança veio junto.

Isso é útil quando você começa a mexer e percebe que devia estar em outro branch: troque com git switch (ou crie um com -c) e faça o commit lá.

Quando atrapalham, o Git se recusa a trocar

A Ana commitou a cobertura no main (agora o bolo.txt é diferente nos dois ramos), foi para o sobremesas, mexeu no bolo de novo e, sem commitar, tentou voltar:

$ git commit -q -am 'Melhora o bolo'
$ git switch -q sobremesas
$ echo 'Bolo de cenoura sem açúcar' > bolo.txt
$ git switch main
error: Your local changes to the following files would be overwritten by checkout:
        bolo.txt
Please commit your changes or stash them before you switch branches.
Aborting

Linha por linha:

error: Your local changes to the following files would be overwritten by checkout:
"Erro: as suas mudanças locais nos arquivos abaixo seriam sobrescritas pela troca". O bolo.txt do main é diferente do bolo.txt do sobremesas; para trocar, o Git teria de escrever a versão do main por cima do seu rabisco. (A palavra checkout aparece porque o switch usa, por baixo, o mesmo mecanismo do comando antigo.)
bolo.txt
A lista dos arquivos em perigo.
Please commit your changes or stash them before you switch branches.
"Por favor, faça commit das suas mudanças ou guarde-as (stash) antes de trocar de branch". A própria mensagem ensina as saídas.
Aborting
"Abortando": a troca foi cancelada.

Nada mudou: a Ana continua no sobremesas, com a mudança intacta. Ela tem três saídas:

  1. Commitar a mudança no branch atual e depois trocar (o mais comum).
  2. Guardar para depois com git stash, trocar, e recuperar mais tarde.
  3. Jogar a mudança fora e trocar mesmo assim, com --discard-changes (cuidado: o rabisco se perde):
$ git switch --discard-changes main
Switched to branch 'main'
$ git status
No ramo main
nothing to commit, working tree clean
$ cat bolo.txt
Bolo de cenoura com cobertura              « a versão do main; o "sem açúcar" se perdeu

Experimente

O terminal está na pasta receitas, com os três commits da Ana no main. Use ls e git log --oneline --graph --all depois de cada troca.

Missão: crie o branch salgados e mude para ele com um comando só. Lá, crie o arquivo coxinha.txt com o texto Coxinha e faça um commit. Depois, experimente git switch - duas vezes e veja a coxinha sumir e voltar no ls.

Missão: a Ana está no sobremesas, com uma mudança não commitada no bolo.txt. Tente git switch main e leia o erro. Depois, sem perder a mudança, faça um commit dela no sobremesas e aí sim volte para o main.

Formas diferentes de trocar de branch

ComandoO que faz
git switch NOMEMuda para um branch que existe
git switch -c NOMECria no commit atual e muda
git switch -c NOME PONTOCria a partir de outro commit ou branch e muda
git switch -Volta para o branch anterior
git branch NOME + git switch NOMEO mesmo que -c, em dois passos
git checkout NOME / git checkout -b NOMEO jeito antigo (aula própria)

Qual usar? git switch para trocar e git switch -c para criar e trocar. Eles fazem uma coisa só e recusam o que não é troca de branch (por exemplo, git switch num commit solto exige --detach; veja HEAD Destacado). O git checkout ainda funciona, mas faz muitas coisas diferentes com o mesmo nome.

Quando dá errado

fatal: invalid reference: bebidas 
$ git switch bebidas
fatal: invalid reference: bebidas

"Referência inválida": não existe branch (nem commit) com esse nome. Como confirmar: git branch lista os que existem; confira se não é erro de digitação ou de maiúscula. Como resolver: para criar o branch, use git switch -c bebidas.

fatal: a branch named 'salgados' already exists 
$ git switch -c salgados
fatal: a branch named 'salgados' already exists

O -c só cria branches novos. Como resolver: para ir até o que já existe, tire o -c: git switch salgados. (O -C, maiúsculo, recria o branch no ponto atual, jogando a etiqueta antiga fora: Switched to and reset branch 'salgados'. Commits que só esse branch tinha ficam sem etiqueta; evite.)

error: Your local changes … would be overwritten by checkout

A mensagem da seção 5. O que aconteceu: você tem mudanças não commitadas num arquivo que é diferente no outro branch. Como confirmar: git status mostra o arquivo como modificado. Como resolver: faça commit (git commit -am '…'), guarde com git stash (aula própria) ou, se a mudança não presta, descarte com git restore bolo.txt (ou git switch --discard-changes main).

error: The following untracked working tree files would be overwritten by checkout 
$ echo 'Doce de leite' > doce.txt
$ git switch sobremesas
error: The following untracked working tree files would be overwritten by checkout:
        doce.txt
Please move or remove them before you switch branches.
Aborting

"Os arquivos não rastreados abaixo seriam sobrescritos pela troca. Por favor, mova-os ou apague-os antes de trocar de branch." O que aconteceu: no main, a Ana criou um doce.txt novo (nunca commitado), mas no sobremesas existe um doce.txt commitado (o brigadeiro). Para trocar, o Git teria de apagar o arquivo dela. Como resolver: renomeie (mv doce.txt doce-de-leite.txt), apague se não precisar (rm doce.txt) ou commite-o no main. Depois, troque de novo.

fatal: a branch is expected, got commit '…' 
$ git switch HEAD~1
fatal: a branch is expected, got commit 'HEAD~1'
hint: If you want to detach HEAD at the commit, try again with the --detach option.

"Era esperado um branch, veio um commit". O git switch só aceita branches. Se você der um hash ou HEAD~1, ele recusa e a dica sugere repetir com --detach ("destacar"), para você não ir parar sem querer num "HEAD destacado". O que é isso, e quando vale a pena, está na aula HEAD Destacado.

Referência rápida

ComandoO que faz
git switch NOMEMuda para o branch
git switch -c NOME [PONTO]Cria (no atual ou em PONTO) e muda
git switch -C NOME [PONTO]Como -c, mas se o branch já existir ele é movido para o ponto (cuidado: commits só dele podem ficar sem etiqueta)
git switch -Volta para o branch anterior
git switch --discard-changes NOMETroca descartando as mudanças não commitadas
git switch --detach COMMITVai para um commit sem branch (HEAD destacado)
git switch -q NOMETroca sem mostrar mensagens

Exercícios

1. Complete os comandos

Ir para o branch salgados: git salgados
Criar o branch bebidas e ir para ele: git switch bebidas
Voltar para o branch anterior: git switch

2. A Ana está no main, que não tem o arquivo pudim.txt. O branch sobremesas tem. O que acontece com a pasta depois de git switch sobremesas?

3. A Ana mudou o README.md (sem commitar) e o README.md é igual nos dois branches. O que acontece com git switch salgados?

4. O Git respondeu error: Your local changes to the following files would be overwritten by checkout. Qual destas não é uma saída que mantém a sua mudança?

Resumo

  • git switch NOME muda o HEAD para o branch e deixa a pasta igual ao último commit dele: arquivos aparecem, somem e mudam.
  • git switch -c NOME cria e muda; com um ponto no fim (-c bebidas sobremesas), o branch novo nasce lá.
  • git switch - volta para o branch anterior.
  • Mudanças não commitadas ficam na pasta e vão junto, se não atrapalham. Se a troca fosse sobrescrevê-las, o Git se recusa: commite, guarde com git stash ou descarte com --discard-changes.
  • Branch que não existe dá fatal: invalid reference; para criar, use -c.
