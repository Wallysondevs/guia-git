Git log --graph: Vendo os Galhos

Enquanto você trabalha num branch só, o histórico é uma fila: um commit depois do outro. Mas quando aparecem os branches (ramos), a história se divide em galhos que crescem lado a lado e, depois, se juntam num merge. O git log comum continua mostrando uma lista, e uma lista não mostra galhos. Para ver a árvore de verdade, existe o git log --graph: ele desenha o histórico no terminal, com riscos e asteriscos.

Você vai aprender
  • Por que o git log sozinho esconde os outros branches, e como o --all mostra todos.
  • A ler o desenho do --graph: o *, o |, o |/ (onde um galho nasce) e o |\ (onde dois galhos se juntam).
  • O que são as etiquetas (HEAD -> main) e (doces).
  • Como o desenho fica depois de um merge, e os atalhos --first-parent e --simplify-by-decoration.
  • A criar o apelido git arvore para não digitar tudo isso todo dia.

As saídas desta aula saíram do Git 2.53 do Ubuntu 26.04, num terminal de verdade da máquina da Ana (no terminal, o Git mostra as etiquetas dos branches e cores; as cores não aparecem aqui).

A ideia: o mapa do metrô

Pense no mapa do metrô. Cada estação é um ponto; as linhas ligam as estações. Numa linha só, o mapa é um risco reto. Quando uma linha se divide em duas (uma vai para o centro, outra para o aeroporto), o mapa mostra a bifurcação. E quando duas linhas chegam à mesma estação, o mapa mostra o encontro.

O git log --graph é o mapa do metrô do seu repositório: cada commit é uma estação (um *), os riscos (|, /, \) são as linhas, e os branches são os nomes das linhas.

O repositório desta aula

A Ana criou o README e a receita de bolo no main. Depois criou o branch doces e fez dois commits nele (brigadeiro e beijinho). Por fim, voltou ao main e corrigiu o tempo de forno do bolo. Em desenho simples, a situação é esta:

                      brigadeiro --- beijinho     ← doces
                     /
README --- bolo ----+
                     \
                      forno do bolo               ← main (HEAD)

Agora vamos ver o que o Git mostra.

1. O problema: o git log só mostra o branch atual

$ git log --oneline
c20285a (HEAD -> main) Corrige o tempo de forno do bolo
c34349b Adiciona a receita de bolo
700bbd5 Cria o README

Só 3 commits. Cadê o brigadeiro e o beijinho? Eles existem, mas o git log mostra só o caminho que leva ao commit atual (o HEAD), voltando de pai em pai. Os commits do doces não estão nesse caminho: estão em outro galho.

Repare na etiqueta entre parênteses no primeiro commit:

(HEAD -> main)
"Você está aqui". O HEAD aponta (->) para o branch main, que aponta para este commit. Ou seja: você está no branch main, e este é o último commit dele.

2. Todos os branches: --all

$ git log --oneline --all
e26a98a (doces) Adiciona a receita de beijinho
c20285a (HEAD -> main) Corrige o tempo de forno do bolo
abceaaf Adiciona a receita de brigadeiro
c34349b Adiciona a receita de bolo
700bbd5 Cria o README
--all
"Todos": começa de todos os branches (e tags), não só do atual. Agora os 5 commits aparecem.
(doces)
A etiqueta do branch doces: este é o último commit dele. Sem o HEAD ->, porque você não está nele.

Apareceu tudo, mas a lista ficou misturada: o brigadeiro (do doces) está entre a correção do forno (do main) e o bolo. Olhando só a lista, não dá para saber o que é de qual branch. Pior: como a Ana fez todos os commits no mesmo minuto, nem a ordem de data ajuda. Falta o desenho.

3. O desenho: --graph

$ git log --oneline --graph --all
* e26a98a (doces) Adiciona a receita de beijinho
* abceaaf Adiciona a receita de brigadeiro
| * c20285a (HEAD -> main) Corrige o tempo de forno do bolo
|/
* c34349b Adiciona a receita de bolo
* 700bbd5 Cria o README

Agora sim. Leia de baixo para cima, que é a ordem em que as coisas aconteceram:

* 700bbd5 … Cria o README
Cada * é um commit (uma "estação"). Este é o primeiro.
* c34349b … receita de bolo
O segundo commit, logo acima: é filho do README. Até aqui, um galho só.
|/
A bifurcação: aqui a história se dividiu em duas. O risco / sai do bolo e sobe para a coluna da direita.
| * c20285a (HEAD -> main) …
Na coluna da direita, o commit do main: a correção do forno. O | à esquerda é a outra linha passando ao lado.
* abceaaf … brigadeiro
* e26a98a (doces) … beijinho
Na coluna da esquerda, os dois commits do doces, um em cima do outro. A etiqueta (doces) marca a ponta do galho.

É o mesmo desenho que você viu lá em cima, só que deitado: o Git desenha de cima (mais novo) para baixo (mais antigo).

Dá para pedir um branch específico

No lugar do --all, você pode dizer qual branch quer ver: git log --oneline --graph doces mostra o caminho do doces até o começo.

$ git log --oneline --graph doces
* e26a98a (doces) Adiciona a receita de beijinho
* abceaaf Adiciona a receita de brigadeiro
* c34349b Adiciona a receita de bolo
* 700bbd5 Cria o README

Para o doces, a história é uma linha reta: a correção do forno, que aconteceu no main, não faz parte dela.

Missão: você está no main do repositório da Ana. Rode git log --oneline e repare que o brigadeiro e o beijinho não aparecem. Depois, desenhe o histórico de todos os branches.

4. Depois do merge: os galhos se juntam

A Ana gostou dos doces e juntou o branch doces no main com um merge (veja git merge e Merge de Três Vias):

$ git merge doces -m "Junta o branch 'doces'"
Merge made by the 'ort' strategy.
 beijinho.txt   | 1 +
 brigadeiro.txt | 1 +
 2 files changed, 2 insertions(+)
 create mode 100644 beijinho.txt
 create mode 100644 brigadeiro.txt
$ git log --oneline --graph
*   7b950b8 (HEAD -> main) Junta o branch 'doces'
|\
| * e26a98a (doces) Adiciona a receita de beijinho
| * abceaaf Adiciona a receita de brigadeiro
* | c20285a Corrige o tempo de forno do bolo
|/
* c34349b Adiciona a receita de bolo
* 700bbd5 Cria o README

Repare que agora nem foi preciso o --all: os commits do doces fazem parte da história do main, porque o merge os trouxe. As novidades do desenho:

* 7b950b8 … Junta o branch 'doces'
O commit de merge. Os espaços depois do * abrem lugar para o risco que vem embaixo.
|\
O encontro: o commit de merge tem dois pais. O | desce para o pai da esquerda (o forno, que era o main) e o \ desce para o pai da direita (o beijinho, que era o doces).
* | c20285a …
O commit do main agora está na coluna da esquerda, com o galho do doces passando ao lado (|). O Git reorganizou as colunas: o primeiro pai do merge (o main, o branch em que a Ana estava quando fez o merge) fica sempre na coluna da esquerda.
|/
A bifurcação, a mesma de antes: os dois galhos nasceram do bolo.

O desenho completo agora parece um "olho": a história se abre no bolo e se fecha no merge.

README --- bolo ----+--- forno do bolo ---------+--- merge   ← main (HEAD)
                     \                          /
                      brigadeiro --- beijinho -+              ← doces

Missão: junte o branch doces no main com git merge doces (dê uma mensagem com -m) e veja o desenho do histórico com --graph. Procure o |\.

5. Mais um branch, e os atalhos

A Ana criou um terceiro branch, salgados, com a receita de coxinha, e voltou para o main. Com três branches, o desenho completo fica assim:

$ git log --oneline --graph --all
* be7090d (salgados) Adiciona a receita de coxinha
*   7b950b8 (HEAD -> main) Junta o branch 'doces'
|\
| * e26a98a (doces) Adiciona a receita de beijinho
| * abceaaf Adiciona a receita de brigadeiro
* | c20285a Corrige o tempo de forno do bolo
|/
* c34349b Adiciona a receita de bolo
* 700bbd5 Cria o README

O salgados nasceu do commit de merge e tem um commit a mais: por isso aparece logo acima dele, na mesma coluna.

Só os commits do "tronco": --first-parent

Num projeto grande, os galhos podem ser tantos que o desenho vira um emaranhado. O --first-parent ("só o primeiro pai") segue apenas o primeiro pai de cada merge, que é o branch em que você estava quando fez o merge. O resultado é o "tronco" do main, sem os commits de dentro dos galhos:

$ git log --oneline --first-parent
7b950b8 (HEAD -> main) Junta o branch 'doces'
c20285a Corrige o tempo de forno do bolo
c34349b Adiciona a receita de bolo
700bbd5 Cria o README

O brigadeiro e o beijinho sumiram da lista, mas o merge que os trouxe está lá. É um bom jeito de ver "o que entrou no main, um passo por vez".

Só os pontos importantes: --simplify-by-decoration

Para ter só uma visão geral dos branches, peça apenas os commits que têm etiqueta (as "decorações"), mais os que são necessários para ligar o desenho:

$ git log --oneline --graph --all --simplify-by-decoration
* be7090d (salgados) Adiciona a receita de coxinha
* 7b950b8 (HEAD -> main) Junta o branch 'doces'
* e26a98a (doces) Adiciona a receita de beijinho
* 700bbd5 Cria o README

Limitando com -n

Os filtros da aula git log: Filtros e Formatos também valem com o --graph. Com -3, o desenho para no terceiro commit, mesmo no meio de um galho:

$ git log --oneline --graph --all -3
* be7090d (salgados) Adiciona a receita de coxinha
*   7b950b8 (HEAD -> main) Junta o branch 'doces'
|\
| * e26a98a (doces) Adiciona a receita de beijinho

6. Sem o --oneline, e com o seu formato

O --graph também funciona com o formato completo do git log: os riscos continuam na margem esquerda, ao lado de cada commit. Fica comprido (5 linhas por commit), então o --oneline é o parceiro de sempre. Um meio-termo é o --format, com o nome do autor no fim:

$ git log --graph --format='%h %s (%an)' --all
* be7090d Adiciona a receita de coxinha (Ana Souza)
*   7b950b8 Junta o branch 'doces' (Ana Souza)
|\
| * e26a98a Adiciona a receita de beijinho (Ana Souza)
| * abceaaf Adiciona a receita de brigadeiro (Ana Souza)
* | c20285a Corrige o tempo de forno do bolo (Ana Souza)
|/
* c34349b Adiciona a receita de bolo (Ana Souza)
* 700bbd5 Cria o README (Ana Souza)

Com um --format próprio, as etiquetas dos branches somem: elas são parte do --oneline e do formato normal. Para tê-las no seu formato, use o código %d (de decorations, "enfeites"):

$ git log --format="%h%d %s" -3
7b950b8 (HEAD -> main) Junta o branch 'doces'
c20285a Corrige o tempo de forno do bolo
e26a98a (doces) Adiciona a receita de beijinho

7. Um apelido: git arvore

Digitar git log --oneline --graph --all várias vezes por dia cansa. Crie um apelido (veja Apelidos):

$ git config --global alias.arvore 'log --oneline --graph --all'
$ git arvore
* be7090d (salgados) Adiciona a receita de coxinha
*   7b950b8 (HEAD -> main) Junta o branch 'doces'
|\
| * e26a98a (doces) Adiciona a receita de beijinho
| * abceaaf Adiciona a receita de brigadeiro
* | c20285a Corrige o tempo de forno do bolo
|/
* c34349b Adiciona a receita de bolo
* 700bbd5 Cria o README
git config --global
Guarda uma configuração para todos os seus repositórios (no arquivo ~/.gitconfig).
alias.arvore
O nome do apelido: git arvore vai passar a existir.
'log --oneline --graph --all'
O que o apelido faz: o Git troca arvore por esse texto. Sem o git na frente.

Muita gente chama esse apelido de git lg ou git tree. O nome é você quem escolhe.

Missão: crie o apelido arvore para log --oneline --graph --all e use-o: git arvore.

Formas diferentes de ver os galhos

ComandoO que mostraQuando usar
git log --onelineSó o branch atual, em listaHistórico do branch em que você está
git log --oneline --allTodos os branches, em lista (misturados)Procurar um commit pelo nome, sem se importar com o galho
git log --oneline --graph --allTodos os branches, desenhadosEntender onde cada galho nasceu e onde se juntou (o mais útil)
git log --oneline --graph NOMEO caminho de um branchVer só a história de um branch
git log --oneline --first-parentO "tronco", sem o interior dos galhosVer o que entrou no main, merge por merge
git log --oneline --graph --all --simplify-by-decorationSó as pontas dos branchesVisão geral rápida

Também existem programas que desenham o histórico com janelas e cores, como o gitk e as extensões dos editores de código (veja Interfaces Gráficas). Eles mostram o mesmo grafo; o --graph tem a vantagem de funcionar em qualquer terminal.

Quando dá errado

As mensagens de erro abaixo saíram como no Git do Ubuntu: umas em português, outras em inglês, porque a tradução do Git no Ubuntu é parcial (a aula Seu Primeiro Commit explica).

"Sumiram" os commits do outro branch 
$ git log --oneline
c20285a (HEAD -> main) Corrige o tempo de forno do bolo
c34349b Adiciona a receita de bolo
700bbd5 Cria o README

O que aconteceu: nada se perdeu. O git log mostra só a história do branch atual, e os commits do doces estão em outro galho.

Como confirmar: git branch lista os branches que existem (o * marca o atual):

$ git branch
  doces
* main

Como resolver: git log --oneline --graph --all, ou git log --oneline doces para ver só aquele branch.

Nome do branch errado: ambiguous argument 
$ git log --oneline --graph doce
fatal: ambiguous argument 'doce': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

O que aconteceu: não existe branch (nem commit, nem arquivo) chamado doce: o nome certo é doces. A mensagem diz "argumento ambíguo: revisão desconhecida ou caminho fora da pasta de trabalho".

Como resolver: confira o nome com git branch e use o Tab para completar.

Opção escrita errado 
$ git log --oneline --grpah
fatal: argumento não reconhecido: --grpah

O que aconteceu: um erro de digitação (grpah no lugar de graph, "gráfico" em inglês). O Git não tenta adivinhar e para.

Como resolver: corrija para --graph. Um apelido como o git arvore evita esse tipo de erro.

O desenho é grande demais e "prende" o terminal

Num repositório com muitos commits, o git log --graph abre no paginador (less), e o prompt não volta.

Como resolver: use as setas ou o espaço para rolar e q para sair. Para ver só o começo, limite: git log --oneline --graph --all -15.

Exercícios

1. Complete o comando

Desenhe o histórico de todos os branches, uma linha por commit:

git log --oneline

2. No desenho do --graph, o que quer dizer um |\ logo abaixo de um *?

3. A Ana está no main e rodou git log --oneline. Os commits do branch doces (que ainda não foi juntado) não apareceram. Por quê?

4. O que mostra a etiqueta (HEAD -> main)?

5. Qual opção mostra só o "tronco" do main, sem os commits de dentro dos branches juntados?

Resumo

  • O git log mostra só a história do branch atual; --all mostra todos os branches.
  • --graph desenha os galhos: * é commit, |/ é onde um galho nasce, |\ é um merge (dois pais). Leia de baixo para cima.
  • As etiquetas mostram onde estão os branches: (HEAD -> main) é onde você está.
  • Depois de um merge, os commits do outro branch passam a fazer parte da história, e o desenho fecha o "olho".
  • --first-parent mostra o tronco; --simplify-by-decoration, só as pontas; -n limita o desenho.
  • O trio de todo dia é git log --oneline --graph --all: vale um apelido (git arvore).
