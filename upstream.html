Git Branch de Rastreamento (upstream)

Por que, depois do primeiro git push -u origin main, basta digitar git push e git pull? E como o git status sabe dizer "à frente de 'origin/main' por 1"? Porque o seu main ganhou um par no remoto. Esse par se chama upstream (em inglês, "rio acima": de onde vem a água), ou branch de rastreamento. Nesta aula você aprende a ver, criar, trocar e apagar esse par.

Você vai aprender
  • O que é o upstream e o que ele permite: push e pull sem argumentos, e o "à frente/atrás" do git status.
  • Como ver o par de cada branch com git branch -vv (e ler ahead, behind e gone).
  • As formas de criar o par: git push -u, git branch -u e o git switch que cria o branch a partir do remoto.
  • O atalho @{u} e onde o Git anota o par.
  • Os erros: no upstream configured, There is no tracking information e the upstream is gone.

A ideia antes do comando

Pense em duas pessoas que combinam de dividir um caderno: cada uma tem a sua cópia, e elas anotam na primeira página "a minha cópia é par da cópia da Maria". Com essa anotação, você não precisa perguntar "de quem eu copio?" toda vez, e consegue comparar: "estou duas páginas na frente dela".

No Git, a anotação diz: "o meu main é par do origin/main". Com ela:

Com upstreamSem upstream
git push sabe para onde enviarfatal: The current branch … has no upstream branch
git pull sabe de onde puxarThere is no tracking information for the current branch
git status diz se você está à frente, atrás ou em diagit status não fala nada sobre o remoto

Vendo os pares: git branch -vv

git branch
Lista os branches (veja git branch).
-v
verbose ("detalhado"): mostra também o último commit de cada branch.
-vv
Mais detalhado ainda: mostra, entre colchetes, o upstream de cada branch e a distância até ele.
$ git branch -vv
* main 4f68d0e [origin/main] Adiciona receita de bolo        « o par do main é origin/main

A Ana cria um branch novo. Ele nasce sem par: repare na falta dos colchetes, e no git status sem a linha sobre o remoto:

$ git switch -c salgados
Switched to a new branch 'salgados'
$ git branch -vv
  main     4f68d0e [origin/main] Adiciona receita de bolo
* salgados 4f68d0e Adiciona receita de bolo                   « sem colchetes: sem upstream
$ git status
No ramo salgados
nothing to commit, working tree clean                         « nada sobre o remoto

Criando o par

Forma 1: no primeiro push, com -u

É a forma mais comum: enviar o branch e criar o par no mesmo comando (veja git push).

$ git push -u origin salgados
Enumerating objects: 6, done.
Counting objects: 100% (6/6), done.

Compressing objects: 100% (3/3), done.
Writing objects: 100% (6/6), 504 bytes | 504.00 KiB/s, done.
Total 6 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
remote:
remote: Create a pull request for 'salgados' on GitHub by visiting:
remote:      https://github.com/ana-souza/receitas/pull/new/salgados

To https://github.com/ana-souza/receitas.git
 * [new branch]      salgados -> salgados
branch 'salgados' set up to track 'origin/salgados'.          « o par foi criado
$ git branch -vv
  main     4f68d0e [origin/main] Adiciona receita de bolo
* salgados 4f68d0e [origin/salgados] Adiciona receita de bolo  « agora tem colchetes

branch 'salgados' set up to track 'origin/salgados' = "o branch salgados foi configurado para rastrear o origin/salgados".

"Ligue o branch atual ao origin/doces". -u é a forma curta de --set-upstream-to=; a forma longa é git branch --set-upstream-to=origin/doces.
git branch -u origin/doces outro
Com um nome no fim, liga outro branch, sem precisar trocar para ele.

(Os outros branches da lista, bebidas, main e salgados, aparecem nas próximas seções.)

Forma 3: o git switch cria o branch já com par

O Bruno enviou o branch bebidas. Depois de um git fetch, a Ana tem o origin/bebidas, mas não um bebidas dela. Basta trocar para ele pelo nome:

$ git switch bebidas
branch 'bebidas' set up to track 'origin/bebidas'.             « criou e já ligou
Switched to a new branch 'bebidas'

Como não existe um bebidas local, mas existe um origin/bebidas, o Git entende que você quer trabalhar no branch do remoto: cria o seu bebidas no mesmo commit e já o liga ao origin/bebidas. O git clone faz a mesma coisa com o main: por isso, num repositório clonado, o main já nasce com par.

Lendo o "à frente" e o "atrás"

O git branch -vv e o git status comparam o seu branch com a lembrança do remoto (origin/main), que só se atualiza com fetch, pull ou push. Depois de um git fetch que trouxe o commit do óleo do Bruno:

$ git fetch -q
$ git branch -vv
* main     4f68d0e [origin/main: behind 1] Adiciona receita de bolo     « 1 atrás
  salgados 4f68d0e [origin/salgados] Adiciona receita de bolo

E depois que a Ana fez o commit do pudim, sem ainda ter puxado o do Bruno:

$ git branch -vv
* main     382be8d [origin/main: ahead 1, behind 1] Adiciona receita de pudim   « 1 à frente e 1 atrás
  salgados 4f68d0e [origin/salgados] Adiciona receita de bolo
$ git status
No ramo main
O seu branch e 'origin/main' divergiram-se,
e cada um tem 1 e 1 submissões, respectivamente.
  (use "git pull" if you want to integrate the remote branch with yours)

nothing to commit, working tree clean
No git branch -vvNo git statusO que fazer

[origin/main: ahead 2]Seu ramo está à frente de 'origin/main' por 2 submissões.git push
[origin/main: behind 1]Seu ramo está atrás de 'origin/main' em 1 submissão, e pode ser avançado.git pull
[origin/main: ahead 1, behind 1]O seu branch e 'origin/main' divergiram-se …git pull (escolhendo merge ou rebase), depois git push

(ahead = "à frente"; behind = "atrás"; gone = "sumiu". Como a tradução do Git no Ubuntu é parcial, o git branch -vv mostra essas palavras em inglês mesmo num sistema em português.)

O atalho @{u}

Em qualquer comando que aceita um nome de branch, @{u} (ou @{upstream}) quer dizer "o upstream do branch atual". Assim você não precisa lembrar se o par é origin/main ou outro:

$ git log --oneline -1 @{u}
3dbde00 (origin/main, origin/HEAD) Adiciona óleo ao bolo       « o último commit do par
$ git rev-parse --abbrev-ref @{u}
origin/main                                                    « qual é o par

Combinações úteis: git log @{u}.. (o que eu tenho e o par não: o que o push vai enviar) e git log ..@{u} (o que o par tem e eu não: o que o pull vai trazer).

Onde o Git anota o par

No arquivo .git/config do repositório. Não precisa editar à mão, mas vale a pena olhar uma vez:

$ cat .git/config
[core]
        repositoryformatversion = 0
        filemode = true
        bare = false
        logallrefupdates = true
[remote "origin"]                                         « o remoto
        url = https://github.com/ana-souza/receitas.git
        fetch = +refs/heads/*:refs/remotes/origin/*
[branch "main"]                                           « o par do main:
        remote = origin                                   « o remoto é o origin
        merge = refs/heads/main                           « e o branch de lá é o main

Quando dá errado

"no upstream configured for branch" 
$ git switch -c teste
Switched to a new branch 'teste'
$ git rev-parse --abbrev-ref @{u}
fatal: no upstream configured for branch 'teste'

O que aconteceu: "nenhum upstream configurado para o branch teste". O @{u} só funciona em branch com par. O mesmo branch, no git pull, dá There is no tracking information for the current branch e, no git push, has no upstream branch (veja git pull e git push).

Como resolver: git push -u origin teste (se o branch é seu e ainda não está no remoto) ou git branch -u origin/NOME (se já existe lá).

"O solicitado a montante branch … não existe" 
$ git branch -u origin/doce
fatal: O solicitado a montante branch 'origin/doce' não existe
hint:
hint: If you are planning on basing your work on an upstream
hint: branch that already exists at the remote, you may need to
hint: run "git fetch" to retrieve it.
hint:
hint: If you are planning to push out a new local branch that
hint: will track its remote counterpart, you may want to use
hint: "git push -u" to set the upstream config as you push.
hint: Disable this message with "git config set advice.setUpstreamFailure false"

O que aconteceu: a frase em português é uma tradução literal e estranha de "the requested upstream branch 'origin/doce' does not exist": "o branch upstream pedido, origin/doce, não existe" ("a montante" é a tradução de upstream). Aqui foi erro de digitação (doce em vez de doces). A dica lembra duas outras causas: o branch existe no remoto, mas você ainda não fez git fetch; ou o branch ainda não existe lá, e o certo é git push -u.

Como confirmar: git branch -r lista os branches remotos que o seu Git conhece.

"Your branch is based on 'origin/…', but the upstream is gone." 
$ git fetch --prune
From https://github.com/ana-souza/receitas
 - [deleted]         (none)     -> origin/salgados
$ git status
No ramo salgados
Your branch is based on 'origin/salgados', but the upstream is gone.
  (use "git branch --unset-upstream" to fixup)

nothing to commit, working tree clean
$ git branch -vv
  bebidas  ee0aa0e [origin/bebidas] Adiciona limonada
  main     382be8d [origin/main: ahead 1, behind 1] Adiciona receita de pudim
* salgados 4f68d0e [origin/salgados: gone] Adiciona receita de bolo      « gone = sumiu

O que aconteceu: "seu branch é baseado no origin/salgados, mas o upstream sumiu". O branch foi apagado no GitHub (é comum depois que um pull request é aceito) e o --prune apagou a lembrança.

Como resolver: se o trabalho já foi juntado ao main, apague o branch local (git switch main e git branch -d salgados; veja Apagando Branches). Se quer continuar nele, desfaça o par com git branch --unset-upstream, como a dica sugere, e envie de novo com git push -u origin salgados quando quiser.

"O status diz que estou em dia, mas não estou"

O que aconteceu: a comparação é com a lembrança (origin/main), não com o GitHub ao vivo.

Como resolver: git fetch e olhe de novo (veja git fetch).

Resumo

  • O upstream é o par de um branch local no remoto (ex.: main ↔ origin/main), anotado no .git/config.
  • Com ele, git push e git pull funcionam sem argumentos e o git status diz se você está à frente ou atrás.
  • git branch -vv mostra o par de cada branch: ahead (à frente), behind (atrás), gone (sumiu); sem colchetes, sem par.
  • Crie o par com git push -u, git branch -u origin/NOME ou git switch NOME (branch do remoto); desfaça com git branch --unset-upstream.
  • @{u} é o atalho para "o upstream do branch atual".
