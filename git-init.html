Git Criando um Repositório (git init)

Uma pasta comum não tem história nenhuma: o Git nem sabe que ela existe. O comando git init ("inicializar") transforma a pasta atual num repositório, criando dentro dela a pasta escondida .git, onde a história vai ser guardada. É o primeiro comando de todo projeto novo. Nesta aula você vai criar o repositório das receitas da Ana e entender cada linha que o Git responde.

Você vai aprender
  • Criar um repositório com git init e ler a resposta.
  • O que é a pasta .git e por que não mexer nela.
  • O primeiro git status de um repositório vazio.
  • A dica do master × main e como escolher o nome do ramo inicial.
  • O que fazer quando o git init foi rodado na pasta errada.

A ideia: comprar o álbum antes de tirar as fotos

Na primeira aula, o Git era um álbum de fotografias do projeto. O git init é o momento em que você compra o álbum e o deixa na pasta: ele ainda está vazio, nenhuma foto foi tirada, mas a partir de agora existe um lugar para guardá-las. As fotos (os commits) vêm na aula seguinte, Seu Primeiro Commit.

Criando o repositório

A Ana cria a pasta do projeto, entra nela e confere que está vazia:

$ mkdir receitas
$ cd receitas
$ ls -a
.  ..

Agora, o git init. Ele age na pasta atual, por isso é importante estar dentro da pasta certa:

$ git init
Repositório vazio Git inicializado em  /home/ana/receitas/.git/
git
O programa.
init
O comando: "inicialize um repositório aqui".

A resposta quer dizer: "criei um repositório Git vazio em /home/ana/receitas/.git/". Repare no caminho: ele termina em .git/, porque o repositório de verdade, a "caixa" com a história, é essa pasta. "Vazio" quer dizer que ainda não há nenhum commit. (Os dois espaços antes do caminho estão assim mesmo na tradução do Git.)

A pasta .git

O ls comum não mostra a pasta nova, porque o nome começa com ponto. Com -a ela aparece:

$ ls -a
.  ..  .git                         « nova: é aqui que o Git guarda tudo
$ ls .git
HEAD  config  description  hooks  info  objects  refs

Você não precisa entender esses arquivos agora (eles aparecem em Como o Git Guarda as Coisas). Por enquanto, guarde duas regras:

  • Não edite nem apague nada dentro de .git à mão. Quem cuida dela são os comandos do Git.
  • Apagar a pasta .git apaga a história inteira: os seus arquivos continuam lá, mas o repositório deixa de existir.
Antes do git initDepois do git init
A pasta receitasUma pasta comumUm repositório (a "pasta de trabalho" do projeto)
A pasta .gitNão existeExiste, com a estrutura do repositório
Commits—Nenhum ainda
Os seus arquivosIntocadosIntocados (o git init não mexe neles)

Missão: crie a pasta receitas, entre nela e transforme-a num repositório com git init. Depois confira a pasta escondida com ls -a.

O primeiro git status

O git status ("situação") é o comando que você mais vai digitar: ele diz em que pé está o repositório. Num repositório recém-criado:

$ git status
No ramo main                       « você está no ramo (branch) main

No commits yet                     « "ainda não há commits"

nada para enviar (crie/copie arquivos e use "git add" para registrar)
  • No ramo main: o repositório já nasce com um ramo, chamado main. Ramos têm aula própria (O que é um Branch); por enquanto, é "a linha principal da história".
  • No commits yet: ainda não há nenhum commit (esta linha não tem tradução).
  • A última linha diz que não há nada para registrar e dá a dica do próximo passo: criar ou copiar arquivos e usar git add.

A Ana segue a dica e cria o primeiro arquivo. O git status percebe na hora:

$ echo '# Receitas da Ana' > README.md
$ git status
No ramo main

No commits yet

Arquivos não monitorados:                                       « arquivos que o Git ainda não acompanha
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	README.md

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)

O Git viu o README.md, mas ainda não o acompanha: ele é um arquivo "não monitorado". A tradução desta mensagem mistura palavras ("submetido", "envio", "registrar", e até um "to" em inglês), mas o recado é um só: use git add. É exatamente o que a próxima aula faz. O git status e as suas mensagens são explicados em detalhe em git status.

A dica do master e do main

Na máquina da Ana, o repositório nasceu no ramo main porque ela configurou isso na aula git config. Num Git recém-instalado, sem essa configuração, o git init responde assim:

$ git init
hint: Using 'master' as the name for the initial branch. This default branch name
hint: will change to "main" in Git 3.0. To configure the initial branch name
hint: to use in all of your new repositories, which will suppress this warning,
hint: call:
hint:
hint: 	git config --global init.defaultBranch <name>
hint:
hint: Names commonly chosen instead of 'master' are 'main', 'trunk' and
hint: 'development'. The just-created branch can be renamed via this command:
hint:
hint: 	git branch -m <name>
hint:
hint: Disable this message with "git config set advice.defaultBranchName false"
Repositório vazio Git inicializado em  /home/ana/receitas/.git/

As linhas com hint: ("dica") não são um erro: o repositório foi criado normalmente (última linha). A dica, em português:

"Usando master como nome do ramo inicial. Este nome padrão vai mudar para main no Git 3.0. Para configurar o nome do ramo inicial de todos os seus repositórios novos, o que também tira este aviso, rode git config --global init.defaultBranch <nome>. Nomes comuns no lugar de master são main, trunk e development. O ramo recém-criado pode ser renomeado com git branch -m <nome>. Para não ver mais esta mensagem: git config set advice.defaultBranchName false."

Por que dois nomes?

Durante muitos anos, o Git chamou o ramo inicial de master ("mestre"). Em 2020, o GitHub e outros serviços passaram a usar main ("principal") nos repositórios novos, e o próprio Git avisa que vai adotar main no Git 3.0. Os dois funcionam igual; o que importa é o seu repositório e o do GitHub usarem o mesmo nome. Este guia usa main. Você vai ver master em muitos projetos e tutoriais antigos.

Os dois jeitos de resolver, que a própria dica ensina

Para os próximos repositórios, configure uma vez (se você fez a aula de git config, já está feito):

git config --global init.defaultBranch main

Para o repositório que acabou de nascer como master, renomeie o ramo com git branch -m (move, "mover/renomear"):

$ git status
No ramo master                     « nasceu como master

No commits yet

nada para enviar (crie/copie arquivos e use "git add" para registrar)
$ git branch -m main
$ git status
No ramo main                       « agora é main

No commits yet

nada para enviar (crie/copie arquivos e use "git add" para registrar)

Formas diferentes de criar um repositório

Criar a pasta e o repositório de uma vez

Com um nome depois do init, o Git cria a pasta (se não existir) e o repositório dentro dela. Você continua onde estava:

$ git init loja
Repositório vazio Git inicializado em  /home/ana/loja/.git/
$ ls loja -a
.  ..  .git

Escolher o nome do ramo só desta vez: -b

A opção -b (de branch; a forma longa é --initial-branch) escolhe o nome do ramo inicial deste repositório, sem mexer na configuração:

$ git init -b principal teste
Repositório vazio Git inicializado em  /home/ana/teste/.git/
$ cd teste
$ git status
No ramo principal

No commits yet

nada para enviar (crie/copie arquivos e use "git add" para registrar)

Sem mensagem: -q

git init -q (quiet, "quieto") faz o mesmo sem mostrar nada. É útil em scripts.

Clonar em vez de iniciar

Se o projeto já existe no GitHub, você não usa git init: usa git clone, que baixa o repositório com toda a história (aula git clone).

SituaçãoUse
Projeto novo, numa pasta onde você já estágit init
Projeto novo, numa pasta que ainda não existegit init nome-da-pasta
Projeto que já tem arquivos (mas não é repositório)cd até a pasta e git init: os arquivos ficam intocados
Quero um nome de ramo diferente só aquigit init -b nome
O projeto já está no GitHubgit clone endereço

Quando dá errado

fatal: not a git repository 
$ git status
fatal: not a git repository (or any of the parent directories): .git

O que aconteceu: "fatal: não é um repositório git (nem nenhuma das pastas acima): .git". O Git procurou uma pasta .git na pasta atual e em todas as pastas acima dela, até a raiz, e não achou. Ou você ainda não rodou git init, ou está na pasta errada. (Esta mensagem ainda não tem tradução.)

Como confirmar: pwd mostra onde você está; ls -a mostra se há uma .git aqui.

Como resolver: vá para a pasta do projeto com cd. Se ela nunca foi um repositório, rode git init lá dentro.

Rodei git init duas vezes 
$ git init
Reinitialized existing Git repository in /home/ana/receitas/.git/

O que aconteceu: "repositório Git existente reinicializado". Não se preocupe: rodar git init num repositório que já existe não apaga nada. Os commits, os ramos e a configuração continuam lá; o Git só confere a estrutura da pasta .git.

Rodei git init na pasta errada (por exemplo, na pasta pessoal) 
$ git init
Repositório vazio Git inicializado em  /home/ana/.git/
$ git status
No ramo main

No commits yet

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	.bash_history
	.bash_logout
	.bashrc
	.config/
	.gitconfig
	.profile
	loja/
	receitas/

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)

O que aconteceu: a Ana estava na pasta pessoal (~), não na do projeto. Agora a pasta pessoal inteira virou um repositório, e o git status lista os arquivos de configuração dela como "não monitorados". (As pastas Documentos, Imagens etc. não aparecem aqui porque, nesta máquina, estão vazias, e o Git não acompanha pastas vazias. Com arquivos dentro, elas apareceriam também.) Pior: como o Git procura a .git nas pastas acima, qualquer pasta dentro da pessoal passa a parecer parte desse repositório.

Como resolver: se você acabou de criar e ainda não fez nenhum commit, apague só a pasta .git criada por engano. Confira duas vezes que está na pasta certa e que é a .git nova, antes de apagar:

$ rm -rf .git
$ git status
fatal: not a git repository (or any of the parent directories): .git   « voltou a ser uma pasta comum

rm -rf apaga sem perguntar e sem lixeira: use com muito cuidado, e nunca numa .git com história que você quer manter.

Missão: a Ana rodou git init sem querer na pasta pessoal. Confira com git status, desfaça apagando a pasta .git com rm -rf .git e confira de novo: o git status deve dizer que aqui não é um repositório.

Em qual repositório eu estou?

Numa subpasta de um repositório, o Git funciona normalmente, porque ele sobe procurando a .git. Para saber qual pasta é a "raiz" do repositório:

$ git rev-parse --show-toplevel
/home/ana/receitas

Se a resposta for a sua pasta pessoal, você caiu no caso anterior.

Resumo

  • git init transforma a pasta atual num repositório, criando a pasta oculta .git; os seus arquivos não são tocados.
  • A .git guarda toda a história: não mexa nela à mão; apagá-la apaga o repositório.
  • Num repositório novo, git status diz "No commits yet" e sugere criar arquivos e usar git add.
  • Sem init.defaultBranch, o Git usa master e mostra uma dica; configure main ou renomeie com git branch -m main.
  • fatal: not a git repository = pasta errada ou falta o git init. Rodar git init de novo não apaga nada.
