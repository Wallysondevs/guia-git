Git: Renomeando e Apagando Branches

Branches nascem o tempo todo: um para cada ideia, cada receita nova, cada conserto. Por isso é preciso saber arrumar: trocar um nome digitado errado e apagar os branches que já cumpriram o seu papel. Tudo isso se faz com opções do git branch: -m (de move, "mover", aqui no sentido de renomear) e -d (de delete, "apagar"). E o Git tem uma rede de proteção: ele se recusa a apagar um branch cujo trabalho ainda não foi guardado em outro lugar.

Você vai aprender
  • Renomear um branch com git branch -m, inclusive o clássico master → main.
  • Apagar com git branch -d e entender a recusa not fully merged.
  • Apagar à força com -D, e recuperar um branch apagado sem querer.
  • Por que não dá para apagar o branch em que você está.
  • Apagar o branch também no GitHub: git push origin --delete.

As saídas vieram do Git 2.53 do Ubuntu 26.04, na máquina da Ana, com o sistema em português. As mensagens desta aula saem em inglês, porque a tradução do Git no Ubuntu ainda não as cobre; cada uma vem traduzida aqui.

A ideia: etiquetas, não gavetas

Lembre que um branch é só uma etiqueta colada num commit (O que é um Branch). Por isso:

  • renomear é trocar o que está escrito na etiqueta: os commits não mudam;
  • apagar é descolar a etiqueta: os commits continuam lá. O problema é quando aquela etiqueta era o único caminho até alguns commits; aí eles ficam perdidos, sem nome. É disso que o -d protege você.

1. Renomear: git branch -m

A Ana criou um branch e digitou o nome no singular. Ela corrige:

$ git branch sobremesa
$ git branch
* main
  sobremesa
$ git branch -m sobremesa sobremesas
$ git branch
* main
  sobremesas                      « nome novo
git branch -m
"Renomear branch".
sobremesa
O nome atual.
sobremesas
O nome novo. Como em todo o Git, sem mensagem quer dizer que deu certo.
Antes:   A---B---C   ← main ← HEAD
                     ← sobremesa

Depois:  A---B---C   ← main ← HEAD
                     ← sobremesas          (o commit é o mesmo: só a etiqueta mudou)

Renomear o branch atual: um nome só

Com um nome só, o -m renomeia o branch em que você está. O uso mais famoso: um repositório criado com master (o nome antigo do primeiro branch; veja Criando um Repositório), que a Ana quer chamar de main:

$ git status
No ramo master
nothing to commit, working tree clean
$ git branch -m main
$ git branch
* main
$ git status
No ramo main
nothing to commit, working tree clean

O HEAD vai junto: a Ana continua "no mesmo branch", que agora se chama main.

Quando o nome novo já existe: -M

$ git branch -m sobremesas main
fatal: a branch named 'main' already exists

"Um branch chamado 'main' já existe". O -m nunca passa por cima de outro branch. Existe o -M maiúsculo, que força: o branch que tinha aquele nome some, e os commits que só ele tinha ficam sem etiqueta. Quase nunca é o que você quer; confira com git log --oneline --graph --all antes.

2. Apagar um branch: git branch -d

A Ana criou um branch teste e desistiu dele antes de fazer qualquer commit:

$ git branch teste
$ git branch -d teste
Deleted branch teste (was 0244251).
$ git branch
* main
  sobremesas
git branch -d teste
Apaga o branch teste, se for seguro: se todos os commits dele também estiverem no branch atual (ou no branch que ele acompanha no GitHub).
Deleted branch teste (was 0244251).
"Branch teste apagado (era 0244251)". O Git informa para onde a etiqueta apontava. Guarde esse hash: com ele, dá para desfazer o apagamento (seção 4).

3. A recusa: not fully merged

Agora a Ana fez um commit no sobremesas (o pudim), voltou para o main e tentou apagar o sobremesas:

$ git log --oneline --graph --all
* d6f2336 (sobremesas) Adiciona receita de pudim     « só o sobremesas tem este commit
* 0244251 (HEAD -> main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README
$ git branch -d sobremesas
error: the branch 'sobremesas' is not fully merged
hint: If you are sure you want to delete it, run 'git branch -D sobremesas'
hint: Disable this message with "git config set advice.forceDeleteBranch false"

Linha por linha:

error: the branch 'sobremesas' is not fully merged
"O branch 'sobremesas' não foi totalmente mesclado". Ou seja: ele tem commits (o do pudim) que o main não tem. Se a etiqueta sumisse, ninguém mais levaria até esses commits.
hint: If you are sure you want to delete it, run 'git branch -D sobremesas'
"Se tem certeza de que quer apagá-lo, rode git branch -D sobremesas". O -D maiúsculo apaga mesmo assim.
hint: Disable this message …
Como desligar esta dica.

Nada foi apagado. A Ana tem duas saídas:

  1. Quer o pudim no main? Junte primeiro (git merge sobremesas, aula git merge) e depois apague com -d, que vai aceitar.
  2. O pudim não presta? Apague à força com -D.

4. Apagar à força: -D, e como desfazer

A Ana decidiu que não quer mais o pudim:

$ git branch -D sobremesas
Deleted branch sobremesas (was d6f2336).
$ git log --oneline --graph --all
* 0244251 (HEAD -> main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README

Antes:   A---B---C   ← main ← HEAD
                  \
                   D   ← sobremesas     (D = d6f2336, o pudim)

Depois:  A---B---C   ← main ← HEAD
                  \
                   D       (sem etiqueta: some do git log --all)

O -D é o mesmo que --delete --force ("apagar, forçando"). O commit do pudim continua dentro do .git por um tempo, mas nada mais leva até ele.

Arrependeu? Cole a etiqueta de novo

Lembra do (was d6f2336)? É só criar um branch com o mesmo nome naquele commit:

$ git branch sobremesas d6f2336
$ git log --oneline --graph --all
* d6f2336 (sobremesas) Adiciona receita de pudim     « voltou!
* 0244251 (HEAD -> main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README

Perdeu o hash? O git reflog lembra por onde o HEAD passou, inclusive o commit do pudim:

$ git reflog -4
0244251 (HEAD -> main) HEAD@{0}: checkout: moving from sobremesas to main
d6f2336 (sobremesas) HEAD@{1}: commit: Adiciona receita de pudim      « o hash está aqui
0244251 (HEAD -> main) HEAD@{2}: checkout: moving from main to sobremesas
0244251 (HEAD -> main) HEAD@{3}: checkout: moving from sobremesas to main
Não confie para sempre

Commits sem etiqueta são apagados de vez pela limpeza automática do Git (o git gc), depois de algumas semanas. Recupere logo, e use o -D só quando tiver certeza.

5. Não dá para apagar o branch onde você está

$ git switch -c ideia
Switched to a new branch 'ideia'
$ git branch -d ideia
error: cannot delete branch 'ideia' used by worktree at '/home/ana/receitas'
$ git switch -q main
$ git branch -d ideia
Deleted branch ideia (was 0244251).

"Não é possível apagar o branch 'ideia', usado pela pasta de trabalho em '/home/ana/receitas'". O HEAD está apontando para ele; sem ele, o HEAD ficaria apontando para o nada. (Worktree é a pasta de trabalho; um repositório pode ter várias, assunto de git worktree.) Solução: mude para outro branch e apague de lá. Vale até com -D.

6. O caminho normal: juntar e depois apagar

Este é o fim de vida de quase todo branch: o trabalho dele entra no main e a etiqueta é jogada fora. A Ana fez isso com um branch lanches:

$ git switch -c lanches
Switched to a new branch 'lanches'
$ echo 'Coxinha' > coxinha.txt
$ git add coxinha.txt && git commit -q -m 'Adiciona coxinha'
$ git switch -q main
$ git merge -q lanches
$ git branch -d lanches
Deleted branch lanches (was ccf325f).

Depois do git merge, o commit da coxinha está no main, então o -d apagou sem reclamar:

Depois do commit:   A---B---C   ← main
                             \
                              E   ← lanches ← HEAD       (E = ccf325f, a coxinha)

Depois do merge:    A---B---C---E   ← main ← HEAD
                                    ← lanches

Depois do -d:       A---B---C---E   ← main ← HEAD        (nada se perdeu)

(O sobremesas, recriado na seção 4, continua de lado, no commit do pudim; ficou fora do desenho para simplificar. E repare que aqui o merge só empurrou a etiqueta main para frente: é o merge fast-forward.)

7. Apagar o branch no GitHub

Se o branch também foi enviado para o GitHub (git push), apagar a etiqueta no seu computador não apaga a do GitHub, e vice-versa. A Ana enviou o main e o sobremesas para o repositório ana-souza/receitas (o GitHub de mentira do laboratório):

$ git branch -a
* main
  sobremesas
  remotes/origin/main
  remotes/origin/sobremesas          « a cópia do branch que está no GitHub
$ git push origin --delete sobremesas
To https://github.com/ana-souza/receitas.git
 - [deleted]         sobremesas       « apagado no GitHub
$ git branch -a
* main
  sobremesas                         « o local continua
  remotes/origin/main
git push origin --delete sobremesas
"Envie para o origin (o GitHub): apague o branch sobremesas". O branch local continua; para apagá-lo também, git branch -d sobremesas.
- [deleted] sobremesas
"[apagado]": o GitHub confirmou.

No site do GitHub também dá para apagar um branch, na página de branches do repositório, e o GitHub oferece apagar o branch quando um pull request é mesclado (ilustrativo; veja Pull Request e a documentação em docs.github.com/pt). Renomear no GitHub é outra história: lá, um branch renomeado é um branch novo; o jeito mais simples é enviar o nome novo (git push -u origin NOVO) e apagar o antigo com --delete.

Experimente

O terminal está na pasta receitas. Use git branch -v e git log --oneline --graph --all antes e depois.

Missão: a Ana criou o branch sobremessas (com dois "s" no meio, errado) e um teste que não serve para nada. Corrija o nome para sobremesas e apague o teste.

Missão: o branch lanches tem uma coxinha que deve ir para o main; o rascunho tem um sanduíche de jiló que ninguém quer. Junte o lanches no main (git merge lanches) e apague os dois branches. Repare qual deles precisa de -D, e por quê.

Formas diferentes

ParaSeguroÀ força
Renomeargit branch -m VELHO NOVO (ou -m NOVO no atual)git branch -M VELHO NOVO (passa por cima de NOVO)
Apagargit branch -d NOME (--delete)git branch -D NOME (--delete --force)
Apagar váriosgit branch -d teste ideia rascunho
Apagar no GitHubgit push origin --delete NOME (forma antiga: git push origin :NOME)

Qual usar? Sempre o -d primeiro. Se ele recusar, pare e pense: o not fully merged quer dizer que há trabalho que só existe ali. Junte ou confira com git log --oneline --graph --all; só depois use -D.

Quando dá errado

error: the branch 'sobremesas' is not fully merged

A seção 3. O que aconteceu: o branch tem commits que o atual não tem. Como confirmar: git log --oneline main..sobremesas lista esses commits (git log: Filtros), ou git branch --no-merged. Como resolver: junte com git merge e apague com -d; ou, se não quer o trabalho, -D.

error: cannot delete branch 'ideia' used by worktree at '…'

Você está no branch que quer apagar (seção 5). Como resolver: git switch main e apague de novo.

error: branch 'naoexiste' not found 
$ git branch -d naoexiste
error: branch 'naoexiste' not found

"Branch 'naoexiste' não encontrado". Erro de digitação, ou ele já foi apagado. Como confirmar: git branch.

fatal: a branch named 'main' already exists ao renomear

O nome novo já está em uso (seção 1). Como resolver: escolha outro nome, ou apague/renomeie o outro branch antes.

Apaguei com -D e me arrependi

Como resolver: git branch NOME HASH, com o hash do Deleted branch NOME (was HASH). Sem o hash, procure no git reflog (seção 4).

Resumo

  • git branch -m NOVO renomeia o branch atual (o clássico master → main); -m VELHO NOVO renomeia outro. Os commits não mudam.
  • git branch -d NOME apaga com segurança: recusa com not fully merged se houver trabalho que só existe ali.
  • -D apaga mesmo assim. O Deleted branch NOME (was HASH) dá o hash para desfazer: git branch NOME HASH.
  • Não dá para apagar o branch atual: mude de branch antes.
  • O branch no GitHub é separado: git push origin --delete NOME.
