Git O que é um Repositório Remoto

Até aqui, tudo o que você fez com o Git ficou no seu computador: os commits, os branches, o histórico inteiro moram na pasta .git do projeto. Se o notebook quebrar, vai tudo junto. E se o Bruno quiser ajudar no site de receitas, ele não tem como ver os seus commits. A solução é ter outra cópia do repositório em outro lugar, normalmente no GitHub. Essa outra cópia se chama repositório remoto.

Você vai aprender
  • O que é um repositório remoto, e o que quer dizer origin.
  • O ciclo de trabalho com um remoto: clone, push, fetch e pull (cada um tem a sua aula).
  • O que é o origin/main que aparece no git log e no git status.
  • O que querem dizer "à frente" e "atrás" de origin/main.
  • Os erros de quem tenta enviar sem ter um remoto.

As saídas desta aula saíram do Git 2.53 do Ubuntu 26.04, num terminal de verdade da máquina da Ana. O "GitHub" do laboratório é uma imitação local do GitHub, que responde aos comandos do Git como o de verdade. Repare que algumas mensagens saem em português e outras em inglês: a tradução do Git no Ubuntu é parcial (em outros sistemas, as frases podem estar diferentes ou todas em inglês).

A ideia: o caderno de receitas da avó

Na família da Ana, cada pessoa tem em casa uma cópia do caderno de receitas. O caderno "oficial" fica na casa da avó. Quando a Ana inventa uma receita, ela escreve no caderno dela; no domingo, leva até a casa da avó e copia para o oficial. Quando o Bruno quer as novidades, ele vai à casa da avó e copia do oficial para o caderno dele.

Três detalhes dessa história valem para o Git:

  • Cada um tem a cópia completa, com todas as receitas e toda a história. Dá para trabalhar sem ir à casa da avó (sem internet).
  • Nada se copia sozinho. Diferente de uma pasta do Google Drive, o Git não sincroniza nada por conta própria: você manda (push) e busca (fetch/pull) quando quer.
  • O caderno da avó é só mais uma cópia, combinada como ponto de encontro. No Git, esse ponto de encontro é o remoto, e o mais comum é ele estar no GitHub.
        computador da Ana                 GitHub                  computador do Bruno
     ┌───────────────────┐   push   ┌───────────────────┐  clone/  ┌───────────────────┐
     │ receitas/         │ ───────→ │ ana-souza/        │  fetch/  │ receitas/         │
     │   .git (cópia     │          │   receitas        │  pull    │   .git (cópia     │
     │    completa)      │ ←─────── │ (o "remoto")      │ ───────→ │    completa)      │
     └───────────────────┘  fetch/  └───────────────────┘ ←─────── └───────────────────┘
                            pull                             push

O vocabulário

PalavraO que é
remoto (remote)Outra cópia do repositório, em outro lugar (GitHub, um servidor, outra pasta), que o seu repositório conhece por um nome.
originO nome tradicional do remoto principal ("origem"). É só um apelido para a URL; o Git o cria sozinho no git clone.
URLO endereço do remoto, como https://github.com/ana-souza/receitas.git.
git cloneCopia um repositório remoto inteiro para o seu computador (aula git clone).
git push"Empurra": envia os seus commits para o remoto (aula git push).
git fetch"Busca": traz os commits novos do remoto, sem mexer nos seus arquivos (aula git fetch).
git pull"Puxa": busca e já junta no seu branch (aula git pull).
origin/mainA "lembrança" que o seu repositório guarda de onde estava o main do remoto da última vez que vocês conversaram.

1. Um repositório sem remoto

A Ana tem o repositório de receitas com 2 commits, feito com git init. O comando que lista os remotos é o git remote (aula git remote); com -v, ele mostra as URLs:

$ git remote -v

Nada: o repositório só existe no notebook. Um repositório criado com git init começa sem nenhum remoto.

2. Ligando o repositório ao GitHub

A Ana criou um repositório vazio no site do GitHub, chamado receitas (como fazer isso está na aula Criando um Repositório no GitHub). O GitHub mostra o endereço dele, e ela o registra no Git com o nome origin:

$ git remote add origin https://github.com/ana-souza/receitas.git
$ git remote -v
origin  https://github.com/ana-souza/receitas.git (fetch)
origin  https://github.com/ana-souza/receitas.git (push)
git remote add
"Acrescente um remoto".
origin
O nome do remoto. Daqui em diante, em vez da URL inteira, a Ana escreve só origin.
https://github.com/ana-souza/receitas.git
A URL: no GitHub, o usuário (ana-souza), o repositório (receitas) e o .git no fim.
(fetch) e (push)
O endereço usado para buscar e o usado para enviar. Quase sempre são o mesmo.

O git remote add não conversa com o GitHub: ele só anota o endereço no arquivo .git/config. A conversa começa no primeiro push.

3. O primeiro envio e o origin/main

$ git push -u origin main
Enumerating objects: 6, done.
Counting objects: 100% (6/6), done.
Delta compression using up to 4 threads
Compressing objects: 100% (3/3), done.
Writing objects: 100% (6/6), 498 bytes | 498.00 KiB/s, done.
Total 6 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
To https://github.com/ana-souza/receitas.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.

Os detalhes do push estão na aula git push. Por enquanto, o importante: as linhas de cima são o Git contando e empacotando os commits; * [new branch] main -> main diz que o main da Ana virou um branch main novo no GitHub; e a última linha diz que, a partir de agora, o main da Ana "acompanha" o origin/main. Veja onde ele aparece:

$ git log --oneline
c34349b (HEAD -> main, origin/main) Adiciona a receita de bolo
700bbd5 Cria o README
$ git status
No ramo main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
$ git branch -a
* main
  remotes/origin/main
(HEAD -> main, origin/main)
Duas etiquetas no mesmo commit: o seu main e o origin/main (o main do remoto origin) estão no mesmo lugar.
Your branch is up to date with 'origin/main'.
"O seu branch está em dia com o origin/main": nada a enviar, nada a receber (até onde o Git sabe).
remotes/origin/main
No git branch -a (de all, todos), o origin/main aparece como um branch de outro tipo: um branch remoto (os livros chamam de remote-tracking branch, "branch que acompanha o remoto"). Você não trabalha nele; o Git o atualiza sozinho a cada push, fetch e pull.
O origin/main é uma foto, não uma janela

O origin/main mostra onde o main do GitHub estava na última vez que o seu Git conversou com ele. Se o Bruno enviar commits agora, o seu origin/main não muda sozinho, e o git status continua dizendo "em dia". Para atualizar a foto, é preciso um git fetch (seção 5).

Missão: o repositório de receitas da Ana já está ligado ao GitHub. Descubra o nome e o endereço (URL) do remoto.

4. À frente: commits que o GitHub ainda não tem

A Ana corrigiu o tempo de forno e fez um commit. Ele existe só no notebook:

$ echo 'Forno: 40 minutos' >> bolo.txt
$ git commit -q -am 'Corrige o tempo de forno do bolo'
$ git status
No ramo main
Seu ramo está à frente de 'origin/main' por 1 submissão.
  (use "git push" to publish your local commits)

nothing to commit, working tree clean
$ git log --oneline
c20285a (HEAD -> main) Corrige o tempo de forno do bolo
c34349b (origin/main) Adiciona a receita de bolo
700bbd5 Cria o README
Seu ramo está à frente de 'origin/main' por 1 submissão.
"O seu branch está à frente do origin/main em 1 commit" (a tradução do Ubuntu chama commit de "submissão"): você tem 1 commit que o GitHub ainda não tem.
(use "git push" to publish your local commits)
A dica: "use git push para publicar os seus commits locais".
c34349b (origin/main)
No git log, as duas etiquetas se separaram: o main andou, o origin/main ficou para trás.

Seguindo a dica:

$ git push
Enumerating objects: 5, done.
Counting objects: 100% (5/5), done.
Delta compression using up to 4 threads
Compressing objects: 100% (2/2), done.
Writing objects: 100% (3/3), 323 bytes | 323.00 KiB/s, done.
Total 3 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
To https://github.com/ana-souza/receitas.git
   c34349b..c20285a  main -> main
$ git log --oneline
c20285a (HEAD -> main, origin/main) Corrige o tempo de forno do bolo
c34349b Adiciona a receita de bolo
700bbd5 Cria o README

Agora bastou git push, sem origin main: o -u do primeiro envio deixou combinado para onde o main vai. A linha c34349b..c20285a main -> main diz que o main do GitHub andou do commit c34349b para o c20285a. E as etiquetas se juntaram de novo.

Missão: a Ana tem 1 commit que o GitHub ainda não tem. Confira com git status, envie com git push e rode o git status de novo até ele dizer que está em dia (up to date).

5. Atrás: commits que você ainda não tem

No computador dele, o Bruno clonou o repositório, acrescentou a receita de pão de queijo e enviou com git push. No notebook da Ana, nada mudou, nem a "foto":

$ git log --oneline
c20285a (HEAD -> main, origin/main) Corrige o tempo de forno do bolo
c34349b Adiciona a receita de bolo
700bbd5 Cria o README

O Git da Ana só fica sabendo quando ela pede notícias com git fetch:

$ git fetch
remote: Enumerating objects: 4, done.
remote: Counting objects: 100% (4/4), done.
remote: Compressing objects: 100% (2/2), done.
remote: Total 3 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)

   c20285a..73a019c  main       -> origin/main
$ git status
No ramo main
Seu ramo está atrás de 'origin/main' em 1 submissão, e pode ser avançado.
  (use "git pull" to update your local branch)

nothing to commit, working tree clean
$ git log --oneline --graph --all
* 73a019c (origin/main, origin/HEAD) Adiciona a receita de pão de queijo
* c20285a (HEAD -> main) Corrige o tempo de forno do bolo
* c34349b Adiciona a receita de bolo
* 700bbd5 Cria o README

O main do GitHub tinha andado até o 73a019c, e o origin/main da Ana foi atualizado para lá.
Seu ramo está atrás de 'origin/main' em 1 submissão, e pode ser avançado.
"O seu branch está 1 commit atrás do origin/main, e pode ser avançado" (sem conflito: é só andar para a frente).
(use "git pull" to update your local branch)
A dica: "use git pull para atualizar o seu branch local".
origin/HEAD
Uma etiqueta que diz qual é o branch principal do remoto (aqui, o main).

O commit do Bruno já está no computador da Ana (no origin/main), mas o main dela e os arquivos da pasta ainda não mudaram. O passo seguinte, o git pull, é assunto da aula git pull.

Formas de ter um remoto

SituaçãoComo o remoto aparece
O projeto já existe no GitHub e você quer uma cópiagit clone URL: o Git cria o origin sozinho (aula git clone)
O projeto nasceu no seu computador (git init)Crie o repositório vazio no GitHub e rode git remote add origin URL + git push -u origin main
Você quer mandar para dois lugares (GitHub e outro servidor)Dois remotos com nomes diferentes (aula git remote)

O remoto não precisa ser o GitHub. Pode ser o GitLab, o Bitbucket, um servidor da empresa ou até outra pasta do mesmo computador. E a URL pode ter três formatos:

FormatoExemploQuando
HTTPShttps://github.com/ana-souza/receitas.gitO mais simples; para enviar, o GitHub pede um token (aula HTTPS e Token)
SSHgit@github.com:ana-souza/receitas.gitCom uma chave SSH configurada, não pede senha (aula Chaves SSH)
Caminho local/home/ana/servidor/receitas.gitOutra pasta do computador (bom para treinar)

Quando dá errado

fatal: No configured push destination. 
$ git push
fatal: No configured push destination.
Either specify the URL from the command-line or configure a remote repository using

    git remote add <name> <url>

and then push using the remote name

    git push <name>

O que aconteceu: "nenhum destino de envio configurado". O repositório não tem remoto, então o push não sabe para onde ir. A dica, em inglês: "informe a URL no comando ou configure um repositório remoto com git remote add <nome> <url> e depois envie com git push <nome>".

Como confirmar: git remote -v não mostra nada.

Como resolver: git remote add origin URL e depois git push -u origin main.

fatal: 'origin' does not appear to be a git repository 
$ git push origin main
fatal: 'origin' does not appear to be a git repository
fatal: Could not read from remote repository.

Please make sure you have the correct access rights
and the repository exists.

O que aconteceu: "origin não parece ser um repositório Git". Não existe remoto com esse nome, então o Git tentou usar origin como se fosse um endereço, e falhou. O resto da mensagem ("não consegui ler do repositório remoto; confira se você tem acesso e se o repositório existe") é genérico.

Como resolver: confira os nomes com git remote -v. Se a lista está vazia, falta o git remote add; se o remoto tem outro nome, use esse nome.

There is no tracking information for the current branch. 
$ git pull
There is no tracking information for the current branch.
Please specify which branch you want to merge with.
See git-pull(1) for details.

    git pull <remote> <branch>

If you wish to set tracking information for this branch you can do so with:

    git branch --set-upstream-to=<remote>/<branch> main

O que aconteceu: "não há informação de acompanhamento para o branch atual": o main não está ligado a nenhum branch remoto, então o pull não sabe de onde puxar. Repare que, num repositório assim, o git status nem fala de origin/main:

$ git status
No ramo main
nothing to commit, working tree clean

Como resolver: se o remoto ainda não existe, crie com git remote add. Se ele existe, ligue o branch no primeiro envio (git push -u origin main) ou com o comando da dica. Mais na aula Upstream.

"O GitHub tem coisas que eu não vejo"

O que aconteceu: o seu origin/main é a foto da última conversa com o GitHub. Sem git fetch (ou git pull), o git status pode dizer "em dia" mesmo com commits novos lá.

Como resolver: git fetch e depois git status.

Resumo

  • Um remoto é outra cópia do repositório (normalmente no GitHub), conhecida por um nome; o tradicional é origin.
  • Cada cópia tem o histórico completo, e nada se sincroniza sozinho: push envia, fetch busca, pull busca e junta, clone copia tudo pela primeira vez.
  • git remote -v mostra os remotos; git remote add origin URL cria um.
  • origin/main é a foto do main do remoto na última conversa: o git status compara o seu branch com ela ("em dia", "à frente", "atrás").
  • Sem remoto, o push reclama No configured push destination.
