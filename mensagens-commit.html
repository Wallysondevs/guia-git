Git Boas Mensagens de Commit

Todo commit leva uma mensagem, e é muito tentador escrever qualquer coisa: "update", "ajustes", "agora vai". Hoje você lembra o que fez; daqui a três meses, não. A mensagem é a legenda da foto: é ela que vai fazer você (ou o seu colega) achar o commit certo quando precisar saber quando e por que algo mudou. Esta aula mostra as regras que quase todo projeto segue, com o porquê de cada uma.

Você vai aprender
  • Por que a mensagem importa, comparando um histórico bagunçado com um arrumado.
  • As partes de uma mensagem: título e corpo.
  • As regras do título: curto, começando com um verbo, sem ponto final.
  • O que pôr no corpo: o porquê da mudança.
  • O que evitar, e os enganos com aspas e apóstrofo no terminal.

As saídas são reais, do Git 2.53 da máquina da Ana (Ubuntu 26.04). Como fazer o commit com título e corpo (dois -m ou o editor) está em git commit.

A ideia: o caderno de receitas da família

Imagine o caderno de receitas da sua avó, com anotações na margem. Uma diz "mais 1 ovo, porque com 3 a massa fica seca (Natal de 2019)". Outra diz só "mudei". Qual das duas ajuda quem vai fazer o bolo daqui a dez anos? A primeira conta o que mudou e por quê. A segunda não diz nada.

O histórico do Git é esse caderno. Ele já guarda sozinho o que mudou em cada linha (você vê com o git show). O que só você pode escrever é o resumo e o motivo.

2. As partes de uma mensagem

Corrige a quantidade de ovos do bolo

A receita da vó leva 4 ovos, não 3. Com 3 a massa fica seca.
1ª linha: o título
Um resumo curto do que o commit faz. É o que aparece no git log --oneline, na resposta do git commit e nas listas de commits do GitHub. Obrigatório.
2ª linha: em branco
Separa o título do corpo. O Git e as outras ferramentas usam essa linha vazia para saber onde o título termina. Com dois -m, o Git a põe sozinho.
3ª linha em diante: o corpo
Opcional. Explica por que a mudança foi feita, o que estava errado antes, o que alguém precisa saber. Pode ter vários parágrafos.

3. As regras do título

Curto: até uns 50 caracteres

O título deve caber numa olhada. A recomendação mais comum é até 50 caracteres, e nunca passar de 72. Viu o primeiro git log --oneline da Ana? Um título longo quebra a linha e esconde o resumo. Se você não consegue resumir em 50 caracteres, talvez o commit esteja fazendo coisas demais (regra 6).

Começa com um verbo que diz o que o commit faz

Um bom título completa a frase "Este commit…":

  • "Este commit… adiciona a receita de pudim" → Adiciona a receita de pudim
  • "Este commit… corrige a quantidade de ovos do bolo" → Corrige a quantidade de ovos do bolo
  • "Este commit… remove a receita repetida de brigadeiro" → Remove a receita repetida de brigadeiro

Em projetos em português, os dois costumes mais comuns são esse (Adiciona, Corrige) e o imperativo (Adicione, Corrija, como uma ordem). Em projetos em inglês, a regra do próprio Git é o imperativo: Add pudim recipe, Fix egg amount. O importante é escolher um jeito e usar sempre o mesmo no projeto. Evite o passado (Adicionei, Corrigido): o título descreve o que o commit faz, não o que você fez ontem.

Sem ponto final, com letra maiúscula no começo

O título é como o título de um livro: Adiciona a receita de pudim, sem ponto no fim. É só um costume, mas deixa o histórico uniforme.

Diz o que mudou, não só onde

Muda bolo.txt não ajuda: o Git já sabe qual arquivo mudou. Corrige a quantidade de ovos do bolo diz o que mudou.

4. O corpo: o porquê

Nem todo commit precisa de corpo: Adiciona a receita de pudim já diz tudo. O corpo vale ouro quando o motivo não é óbvio:

  • por que a mudança foi necessária (o que estava errado, quem pediu);
  • por que você escolheu esse jeito, e não outro;
  • o que alguém precisa saber depois (um efeito colateral, um "não mexa nisso porque…").

Não descreva linha por linha o que mudou: isso o git show e o git diff já mostram. Quebre as linhas do corpo em até uns 72 caracteres, para ele ficar legível no terminal (no editor, aperte Enter; o Git não quebra sozinho).

Um corpo com mais de um parágrafo fica mais fácil no editor (git commit sem -m). Por exemplo:

Troca o açúcar refinado por mascavo no bolo

A Carla é diabética e pediu uma versão com menos açúcar refinado.
O mascavo deixa a massa mais escura, então a foto do site também
precisa ser trocada (fica para outro commit).

5. Mensagem no terminal: cuidado com as aspas

Com o -m, a mensagem passa pelo terminal antes de chegar ao Git, e o terminal tem as suas regras de aspas. A pegadinha mais comum em português é o apóstrofo dentro de aspas simples:

$ git commit -m 'Adiciona o copo d'água'
> ^C

O apóstrofo de d'água fechou as aspas simples, e o último ' abriu outras, que nunca fecham. O terminal mostrou >, esperando o resto. A Ana cancelou com Ctrl+C (o ^C), e nenhum commit foi feito. Como evitar: use aspas duplas quando a mensagem tiver apóstrofo: git commit -m "Adiciona o copo d'água". E, se a mensagem tiver aspas duplas dentro, use aspas simples por fora: git commit -m 'Adiciona a seção "Dicas"'. Na dúvida, use o editor: lá não há regra de aspas.

6. Um commit, um assunto

A mensagem boa começa antes de você escrevê-la: no tamanho do commit. Se o título precisa de um "e" ("Adiciona o pudim e corrige os ovos"), separe em dois commits com a área de preparo. Commits pequenos têm mensagens fáceis, e são fáceis de desfazer (git revert) sem levar junto o que estava certo.

Qual usar? O que o projeto já usa (olhe o git log --oneline antes do primeiro commit num projeto dos outros). Num projeto seu, escolha um e mantenha.

Quando dá errado

Errei a mensagem do último commit

Se o commit ainda não foi enviado ao GitHub, dá para trocar a mensagem com git commit --amend -m "mensagem nova". Isso cria um commit novo no lugar do antigo (com outro hash). Os detalhes, e por que não fazer isso com um commit já enviado, estão em Corrigindo o Último Commit.

O terminal mostrou > e não sai

Você abriu aspas e não fechou (seção 5). Feche as aspas e aperte Enter (a quebra de linha entra na mensagem), ou cancele com Ctrl+C e digite de novo.

Mensagem vazia

Com -m "" ou fechando o editor sem escrever nada, o Git cancela o commit com Aborting commit due to empty commit message.. O Git não aceita commit sem mensagem (aula git commit).

Missão final: dois commits, duas boas mensagens

Missão: há duas mudanças sem relação: o brigadeiro novo e a correção dos ovos do bolo. Faça dois commits: um que fale do brigadeiro e outro que fale dos ovos. O último commit deve ter título e corpo (use dois -m), com o corpo explicando o motivo.

Resumo

  • A mensagem é a legenda do commit: ela diz o que mudou (resumo) e por quê (corpo). O Git já guarda os detalhes linha por linha.
  • Título: curto (até ~50 caracteres), começando com um verbo que completa "Este commit…", maiúscula no começo, sem ponto final.
  • Linha em branco, depois o corpo (opcional), explicando o motivo, com linhas de até ~72 caracteres.
  • Evite update, ajustes, asdf: mensagem vaga é o mesmo que nenhuma.
  • Um commit, um assunto. Se o título precisa de um "e", são dois commits.
  • Apóstrofo na mensagem: use aspas duplas. Na dúvida, escreva no editor.
