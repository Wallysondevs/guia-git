Git Git × GitHub

"Sobe no Git", "manda pelo GitHub", "me passa o link do Git"… Muita gente usa os dois nomes como se fossem a mesma coisa, mas não são. O Git é um programa que roda no seu computador. O GitHub é um site, na internet, onde as pessoas guardam e compartilham repositórios Git. Nesta aula você vai separar bem os dois e entender como eles conversam.

Você vai aprender
  • O que é o Git e o que é o GitHub, com uma comparação do dia a dia.
  • O que o GitHub acrescenta ao Git: hospedagem, pull requests, issues, Pages e Actions.
  • Os poucos comandos do Git que conversam com o GitHub.
  • As alternativas ao GitHub: GitLab, Bitbucket, Codeberg.

A ideia: a câmera e o álbum na nuvem

Lembra do álbum de fotografias da primeira aula? Continue com ele:

  • O Git é a câmera e o álbum, que ficam com você. Ele tira as fotos (os commits) e guarda o álbum (o repositório) no seu computador. Funciona sem internet.
  • O GitHub é um serviço de álbuns na nuvem, como os sites de guardar fotos. Você manda uma cópia do álbum para lá, para ter um backup, para mostrar a outras pessoas e para elas acrescentarem fotos também.

Dá para usar o Git a vida inteira sem nunca abrir o GitHub (só no seu computador). Mas não dá para usar o GitHub sem o Git: tudo o que está lá dentro são repositórios Git.

O que o GitHub acrescenta

Guardar uma cópia do repositório é só o começo. O GitHub junta, em volta dos repositórios, ferramentas para pessoas trabalharem juntas. Nenhuma delas faz parte do Git: são do site.

"Pull request" é do GitHub, não do Git

Não existe um comando git pull-request. O pull request é uma página do site, onde as pessoas comentam e aprovam mudanças. Os outros serviços têm o mesmo recurso com outro nome: no GitLab, ele se chama merge request.

Como os dois conversam

O seu repositório no computador e a cópia dele no GitHub são dois repositórios, cada um com a sua história. Eles não se sincronizam sozinhos: você é quem manda o Git buscar ou enviar commits. Para o Git, a cópia no GitHub é um remoto (remote), um outro repositório que ele conhece por um nome curto, quase sempre origin ("origem").

  seu computador                                 github.com
  ┌──────────────────────┐   git push  ──►   ┌──────────────────────┐
  │  receitas            │                   │  ana-souza/receitas  │
  │  (repositório Git)   │   ◄──  git pull   │  (repositório Git)   │
  └──────────────────────┘                   └──────────────────────┘

São poucos os comandos que usam a internet. Todo o resto do Git (commit, log, status, branch, merge…) trabalha só no seu computador.

ComandoO que faz com o GitHub
git cloneCopia um repositório do GitHub para o seu computador, com toda a história (git clone).
git pushEnvia ("empurra") os seus commits novos para o GitHub (git push).
git fetchBusca os commits novos do GitHub, sem mexer nos seus arquivos (git fetch).
git pullBusca e já junta ao seu trabalho (git pull).
git remoteLista e configura os remotos que o repositório conhece (git remote).

Vendo o remoto de um repositório

O repositório receitas da Ana já está ligado à cópia dela no GitHub. O comando git remote -v mostra isso:

git remote
O subcomando que cuida dos remotos. Sozinho, lista só os nomes.
-v
verbose ("detalhado"): mostra também o endereço de cada remoto.
$ git remote
origin
$ git remote -v
origin	https://github.com/ana-souza/receitas.git (fetch)
origin	https://github.com/ana-souza/receitas.git (push)
  • origin: o apelido do remoto. É o nome que o Git dá automaticamente quando você clona um repositório.
  • https://github.com/ana-souza/receitas.git: o endereço do repositório no GitHub. Repare no formato: github.com/, o nome de usuário (ana-souza), uma barra e o nome do repositório.
  • (fetch) e (push): o endereço usado para buscar e o usado para enviar. Quase sempre são o mesmo.

O GitHub não é o único

Como tudo o que o GitHub guarda são repositórios Git comuns, existem outros sites que fazem o mesmo trabalho. Os comandos do Git são exatamente iguais em todos: muda só o endereço do remoto.

ServiçoQuem fazBom saber
GitHubGitHub (Microsoft)O mais usado, onde está a maior parte do software livre. É o deste guia.
GitLabGitLab Inc.Muito usado por empresas; também pode ser instalado num servidor próprio. Chama o pull request de merge request.

Um mesmo repositório pode até ter vários remotos: a Ana poderia mandar os mesmos commits para o GitHub e para o Codeberg. Isso aparece em Repositórios Remotos.

Quando dá errado

"Instalei o GitHub Desktop, então já tenho o Git?"

O que aconteceu: o GitHub Desktop é um programa com janelas para usar Git e GitHub sem terminal. Ele usa um Git próprio, interno, que não fica disponível para o seu terminal. Este guia ensina o Git pela linha de comando, que precisa do Git instalado no sistema.

Como confirmar: abra o terminal e rode git --version. Se o terminal disser que o comando não foi encontrado, o Git não está instalado para ele.

Como resolver: instale o Git (aula Instalar o Git). Os dois convivem sem problema. Programas com janelas têm aula própria: Interfaces Gráficas.

O repositório não tem remoto nenhum 
$ git remote -v
$ echo $?
0                                  « código de saída 0: deu certo, só não há remotos

O que aconteceu: o git remote -v não mostrou nada. Não é um erro: este repositório foi criado com git init no computador da Ana e nunca foi ligado a nenhum GitHub. Ele vive só no notebook dela, e tudo bem.

Como resolver: se ela quiser uma cópia no GitHub, cria o repositório lá e liga com git remote add origin … (aulas Criando um Repositório no GitHub e git remote).

Resumo

  • Git = o programa, no seu computador, que guarda a história. Livre, grátis, funciona sem internet.
  • GitHub = um site que hospeda repositórios Git e acrescenta pull requests, forks, issues, Pages e Actions.
  • Para o Git, a cópia no GitHub é um remoto, quase sempre chamado origin (git remote -v).
  • Só clone, push, fetch e pull usam a internet; o resto é local.
  • GitLab, Bitbucket e Codeberg fazem o mesmo papel; os comandos do Git não mudam.
