Git diff

O git status diz quais arquivos mudaram: "o bolo.txt foi modificado". Mas o que mudou lá dentro? Uma vírgula? A receita inteira? Para isso existe o git diff (de difference, "diferença"): ele mostra, linha por linha, o que você tirou e o que você pôs. É o comando que você roda antes de cada git add para conferir o próprio trabalho.

Você vai aprender
  • O que o git diff compara: a sua pasta com a área de preparo.
  • A ler um diff unificado linha por linha: diff --git, index, --- e +++, o @@ -1,3 +1,4 @@ e as linhas com +, - e espaço.
  • Por que um diff pode ter vários trechos (hunks) e o que é a "linha de contexto".
  • Os resumos: git diff arquivo, --stat, --word-diff, --name-only.
  • Por que o git diff às vezes não mostra nada, mesmo com mudanças (e qual comando usar então).

Todas as saídas desta aula saíram do Git do Ubuntu 26.04, na máquina da Ana (usuária ana, computador notebook), com o sistema em português. Com o sistema em inglês, as mensagens do Git saem em inglês, mas o diff em si (as linhas com + e -) é igual.

A ideia: o "jogo dos 7 erros"

Lembra do jogo dos 7 erros do jornal? Duas figuras quase iguais, lado a lado, e você tem de achar as diferenças. Agora imagine que alguém já circulou cada diferença para você, com vermelho no que sumiu e verde no que apareceu. É isso que o git diff faz com os seus arquivos de texto.

As duas "figuras" que ele compara são:

  • a sua pasta de trabalho: os arquivos como estão agora no disco, com as mudanças que você acabou de fazer;
  • a área de preparo (staging area, veja A Área de Preparo): a versão que iria para o próximo commit. Logo depois de um commit, ela é igual ao último commit.
   último commit        área de preparo         sua pasta
  ┌─────────────┐      ┌──────────────┐      ┌─────────────┐
  │  bolo.txt   │ ───► │   bolo.txt   │      │  bolo.txt   │
  │  (4 ovos)   │      │   (4 ovos)   │      │  (3 ovos)   │
  └─────────────┘      └──────────────┘      └─────────────┘
                              └──── git diff ────┘
                       "o que eu mudei e ainda NÃO preparei"

Ou seja: git diff, sem nada, mostra as mudanças que você ainda não deu git add. O que já foi preparado aparece com outro comando, o git diff --staged (a próxima aula).

1. Preparando o terreno

A Ana tem um repositório receitas com a receita de bolo em 3 linhas, já commitada:

$ mkdir receitas
$ cd receitas
$ git init -q
$ printf 'Bolo de cenoura\n3 cenouras\n4 ovos\n' > bolo.txt
$ git add bolo.txt
$ git commit -q -m 'Adiciona receita de bolo'
$ git diff
$

O -q (de quiet, "quieto") só faz o git init e o git commit não falarem nada, para o exemplo ficar curto. Repare no último comando: o git diff não mostrou nada. Isso não é erro: quer dizer "não há diferença nenhuma". A pasta está igual ao que foi commitado.

Silêncio é uma resposta

Muitos comandos do Git (e do terminal em geral) seguem a regra: "se não há nada a dizer, não diga nada". Um git diff vazio é a resposta "nada mudou desde o último git add".

2. O primeiro diff

A Ana testou a receita e mudou duas coisas: bastam 3 ovos, e faltava a farinha. O arquivo agora tem 4 linhas:

Bolo de cenoura
3 cenouras
3 ovos
2 xícaras de farinha

O git status só avisa que o arquivo mudou (modified = "modificado"):

$ git status
No ramo main
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   bolo.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

Repare que parte das linhas saiu em inglês (Changes not staged for commit = "mudanças não preparadas para o commit"). Não é defeito da sua máquina: a tradução do Git para o português ainda não está completa, e o Git do Ubuntu mostra exatamente isso. A aula git status explica cada linha.

E o git diff mostra o quê mudou:

$ git diff
diff --git a/bolo.txt b/bolo.txt
index 10a5c6d..c8726b3 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -1,3 +1,4 @@
 Bolo de cenoura
 3 cenouras
-4 ovos
+3 ovos
+2 xícaras de farinha

À primeira vista parece uma sopa de símbolos. Mas cada linha tem um papel, e depois de ler esta seção você vai ler qualquer diff.

Linha por linha

diff --git a/bolo.txt b/bolo.txt
O cabeçalho: começa a comparação de um arquivo. O Git chama a versão antiga de a/ e a nova de b/ (são só rótulos, não pastas de verdade). Aqui o arquivo não mudou de nome, então os dois lados são bolo.txt. Quando várias coisas mudaram, cada arquivo ganha o seu diff --git.
index 10a5c6d..c8726b3 100644
Detalhes técnicos que você pode ignorar no dia a dia. 10a5c6d e c8726b3 são os começos das "impressões digitais" (os hashes, veja O Hash do Commit) do conteúdo antigo e do novo do arquivo: antes..depois. 100644 é o tipo do arquivo: um arquivo comum, que não é programa executável.
--- a/bolo.txt
"Linhas com menos (-) vêm da versão a", a antiga.
+++ b/bolo.txt
"Linhas com mais (+) vêm da versão b", a nova. Essas duas linhas são a legenda do que vem a seguir.
@@ -1,3 +1,4 @@
O começo de um trecho (em inglês, hunk, "pedaço"). Leia assim: "-1,3: na versão antiga, este trecho começa na linha 1 e tem 3 linhas; +1,4: na versão nova, começa na linha 1 e tem 4 linhas". O arquivo cresceu uma linha.
␣Bolo de cenoura
Linha que começa com um espaço (o ␣ só marca o espaço; ele não aparece no terminal): é uma linha de contexto, que não mudou. Ela está ali para você se localizar no arquivo.
␣3 cenouras
Outra linha de contexto, igual nas duas versões.
-4 ovos
Linha que começa com -: existia na versão antiga e saiu. No terminal ela aparece em vermelho.
+3 ovos
Linha que começa com +: entrou na versão nova. No terminal, em verde. Repare: o Git não tem um símbolo para "linha alterada". Trocar 4 ovos por 3 ovos aparece como "saiu a linha velha, entrou a nova".
+2 xícaras de farinha
Mais uma linha que entrou: a farinha que a Ana acrescentou.

Confira a conta do @@: na versão antiga, o trecho tem as linhas de contexto e as com - (2 + 1 = 3); na nova, as de contexto e as com + (2 + 2 = 4). Por isso -1,3 +1,4.

De onde vêm o a/, o b/ e o ---/+++?

Esse jeito de mostrar diferenças é o diff unificado, bem mais antigo que o Git: é o mesmo formato do comando diff -u do Linux. O Git só acrescenta as linhas diff --git e index. Por isso, quem aprende a ler um git diff lê também os diffs do GitHub, das revisões de código e de muitos outros programas.

As cores

No terminal de verdade, o Git pinta o diff: o cabeçalho em negrito, a linha @@ em azul-ciano, as linhas com - em vermelho e as com + em verde. As cores ajudam muito, mas o que manda são os sinais no começo da linha: mesmo sem cor (num e-mail, num arquivo, num terminal sem cores), o + e o - dizem tudo. Também é por isso que a linha de contexto começa com um espaço: para todas as linhas terem uma "coluna de sinal".

Missão: o repositório receitas desta caixa já tem a mudança da Ana no bolo.txt. Rode git status e depois git diff, e encontre no diff: a linha que saiu, as duas que entraram e o @@ -1,3 +1,4 @@.

3. Um diff com vários trechos

O Git não mostra o arquivo inteiro: ele mostra só os pedaços que mudaram, com até 3 linhas de contexto antes e depois de cada mudança. Se duas mudanças estão longe uma da outra, cada uma vira um trecho @@ separado. Na lojinha da Ana, a lista de produtos tem 15 linhas:

$ cat -n produtos.txt
     1	Lojinha da Ana
     2
     3	Produtos:
     4	- caneca branca: R$ 25
     5	- caneca preta: R$ 25
     6	- camiseta P: R$ 40
     7	- camiseta M: R$ 40
     8	- camiseta G: R$ 45
     9	- boné: R$ 30
    10	- chaveiro: R$ 10
    11	- adesivo: R$ 5
    12	- bolsa de pano: R$ 35
    13
    14	Entrega em todo o Brasil.
    15	Contato: ana@exemplo.com

Ela fez duas mudanças, longe uma da outra: aumentou o preço da caneca preta (linha 5) e escreveu sobre o frete (linha 14). O diff:

$ git diff
diff --git a/produtos.txt b/produtos.txt
index ad1ef9e..484712b 100644
--- a/produtos.txt
+++ b/produtos.txt
@@ -2,7 +2,7 @@ Lojinha da Ana

 Produtos:
 - caneca branca: R$ 25
-- caneca preta: R$ 25
+- caneca preta: R$ 28
 - camiseta P: R$ 40
 - camiseta M: R$ 40
 - camiseta G: R$ 45
@@ -11,5 +11,5 @@ Produtos:
 - adesivo: R$ 5
 - bolsa de pano: R$ 35

-Entrega em todo o Brasil.
+Entrega em todo o Brasil (frete grátis acima de R$ 100).
 Contato: ana@exemplo.com

Agora há dois trechos, cada um com o seu @@:

  • @@ -2,7 +2,7 @@: começa na linha 2 e tem 7 linhas, antes e depois (o número de linhas não mudou, porque uma linha saiu e outra entrou no lugar). São 3 linhas de contexto acima da caneca preta (a linha em branco, Produtos: e a caneca branca), a troca, e 3 de contexto abaixo (as camisetas).
  • @@ -11,5 +11,5 @@: começa na linha 11 e tem 5 linhas: 3 de contexto acima do frete, a troca e só 1 abaixo, porque o arquivo acaba ali.

As linhas 9 e 10 (o boné e o chaveiro) não aparecem: estão longe das duas mudanças e não serviriam de contexto. Quando duas mudanças ficam perto (menos de 6 linhas entre elas), os contextos se encostam e o Git as junta num trecho só. Por exemplo, se a Ana também tivesse apagado o chaveiro (linha 10), tudo viraria um único trecho, @@ -2,14 +2,13 @@ Lojinha da Ana, com uma linha -- chaveiro: R$ 10 no meio (o primeiro - é o sinal do diff, o segundo é o tracinho da lista, que faz parte do texto).

O texto que às vezes aparece depois do segundo @@ na mesma linha (como o Lojinha da Ana em @@ -2,7 +2,7 @@ Lojinha da Ana) não faz parte da mudança: é uma "dica de onde você está", uma linha mais acima do arquivo que o Git achou útil mostrar (em programas, costuma ser o nome da função).

Menos (ou mais) contexto: -U

As 3 linhas de contexto são o padrão. Com -U (de unified) seguido de um número, você escolhe quantas:

$ git diff -U1
diff --git a/produtos.txt b/produtos.txt
index ad1ef9e..484712b 100644
--- a/produtos.txt
+++ b/produtos.txt
@@ -4,3 +4,3 @@ Produtos:
 - caneca branca: R$ 25
-- caneca preta: R$ 25
+- caneca preta: R$ 28
 - camiseta P: R$ 40
@@ -13,3 +13,3 @@ Produtos:

-Entrega em todo o Brasil.
+Entrega em todo o Brasil (frete grátis acima de R$ 100).
 Contato: ana@exemplo.com
$ git diff -U0
diff --git a/produtos.txt b/produtos.txt
index ad1ef9e..484712b 100644
--- a/produtos.txt
+++ b/produtos.txt
@@ -5 +5 @@ Produtos:
-- caneca preta: R$ 25
+- caneca preta: R$ 28
@@ -14 +14 @@ Produtos:
-Entrega em todo o Brasil.
+Entrega em todo o Brasil (frete grátis acima de R$ 100).

Com -U1, cada trecho tem só 1 linha de contexto de cada lado (3 linhas no total). Com -U0, sai só o que mudou, sem contexto nenhum; e como cada trecho tem 1 linha só, o Git escreve @@ -5 +5 @@ em vez de @@ -5,1 +5,1 @@. Contexto demais cansa; contexto de menos deixa você perdido no arquivo. O padrão (3) costuma ser o melhor.

4. Só um arquivo: git diff arquivo

Quando muitos arquivos mudaram, você pode pedir o diff de um só, escrevendo o nome dele no fim:

$ git diff bolo.txt
diff --git a/bolo.txt b/bolo.txt
index 10a5c6d..c8726b3 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -1,3 +1,4 @@
 Bolo de cenoura
 3 cenouras
-4 ovos
+3 ovos
+2 xícaras de farinha
git diff
O comando.
bolo.txt
Um caminho: limita o diff a esse arquivo. Pode ser mais de um (git diff bolo.txt pudim.txt), uma pasta inteira (git diff doces/) ou um padrão entre aspas (git diff '*.txt').

Também dá para escrever git diff -- bolo.txt. O -- quer dizer "daqui em diante, só nomes de arquivo". Ele só é necessário quando o nome do arquivo pode ser confundido com outra coisa (veja Quando dá errado).

5. Resumos: --stat, --name-only e --word-diff

--stat: quantas linhas, em cada arquivo

$ git diff --stat
 bolo.txt | 3 ++-
 1 file changed, 2 insertions(+), 1 deletion(-)

Uma linha por arquivo, com o número de linhas mexidas e um "gráfico" de + e -, e no fim o total. Aqui: o bolo.txt teve 3 linhas mexidas, 2 que entraram (++) e 1 que saiu (-). A última linha diz, em inglês: "1 arquivo mudado, 2 inserções (+), 1 remoção (-)".

--name-only e --name-status: só os nomes

$ git diff --name-only
bolo.txt
$ git diff --name-status
M	bolo.txt

O --name-status põe uma letra antes do nome: M de modified (modificado). Em outras situações aparecem A (added, novo) e D (deleted, apagado).

--word-diff: palavra por palavra

Num texto comprido (o TCC da Ana, um parágrafo de README), mudar uma palavra faz a linha inteira aparecer duas vezes, com - e com +. O --word-diff mostra só as palavras que mudaram, dentro da linha:

$ git diff --word-diff
diff --git a/bolo.txt b/bolo.txt
index 10a5c6d..c8726b3 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -1,3 +1,4 @@
Bolo de cenoura
3 cenouras
[-4-]{+3+} ovos
{+2 xícaras de farinha+}

[-4-] é o que saiu (entre [- e -]) e {+3+} é o que entrou (entre {+ e +}). No terminal com cores, o Git também tem o --color-words, que pinta as palavras de vermelho e verde sem os colchetes.

6. Quando o git diff fica vazio (mas mudou alguma coisa)

Depois do git add

A Ana gostou do que viu e preparou o arquivo. E o diff... sumiu:

$ git add bolo.txt
$ git diff
$

As mudanças não se perderam: elas foram para a área de preparo. Como o git diff compara a pasta com a área de preparo, e agora as duas estão iguais, não há diferença a mostrar. Para ver o que está preparado (o que vai entrar no commit), use git diff --staged:

$ git diff --staged
diff --git a/bolo.txt b/bolo.txt
index 10a5c6d..c8726b3 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -1,3 +1,4 @@
 Bolo de cenoura
 3 cenouras
-4 ovos
+3 ovos
+2 xícaras de farinha

Esse é o assunto da próxima aula: git diff --staged.

Arquivo novo, que o Git ainda não conhece

$ git commit -q -m 'Ajusta ovos e farinha'
$ echo 'Bolo de chocolate' > chocolate.txt
$ git status --short
?? chocolate.txt
$ git diff
$ git diff chocolate.txt
$

O git status mostra o chocolate.txt com ?? (não rastreado), mas o git diff não diz nada sobre ele. O Git só compara arquivos que ele já conhece; um arquivo novo não tem "versão anterior" para comparar. Depois do git add chocolate.txt, ele aparece no git diff --staged, com todas as linhas marcadas com +.

7. O fim de arquivo sem quebra de linha

Às vezes aparece uma linha estranha, começando com uma barra invertida:

$ git diff fim.txt
diff --git a/fim.txt b/fim.txt
index d77f1f6..6a6a60c 100644
--- a/fim.txt
+++ b/fim.txt
@@ -1 +1,2 @@
-Contato: ana@exemplo.com
\ No newline at end of file
+Contato: ana@exemplo.com
+Instagram: @lojinha.da.ana
\ No newline at end of file

\ No newline at end of file quer dizer "não há quebra de linha no fim do arquivo" (o Git mostra essa frase sempre em inglês). A última linha do fim.txt antigo terminava sem o "Enter" final. Quando a Ana acrescentou uma linha depois dela, a linha velha ganhou um "Enter", e por isso aparece como removida e adicionada, mesmo com o mesmo texto. Não é erro: é só um aviso. Muitos editores (como o VS Code, com a opção certa) põem o "Enter" final sozinhos e evitam esse ruído.

8. Diff comprido: o paginador

Quando o diff não cabe na tela, o Git o abre num paginador (o programa less), em vez de despejar tudo de uma vez. Você percebe porque o prompt não volta e aparece : (ou (END), no fim) na última linha da tela. Ali (ilustrativo, pois depende do tamanho da sua janela):

  • Espaço ou ↓ descem; b ou ↑ sobem;
  • / seguido de um texto procura esse texto;
  • q (de quit) sai e devolve o prompt.

Se você quiser o diff direto na tela, sem paginador, use git --no-pager diff (ou a forma curta, git -P diff). O --no-pager vem antes do diff, porque é uma opção do git, não do subcomando. Com um tracinho só, o Git não entende:

$ git -no-pager diff
unknown option: -no-pager
usage: git [-v | --version] [-h | --help] [-C <path>] [-c <name>=<value>]
           [--exec-path[=<path>]] [--html-path] [--man-path] [--info-path]
           [-p | --paginate | -P | --no-pager] [--no-replace-objects] [--no-lazy-fetch]
           [--no-optional-locks] [--no-advice] [--bare] [--git-dir=<path>]
           [--work-tree=<path>] [--namespace=<name>] [--config-env=<name>=<envvar>]
           <command> [<args>]
$ git --no-pager diff --stat
 bolo.txt | 3 ++-
 1 file changed, 2 insertions(+), 1 deletion(-)

unknown option = "opção desconhecida"; embaixo vem o resumo de uso do git, onde dá para ver, na terceira linha, o -P | --no-pager certo.

Quando dá errado

O nome do arquivo está errado 
$ git diff nada.txt
fatal: ambiguous argument 'nada.txt': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'
$ git diff -- nada.txt
$

O Git não achou nenhum nada.txt na pasta. Linha por linha (esta mensagem ainda não tem tradução e sai em inglês): fatal: ambiguous argument 'nada.txt' = "argumento ambíguo"; unknown revision or path not in the working tree = "não é uma versão (revision, um commit) conhecida nem um caminho que exista na pasta de trabalho". Como o git diff aceita tanto nomes de commits quanto nomes de arquivos, ele não sabe o que você quis dizer. As duas linhas seguintes sugerem o --: "use -- para separar caminhos de versões". Com o --, o Git entende que nada.txt é um arquivo e simplesmente não mostra nada (não há mudanças nele). Como resolver: confira o nome com ls ou git status (maiúsculas contam: Bolo.txt não é bolo.txt).

Fora de um repositório 
$ git diff
warning: Not a git repository. Use --no-index to compare two paths outside a working tree
uso: git diff --no-index [<options>] <path> <path> [<pathspec>...]

Diff output format options
    -p, --patch           generate patch
    -s, --no-patch        suppress diff output
…  (mais umas 120 linhas com a lista de opções)
$ echo $?
129

A Ana estava na pasta /tmp, que não é um repositório. A primeira linha diz: "aviso: não é um repositório git. Use --no-index para comparar dois caminhos fora de uma árvore de trabalho". Em seguida o Git despeja o modo de usar do git diff --no-index (um jeito de usar o git diff para comparar dois arquivos quaisquer) e a lista inteira de opções, em inglês. O código de saída 129 é o que o Git usa para "você usou o comando do jeito errado". Repare que, ao contrário de outros comandos, aqui não aparece o famoso fatal: not a git repository. Como resolver: entre na pasta do projeto (cd ~/receitas) e rode de novo.

"Mudei o arquivo e o git diff não mostra nada!"

Três causas comuns, da mais à menos provável:

  1. Você já deu git add. Confira com git status: se o arquivo está em "Mudanças a serem submetidas", use git diff --staged.
  2. O arquivo é novo (?? no git status --short): o Git ainda não o conhece. Dê git add e use git diff --staged.
  3. Você não salvou o arquivo no editor. O Git só vê o que está no disco.
"O terminal travou depois do git diff"

Provavelmente não travou: é o paginador (seção 8). Aperte q.

Resumo

  • git diff mostra, linha por linha, o que mudou na sua pasta e ainda não foi para a área de preparo. Vazio quer dizer "nada a mostrar".
  • No diff unificado: diff --git a/… b/… abre um arquivo; index traz os hashes; ---/+++ são a legenda; @@ -início,linhas +início,linhas @@ abre um trecho; linhas com - saíram, com + entraram, com espaço são contexto.
  • Uma linha alterada aparece como uma - seguida de uma +.
  • git diff arquivo limita a um arquivo; --stat, --name-only e --word-diff resumem.
  • Depois do git add, as mudanças saem do git diff e aparecem no git diff --staged. Arquivos novos (não rastreados) não aparecem no git diff.
  • Diff comprido abre no paginador: q para sair.
