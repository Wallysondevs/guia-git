Git Conflitos no Rebase

Na aula git rebase, o Git refez os commits do branch em cima do main sem pedir nada. Mas e se o seu branch e o main mudaram a mesma linha do mesmo arquivo? O Git não sabe qual versão vale, então ele para no meio do rebase e pede a sua ajuda. É um conflito, parecido com o do merge (aula Conflitos de Merge), com três diferenças importantes: ele pode acontecer um commit por vez, os lados trocam de nome, e no fim você usa git rebase --continue em vez de git commit.

Você vai aprender
  • Ler a mensagem do rebase que parou e o git status durante o rebase.
  • Entender as marcas <<<<<<<, ======= e >>>>>>> no rebase (o HEAD é o main, não o seu branch!).
  • Resolver e seguir com git add + git rebase --continue.
  • As outras saídas: git rebase --skip (pular o commit) e git rebase --abort (desistir de tudo).
  • O --ours e o --theirs invertidos, e os erros mais comuns no meio do caminho.

Todos os comandos rodaram no Git 2.53 da máquina da Ana (usuária ana, computador notebook), com o sistema em português. Várias mensagens do rebase saem em inglês (a tradução do Git do Ubuntu não cobre todas): cada uma está explicada no texto.

A ideia: passar a limpo, folha por folha

O rebase é como passar um caderno de rascunho a limpo em cima de um caderno novo, que já tem algumas páginas escritas por outra pessoa. Você copia uma folha do rascunho de cada vez. Na maioria das folhas, nada atrapalha. Mas numa delas, o caderno novo já diz "3 xícaras de açúcar" no mesmo lugar onde o seu rascunho diz "1 xícara e meia". Você para, decide o que fica, escreve a versão final, e continua copiando as folhas seguintes. Se a confusão for grande demais, você pode desistir e deixar o rascunho como estava.

1. A situação

A Ana criou o branch cobertura com dois commits: um acrescenta a cobertura de chocolate ao bolo, outro diminui o açúcar para 1 xícara e meia. Enquanto isso, no main, o açúcar foi aumentado para 3 xícaras. A mesma linha mudou nos dois lados:

$ git log --oneline --graph --all --decorate
* 8d43442 (HEAD -> cobertura) Diminui o açúcar para 1 xícara e meia     « muda a linha do açúcar
* 72e787e Acrescenta a cobertura
| * 8796258 (main) Aumenta o açúcar para 3 xícaras                      « muda a MESMA linha
|/
* 9a47438 Adiciona receita de bolo

2. O rebase para: lendo a mensagem

$ git rebase main
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
error: não foi possível aplicar 8d43442... Diminui o açúcar para 1 xícara e meia
hint: Resolve all conflicts manually, mark them as resolved with
hint: "git add/rm <conflicted_files>", then run "git rebase --continue".
hint: You can instead skip this commit: run "git rebase --skip".
hint: To abort and get back to the state before "git rebase", run "git rebase --abort".
hint: Disable this message with "git config set advice.mergeConflict false"
Could not apply 8d43442... # Diminui o açúcar para 1 xícara e meia

Linha por linha:

  • O 1º commit (a cobertura) foi refeito sem problema; o Git parou no 2º. (Sem terminal, num script, aparece antes também o contador de progresso, Rebasing (1/2)Rebasing (2/2).)
  • Mesclagem automática de bolo.txt: o Git tentou juntar as mudanças do bolo.txt sozinho…
  • CONFLITO (conteúdo): conflito de mesclagem em bolo.txt: …e não conseguiu: os dois lados mexeram nas mesmas linhas.
  • error: não foi possível aplicar 8d43442...: o commit que parou foi o 8d43442, "Diminui o açúcar".
  • As dicas (hint:) dizem as três saídas: "resolva os conflitos à mão, marque como resolvidos com git add e rode git rebase --continue"; "ou pule este commit com git rebase --skip"; "ou desista e volte para antes do rebase com git rebase --abort". A última dica ensina a desligar essas mensagens.

O Git deixou o trabalho pela metade, de propósito: a cobertura já foi refeita, o açúcar espera por você. Nada se perdeu.

O git status no meio do rebase

$ git status
interactive rebase in progress; onto 8796258
Last commands done (2 commands done):
   pick 72e787e # Acrescenta a cobertura
   pick 8d43442 # Diminui o açúcar para 1 xícara e meia
No commands remaining.
You are currently rebasing branch 'cobertura' on '8796258'.
  (corrija os conflitos e então rode "git rebase --continue")
  (use "git rebase --skip" para ignorar este patch)
  (use "git rebase --abort" para verificar o ramo original)

Caminhos não mesclados:
  (use "git restore --staged <file>..." to unstage)
  (usar "git add <arquivo>..." para marcar resolução)
	ambos modificados:   bolo.txt                « os dois lados mudaram este arquivo

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")
  • interactive rebase in progress; onto 8796258: "rebase em andamento, sobre o 8796258" (o último commit do main). Ele diz interactive mesmo num rebase comum: por dentro, o Git usa a mesma máquina do rebase interativo (aula Rebase Interativo).
  • Last commands done: a lista de tarefas do rebase. Dois pick ("pegar o commit") já foram tentados; o último é o que parou. No commands remaining: não há mais commits depois deste.
  • You are currently rebasing branch 'cobertura': você está no meio do rebase do cobertura. Enquanto isso, você está num HEAD destacado (aula HEAD Destacado): o branch só é atualizado no fim.
  • ambos modificados: bolo.txt: o arquivo do conflito.

3. As marcas no arquivo: aqui, o HEAD é o main

$ cat bolo.txt
Bolo de cenoura

3 cenouras
<<<<<<< HEAD
3 xícaras de açúcar                                          « o lado do main (a nova base)
=======
1 xícara e meia de açúcar                                    « o lado do SEU commit
>>>>>>> 8d43442 (Diminui o açúcar para 1 xícara e meia)
180 graus por 40 minutos
Cobertura: 200 g de chocolate                                « o 1º commit já foi refeito
<<<<<<< HEAD
Começa o trecho do HEAD. No rebase, o HEAD é a nova base que está sendo construída: o main mais os commits seus que já foram refeitos. Por isso o "3 xícaras", que veio do main, está aqui.
=======
A divisa entre os dois lados.
>>>>>>> 8d43442 (Diminui o açúcar…)
Termina o trecho do commit que está sendo refeito: o seu.
No rebase, os lados se invertem

No merge, você está no seu branch e o HEAD é o seu lado. No rebase, o Git vai para o main e reaplica os seus commits em cima: o HEAD passa a ser o lado do main, e o seu commit aparece embaixo, com o hash dele. Leia sempre o nome depois das marcas antes de decidir.

4. Resolvendo e continuando

A Ana conversa com o Bruno: vale a versão dela, 1 xícara e meia. Ela edita o bolo.txt no editor, apaga as três marcas e a linha que não fica, e salva. O arquivo fica assim:

Agora ela avisa o Git que resolveu, com git add, e confere:

"Todos os conflitos foram corrigidos: execute git rebase --continue". É o próximo passo:

$ git rebase --continue
[detached HEAD e84e410] Diminui o açúcar para 1 xícara e meia     « o commit refeito, com a sua resolução

Successfully rebased and updated refs/heads/cobertura.            « fim: o branch foi atualizado

Pronto: uma linha reta, e o commit da Ana agora muda o açúcar de 3 xícaras (o que o main tinha) para 1 xícara e meia. O [detached HEAD e84e410] lembra que o commit foi feito com o HEAD destacado, no meio do rebase; a linha seguinte confirma que o cobertura passou a apontar para o resultado.

O editor que abre no --continue

Antes de refazer o commit que deu conflito, o git rebase --continue abre o editor de texto do Git (no Ubuntu da Ana, o nano; aula git config) com a mensagem do commit, para você mudar se quiser. No laboratório, este foi o texto que o editor recebeu:

Diminui o açúcar para 1 xícara e meia

# Conflicts:
#	bolo.txt

# Please enter the commit message for your changes. Lines starting
# with '#' will be ignored, and an empty message aborts the commit.
#
# interactive rebase in progress; onto 8796258
# Last commands done (2 commands done):
#    pick 72e787e # Acrescenta a cobertura
#    pick 8d43442 # Diminui o açúcar para 1 xícara e meia
# No commands remaining.
# You are currently rebasing branch 'cobertura' on '8796258'.
#
# Mudanças a serem submetidas:
#	modified:   bolo.txt
#

A primeira linha é a mensagem. As linhas com # são só informação e são ignoradas ("linhas começando com # serão ignoradas, e uma mensagem vazia cancela o commit"). Para manter a mensagem, é só salvar e sair (no nano: Ctrl+O, Enter, Ctrl+X).

Missão: o rebase do cobertura parou com conflito no bolo.txt. Veja o git status e o cat bolo.txt. Fique com a versão de 1 xícara e meia: tire as marcas e a linha do "3 xícaras" (por exemplo, com sed -i '/^<<<<<<</d;/^=======/d;/^>>>>>>>/d;/^3 xícaras/d' bolo.txt), marque como resolvido e continue o rebase até o fim.

5. As outras saídas: --skip e --abort

Desistir de tudo: git rebase --abort

Conflito difícil, ou você nem queria fazer o rebase agora? O --abort ("abortar") cancela o rebase inteiro e devolve o branch ao estado de antes, como se nada tivesse acontecido:

$ git status --short
UU bolo.txt                                       « UU = conflito, os dois lados mudaram
$ git rebase --abort
$ git status
No ramo cobertura
nothing to commit, working tree clean
$ git log --oneline --graph --all --decorate
* 8d43442 (HEAD -> cobertura) Diminui o açúcar para 1 xícara e meia     « os hashes de antes
* 72e787e Acrescenta a cobertura
| * 8796258 (main) Aumenta o açúcar para 3 xícaras
|/
* 9a47438 Adiciona receita de bolo

O --abort não mostra nada. O git status confirma: de volta ao branch cobertura (No ramo cobertura), pasta limpa ("nada a commitar"), e o desenho é o mesmo do começo da aula, com os hashes originais.

Missão: o mesmo conflito, mas agora a Ana desistiu: ela vai conversar com o Bruno antes. Cancele o rebase e confira com git status e git log --oneline --graph --all que tudo voltou a ser como antes.

Pular o commit: git rebase --skip

O --skip ("pular") descarta o commit que deu conflito e segue para o próximo. Use quando você decide que aquele commit não faz mais sentido. Por exemplo: o main já resolveu a questão do açúcar, e a Ana desiste da mudança dela:

$ git rebase --skip
Successfully rebased and updated refs/heads/cobertura.
$ cat bolo.txt
Bolo de cenoura

3 cenouras
3 xícaras de açúcar                               « ficou o do main
180 graus por 40 minutos
Cobertura: 200 g de chocolate
$ git log --oneline --graph --all --decorate
* f101710 (HEAD -> cobertura) Acrescenta a cobertura     « o commit do açúcar sumiu do branch
* 8796258 (main) Aumenta o açúcar para 3 xícaras
* 9a47438 Adiciona receita de bolo

Cuidado: o commit pulado some do branch. Ele ainda dá para achar por um tempo no git reflog (aula Recuperando Commits Perdidos), mas não confunda --skip com "resolver depois".

O --ours ("o nosso") e o --theirs ("o deles") seguem a mesma inversão das marcas: no rebase, "o nosso" é a base (main) e "o deles" é o seu commit. No laboratório:

$ git status --short
UU bolo.txt
$ git restore --theirs bolo.txt
$ cat bolo.txt
Bolo de cenoura

3 cenouras
1 xícara e meia de açúcar                         « --theirs = o commit da Ana
180 graus por 40 minutos
Cobertura: 200 g de chocolate
$ git restore --ours bolo.txt
$ cat bolo.txt
Bolo de cenoura

3 cenouras
3 xícaras de açúcar                               « --ours = o main
180 graus por 40 minutos
Cobertura: 200 g de chocolate

Repare que a cobertura aparece nas duas versões: ela veio do 1º commit da Ana, que já tinha sido refeito sobre o main. Depois do restore, o arquivo continua marcado como conflito (UU) até o git add.

Quando dá errado

needs merge: continuou sem resolver 
$ git rebase --continue
bolo.txt: needs merge
You must edit all merge conflicts and then
mark them as resolved using git add

"bolo.txt precisa de mesclagem. Você precisa editar todos os conflitos e marcá-los como resolvidos com git add." Você esqueceu de resolver, ou resolveu e esqueceu o git add. Como confirmar: git status ainda mostra ambos modificados. Como resolver: edite o arquivo, rode git add bolo.txt e tente de novo.

Deu git add com as marcas ainda no arquivo

O Git não confere o conteúdo: se você der git add num arquivo que ainda tem <<<<<<<, ele aceita, e as marcas entram no commit. Como evitar: antes do --continue, procure as marcas com git diff --staged ou grep -n '<<<<<<<' bolo.txt. Se já continuou, conserte o arquivo e faça um novo commit (ou desfaça com git rebase --abort, se ainda estiver no meio).

O editor deu problema no --continue 
$ git rebase --continue
A entrada padrão não é um terminal
error: there was a problem with the editor 'nano'
Please supply the message using either -m or -F option.
error: could not commit staged changes.

"Houve um problema com o editor nano; não foi possível commitar as mudanças preparadas." Aconteceu no laboratório porque o comando rodou sem um terminal de verdade, onde o nano não consegue abrir (o mesmo acontece se o editor configurado não existir, ou se você sair do editor apagando a mensagem). O rebase continua parado, com a sua resolução preparada. Como resolver: rode git rebase --continue de novo num terminal normal; se o problema for o editor, configure outro (aula git config).

fatal: no rebase in progress 
$ git rebase --continue
fatal: no rebase in progress

"Não há nenhum rebase em andamento." O rebase já terminou (ou foi cancelado). Nada a fazer: confira com git status e git log --oneline --graph.

Conflito de novo, no commit seguinte

Num branch com vários commits que mexem no mesmo trecho, o rebase pode parar mais de uma vez: um conflito por commit. É normal. Resolva, git add, --continue, e repita até aparecer Successfully rebased. Se os conflitos se repetem muito, juntar os commits antes (aula squash) ou usar um merge (aula Rebase ou Merge?) dá menos trabalho.

Resumo

  • O rebase refaz um commit por vez; se um deles conflita, ele para com CONFLITO e não foi possível aplicar HASH....
  • No arquivo, o lado HEAD é a base (o main); o lado com o hash é o seu commit. O --ours/--theirs seguem essa inversão.
  • Para seguir: edite, tire as marcas, git add, git rebase --continue (o editor abre com a mensagem; salve e feche). Pode haver um conflito por commit.
  • git rebase --skip descarta o commit do conflito; git rebase --abort volta tudo para antes.
  • Na dúvida, git status: ele diz em que ponto o rebase está e qual é o próximo passo.
