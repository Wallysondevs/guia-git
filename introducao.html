Git O que é o Git

O Git é um programa que guarda a história de um projeto. Cada vez que você pede, ele tira uma "fotografia" de todos os arquivos da pasta e anota quem fez, quando e por quê. Com essas fotografias, você pode ver o que mudou, voltar a uma versão antiga e trabalhar junto com outras pessoas sem que uma apague o trabalho da outra. Nesta aula você vai entender o que é o Git, de onde ele veio e o que ele faz.

Você vai aprender
  • O que o Git faz, com uma comparação do dia a dia.
  • As palavras que vão aparecer o tempo todo: repositório, commit e histórico.
  • A história do Git: por que Linus Torvalds o criou em 2005.
  • Como ver, no terminal, a versão do Git e o histórico de um projeto.
  • O que você vai conseguir fazer ao terminar este curso.

A ideia: um álbum de fotografias do projeto

A Ana está fazendo um site de receitas. Ela escreve a página da lasanha, depois a do bolo de cenoura, troca as cores, apaga uma receita, se arrepende… Sem nenhuma ferramenta, ela teria duas escolhas ruins: ou guarda só a versão atual (e perde tudo o que apagou), ou faz cópias da pasta inteira com nomes como receitas-final, receitas-final-2, receitas-agora-vai.

O Git resolve isso como um álbum de fotografias. Quando a Ana chega num ponto que vale a pena guardar, ela pede ao Git: "tire uma foto de como o projeto está agora, com esta legenda". O Git cola a foto no álbum, com a data e o nome dela. A pasta continua uma só; as versões antigas ficam guardadas no álbum, e qualquer uma pode ser olhada ou trazida de volta.

No álbumNo GitEm inglês
O álbum inteiro, com todas as fotosO repositório: a pasta do projeto mais a história guardada pelo Gitrepository (ou repo)
Uma foto, com legenda, data e autorUm commit: o registro de como todos os arquivos estavam num momentocommit ("registro", "compromisso")
A sequência de fotos, da primeira à últimaO históricohistory, log
Um segundo álbum para testar uma ideia sem estragar o principalUm branch ("ramo")branch

Você vai ver cada uma dessas palavras com calma, em aulas próprias. Por enquanto, basta a ideia: o Git guarda fotografias do projeto, e cada fotografia se chama commit.

Por que "commit"?

Em inglês, to commit é "comprometer-se", "registrar de forma definitiva". Fazer um commit é dizer ao Git: "esta versão está boa, registre". Como quase todo mundo, este guia usa a palavra em inglês: "fazer um commit", "o último commit".

Vendo o Git de verdade

O Git é um programa de linha de comando: você o usa digitando no terminal. Todo comando do Git começa com a palavra git, seguida do que você quer que ele faça. O primeiro comando é o mais simples de todos, o que pergunta a versão:

git
O nome do programa. Tudo o que vem depois é um pedido para ele.
--version
Uma opção (começa com dois tracinhos): "mostre a sua versão e pare".
$ git --version
git version 2.53.0                 « o Git 2.53, o que vem no Ubuntu 26.04

Esta resposta saiu em inglês, mesmo com o sistema da Ana em português: é uma das poucas mensagens que o Git não traduz. Quase todas as outras (as do git status, os erros, as dicas) saem em português, como você vai ver.

Missão: pergunte ao Git do terminal do guia qual é a versão dele. Digite git --version e aperte Enter.

O álbum de um projeto pronto

A Ana já tem o site de receitas guardado num repositório, a pasta receitas. O comando git log ("diário de bordo") mostra o histórico. Com a opção --oneline ("uma linha"), cada commit ocupa uma linha só:

$ git log --oneline
7da866d (HEAD -> main) Adiciona a receita de bolo de cenoura   « o mais novo
610cd61 Adiciona a receita de lasanha
700bbd5 Cria o README                                    « o primeiro commit

Leia de baixo para cima: o commit mais antigo está embaixo, o mais novo em cima. Cada linha tem duas partes:

  • um código como 700bbd5: o começo do hash, a "impressão digital" do commit, que o identifica sem confusão (aula O Hash do Commit);
  • a mensagem que a Ana escreveu ao fazer o commit, dizendo o que mudou.

Na primeira linha aparece (HEAD -> main): é o Git dizendo "você está aqui, no último commit do ramo main". Você vai entender isso em O que é HEAD.

Missão: o terminal já está dentro da pasta receitas da Ana. Veja o histórico com git log --oneline. Depois, se quiser, tente git log sem opção: cada commit ocupa várias linhas, com autor e data.

O que o Git faz por você

SituaçãoSem GitCom Git
"Apaguei um parágrafo ontem e agora quero de volta."Se não houver cópia, perdeu.O parágrafo está no commit de ontem: é só trazê-lo de volta (git restore).
"O que eu mudei desde a semana passada?"Comparar arquivos no olho.git diff mostra linha por linha o que entrou e o que saiu.
"Quero testar um layout novo sem estragar o site."Copiar a pasta inteira.Criar um branch, testar e, se gostar, juntar ao principal.
"O Bruno e eu mexemos no mesmo arquivo."Um apaga o trabalho do outro, ou alguém junta tudo à mão.O Git junta as mudanças sozinho e avisa só quando as duas mexeram na mesma linha (conflito).
"Meu notebook quebrou."Tudo perdido, se não havia backup.Uma cópia completa do repositório está no GitHub (git push).

O Git funciona com qualquer tipo de arquivo, mas brilha com arquivos de texto: código de programas, páginas HTML, textos em Markdown, configurações, até um TCC escrito em LaTeX. Nesses, ele mostra exatamente que linhas mudaram. Com fotos, vídeos e planilhas ele também guarda as versões, mas não consegue mostrar "o que mudou" por dentro.

Um Git em cada computador

O Git é distribuído: cada pessoa tem, no próprio computador, o repositório inteiro, com toda a história. Não é preciso internet para fazer commits, ver o histórico ou criar branches. A internet só entra quando você quer trocar commits com outras pessoas, geralmente por um site como o GitHub. A diferença entre o Git e o GitHub tem aula própria: Git × GitHub.

Um pouco de história

Em 2005, o kernel Linux (o "núcleo" do sistema operacional) já era um projeto enorme, com milhares de pessoas mandando mudanças. Para organizar tudo, Linus Torvalds, o criador do Linux, usava um programa de controle de versão chamado BitKeeper, que era pago, mas tinha uma licença gratuita para o projeto. Em abril de 2005 essa licença foi retirada, e o Linux ficou sem ferramenta.

Linus não gostou de nenhuma das opções livres da época e decidiu escrever a sua. Em poucos dias, o Git já guardava a própria história. As metas eram claras: ser rápido, aguentar projetos gigantes, funcionar sem um servidor central e proteger os dados contra corrupção (cada commit é identificado pelo hash do seu conteúdo).

QuandoO que aconteceu

hojeO Git é, de longe, o controle de versão mais usado no mundo. Este guia usa o Git 2.53, o do Ubuntu 26.04.
E o nome?

"Git", na gíria inglesa, quer dizer algo como "pessoa chata, teimosa". Linus brincou que dá nome aos projetos em homenagem a si mesmo (primeiro o Linux, depois o Git). O arquivo de apresentação original chamava o Git de "o rastreador de conteúdo estúpido" (the stupid content tracker), uma piada com a ideia de que ele faz algo simples, e faz bem.

Quando dá errado

Errei o nome do comando 
$ git stauts
git: 'stauts' não é um comando git. Veja 'git --help'.

The most similar command is      « "o comando mais parecido é"
	status

O que aconteceu: a Ana quis digitar git status e trocou duas letras. O Git não conhece nenhum subcomando chamado stauts e avisa isso na primeira linha.

Como resolver: leia as linhas de baixo: o Git procurou o nome mais parecido que ele conhece e sugeriu status. Essa parte saiu em inglês ("The most similar command is" = "o comando mais parecido é"): algumas mensagens do Git ainda não têm tradução. É só digitar de novo, certo. Os comandos e a ajuda do Git ficam em Pedindo Ajuda (git help).

O Git não está instalado

Se o terminal responder que o comando git não foi encontrado, o Git não está instalado no seu computador (ou o terminal ainda não o enxerga). A aula Instalar o Git mostra como instalar no Windows, no macOS e no Linux. Enquanto isso, você pode praticar no terminal do guia, que já tem um Git.

O que você vai conseguir fazer

Ao terminar os níveis e os projetos deste guia, você vai:

  • criar um repositório e registrar o seu trabalho em commits pequenos, com boas mensagens;
  • ver o histórico, comparar versões e desfazer erros sem medo (até os grandes);
  • usar branches para testar ideias e juntá-las com merge, resolvendo conflitos;
  • guardar o seu projeto no GitHub e trabalhar em dupla com clone, push e pull;
  • contribuir com outros projetos usando fork e pull request;
  • publicar um site de graça com o GitHub Pages.

Resumo

  • O Git guarda a história de um projeto como um álbum de fotografias; cada fotografia é um commit.
  • O repositório é a pasta do projeto mais essa história; o histórico é a sequência de commits.
  • O Git é distribuído: cada pessoa tem tudo no próprio computador, e a internet só serve para trocar commits.
  • Foi criado por Linus Torvalds em 2005, para o Linux, e é mantido por Junio Hamano desde então.
  • Todo comando começa com git: git --version mostra a versão, git log --oneline mostra o histórico.
