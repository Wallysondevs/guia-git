Git HEAD

A palavra HEAD apareceu em quase todas as aulas até aqui: git reset HEAD~1, git revert HEAD, git show HEAD, (HEAD -> main) no log. O HEAD (em inglês, "cabeça") é o jeito de o Git dizer "você está aqui": o commit em que você está trabalhando agora, que vai ser o pai do seu próximo commit. Nesta aula você vê o que ele é por dentro (spoiler: um arquivo de uma linha), como ele anda, e como contar commits para trás a partir dele.

Você vai aprender
  • O que é o HEAD e onde ele fica: o arquivo .git/HEAD.
  • A corrente HEAD → branch → commit, e como ela anda a cada commit.
  • Como apontar commits anteriores: HEAD~1, HEAD~2, HEAD^ e o apelido @.
  • O que acontece com o HEAD quando você troca de branch, e o que é o "HEAD destacado".
  • Os erros de HEAD num repositório sem commits.

Todas as saídas desta aula vieram do Git real da máquina da Ana (usuária ana, computador notebook), com o sistema em português. A tradução do Git que vem no Ubuntu é parcial: algumas mensagens saem em português, outras em inglês, outras misturadas. Elas estão aqui exatamente como saíram (no Windows, no macOS ou com o sistema em inglês, as frases podem ser diferentes; o sentido é o mesmo).

A ideia: o marcador "você está aqui"

No mapa de um shopping, há um ponto vermelho: "você está aqui". Ele não é uma loja; é só uma indicação de onde você está entre as lojas. No Git:

  • os commits são as lojas (as fotografias do projeto);
  • os branches são placas com nome presas a um commit (main está aqui; veja O que é um Branch);
  • o HEAD é o "você está aqui": normalmente, ele aponta para uma placa (o branch atual), e a placa aponta para um commit.
HEAD ──► main ──► 91591a1 ("Adiciona receita de pudim")
                     │ pai
                  62fc1c8 ("Adiciona receita de bolo")
                     │ pai
                  fe996fb ("Primeiro commit")

Quando você faz um commit, o Git cria o commit novo com o pai = o commit do HEAD, e então move a placa do branch para o commit novo. O HEAD continua apontando para a placa, então ele "anda junto".

1. O HEAD é um arquivo

Num repositório recém-criado, a Ana espia o arquivo .git/HEAD com o cat:

$ mkdir receitas && cd receitas
$ git init -q
$ cat .git/HEAD
ref: refs/heads/main
$ ls .git/refs/heads

Uma linha só: ref: refs/heads/main, que quer dizer "o HEAD é uma referência ao branch main". O refs/heads/main é o caminho do arquivo do branch, dentro do .git. Mas a pasta .git/refs/heads está vazia: o branch main ainda não existe de verdade, porque não há commit nenhum para ele apontar. O HEAD aponta para uma placa que ainda vai ser pregada.

Depois do primeiro commit:

$ echo '# Receitas da Ana' > README.md
$ git add README.md
$ git commit -q -m "Primeiro commit"
$ cat .git/HEAD
ref: refs/heads/main
$ ls .git/refs/heads
main
$ cat .git/refs/heads/main
fe996fb8ecae7fe25026045fd46f15ca756bc19c

O .git/HEAD não mudou: continua dizendo "estou no main". O que apareceu foi o arquivo do branch, .git/refs/heads/main, com uma linha só: o hash do primeiro commit. Um branch é só isso: um arquivinho com um hash.

O HEAD anda a cada commit

$ printf 'Bolo de cenoura\nTempo: 40 minutos\n' > bolo.txt
$ git add bolo.txt
$ git commit -q -m "Adiciona receita de bolo"
$ cat .git/refs/heads/main
62fc1c8c3360d4d2a8fdd305433da11404bd3aa7   « o main andou para o commit novo
$ echo 'Pudim de leite' > pudim.txt
$ git add pudim.txt
$ git commit -q -m "Adiciona receita de pudim"
$ git log --oneline --decorate
91591a1 (HEAD -> main) Adiciona receita de pudim
62fc1c8 Adiciona receita de bolo
fe996fb Primeiro commit

A cada commit, o Git escreveu o hash novo no arquivo do main. E o git log --oneline --decorate mostra as placas: (HEAD -> main) quer dizer "o HEAD aponta para o main, que está neste commit". (A opção --decorate, "decorar", mostra os nomes ao lado dos commits; no terminal do dia a dia ela já vem ligada, e você vê o (HEAD -> main) mesmo sem pedir.)

Para traduzir HEAD (ou um branch) em hash, use o git rev-parse:

$ git rev-parse HEAD
91591a1289296941f2457423b98987a08fc12c29
$ git rev-parse main
91591a1289296941f2457423b98987a08fc12c29

Os dois dão o mesmo hash, porque o HEAD está no main. Na maioria dos comandos, HEAD e o nome do branch atual são intercambiáveis. E há um apelido mais curto ainda para o HEAD, o @:

$ git show --stat --oneline @
91591a1 (HEAD -> main) Adiciona receita de pudim
 pudim.txt | 1 +
 1 file changed, 1 insertion(+)

2. Contando para trás: HEAD~1, HEAD~2, HEAD^

Como cada commit sabe quem é o seu pai, dá para andar para trás a partir do HEAD:

HEAD~1
"Um commit antes do HEAD": o pai. O ~ (til) seguido de um número conta gerações para trás.
HEAD~2
"Dois commits antes": o avô (o pai do pai).
HEAD^
Outro jeito de dizer "o pai" (o ^ é o acento circunflexo, sozinho). HEAD^^ é o avô.
HEAD~
Sem número, o til vale 1: o mesmo que HEAD~1.
$ git rev-parse HEAD~1 HEAD^ HEAD~2 HEAD^^
62fc1c8c3360d4d2a8fdd305433da11404bd3aa7   « HEAD~1: o bolo
62fc1c8c3360d4d2a8fdd305433da11404bd3aa7   « HEAD^: o mesmo
fe996fb8ecae7fe25026045fd46f15ca756bc19c   « HEAD~2: o primeiro commit
fe996fb8ecae7fe25026045fd46f15ca756bc19c   « HEAD^^: o mesmo
$ git show --stat HEAD~1
commit 62fc1c8c3360d4d2a8fdd305433da11404bd3aa7
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona receita de bolo

 bolo.txt | 2 ++
 1 file changed, 2 insertions(+)
$ git log --oneline HEAD~1
62fc1c8 Adiciona receita de bolo
fe996fb Primeiro commit
$ git show HEAD~2:README.md
# Receitas da Ana

Os nomes relativos funcionam em todo comando que aceita um commit: o git log HEAD~1 mostra o histórico a partir do pai; o git show HEAD~2:README.md mostra o README como estava dois commits atrás. E também se combinam: HEAD~1~1 é o mesmo que HEAD~2.

~ ou ^?

Para "voltar N commits", use o ~: HEAD~3 é mais fácil de ler que HEAD^^^. O ^ tem um uso especial em commits de merge, que têm dois pais: HEAD^1 é o primeiro pai e HEAD^2 é o segundo. Em commits comuns, com um pai só, os dois dão no mesmo. Um cuidado no terminal: em alguns shells (como o zsh, padrão do macOS, dependendo da configuração), o ^ tem significado especial e precisa de aspas: git show 'HEAD^'. No bash do Ubuntu, não precisa.

Missão: o repositório da Ana tem três commits. Sem usar hash, mostre com git show o commit que está dois commits antes do HEAD (o "Primeiro commit"). Use HEAD~2 ou HEAD^^.

3. O HEAD ao trocar de branch

Quando você troca de branch (veja git switch), o que muda é o arquivo .git/HEAD: ele passa a apontar para outra placa.

$ git switch -c testes
Switched to a new branch 'testes'
$ cat .git/HEAD
ref: refs/heads/testes   « o HEAD mudou de placa
$ git log --oneline --decorate
91591a1 (HEAD -> testes, main) Adiciona receita de pudim
62fc1c8 Adiciona receita de bolo
fe996fb Primeiro commit
$ git switch main
Switched to branch 'main'
$ cat .git/HEAD
ref: refs/heads/main

O git switch -c testes criou o branch testes e mudou o HEAD para ele ("Mudou para um novo branch 'testes'"; estas mensagens o Git do Ubuntu ainda não traduziu). No log, (HEAD -> testes, main): as duas placas estão no mesmo commit, e o HEAD aponta para a testes. Um próximo commit moveria só a placa testes, a que o HEAD aponta. Com git switch main, o HEAD voltou para o main.

Uma olhada no HEAD destacado

O HEAD também pode apontar direto para um commit, sem placa no meio. Isso se chama HEAD destacado (detached HEAD), e acontece quando você vai para um commit antigo para dar uma olhada:

$ git switch --detach HEAD~1
HEAD is now at 62fc1c8 Adiciona receita de bolo
$ cat .git/HEAD
62fc1c8c3360d4d2a8fdd305433da11404bd3aa7   « um hash, e não "ref: …"
$ git status
HEAD detached at 62fc1c8
nothing to commit, working tree clean
$ git log --oneline --decorate --all
91591a1 (testes, main) Adiciona receita de pudim
62fc1c8 (HEAD) Adiciona receita de bolo
fe996fb Primeiro commit
$ git switch main
Previous HEAD position was 62fc1c8 Adiciona receita de bolo
Switched to branch 'main'

O .git/HEAD agora tem um hash em vez de ref: refs/heads/…, o git status avisa HEAD detached at 62fc1c8 ("HEAD destacado em 62fc1c8"), e o log mostra (HEAD) sozinho, sem seta para branch nenhum. Nada de grave: é só "estou olhando um commit antigo, fora de qualquer branch". O git switch main trouxe tudo de volta ("posição anterior do HEAD era 62fc1c8…; mudou para o branch 'main'"). O que dá para fazer (e o que evitar) nesse estado é assunto da aula HEAD Destacado.

Quando dá errado

Repositório sem nenhum commit 
$ git log
fatal: your current branch 'main' does not have any commits yet
$ git rev-parse HEAD
fatal: ambiguous argument 'HEAD': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'
HEAD
$ git show HEAD
fatal: ambiguous argument 'HEAD': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

"O seu branch atual, main, ainda não tem nenhum commit." Num repositório recém-criado, o HEAD aponta para o main, mas o main ainda não existe (lembre-se: a pasta .git/refs/heads estava vazia). Por isso, todo comando que precisa do commit do HEAD falha: HEAD não leva a commit nenhum. (O git rev-parse ainda repete o argumento, HEAD, na última linha.) Como resolver: faça o primeiro commit (veja Seu Primeiro Commit).

Voltou mais commits do que existem 
$ git show HEAD~3
fatal: ambiguous argument 'HEAD~3': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

O histórico tem 3 commits: HEAD, HEAD~1 e HEAD~2. O HEAD~3 seria o pai do primeiro commit, e o primeiro commit não tem pai. Como resolver: conte no git log --oneline; o último da lista é HEAD~(número de commits − 1).

Escreveu head em minúsculas 
$ git show head
fatal: ambiguous argument 'head': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

No Linux, o nome é HEAD, em maiúsculas: head é outra coisa (e não existe). Em computadores com Windows ou macOS, o head minúsculo às vezes "funciona" por acidente, porque o sistema de arquivos não diferencia maiúsculas, mas isso causa problemas estranhos com branches. Como resolver: escreva HEAD, ou use o apelido @.

Resumo

  • O HEAD é o "você está aqui" do Git: o commit atual, pai do próximo commit.
  • Por dentro, é o arquivo .git/HEAD, que normalmente diz ref: refs/heads/main: o HEAD aponta para o branch, e o branch (o arquivo .git/refs/heads/main) aponta para um commit.
  • A cada commit, o branch atual anda para o commit novo, e o HEAD anda junto.
  • HEAD~1 (ou HEAD^) é o pai; HEAD~2, o avô; @ é um apelido para o HEAD.
  • Trocar de branch muda o .git/HEAD. Se ele apontar direto para um commit, o HEAD está destacado (HEAD detached at …).
  • Sem nenhum commit, HEAD não leva a lugar nenhum: does not have any commits yet.
