Git O Mínimo de Terminal para o Git

O Git se usa no terminal, e todo comando do Git age sobre a pasta em que você está. Por isso, antes do primeiro commit, você precisa saber responder três perguntas: onde eu estou, o que tem aqui e como vou para outra pasta. Esta aula ensina só o mínimo para isso. Se você já se vira no terminal, pode pular para git config.

Você vai aprender
  • Ler o prompt, a linha que espera o seu comando.
  • Saber onde está (pwd), ver o que tem na pasta (ls, ls -a) e mudar de pasta (cd).
  • Criar uma pasta (mkdir), criar um arquivo e ver o conteúdo dele (cat).
  • Entender os erros mais comuns: pasta que não existe, nome com espaço.

A ideia: o terminal é um "andar por pastas" com palavras

No gerenciador de arquivos (o Explorador do Windows, o Finder do Mac), você dá dois cliques numa pasta para entrar nela e vê os arquivos em ícones. No terminal é a mesma coisa, só que com palavras: você diz "entre nesta pasta" (cd) e "me mostre o que tem aqui" (ls). A qualquer momento, o terminal está "dentro" de uma pasta, a pasta atual.

Isso importa muito para o Git: git status, git commit e quase todos os outros olham para o repositório da pasta atual. Rodar um comando do Git na pasta errada é o erro número um de quem está começando.

O prompt

Quando o terminal está pronto, ele mostra uma linha assim e espera você digitar:

ana@notebook:~$
ana
O nome da usuária.
@notebook
O nome do computador.
:~
A pasta atual. O ~ (til) é um apelido para a sua pasta pessoal, aqui /home/ana.
$
O sinal de "pode digitar". Você digita depois dele e aperta Enter.

Neste guia, nas caixas de terminal, a linha do comando começa com $: é o que você digita. As linhas sem $ são a resposta. O prompt completo aparece quando a pasta muda, como ana@notebook:~/receitas$. No Git Bash do Windows e no Terminal do Mac, o prompt tem outra cara, mas a ideia é a mesma.

Onde estou? pwd

pwd quer dizer print working directory, "mostre a pasta de trabalho". Ele responde o caminho completo da pasta atual:

$ pwd
/home/ana                          « a pasta pessoal da Ana

Um caminho é o endereço de uma pasta: cada / separa uma pasta da de dentro. /home/ana é a pasta ana, dentro da pasta home, que fica na raiz do sistema (/). No Git Bash do Windows, os caminhos têm a mesma forma, com o disco no começo: /c/Users/ana é a pasta C:\Users\ana.

O que tem aqui? ls

ls vem de list, "listar". Ele mostra o que tem na pasta atual:

$ ls
 Documentos   Imagens   Música    Vídeos    'Área de trabalho'
 Downloads    Modelos   Público

Repare em 'Área de trabalho': o ls mostra entre aspas os nomes com espaço, para você saber onde o nome começa e termina.

Os escondidos: ls -a

Arquivos e pastas cujo nome começa com ponto (.) são ocultos: o ls não os mostra. A opção -a (all, "todos") mostra tudo. Isso é importante para o Git, porque ele guarda toda a história numa pasta oculta chamada .git. Veja a pasta receitas, que já é um repositório:

$ ls
README.md  lasanha.txt
$ ls -a
.  ..  .git  README.md  lasanha.txt
  • . é um apelido para a própria pasta atual, e .. para a pasta de cima. Toda pasta tem os dois.
  • .git é o "cofre" do Git, com todos os commits. Só aparece com -a. Não mexa nele à mão: quem cuida dele são os comandos do Git. Se você apagá-lo, a pasta deixa de ser um repositório e toda a história vai junto.

Mudando de pasta: cd

cd vem de change directory, "mudar de pasta". Ele não mostra nada quando dá certo: a mudança aparece no prompt e no pwd.

$ cd receitas
$ pwd
/home/ana/receitas
$ cd ..                            « sobe para a pasta de cima
$ pwd
/home/ana
$ cd receitas
$ cd ~                             « volta para a pasta pessoal, de qualquer lugar
$ pwd
/home/ana
$ cd -                             « volta para a pasta onde estava antes
/home/ana/receitas
ComandoVai para…
cd receitasA pasta receitas, dentro da atual.
cd ..A pasta de cima.
cd ~ ou só cdA sua pasta pessoal.
cd -A pasta anterior (e mostra qual é).
cd ~/receitasA pasta receitas da pasta pessoal, de qualquer lugar.
Deixe o Tab digitar por você

Digite cd rec e aperte Tab: o terminal completa para cd receitas/. Além de poupar tempo, evita erros de digitação. As setas ↑ e ↓ trazem de volta os comandos que você já digitou.

Criando uma pasta e arquivos

Uma pasta: mkdir

mkdir vem de make directory, "criar pasta". Também não mostra nada quando dá certo:

$ mkdir receitas
$ cd receitas
$ pwd
/home/ana/receitas

Um arquivo: echo com >

Nas aulas, para criar um arquivo pequeno sem abrir editor, vamos usar o echo (que "ecoa", repete um texto) com o sinal >, que manda o texto para um arquivo em vez da tela:

echo
Mostra o texto que vem depois.
'# Receitas da Ana'
O texto, entre aspas simples para o terminal não mexer em nada dentro dele.
> README.md
Em vez de mostrar na tela, grave no arquivo README.md. Se o arquivo existe, ele é substituído; com >>, o texto é acrescentado no fim.
$ echo '# Receitas da Ana' > README.md
$ ls
README.md
$ cat README.md                    « cat mostra o conteúdo do arquivo
# Receitas da Ana

O cat (de concatenate, "juntar") mostra o conteúdo de arquivos de texto. É o jeito rápido de conferir um arquivo antes de fazer um commit.

Arquivos maiores: um editor

No dia a dia, você vai editar os arquivos num editor de verdade: o VS Code, o Bloco de Notas, o gedit, o nano no próprio terminal… Para o Git, tanto faz: ele só olha o que está gravado na pasta. Uma dica útil: com o VS Code instalado, o comando code . abre a pasta atual nele (o . é "esta pasta").

Missão: crie a pasta receitas, entre nela e crie um arquivo README.md com o texto # Receitas da Ana. Confira com pwd, ls e cat README.md.

Missão: você está na pasta pessoal. Entre na pasta receitas e encontre a pasta escondida do Git com ls -a.

Quando dá errado

A pasta não existe 
$ cd receita
bash: cd: receita: Arquivo ou diretório inexistente

O que aconteceu: não existe uma pasta chamada receita (sem o "s") na pasta atual. "Diretório" é o nome técnico de pasta.

Como confirmar: pwd para ver onde você está e ls para ver o que existe aqui. Muitas vezes o nome está certo e é você que está na pasta errada.

Como resolver: corrija o nome (use o Tab!) ou vá antes para a pasta certa.

Nome de pasta com espaço 
$ cd Área de trabalho
bash: cd: número excessivo de argumentos
$ cd Área\ de\ trabalho
$ pwd
/home/ana/Área de trabalho

O que aconteceu: o terminal separa as palavras pelos espaços. Ele entendeu cd com três nomes, Área, de e trabalho, e o cd só aceita um.

Como resolver: ponha o nome entre aspas (cd "Área de trabalho") ou uma barra invertida antes de cada espaço (cd Área\ de\ trabalho, que é o que o Tab escreve). Melhor ainda: nas pastas de projeto, use nomes sem espaço e sem acento, como receitas ou meu-site.

A pasta já existe 
$ mkdir receitas
mkdir: receitas: Arquivo existe

O que aconteceu: já há uma pasta (ou arquivo) com esse nome aqui. Nada foi apagado nem mudado.

Como resolver: se é a pasta que você queria, é só entrar nela com cd receitas. Se queria uma nova, escolha outro nome.

Rodei um comando do Git na pasta errada

Se o Git responder fatal: not a git repository ("não é um repositório git"), quase sempre o terminal está fora da pasta do projeto. Rode pwd, vá para a pasta certa com cd e tente de novo. Essa mensagem aparece explicada em Criando um Repositório.

Resumo

  • Todo comando do Git age sobre a pasta atual: saiba sempre onde você está (pwd, ou o prompt).
  • ls mostra o que tem na pasta; ls -a mostra também os ocultos, como a pasta .git, onde o Git guarda a história.
  • cd pasta entra, cd .. sobe, cd volta para a pasta pessoal; mkdir cria pastas.
  • echo 'texto' > arquivo cria um arquivo pequeno; cat mostra o conteúdo; um editor serve para o resto.
  • Nomes com espaço precisam de aspas; nas pastas de projeto, prefira nomes sem espaço.
