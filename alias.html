Git Atalhos (alias)

Depois de algumas semanas usando Git, você vai perceber que digita as mesmas coisas o dia inteiro: git status, git log --oneline --graph --all… Um alias (em inglês, "apelido") é um nome curto que você inventa para um comando do Git. Você ensina uma vez, e daí em diante git st faz o mesmo que git status.

Você vai aprender
  • Como criar um alias com git config --global alias.NOME.
  • Como guardar um comando comprido, com opções, num nome curto (o famoso git lg).
  • Onde os aliases ficam guardados, como listá-los e apagá-los.
  • Como chamar outros programas com um alias que começa com !.
  • O que acontece quando você digita um alias errado, ou tenta trocar um comando do próprio Git.

Todas as saídas desta aula vieram do Git real do Ubuntu na máquina da Ana (usuária ana, computador notebook), com o sistema em português.

A ideia: os contatos do celular

Ninguém guarda o telefone da mãe como +55 11 98765-4321 e digita tudo toda vez: a gente salva o contato como "Mãe" e toca no nome. O número continua o mesmo; você só ganhou um nome fácil para ele.

Um alias do Git é isso: st é o "contato", e status é o "número". Quando você digita git st, o Git procura na lista de aliases, acha st = status e roda git status. Nada muda no repositório: é só um atalho de digitação.

1. O primeiro alias: git st

A Ana está no repositório do site de receitas, com o bolo.txt modificado. Ela criou o alias e usou na mesma hora:

$ git config --global alias.st status
$ git st
No ramo main
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   bolo.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

(Algumas linhas do git status saem em inglês no Git 2.53 do Ubuntu, mesmo com o sistema em português, porque a tradução não está completa: "Changes not staged for commit" é "mudanças fora da área de preparo", e "modified" é "modificado".)

git config
O comando que guarda configurações do Git (o mesmo de git config, onde a Ana configurou o nome e o e-mail).
--global
Guarda para todos os repositórios da Ana, no arquivo ~/.gitconfig. Sem ele, o alias valeria só no repositório atual.
alias.st
O nome da configuração: a seção alias e, depois do ponto, o nome do atalho, st.
status
O que o atalho quer dizer: o comando do Git sem a palavra git.

O git config não responde nada quando dá certo. Logo depois, git st mostrou exatamente o que o git status mostraria: o branch, e o bolo.txt modificado, com as mesmas dicas.

Missão: crie o alias st para o status e use-o, digitando git st.

2. Atalho com opções: o git lg

O ganho de verdade aparece nos comandos compridos. Para ver o histórico com o desenho dos branches (veja log --graph), a Ana digitava git log --oneline --graph --all. Agora:

$ git config --global alias.lg 'log --oneline --graph --all'
$ git lg
* 7d39e7d (pudim) Adiciona pudim
* 6743c4a (HEAD -> main) Adiciona bolo de cenoura
* fe996fb Primeiro commit

Três palavras viraram duas letras. O Adiciona pudim está no branch pudim, um passo à frente do main; os nomes entre parênteses mostram onde cada branch está (e o HEAD -> main, onde você está). Por isso o desenho ainda é uma linha reta (os galhos aparecem na seção 4, quando o main andar). Outro atalho comum é o ultimo, para ver só o último commit:

$ git config --global alias.ultimo 'log -1 HEAD'
$ git ultimo
commit 6743c4aecca1d7a877b0ea2afc03a524ca18703f (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona bolo de cenoura

Quando o alias tem mais de uma palavra, ponha entre aspas ('log --oneline --graph --all'): sem elas, o terminal entregaria só log ao git config e o resto viraria outros argumentos.

Você ainda pode acrescentar opções

O que você escreve depois do alias é colado no fim do comando. git lg -2 vira git log --oneline --graph --all -2; um alias para desfazer o add (veja Tirando da Área de Preparo) recebe o nome do arquivo no fim:

$ git config --global alias.despreparar 'restore --staged'
$ git add bolo.txt
$ git st -s
M  bolo.txt                « M na 1ª coluna: preparado
$ git despreparar bolo.txt
$ git st -s
 M bolo.txt                « M na 2ª coluna: fora da área de preparo

O git st -s virou git status -s (o status curto), e o git despreparar bolo.txt virou git restore --staged bolo.txt.

Os aliases podem ter acento e hífen, mas evite acento: nem todo teclado e nem todo terminal ajudam.

3. Onde os aliases ficam guardados

Com --global, tudo vai para o arquivo ~/.gitconfig, na pasta pessoal da Ana. Para ver só os aliases, peça as configurações que começam com alias.:

$ git config --global --get-regexp '^alias\.'
alias.st status
alias.lg log --oneline --graph --all
alias.ultimo log -1 HEAD
alias.despreparar restore --staged
$ cat ~/.gitconfig
[user]
	name = Ana Souza
	email = ana@exemplo.com
[init]
	defaultBranch = main
[core]
	editor = nano
[alias]                                  « a seção dos atalhos
	st = status
	lg = log --oneline --graph --all
	ultimo = log -1 HEAD
	despreparar = restore --staged

Para ver um alias só, pergunte pelo nome: git config --global alias.lg responde log --oneline --graph --all. Se o alias não existe, a resposta é nada (e o código de saída é 1).

A forma nova do git config git 2.46+

Nos Gits mais novos, o git config ganhou subcomandos com nome: git config set, get, list e unset. Os dois jeitos funcionam; a forma antiga, que você vê nos tutoriais, continua valendo:

$ git config set --global alias.br branch
$ git br
* main
  pudim
$ git config get alias.lg
log --oneline --graph --all

O arquivo é texto comum, numa seção [alias]. Dá para editá-lo direto, com git config --global --edit ou com qualquer editor; o resultado é o mesmo que usar o git config.

Perguntando ao Git o que um alias faz

$ git help st
'st' is aliased to 'status'

"st é um apelido de status" (essa mensagem também ainda sai em inglês).

O git help (veja git help) reconhece o alias e conta o que ele quer dizer, em vez de abrir um manual.

4. Alias que roda outros programas: o !

Normalmente o alias é um comando do Git. Se ele começar com !, o Git entrega o resto para o shell, e aí vale qualquer coisa: outros programas, vários comandos, $(…).

$ git config --global alias.oi '!echo "Olá, $(git config user.name)! Você está no branch $(git branch --show-current)."'
$ git oi
Olá, Ana Souza! Você está no branch main.

O alias inteiro está entre aspas simples, para o terminal não trocar o $(…) na hora de criar o alias: a troca acontece depois, toda vez que a Ana roda git oi.

Com uma pequena função de shell, o alias recebe argumentos onde você quiser ($1, $2…). Este faz o add e o commit de um arquivo de uma vez:

$ git config --global alias.adiciona-e-commita '!f() { git add "$1" && git commit -m "$2"; }; f'
$ echo 'Bolo de chocolate' > chocolate.txt
$ git adiciona-e-commita chocolate.txt 'Adiciona bolo de chocolate'
[main 05f49f7] Adiciona bolo de chocolate
 1 file changed, 1 insertion(+)
 create mode 100644 chocolate.txt
$ git lg
* 05f49f7 (HEAD -> main) Adiciona bolo de chocolate     « o main andou...
| * 7d39e7d (pudim) Adiciona pudim       « ...e o pudim virou um galho
|/
* 6743c4a Adiciona bolo de cenoura
* fe996fb Primeiro commit
!
"O que vem depois é um comando de shell, não do Git."
f() { … }; f
Cria uma função chamada f e a chama em seguida. Os argumentos do alias (chocolate.txt e a mensagem) chegam na função como $1 e $2.
git add "$1" && git commit -m "$2"
Prepara o arquivo e, se deu certo (&&), commita com a mensagem.
Atalho bom não esconde o que faz

Um alias que junta add e commit é prático, mas pula a hora de olhar o git status. Para quem está aprendendo, prefira aliases que só encurtam (st, lg) e deixe os passos importantes à vista.

5. Apagando um alias

$ git config --global --unset alias.ultimo
$ git ultimo
git: 'ultimo' não é um comando git. Veja 'git --help'.

The most similar command is
	quiltimport

Depois do --unset, o nome deixa de existir, e o Git reclama como de qualquer comando desconhecido: "ultimo não é um comando git". A sugestão, quiltimport ("o comando mais parecido é…"), é só o nome de comando do Git que mais se parece com ultimo, e não tem nada a ver com o que a Ana queria.

Formas diferentes de fazer a mesma coisa

Também dá para criar o atalho no Bash, em vez de no Git (veja a aula de alias do Guia Bash, em wallysondevs.github.io/guia-bash/alias.html): alias gs='git status', guardado no ~/.bashrc. A diferença é que o alias do Bash é um comando novo (gs, sem git na frente) e só existe naquele shell; o alias do Git vale em qualquer terminal e em qualquer programa que chame o Git.

Quando dá errado

Digitou o alias errado 
$ git stt
git: 'stt' não é um comando git. Veja 'git --help'.

The most similar commands are
	st
	status
$ git sts
git: 'sts' não é um comando git. Veja 'git --help'.

The most similar command is
	stash

O que aconteceu: stt e sts não são comandos nem aliases. O Git procura nomes parecidos, inclusive entre os seus aliases, e sugere ("The most similar commands are" = "os comandos mais parecidos são"). Cuidado com a sugestão: para sts ele sugeriu stash, que faz uma coisa bem diferente (veja git stash). Como resolver: digite o nome certo. Se você erra sempre o mesmo, a aula Configurações Úteis mostra o help.autocorrect.

Tentou trocar um comando do próprio Git 
$ git config --global alias.status 'status -s'
$ git status
No ramo main
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   bolo.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

O que aconteceu: um alias não pode ter o nome de um comando que já existe no Git. O Git aceitou a configuração sem reclamar, mas a ignora: git status continua sendo o status de sempre. (É de propósito: assim, um alias nunca muda o comportamento de um comando que você conhece.) Como resolver: use outro nome (git s, git ss) e apague o que não funciona com git config --global --unset alias.status.

Esqueceu as aspas 
$ git config --global alias.lg3 log --oneline --graph
error: no action specified
$ git config --global alias.lg4 log --oneline
$ git config --global alias.lg4
log

O que aconteceu: sem aspas, o terminal entrega ao git config várias palavras soltas. Com três, ele não entendeu o pedido ("no action specified" = "nenhuma ação indicada") e não guardou nada. Com duas, foi pior: ele não reclamou, mas guardou só log (o --oneline foi entendido como outra coisa). Como confirmar: git config --global alias.lg4 mostra o que ficou guardado. Como resolver: rode de novo com o comando inteiro entre aspas simples: git config --global alias.lg4 'log --oneline'.

Aliases populares, para você se inspirar (crie só os que for usar): st = status, sw = switch, br = branch, ci = commit, lg = log --oneline --graph --all, ultimo = log -1 HEAD, despreparar = restore --staged.

Resumo

  • Alias = nome curto para um comando do Git: git config --global alias.st status e depois git st.
  • Comando com opções vai entre aspas; o que você digita depois do alias é colado no fim.
  • Com --global, os aliases ficam na seção [alias] do ~/.gitconfig; liste com --get-regexp '^alias\.', apague com --unset.
  • Começando com !, o alias roda no shell.
  • Um alias nunca substitui um comando do Git que já existe.
