Git GitHub CLI (gh)

O git cuida do seu repositório: commits, branches, push. Mas criar o repositório no GitHub, abrir um pull request ou ver as issues são coisas do site, e o git não sabe fazer. Para não precisar sair do terminal, o GitHub criou o GitHub CLI, o comando gh (CLI = command-line interface, "interface de linha de comando"). Com ele, a Ana cria o repositório, abre o pull request e vê se o Bruno aprovou, tudo no terminal.

Você vai aprender
  • A diferença entre git (o repositório) e gh (o site do GitHub).
  • Como instalar e entrar na conta: gh auth login.
  • Como criar e clonar repositórios: gh repo create e gh repo clone.
  • O fluxo de um pull request pelo terminal: gh pr create, gh pr list, gh pr checkout.
  • Issues e atalhos: gh issue e gh browse.
O que nesta aula é real e o que é ilustrativo

O gh conversa com o GitHub de verdade, pela internet, com a sua conta. A máquina da Ana usada no guia (Git 2.53 do Ubuntu, usuária ana, computador notebook) não tem internet nem o gh: por isso as saídas de git desta aula são reais, e os comandos gh são ilustrativos, baseados no manual oficial (cli.github.com/manual). As respostas que o gh dá dependem da sua conta e mudam de versão para versão; quando esta aula foi escrita, a versão era a 2.102.

A ideia: o carteiro e a agência dos Correios

O git push é o carteiro: leva o pacote (os commits) até o endereço. Mas abrir uma caixa postal nova, registrar uma reclamação ou acompanhar o pedido são coisas que você resolve no balcão da agência: no caso do GitHub, o site.

O gh é um balcão da agência dentro do seu terminal:

gitgh
Quem fezO projeto Git (software livre)O GitHub (também software livre)
Funciona comQualquer servidor (GitHub, GitLab, um servidor da empresa) e até sem servidorSó com o GitHub
Cuida deCommits, branches, merge, push, pullRepositórios no site, pull requests, issues, releases, Actions
Precisa de internetSó para push, pull, fetch, clonePara quase tudo

Um não substitui o outro: o gh usa o git por baixo (por exemplo, o gh repo clone roda um git clone) e você continua commitando com o git.

2. Entrando na conta: gh auth login (ilustrativo)

gh auth login

O gh faz algumas perguntas no próprio terminal (em qual GitHub entrar, se o Git deve usar HTTPS ou SSH) e, no modo padrão, abre o navegador para você confirmar o login na sua conta. No fim, ele guarda um token de acesso no cofre de senhas do sistema. Pelo manual:

gh auth login
Entra numa conta do GitHub. O padrão é o github.com; com --hostname, entra no GitHub de uma empresa.
--web
Abre o navegador para entrar.
--git-protocol ssh
(ou https) Qual protocolo o Git vai usar com esse GitHub (veja Chave SSH e HTTPS e Token).
--with-token
Lê um token da entrada padrão, em vez de perguntar (para scripts).

Para conferir se entrou, use gh auth status. Com o protocolo HTTPS, o gh também pode servir de "porteiro de senhas" do git (o comando gh auth setup-git): o git push passa a usar o login do gh, sem pedir token.

O token é uma senha

Nunca cole o token num arquivo do repositório nem num print (veja Commitei uma Senha!). Se ele vazar, revogue-o nas configurações da conta do GitHub.

3. Repositórios: gh repo (ilustrativo)

Em Criando um Repositório no GitHub, a Ana criou o repositório pelo site e depois ligou a pasta com git remote add. Com o gh, tudo isso é um comando. Ela já tinha o site de receitas commitado na pasta (saída real do git):

$ git log --oneline
6743c4a Adiciona bolo de cenoura
fe996fb Primeiro commit
$ git remote -v

O git remote -v não respondeu nada: a pasta ainda não está ligada a nenhum servidor. E então, pelo manual do gh repo create:

gh repo create receitas --public --source=. --push
gh repo create receitas
Cria, no GitHub da Ana, o repositório receitas (vira ana-souza/receitas).
--public
Público (ou --private, privado). Sem essas opções, o gh pergunta.
--source=.
"Use a pasta atual como origem": liga este repositório local ao novo, criando o remoto (por padrão, origin; --remote escolhe outro nome).
--push
Já envia os commits locais.

O resultado é o mesmo do caminho pelo site: depois disso, git remote -v mostraria o origin apontando para o GitHub. Outros comandos de repositório:

ComandoO que fazEquivalente
gh repo create meu-projeto --public --cloneCria no GitHub e clona para cáSite + git clone
gh repo clone ana-souza/receitasClona usando só "dono/nome"git clone https://github.com/ana-souza/receitas.git
gh repo forkFaz um fork do repositório (veja Fork)Botão de fork no site
gh repo view --webAbre a página do repositório no navegador
gh browseAbre no navegador o repositório da pasta atual

4. Um pull request inteiro pelo terminal

O Bruno pediu à Ana a receita de pudim. Ela segue o GitHub Flow: branch novo, commit, push e pull request. A parte do git é a de sempre (saída real):

$ git switch -c receita-pudim
Switched to a new branch 'receita-pudim'
$ echo 'Pudim de leite' > pudim.txt
$ git add pudim.txt
$ git commit -m 'Adiciona receita de pudim'
[receita-pudim 89b71e4] Adiciona receita de pudim
 1 file changed, 1 insertion(+)
 create mode 100644 pudim.txt

("Switched to a new branch" = "trocou para um branch novo"; essa mensagem ainda sai em inglês no Git do Ubuntu.) Depois do git push (com o push.autoSetupRemote de Configurações Úteis, ele cria o branch no GitHub sozinho), em vez de abrir o site, ela usa o gh:

gh pr create --title "Adiciona receita de pudim" --body "O Bruno pediu. Testei a receita no sábado."
gh pr create
Abre um pull request do branch atual. Se der certo, o gh mostra o endereço (URL) do pull request criado.
--title / --body
O título e a descrição. Sem eles, o gh pergunta no terminal.
--base
(opcional) Para qual branch o pull request vai. O padrão é o branch principal do repositório (main).
--fill
(alternativa) Usa a mensagem do commit como título e descrição.
--draft
(opcional) Abre como rascunho: "ainda não está pronto para revisão".
--reviewer bruno-lima
(opcional) Pede a revisão do Bruno.
--web
(alternativa) Abre o formulário do pull request no navegador, já preenchido.

Na página do GitHub CLI, a sessão de exemplo mostra a primeira linha da resposta assim: Creating pull request for feature-branch into main in ampinsk/test ("criando pull request do feature-branch para o main em ampinsk/test"). No caso da Ana, apareceriam receita-pudim, main e ana-souza/receitas.

Acompanhando e revisando

Depois do merge no GitHub, o resto volta a ser git: git switch main e git pull para trazer o pudim para a sua cópia.

Missão: o terminal do guia não tem o gh nem internet, mas você pode deixar tudo pronto para o gh pr create: crie o branch receita-pudim, crie o pudim.txt com uma linha e faça o commit dele nesse branch.

Quando dá errado

Comando 'gh' não encontrado 
$ gh auth login
Comando 'gh' não encontrado, mas poder ser instalado com:
sudo apt install gh

O que aconteceu: o gh não vem com o Git; é outro programa. Como resolver: instale (seção 1) e abra um terminal novo.

"Não estou logado" (ilustrativo)

O que aconteceu: qualquer comando que fale com o GitHub (gh pr list, gh repo create) precisa do login. O gh avisa e sugere rodar gh auth login. Como confirmar: gh auth status. Como resolver: gh auth login.

O pull request saiu sem o último commit

O que aconteceu: o pull request mostra o que está no GitHub. Se você commitou e não fez git push, o commit só existe no seu computador. Como confirmar: o git status avisa (saída real, depois de a Ana commitar a calda do pudim sem enviar):

$ git status
No ramo receita-pudim
Seu ramo está à frente de 'origin/receita-pudim' por 1 submissão.
  (use "git push" to publish your local commits)

nothing to commit, working tree clean

"À frente por 1 submissão" (submissão é como o Git em português chama o commit) e a dica "use git push para publicar os seus commits locais". Como resolver: git push: o pull request se atualiza sozinho.

"not a git repository" ou o repositório errado

O que aconteceu: o gh pr e o gh issue descobrem o repositório pela pasta atual (pelos remotos do git). Fora de um repositório, ou numa pasta com outro remoto, eles reclamam ou falam com o repositório errado. Como confirmar: git remote -v. Como resolver: entre na pasta certa, ou diga o repositório com -R dono/nome (por exemplo, gh issue list -R ana-souza/receitas).

Resumo

  • git cuida do repositório; gh cuida do que é do site do GitHub (repositórios, pull requests, issues). Um não substitui o outro.
  • Instale o gh (cli.github.com) e entre com gh auth login.
  • gh repo create NOME --source=. --push cria o repositório e envia a pasta atual; gh repo clone dono/nome clona.
  • Pull request pelo terminal: gh pr create, gh pr list, gh pr checkout N, gh pr merge N.
  • O pull request mostra o que está no GitHub: commitou, faça git push.
