Git commit

O git commit é o comando que guarda uma versão do projeto no histórico. Cada commit (em português, "registro"; aqui no guia, uma fotografia) leva tudo o que está na área de preparo, com o nome de quem fez, a data e uma mensagem explicando o que mudou. Você já fez commits em Seu Primeiro Commit; nesta aula você vai ver todas as formas de usar o comando, a saída dele linha por linha e o que fazer quando ele recusa.

Você vai aprender
  • A anatomia do git commit -m "mensagem" e cada linha da resposta.
  • Uma mensagem com título e corpo: com dois -m ou pelo editor de texto.
  • O -a, que prepara e commita os arquivos rastreados de uma vez, e o commit de um arquivo só.
  • As opções -q e --allow-empty.
  • Os erros reais: o -m sem mensagem, a mensagem sem aspas, nada para commitar, a mensagem vazia e o git comit.

As saídas são reais, do Git 2.53 da máquina da Ana (Ubuntu 26.04 em português; parte das mensagens do Git sai em inglês, porque a tradução do Ubuntu está incompleta). O nome e o e-mail da Ana já estão configurados (aula git config).

A ideia: a foto com legenda

Uma foto no álbum de família tem três coisas além da imagem: quem tirou, quando e uma legenda ("Natal na casa da vó, 2025"). Daqui a dez anos, é a legenda que vai fazer você achar a foto certa. Um commit é igual: o Git guarda o conteúdo dos arquivos, o autor, a data e a mensagem que você escreveu. O git commit é o botão da câmera: ele fotografa a área de preparo (o que você escolheu com git add, aula git add) e cola a foto no álbum.

Uma vez feito, o commit fica guardado: você pode voltar a ele, comparar com ele, desfazê-lo. Por isso o Git é tão seguro: o que foi commitado, quase nunca se perde (a aula Recuperando Commits Perdidos mostra até como achar um commit "apagado").

1. A forma mais usada: git commit -m

$ git add README.md
$ git commit -m "Adiciona o README"
[main (root-commit) d84dc97] Adiciona o README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
git commit
"Registre": cria um commit com o que está na área de preparo.
-m
De message: a mensagem vem logo em seguida. Também se escreve --message.
"Adiciona o README"
A mensagem. As aspas são obrigatórias quando ela tem espaços (seção Quando dá errado). Aspas simples também servem: 'Adiciona o README'.

A resposta:

[main (root-commit) d84dc97]
O ramo onde o commit foi feito (main); root-commit aparece só no primeiro commit do repositório (a raiz do histórico); d84dc97 é o começo do código do commit, o hash (aula O Hash do Commit).
Adiciona o README
A primeira linha da mensagem.
1 file changed, 1 insertion(+)
"1 arquivo alterado, 1 inserção": quantos arquivos o commit mudou e quantas linhas entraram. Quando há linhas removidas, aparece também 1 deletion(-) ("1 remoção").
create mode 100644 README.md
O arquivo é novo no histórico (create), e 100644 quer dizer "arquivo comum". Para arquivos que só mudaram, esta linha não aparece; para um arquivo apagado, aparece delete mode.

Do segundo commit em diante, o (root-commit) some:

$ echo 'Pudim de leite' > pudim.txt
$ git add pudim.txt
$ git commit -m "Adiciona o pudim"
[main 98ae2a6] Adiciona o pudim
 1 file changed, 1 insertion(+)
 create mode 100644 pudim.txt

Missão: o pudim.txt já está na área de preparo (confira com git status). Faça o commit com uma mensagem que tenha a palavra pudim, por exemplo "Adiciona a receita de pudim". Repare na resposta: tem (root-commit)?

2. Título e corpo: dois -m

Uma mensagem de commit pode ter duas partes: um título curto (a primeira linha) e um corpo, separado por uma linha em branco, com os detalhes: o porquê da mudança. Com dois -m, o primeiro vira o título e o segundo, o corpo:

$ git commit -m "Adiciona a receita de bolo" -m "A receita é da minha avó. Ainda faltam os ingredientes."
[main d71d267] Adiciona a receita de bolo
 1 file changed, 1 insertion(+)
 create mode 100644 bolo.txt
$ git log -1
commit d71d2670b7a02ec5fa25e8dc14a56961aa231da8 (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona a receita de bolo                                « o título

    A receita é da minha avó. Ainda faltam os ingredientes.   « o corpo

A resposta do git commit mostra só o título; o git log -1 (o último commit; aula git log) mostra a mensagem inteira. O Git pôs a linha em branco entre os dois -m sozinho. Como escrever um bom título e um bom corpo é assunto da aula Boas Mensagens de Commit.

Se você abrir aspas e apertar Enter antes de fechá-las, o terminal mostra > e continua esperando: a quebra de linha vira parte da mensagem.

$ git commit -m "Acrescenta canela
> no bolo"
[main b1e64ff] Acrescenta canela no bolo
 1 file changed, 1 insertion(+)
$ git log -1
commit b1e64ff9132f9d39d78df31ab978ab46b16c2e17 (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Acrescenta canela
    no bolo

Na resposta do commit, o título aparece numa linha só (Acrescenta canela no bolo), mas no histórico ficaram duas linhas sem a linha em branco, e ferramentas que leem só o título vão se confundir. Para título e corpo, prefira os dois -m ou o editor.

3. Sem -m: a mensagem no editor

Sem o -m, o Git abre um editor de texto dentro do terminal para você escrever a mensagem com calma. Na máquina da Ana o editor é o nano (é o que ela configurou; sem configuração, o Git do Ubuntu abre o editor padrão do sistema, que no Ubuntu também é o nano; em outros sistemas pode ser o vim). Com o pudim.txt preparado, ela rodou git commit e a tela ficou assim:

  GNU nano 8.7.1        /home/ana/receitas/.git/COMMIT_EDITMSG

# Please enter the commit message for your changes. Lines starting
# with '#' will be ignored, and an empty message aborts the commit.
#
# No ramo main
# Mudanças a serem submetidas:
#       new file:   pudim.txt
#

                               [ 8 linhas lidas ]
^G Ajuda     ^O Gravar    ^F Onde está?^K Recortar  ^T Executar  ^C Local
^X Sair      ^R Ler o arq ^\ Substituir^U Colar     ^J Justificar^/ Ir p/ linha
.git/COMMIT_EDITMSG
O arquivo que você está editando: um arquivo temporário do Git, dentro da pasta .git. Quando você fecha o editor, o Git lê a mensagem dele.
a primeira linha, vazia
É onde o cursor está, e onde você escreve o título. Para um corpo, deixe uma linha em branco depois do título e escreva embaixo.
as linhas com #
Um lembrete que não entra na mensagem: "escreva a mensagem do commit; linhas começando com # serão ignoradas, e uma mensagem vazia cancela o commit". Embaixo, o mesmo resumo do git status, para você lembrar o que está commitando.
^X Sair, ^O Gravar…
Os atalhos do nano: o ^ é a tecla Ctrl. Ctrl+X sai.

A Ana escreveu Acrescenta cravo no bolo na primeira linha, apertou Ctrl+X, respondeu S ("Sim") à pergunta Salvar o buffer modificado? (buffer é o texto que está no editor) e apertou Enter para confirmar o nome do arquivo. O nano fechou e o commit aconteceu:

$ git commit
[main 00de704] Acrescenta cravo no bolo
 1 file changed, 1 insertion(+)

Se ela tivesse saído sem escrever nada, o Git cancelaria: Aborting commit due to empty commit message. (veja Quando dá errado). Para usar outro editor (o do VS Code, por exemplo), configure o core.editor (aula Configurações Úteis).

Caiu no vim e não sabe sair?

Em sistemas onde o editor padrão é o vim, a tela é parecida, mas os atalhos não aparecem embaixo. Para sair: aperte Esc, digite :q! e Enter (sai sem salvar e o commit é cancelado). Para escrever: aperte i, digite a mensagem, depois Esc, :wq e Enter (salva e sai).

4. Preparar e commitar de uma vez: -a

O -a (de all, "todos") faz o git add de todos os arquivos rastreados que mudaram (inclusive os apagados) e já faz o commit:

$ echo '3 ovos' >> bolo.txt
$ echo 'Calda de caramelo' >> pudim.txt
$ git status -s
 M bolo.txt
 M pudim.txt
$ git commit -a -m "Completa o bolo e o pudim"
[main 00e4be2] Completa o bolo e o pudim
 2 files changed, 2 insertions(+)

Os dois arquivos estavam modificados e não preparados ( M), e o commit levou os dois. As opções de uma letra podem ser juntadas: git commit -am "mensagem" é o mesmo que git commit -a -m "mensagem". Mas atenção: o -a não pega arquivos novos (os ??). Arquivo novo precisa de git add na primeira vez (veja A Área de Preparo).

5. Commitar um arquivo só

Dá para dar nomes de arquivos ao git commit: ele commita só esses arquivos, na versão da pasta, sem precisar de git add (desde que sejam rastreados), e deixa o resto como está:

$ echo '1 xícara de óleo' >> bolo.txt
$ echo 'Leite condensado' >> pudim.txt
$ git commit bolo.txt -m "Acrescenta o óleo no bolo"
[main 216814d] Acrescenta o óleo no bolo
 1 file changed, 1 insertion(+)
$ git status -s
 M pudim.txt                « o pudim ficou para outro commit

6. Outras opções úteis

-q: sem a resposta

O -q (de quiet, "quieto") faz o commit sem mostrar nada quando dá certo. É útil em scripts:

$ echo 'Pudim de leite' > pudim.txt
$ git add pudim.txt
$ git commit -q -m "Adiciona o pudim"

--allow-empty: um commit sem mudanças

Normalmente o Git recusa um commit sem nada novo. Com --allow-empty ("permitir vazio"), ele aceita. É raro, mas aparece em tutoriais de automação (para "disparar" um serviço do GitHub, por exemplo):

$ git commit --allow-empty -m "Commit vazio de teste"
[main 2ad784c] Commit vazio de teste

Repare que não há a linha files changed: nada mudou.

Formas diferentes

FormaQuando usar
git add … + git commit -m "…"O padrão: você escolhe o que entra, e a mensagem cabe numa linha.
git commit -m "título" -m "corpo"Quando a mudança precisa de uma explicação.

git commit arquivo -m "…"Commitar só um arquivo rastreado, sem mexer na área de preparo dos outros.

Quando dá errado

"switch `m' requires a value" 
$ git commit -m
error: switch `m' requires a value

"A opção m precisa de um valor": você escreveu o -m e esqueceu a mensagem. Nenhum commit foi feito. Como resolver: git commit -m "sua mensagem".

Mensagem sem aspas: "pathspec … did not match any file(s)" 
$ git commit -m Adiciona o leite condensado
error: pathspec 'o' did not match any file(s) known to git
error: pathspec 'leite' did not match any file(s) known to git
error: pathspec 'condensado' did not match any file(s) known to git

Sem aspas, o terminal separa as palavras: o -m ficou só com Adiciona, e o Git achou que o, leite e condensado eram nomes de arquivos para commitar (como na seção 5). Como não existem arquivos com esses nomes, ele reclamou de cada um ("o caminho não corresponde a nenhum arquivo que o Git conhece") e não fez o commit. Como resolver: ponha a mensagem entre aspas.

"nothing to commit, working tree clean" 
$ git commit -m "Nada"
No ramo main
nothing to commit, working tree clean

"Nada a commitar, pasta de trabalho limpa". Não há nenhuma mudança desde o último commit. Talvez você já tenha commitado (confira com git log --oneline), ou esqueceu de salvar o arquivo no editor. Se há mudanças mas nada preparado, a resposta é outra: o Git mostra o git status com nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a"), e a solução é git add.

"Aborting commit due to empty commit message." 
$ git commit
Aborting commit due to empty commit message.

"Cancelando o commit porque a mensagem está vazia". O editor abriu e você fechou sem escrever nada (ou só deixou as linhas com #). Nada se perdeu: o que estava preparado continua preparado. Como resolver: rode de novo e escreva a mensagem, ou use -m.

"'comit' não é um comando git" 
$ git comit -m "Teste"
git: 'comit' não é um comando git. Veja 'git --help'.

The most similar command is
	commit

Erro de digitação. O Git avisa que comit não existe e sugere o comando mais parecido ("o comando mais parecido é commit"). Como resolver: digite de novo, com dois m. (A seta ↑ traz o comando anterior para você corrigir.)

"Please tell me who you are"

O Git não sabe o seu nome e e-mail, e não faz o commit sem eles. A mensagem completa e a solução estão em Seu Primeiro Commit e em git config.

Missão: o bolo.txt foi modificado e não está preparado. Faça o commit com um comando só, com a mensagem Acrescenta os ovos no bolo. Se errar as aspas, leia a resposta do Git e tente de novo.

Resumo

  • git commit -m "mensagem" registra no histórico tudo o que está na área de preparo, com autor, data e mensagem.
  • A resposta mostra o ramo, o começo do hash, o título, quantos arquivos e linhas mudaram e os arquivos criados (create mode). (root-commit) = primeiro commit.
  • Dois -m = título e corpo. Sem -m, o Git abre o editor (nano no Ubuntu); linhas com # são ignoradas e mensagem vazia cancela.
  • -a prepara e commita os rastreados (não os novos); git commit arquivo commita só aquele arquivo.
  • Mensagem com espaços vai entre aspas. Sem mudanças, o Git responde nothing to commit.
