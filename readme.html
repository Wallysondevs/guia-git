Git README e Markdown

Quando alguém abre um repositório no GitHub, a primeira coisa que vê, logo abaixo da lista de arquivos, é o conteúdo de um arquivo chamado README.md. Ele é a capa do projeto: diz o que é, para que serve e como usar. O nome vem do inglês read me, "leia-me". O .md no fim quer dizer Markdown, um jeito simples de escrever texto com títulos, listas e links usando só caracteres comuns, como # e *. Nesta aula a Ana escreve o README do site de receitas e o versiona com o Git.

Você vai aprender
  • O que é o README e o que ele deve contar.
  • Onde o GitHub procura o README e onde o mostra.
  • O Markdown básico: títulos, parágrafos, negrito, itálico, listas, links, imagens e código.
  • Como criar, commitar e enviar o README com o Git.
  • Os tropeços mais comuns de quem começa no Markdown.

Os comandos desta aula rodaram no Git 2.53 da máquina da Ana (usuária ana, computador notebook), com o sistema em português. A aparência do README no site do GitHub está descrita com base na documentação oficial (Sobre os READMEs) e é ilustrativa.

A ideia: a contracapa do livro

Numa livraria, você pega um livro, vira e lê a contracapa: em poucas linhas, ela diz do que o livro trata e se ele serve para você. Ninguém lê o livro inteiro para descobrir isso. O README é a contracapa do repositório. A documentação do GitHub lista o que ele costuma responder:

  • o que o projeto faz;
  • por que ele é útil;
  • como começar a usar;
  • onde pedir ajuda;
  • quem mantém e contribui.

E o Markdown? É como escrever um bilhete à mão com algumas convenções: sublinhar o título, pôr um tracinho na frente de cada item da lista. No Markdown, o título ganha um # na frente e o item da lista ganha um -. O arquivo continua sendo texto puro (dá para ler no terminal), mas o GitHub o desenha bonito, com letras grandes, marcadores e links clicáveis.

1. Onde o GitHub procura e mostra o README

  • O GitHub procura o README em três lugares, nesta ordem: a pasta .github, a raiz do repositório (o lugar mais comum) e a pasta docs. Use a raiz.
  • Ele aparece na página principal do repositório, abaixo da lista de arquivos (ilustrativo).
  • O GitHub monta sozinho um sumário com os títulos do README, num ícone no alto do arquivo (ilustrativo).
  • Num repositório público com o mesmo nome do seu usuário (para a Ana, ana-souza/ana-souza), o README aparece na sua página de perfil.
  • O que passar de 500 KiB é cortado: README é para ser curto.

Para o Git, o README é um arquivo como outro qualquer: ele é criado, adicionado e commitado do mesmo jeito. Quem dá o destaque é o GitHub.

2. O Markdown básico, peça por peça

Este é o README que a Ana escreveu para o site de receitas:

# Receitas da Ana

Site com as receitas da família, testadas na cozinha da Ana.

## Receitas

- [Bolo de cenoura](bolo.txt)
- Pão de queijo *(em breve)*

## Como contribuir

1. Faça um fork.
2. Crie um branch.
3. Abra um **pull request**.
# Receitas da Ana
Um #, um espaço e o texto: título principal (o maior). Use um só no arquivo, com o nome do projeto.
## Receitas
Dois #: um subtítulo, um nível abaixo. Existem até seis níveis (######).
(linha em branco)
Separa os blocos. Uma linha de texto seguida de outra, sem linha em branco entre elas, vira um parágrafo só.
- item
Um - (ou *) e um espaço: item de lista com marcador.
1. item
Número, ponto e espaço: lista numerada.
[Bolo de cenoura](bolo.txt)
Um link: o texto entre colchetes, o endereço entre parênteses, sem espaço no meio. Aqui o endereço é relativo (o arquivo bolo.txt do próprio repositório); a documentação do GitHub recomenda links relativos, que continuam funcionando para quem clona.
*(em breve)*
Entre um asterisco de cada lado: itálico.
**pull request**
Entre dois asteriscos de cada lado: negrito.

3. Versionando o README com o Git

A Ana já tem o repositório receitas com a receita do bolo. Ela cria o README.md com o editor (ou, no terminal, com cat > README.md e um here-doc, como no laboratório) e olha o git status:

$ git status
No ramo main
Arquivos não monitorados:                                       « arquivos que o Git ainda não acompanha
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	README.md

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)

O README aparece em "Arquivos não monitorados" (não rastreados), como qualquer arquivo novo (aula git status). A dica entre parênteses já diz o próximo passo: git add. Ele entra no histórico pelo caminho de sempre, git add e git commit:

$ git add README.md
$ git commit -m 'Adiciona README'
[main f3deee4] Adiciona README
 1 file changed, 14 insertions(+)
 create mode 100644 README.md                « create = arquivo novo no histórico
$ git log --oneline
f3deee4 (HEAD -> main) Adiciona README
8bf5d5b Adiciona receita de bolo
$ git show --stat HEAD
commit f3deee4f2ad5aefb5d1adc50d93efd6bda4e67c7 (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona README

 README.md | 14 ++++++++++++++              « 14 linhas novas
 1 file changed, 14 insertions(+)

O git show --stat confirma: o commit criou o README.md com as linhas dele (aula git show). Depois, um git push manda o commit ao GitHub (aula git push), e o README aparece na página do repositório.

Criar o repositório com README no site

Na tela de criar repositório (aula Criando um Repositório no GitHub), o GitHub oferece a opção de já começar com um README. Se você marcar essa opção, o repositório nasce com um commit; aí o caminho é clonar (aula git clone), e não git init + git remote add, para não terminar com dois históricos diferentes.

Missão: crie o README.md com o título # Receitas da Ana (dica: echo '# Receitas da Ana' > README.md; as aspas simples impedem o terminal de tratar o # como comentário), confira com git status e faça o commit com a mensagem "Adiciona README".

Missão: acrescente ao fim do README um subtítulo ## Como usar e uma frase embaixo (use >>, que acrescenta ao arquivo; um > só apagaria o título). Veja a mudança com git diff e faça o commit.

Quando dá errado

Commitou sem o git add 
$ git commit -m 'Adiciona README'
No ramo main
Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	README.md

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)

"Nada adicionado ao envio (ao commit), mas há arquivos não registrados." Nenhum commit foi criado. O Git não commita arquivo novo sozinho. A própria mensagem ensina: git add primeiro, depois o commit.

O título não virou título

Você escreveu #Receitas da Ana, sem espaço, e o GitHub mostrou o texto com o # no começo, como frase comum. No Markdown do GitHub, o título precisa de um espaço depois dos #: # Receitas da Ana.

As linhas grudaram

Duas linhas escritas uma embaixo da outra apareceram juntas, no mesmo parágrafo. É o Markdown: uma quebra de linha simples não separa parágrafos. Como resolver: deixe uma linha em branco entre eles.

O link quebrou

[Bolo de cenoura] (bolo.txt), com espaço entre ] e (, não vira link. E [Bolo](Bolo.txt) não acha o arquivo bolo.txt: no GitHub, maiúsculas e minúsculas fazem diferença nos nomes de arquivos. Escreva [Bolo de cenoura](bolo.txt), colado e com o nome exato.

O # sumiu no terminal 
$ echo # Receitas > teste.md

$ ls teste.md
ls: não é possível acessar 'teste.md': Arquivo ou diretório inexistente

Sem aspas, o terminal entende o # como começo de um comentário e ignora o resto da linha, inclusive o > teste.md: sobrou só um echo, que mostrou uma linha vazia, e o arquivo nem foi criado. Use aspas simples: echo '# Receitas' > teste.md.

Resumo

  • O README.md é a capa do repositório: o GitHub o mostra abaixo da lista de arquivos. Ponha-o na raiz.
  • Ele responde: o que é, por que é útil, como começar, onde pedir ajuda, quem mantém.
  • Markdown: # + espaço para títulos, linha em branco entre parágrafos, **negrito**, *itálico*, - para listas, [texto](endereço) para links, crases para código.
  • Para o Git, o README é um arquivo comum: git add README.md, git commit, git push.
