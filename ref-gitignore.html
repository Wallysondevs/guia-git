Git Modelos de .gitignore

Todo projeto tem arquivos que não devem ir para o Git: dependências baixadas (que podem ser baixadas de novo), arquivos gerados pela compilação, senhas, e o "lixo" que o sistema e o editor criam sozinhos. Esta página mostra o que costuma entrar no .gitignore de cada tipo de projeto, com os trechos principais dos modelos oficiais mantidos pelo GitHub, e os comandos para conferir se está funcionando.

De onde vêm os modelos
  • Os trechos desta página foram tirados do repositório github/gitignore, a coleção oficial de modelos do GitHub, distribuída sob a licença CC0 1.0 (domínio público: pode copiar e adaptar à vontade, sem pedir licença). Mostramos só as linhas mais importantes de cada arquivo; o modelo completo está no link de cada seção.
  • São os mesmos modelos que o GitHub oferece na lista "Add .gitignore" ao criar um repositório pelo site (veja Criando um Repositório no GitHub).
  • Para entender as regras com calma, veja a aula Ignorando Arquivos (.gitignore).

Os padrões, em uma tabela

Cada linha do .gitignore é um padrão. Os caminhos são relativos à pasta onde o .gitignore está (em geral, a raiz do projeto).

LinhaIgnoraExemplo de arquivo ignorado
segredo.txtQualquer arquivo ou pasta com esse nome, em qualquer subpasta.segredo.txt, docs/segredo.txt
*.log* = qualquer sequência de caracteres (menos /).erro.log, logs/npm-debug.log
pasta/Com / no fim: só pastas com esse nome (e tudo dentro).node_modules/ inteira
/buildCom / no começo: só na raiz do projeto.build, mas não src/build
docs/*.txtUma / no meio prende o padrão ao caminho a partir da raiz.docs/notas.txt, mas não docs/a/notas.txt
**/temp** = qualquer número de pastas.temp, a/b/temp
log?.txt? = exatamente um caractere.log1.txt, logA.txt
*.py[cod][…] = um dos caracteres entre colchetes.x.pyc, x.pyo, x.pyd
!.env.example! = exceção: volta a incluir algo que uma linha anterior ignorou.(o .env.example deixa de ser ignorado)
# comentárioLinha começando com # é comentário; linha em branco é ignorada.
A exceção não "entra" numa pasta ignorada

Se uma pasta inteira foi ignorada (.vscode/), um !.vscode/settings.json depois não funciona: o Git nem olha dentro dela. Por isso os modelos escrevem .vscode/* (o conteúdo da pasta) e depois as exceções.

Português e inglês misturados? A tradução do Git que vem no Ubuntu é parcial: algumas mensagens saem em português, outras em inglês (e algumas em português de Portugal, como "submissões"). As saídas abaixo estão exatamente como apareceram; as mensagens em inglês ganham tradução no texto. Em outros sistemas, as frases podem sair diferentes ou todas em inglês.

Um exemplo testado

A lojinha da Ana é um projeto Node.js. Antes do .gitignore, o git status quer levar tudo, inclusive a pasta de dependências e o arquivo de senhas. Saída real:

$ git status
No ramo main

No commits yet

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	.DS_Store              « lixo do macOS (veio num arquivo que o Bruno mandou)
	.env                   « senhas!
	.env.example
	.vscode/
	node_modules/          « dependências: milhares de arquivos
	npm-debug.log          « log de erro
	package.json
	src/

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)

Ela cria o .gitignore na raiz do projeto (num editor; aqui, mostrado com cat):

$ cat .gitignore
# Dependências (o npm baixa de novo com "npm install")
node_modules/

# Segredos: nunca no Git
.env
.env.*
!.env.example

# Logs
*.log

# VS Code: só as configurações do projeto
.vscode/*
!.vscode/settings.json
$ git status --short --ignored
?? .DS_Store                « ainda aparece: veja "O .gitignore pessoal", abaixo
?? .env.example             « a exceção funcionou
?? .gitignore               « o próprio .gitignore deve ser commitado
?? .vscode/                 « por causa do settings.json
?? package.json
?? src/
!! .env                     « !! = ignorado
!! .vscode/launch.json
!! node_modules/
!! npm-debug.log

Para saber qual linha está ignorando um arquivo, use git check-ignore -v. Ele mostra arquivo:linha:padrão e o caminho; quando o arquivo não é ignorado, não mostra nada e termina com código 1:

$ git check-ignore -v .env npm-debug.log .vscode/launch.json node_modules/express/index.js
.gitignore:5:.env	.env
.gitignore:10:*.log	npm-debug.log
.gitignore:13:.vscode/*	.vscode/launch.json
.gitignore:2:node_modules/	node_modules/express/index.js
$ git check-ignore -v src/app.js
$ echo $?
1

Missão: crie um .gitignore para a lojinha que ignore a pasta node_modules, o arquivo .env e todos os arquivos .log, e dê git add no próprio .gitignore. Confira com git status --ignored. Dica: printf '%s\n' 'linha1' 'linha2' > .gitignore escreve uma linha por argumento.

Lixo que o sistema operacional cria nas pastas. O .gitignore pessoal (para todos os seus projetos)

O lixo do seu sistema e do seu editor aparece em todo projeto. Em vez de repetir no .gitignore de cada um, crie um arquivo seu e avise o Git com core.excludesFile (veja Configurações). Sem essa configuração, o Git já procura um arquivo em ~/.config/git/ignore.

$ printf '%s\n' '.DS_Store' 'Thumbs.db' '*~' '.idea/' > ~/.gitignore_global
$ git config --global core.excludesFile ~/.gitignore_global
$ git status --short
?? .env.example
?? .gitignore
?? .vscode/
?? package.json
?? src/                                « o .DS_Store sumiu da lista
$ git check-ignore -v .DS_Store
/home/ana/.gitignore_global:1:.DS_Store	.DS_Store   « ignorado pelo arquivo pessoal, linha 1

Quando dá errado

Pus o arquivo no .gitignore e ele continua aparecendo

$ echo '.env' > .gitignore
$ echo 'SENHA=456' > .env
$ git status --short
 M .env                                « continua aparecendo como modificado
?? .gitignore

O que aconteceu: o .gitignore só vale para arquivos não rastreados. O .env já tinha entrado num commit antes, então o Git continua acompanhando.

Como resolver: tire-o do rastreamento, sem apagar da pasta, e commite junto com o .gitignore:

$ git rm --cached .env
rm '.env'                              « "removido" do Git, não da pasta
$ git status --short
D  .env                                « vai sair do repositório no próximo commit
?? .gitignore
$ git add .gitignore
$ git commit -q -m 'Para de rastrear o .env'
$ git status --short
$ ls -A
.env  .git  .gitignore  app.js         « o .env continua na pasta da Ana

Atenção: o .env antigo continua nos commits anteriores. Se ele tinha uma senha de verdade e foi enviado ao GitHub, troque a senha. Veja Commitei uma Senha!.

A exceção (!) não funciona

O que aconteceu: a pasta inteira foi ignorada antes (config/ e depois !config/padrao.json), ou a exceção veio antes da regra que ignora (a ordem importa: a última linha que casa vence).

Como resolver: ignore o conteúdo (config/*) em vez da pasta, ponha a exceção depois e confira com git check-ignore -v config/padrao.json.

O .gitignore não funciona nenhum

O que aconteceu: o arquivo está com nome errado (gitignore sem o ponto, .gitignore.txt, criado assim por alguns editores no Windows) ou numa pasta errada.

Como resolver: ls -a na raiz do projeto: o nome tem de ser exatamente .gitignore. Renomeie com mv .gitignore.txt .gitignore.
