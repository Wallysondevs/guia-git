Tutorial Git

Aprenda Git e GitHub do zero, como numa escola: cada comando é explicado pedaço por pedaço, você vê a resposta real do Git e pratica num terminal aqui mesmo na página, com um Git de verdade imitado dentro do navegador. Você não precisa instalar nada para começar, e não tem como estragar nada.

Experimente agora

A caixa abaixo é o terminal Experimente do guia. A pasta receitas já é um repositório Git e já tem um arquivo, o README.md, que ainda não foi guardado em nenhuma versão. Clique na janela escura, digite os comandos da missão, um de cada vez, e tecle Enter depois de cada um.

Missão: guarde a primeira versão do README.md. Digite git status (o painel do Git), depois git add README.md (separa o arquivo para a próxima versão), depois git commit -m "Cria o README" (tira a "fotografia") e, por fim, git log --oneline para ver a sua versão no histórico.

O que aconteceu: você fez o seu primeiro commit, uma fotografia do projeto naquele momento, com uma etiqueta (a mensagem "Cria o README") e um código único (o hash, 700bbd5). A partir de agora, o Git lembra exatamente como o README.md estava, para sempre. Se amanhã a Ana estragar o arquivo, ela volta a esta versão com um comando. É isso que este guia ensina.

Se você digitou git comit, com um m só, o Git respondeu git: 'comit' não é um comando git. e sugeriu o comando parecido, commit. Se esqueceu o git add, o git commit avisou que não havia nada preparado. O Git não adivinha, mas explica: errar e ler o que ele responde é metade do aprendizado. Todas as aulas mostram os erros mais comuns, com a mensagem real e o jeito de sair da situação.

O que é este guia

Quem já salvou trabalho_final.docx, trabalho_final_2.docx e trabalho_final_agora_vai.docx conhece o problema que o Git resolve. O Git é um controle de versão: ele guarda o histórico de um projeto (cada mudança, quem fez, quando e por quê), deixa você voltar no tempo e permite que várias pessoas trabalhem nos mesmos arquivos sem uma apagar o trabalho da outra. O GitHub é um site que guarda repositórios Git na internet, para você ter uma cópia segura e trabalhar em equipe. A aula Git × GitHub explica a diferença.

Quem aprende Git consegue:

  • guardar versões de qualquer projeto de texto: um site, um programa, um TCC, as receitas da família;
  • desfazer erros sem medo: descartar uma mudança, voltar um arquivo ao que era ontem, recuperar um commit "perdido";
  • testar ideias em branches (ramos) separados e juntá-las depois com um merge, resolvendo os conflitos;
  • publicar o projeto no GitHub e trabalhar em dupla ou em equipe, com push, pull e pull requests;
  • entender o que acontece por dentro, para nunca mais copiar um comando da internet sem saber o que ele faz.

O guia é para quem nunca usou Git e mal usou o terminal. Ele começa do zero absoluto (o que é uma versão? o que é um repositório?) e vai até rebase interativo, recuperação de desastres e o trabalho em equipe no GitHub. Cada aula ensina um assunto só, com calma.

Como as aulas funcionam

Nenhum comando aparece "seco". Toda aula segue o mesmo caminho:

  1. A ideia primeiro. Antes do comando, você entende o problema que ele resolve, com uma comparação do dia a dia: uma caixa de fotos com etiquetas, um caderno de rascunho e um caderno passado a limpo.
  2. Anatomia. Cada parte de um comando é separada e explicada.
  3. A saída real. Depois de cada exemplo, o que o Git respondeu de verdade, explicado linha por linha. O git status aparece o tempo todo: ele é o melhor professor do Git.
  4. Antes e depois. O que mudou na pasta, na área de preparo e no histórico, com o desenho do histórico quando ajuda.
  5. Experimente. Missões no terminal da página, com o repositório já preparado, que conferem sozinhas se você acertou.
  6. Quando dá errado. A mensagem real do Git (fatal: not a git repository, um conflito, um push recusado), o que aconteceu e como sair da situação.
  7. Exercícios e resumo. Perguntas com correção na hora e uma lista curta do que levar da aula.

Exemplo: a anatomia de um comando

$ git commit -m "Cria o README"
git
O programa Git. Todo comando do Git começa assim.
commit
O subcomando: o que você quer que o Git faça. commit = "registre uma versão" (aula git commit).
-m
Uma opção: "a mensagem vem logo a seguir". Sem ela, o Git abre um editor de texto para você escrever a mensagem.
"Cria o README"
A mensagem do commit, entre aspas porque tem espaços. Ela conta o que mudou, no imperativo (aula Boas Mensagens de Commit).

Exemplo: a saída explicada

As aulas mostram o terminal da máquina das aulas: um computador chamado notebook, da usuária ana. Depois do git add, o git status mostra:

$ git status
No ramo main                                   « você está no ramo (branch) main

No commits yet                                 « o repositório ainda não tem nenhuma versão

Mudanças a serem submetidas:                   « o que vai entrar no próximo commit
  (utilize "git rm --cached <arquivo>..." para não apresentar)
	new file:   README.md                      « um arquivo novo, já preparado

Repare na mistura de português e inglês: o Git do Ubuntu é traduzido só em parte, e o guia mostra as mensagens exatamente como elas aparecem. A aula git status explica cada linha, nas duas línguas.

Escolha sua trilha

O guia tem três níveis, uma seção de projetos e uma de referência. Os níveis foram pensados para serem feitos em ordem: cada aula usa o que as anteriores ensinaram.

Nível 1 · Iniciante

Git do zero.

  • Começando: o que é Git, controle de versão, Git × GitHub, instalar, o terminal do guia, o mínimo de terminal e a configuração
  • O primeiro repositório: init, status, add, commit, log, show, diff, .gitignore, rm e mv
  • Desfazendo coisas: restore, --amend, revert, reset e clean
  • Por dentro do Git: como ele guarda as coisas, o hash e o HEAD

Nível 2 · Intermediário

Branches, remotos e o GitHub.

  • Branches: branch, switch, checkout e o HEAD destacado
  • Juntando trabalho: merge, fast-forward, três vias e conflitos
  • Guardando para depois e investigando o histórico: stash, tag, blame, reflog
  • Repositórios remotos: clone, remote, push, fetch, pull e o push recusado
  • GitHub: conta, repositório, SSH e token, README e GitHub Pages
Começar ❯

Reescrever o histórico, equipes e ferramentas.

  • Reescrevendo o histórico: rebase, rebase interativo, squash, cherry-pick e o push --force com segurança
  • Trabalhando em equipe: fork, pull request, revisão de código, GitHub Flow e issues
  • Ferramentas: bisect, worktree, submódulos, hooks, apelidos, LFS, GitHub CLI e Actions
  • Socorro e boas práticas: recuperar um commit, uma senha commitada por engano e os hábitos que evitam problemas

Como estudar

Git se aprende usando, como quem aprende a dirigir dirigindo. Para cada aula, siga estes quatro passos:

  1. Leia com calma. Leia a ideia, a anatomia e a saída. Não pule a parte "Quando dá errado": quem entende a mensagem do Git sai de qualquer enrascada.
  2. Rode git status o tempo todo. Antes e depois de cada comando. Ele diz onde você está e, muitas vezes, qual é o próximo passo.
  3. Faça as missões. As caixas com Missão conferem sozinhas se você acertou. Tente de verdade antes de abrir a solução; se abrir, digite a solução você mesmo em vez de só olhar.
  4. Repita no seu computador. Quando chegar à aula Instalar o Git, instale-o e refaça os exemplos num projeto seu. O GitHub de verdade (criar a conta, o token, o pull request no site) só existe lá.
A regra de ouro

Commits pequenos, com mensagens claras, e git status antes de tudo. Comece pela aula O que é Git e, antes de ir longe, dê uma olhada em O Terminal do Guia.

As saídas foram colhidas no Git 2.53.0 de um Ubuntu 26.04 em português do Brasil, na máquina da Ana: nome Ana Souza, e-mail ana@exemplo.com, branch inicial main e o relógio parado em 15/10/2026, 10:30. No seu computador, com outro nome e outra hora, os hashes serão outros, e as mensagens podem estar em inglês ou com outra tradução: compare a forma da resposta, não os códigos.
