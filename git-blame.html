Git blame: Quem Mudou Esta Linha

A Ana abre a receita de bolo e leva um susto: "3 ovos? Eu tinha certeza de que eram 4!". Quem mudou isso? Quando? Por quê? O git log mostra os commits do arquivo inteiro, mas a Ana quer saber de uma linha só. Para isso existe o git blame: ele mostra o arquivo linha por linha e, ao lado de cada linha, o último commit que mexeu nela, com o autor e a data.

Você vai aprender
  • A ler a saída do git blame: hash, autor, data e número da linha.
  • O que quer dizer o ^ antes do hash e o Not Committed Yet.
  • A olhar só algumas linhas com -L, e a encurtar a saída com -s, -e e --date=short.
  • A ir do blame para o git show, para descobrir o porquê da mudança.
  • A ver o blame de uma versão antiga do arquivo, e os erros mais comuns.

As saídas desta aula saíram do Git 2.53 do Ubuntu 26.04 na máquina da Ana.

A ideia: o caderno com a letra de cada um

Imagine um caderno de receitas da família em que cada pessoa escreve com uma caneta de cor diferente: a avó de azul, a tia de vermelho, o primo de verde. Olhando uma linha, você sabe na hora quem a escreveu, e pode ir perguntar: "tia, por que você trocou o açúcar por mel?".

O git blame pinta cada linha do arquivo com a "cor" de quem a escreveu por último. O nome vem do inglês blame, "culpar", mas não se assuste: ninguém usa para brigar. Ele serve para achar a pessoa certa para perguntar e o commit que explica a mudança. (Existe até um sinônimo mais gentil, git annotate, "anotar".)

O arquivo desta aula

A receita teve 4 commits: a Ana criou o arquivo, o Bruno trocou os ovos, a Ana corrigiu o tempo de forno, e o Bruno acrescentou a cobertura.

$ git log --oneline
8e19196 (HEAD -> main) Adiciona a cobertura de chocolate
e1e63c4 Corrige o tempo de forno do bolo
7b98d46 Usa 3 ovos no bolo
66f49f7 Adiciona a receita de bolo de cenoura
$ cat bolo.txt
Bolo de cenoura

Ingredientes:
3 cenouras
3 ovos
1 xícara de óleo

Forno: 40 minutos
Cobertura: 200 g de chocolate

1. O primeiro git blame

$ git blame bolo.txt
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 1) Bolo de cenoura
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 2) 
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 3) Ingredientes:
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 4) 3 cenouras
7b98d460 (Bruno Lima 2026-10-15 10:30:00 -0300 5) 3 ovos     «
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 6) 1 xícara de óleo
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 7) 
e1e63c4d (Ana Souza  2026-10-15 10:30:00 -0300 8) Forno: 40 minutos
8e191965 (Bruno Lima 2026-10-15 10:30:00 -0300 9) Cobertura: 200 g de chocolate

Cada linha da saída é uma linha do arquivo, com uma "etiqueta" na frente. Pegue a linha 5, a dos ovos:

7b98d460
O hash (curto) do último commit que mudou esta linha. É o mesmo 7b98d46 do git log, com um caractere a mais (o blame usa 8).
Bruno Lima
O autor desse commit. Mistério resolvido: foi o Bruno.
2026-10-15 10:30:00 -0300
A data e hora do commit, com o fuso horário (−3 horas, o horário de Brasília). Aqui são todas iguais porque, na máquina da Ana, todos os commits têm a mesma data; no seu repositório, cada linha mostra o seu dia.
5)
O número da linha no arquivo.
3 ovos
O conteúdo da linha, como está hoje.

Repare nos outros detalhes:

  • As linhas 1 a 4, 6 e 7 ainda são do primeiro commit da Ana (66f49f7): ninguém mexeu nelas desde que o arquivo foi criado. As linhas vazias (2 e 7) também têm dono.
  • O ^ antes de 66f49f7 marca um commit de "fronteira": aqui, o primeiro commit do repositório, que não tem pai. É o jeito do Git dizer "esta linha está aqui desde o começo".
  • A linha 8 (forno) é da correção da Ana (e1e63c4d), e a 9 (cobertura) é do Bruno (8e191965).
O blame mostra só a última mudança

A linha 8 mostra o commit que trocou 30 por 40 minutos. Que ela já existia antes, com "30 minutos", o blame não diz: ele só aponta quem mexeu por último. Para ver a história inteira de uma linha, você vai do blame para o commit (seção 3) ou olha uma versão antiga (seção 4).

2. Só as linhas que interessam: -L

Num arquivo de 500 linhas, a saída inteira não ajuda. A opção -L (de lines, linhas) escolhe um trecho:

$ git blame -L 5,5 bolo.txt
7b98d460 (Bruno Lima 2026-10-15 10:30:00 -0300 5) 3 ovos
$ git blame -L 4,6 bolo.txt
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 4) 3 cenouras
7b98d460 (Bruno Lima 2026-10-15 10:30:00 -0300 5) 3 ovos
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 6) 1 xícara de óleo
-L 5,5
Da linha 5 até a linha 5: só ela.
-L 4,6
Da linha 4 até a 6.

Há outras formas de dizer o trecho:

$ git blame -L 8 bolo.txt
e1e63c4d (Ana Souza  2026-10-15 10:30:00 -0300 8) Forno: 40 minutos
8e191965 (Bruno Lima 2026-10-15 10:30:00 -0300 9) Cobertura: 200 g de chocolate
$ git blame -L 5,+2 bolo.txt
7b98d460 (Bruno Lima 2026-10-15 10:30:00 -0300 5) 3 ovos
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 6) 1 xícara de óleo
$ git blame -L /Forno/,+1 bolo.txt
e1e63c4d (Ana Souza 2026-10-15 10:30:00 -0300 8) Forno: 40 minutos
-L 8
Da linha 8 até o fim do arquivo.
-L 5,+2
A partir da linha 5, 2 linhas (a 5 e a 6).
-L /Forno/,+1
A partir da primeira linha que contém Forno, 1 linha. Ótimo quando você não sabe o número, mas sabe um pedaço do texto.

Repare que, no último, a coluna do autor ficou mais estreita (Ana Souza sem o espaço extra): o Git ajusta a largura ao nome mais comprido que aparece na saída.

Encurtando a saída

$ git blame -s bolo.txt
^66f49f7 1) Bolo de cenoura
^66f49f7 2) 
^66f49f7 3) Ingredientes:
^66f49f7 4) 3 cenouras
7b98d460 5) 3 ovos

$ git blame -e -L 5,5 bolo.txt

-s
Sem autor e sem data: só o hash e a linha (de suppress, "esconder").
-e
O e-mail no lugar do nome.

7b98d460 (Bruno Lima 2026-10-15 5) 3 ovos
^66f49f7 (Ana Souza  2026-10-15 6) 1 xícara de óleo
^66f49f7 (Ana Souza  2026-10-15 7)

3. Do "quem" ao "por quê": git show

O blame diz quem e quando. O porquê está no commit: na mensagem e na mudança completa. Copie o hash da linha e entregue ao git show:

$ git show 7b98d46
commit 7b98d460a27a2d540bcc1a9f48da02e93eea4d45
Author: Bruno Lima <bruno@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Usa 3 ovos no bolo

diff --git a/bolo.txt b/bolo.txt
index 61ce905..9d2e9cf 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -2,7 +2,7 @@ Bolo de cenoura
 
 Ingredientes:
 3 cenouras
-4 ovos     «
+3 ovos     «
 1 xícara de óleo
 
 Forno: 30 minutos

Agora a Ana tem a história completa: a linha era 4 ovos (o - mostra a linha que saiu), o Bruno a trocou por 3 ovos (o +, a linha que entrou), e a mensagem do commit diz o que ele fez. Se a mensagem fosse mais completa ("Usa 3 ovos no bolo: com 4, a massa ficava mole"), nem precisaria perguntar. É por isso que boas mensagens de commit fazem diferença.

Também dá para usar o hash de 8 caracteres do blame (git show 7b98d460): o Git aceita qualquer começo do hash que não seja ambíguo (veja O Hash do Commit).

Missão: o repositório da receita de bolo já está pronto. Descubra com git blame bolo.txt em que commit a linha 3 ovos foi mudada e mostre esse commit com git show, até ver a linha antiga, -4 ovos.

4. O blame de uma versão antiga

E antes da correção do forno, de quem era a linha 8? Dê ao blame um commit antigo, e ele mostra o arquivo como estava naquele commit. Com HEAD~2 ("dois commits antes do atual", o commit dos ovos):

$ git blame HEAD~2 -- bolo.txt
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 1) Bolo de cenoura
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 2) 
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 3) Ingredientes:
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 4) 3 cenouras
7b98d460 (Bruno Lima 2026-10-15 10:30:00 -0300 5) 3 ovos
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 6) 1 xícara de óleo
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 7) 
^66f49f7 (Ana Souza  2026-10-15 10:30:00 -0300 8) Forno: 30 minutos
HEAD~2
A versão do arquivo dois commits atrás. Pode ser também um hash (git blame e1e63c4 -- bolo.txt) ou um branch.
--
Separa o commit do nome do arquivo, como no git log.

Naquela época, o arquivo tinha 8 linhas (a cobertura ainda não existia), e a linha 8 era Forno: 30 minutos, desde o primeiro commit. Seu arquivo de trabalho não mudou: o blame só lê o histórico.

5. Linhas que ainda não têm commit: Not Committed Yet

A Ana acrescentou uma linha no fim da receita e, antes de fazer o commit, rodou o blame:

$ echo 'Rende 12 fatias' >> bolo.txt
$ git blame bolo.txt
^66f49f7 (Ana Souza         2026-10-15 10:30:00 -0300  1) Bolo de cenoura
^66f49f7 (Ana Souza         2026-10-15 10:30:00 -0300  2) 
^66f49f7 (Ana Souza         2026-10-15 10:30:00 -0300  3) Ingredientes:
^66f49f7 (Ana Souza         2026-10-15 10:30:00 -0300  4) 3 cenouras
7b98d460 (Bruno Lima        2026-10-15 10:30:00 -0300  5) 3 ovos
^66f49f7 (Ana Souza         2026-10-15 10:30:00 -0300  6) 1 xícara de óleo
^66f49f7 (Ana Souza         2026-10-15 10:30:00 -0300  7) 
e1e63c4d (Ana Souza         2026-10-15 10:30:00 -0300  8) Forno: 40 minutos
8e191965 (Bruno Lima        2026-10-15 10:30:00 -0300  9) Cobertura: 200 g de chocolate
00000000 (Not Committed Yet 2026-10-15 10:30:00 -0300 10) Rende 12 fatias     «

A linha nova aparece com o hash 00000000 e o autor Not Committed Yet ("ainda não commitada"; essa parte não é traduzida). Ou seja: o blame lê o arquivo como está na pasta, inclusive as mudanças que você ainda não guardou. Assim que a Ana fizer o commit, a linha 10 ganha o hash e o nome dela. (Repare também que a coluna do autor ficou larga, para caber o Not Committed Yet, e o número da linha ganhou um espaço, porque agora são duas casas: 10.)

Formas diferentes de fazer a mesma coisa

PerguntaComando
Quem mudou cada linha deste arquivo, por último?git blame arquivo
Quem mudou a linha 5?git blame -L 5,5 arquivo
Por que mudou?git show HASH (o hash que o blame mostrou)
Quais commits mexeram no arquivo, em ordem?git log --oneline -- arquivo (aula git log: Filtros e Formatos)
Em que commit uma palavra entrou ou saiu do arquivo?git log -S palavra -- arquivo (aula Procurando no Histórico)
O mesmo que o blame, num formato um pouco diferente (com tabs)git annotate arquivo

Os editores de código e o site do GitHub também mostram o blame de um jeito visual: no GitHub, ao abrir um arquivo, há uma opção para ver o blame (descrição ilustrativa; os detalhes da tela estão na documentação do GitHub, em docs.github.com/pt). É a mesma informação do git blame, com links para os commits.

Quando dá errado

As mensagens de erro abaixo saem em inglês mesmo com o sistema em português: a tradução do Git no Ubuntu é parcial (a aula Seu Primeiro Commit explica).

fatal: no such path 'receita.txt' in HEAD 
$ git blame receita.txt
fatal: no such path 'receita.txt' in HEAD

O que aconteceu: "não existe o caminho receita.txt no HEAD". O Git não achou esse arquivo no último commit: o nome está errado (aqui, o certo é bolo.txt), ou o arquivo é novo e nunca foi commitado (o blame precisa de histórico; um arquivo só na pasta não tem).

Como resolver: confira o nome com ls e o git status. Se o arquivo é novo, faça o primeiro commit dele antes.

fatal: file bolo.txt has only 10 lines 
$ git blame -L 20,21 bolo.txt
fatal: file bolo.txt has only 10 lines

O que aconteceu: "o arquivo bolo.txt só tem 10 linhas", e você pediu as linhas 20 e 21.

Como resolver: veja quantas linhas o arquivo tem (wc -l bolo.txt, ou o blame inteiro) e escolha um trecho que exista.

fatal: bad revision 'bolo.txt': dois arquivos de uma vez 
$ git blame bolo.txt receita.txt
fatal: bad revision 'bolo.txt'

O que aconteceu: o git blame trabalha com um arquivo por vez. Com dois nomes, ele achou que o primeiro era um commit (git blame COMMIT arquivo, como na seção 4) e reclamou: "revisão inválida: bolo.txt".

Como resolver: rode um blame para cada arquivo.

O blame aponta um commit que "não mudou nada de importante"

Às vezes a linha aparece com o hash de um commit que só trocou espaços por tabs, ou reorganizou o arquivo. O blame não sabe o que é importante: ele mostra a última mudança, qualquer que seja.

Como resolver: rode o blame na versão de antes desse commit, com ^ depois do hash (git blame e1e63c4^ -- bolo.txt = "o arquivo como estava no pai de e1e63c4"), ou use -w, que ignora mudanças só de espaços em branco.

Exercícios

1. Complete o comando

Mostre quem mudou por último as linhas 10 a 12 do arquivo index.html:

git blame 10,12 index.html

2. Na saída do blame, o que é o 7b98d460 no começo da linha?

3. O blame mostrou 00000000 (Not Committed Yet …) numa linha. O que isso quer dizer?

4. O blame disse quem mudou a linha. Como ver a mensagem e a mudança completa daquele commit?

5. O que quer dizer o ^ em ^66f49f7?

Resumo

  • git blame arquivo mostra, para cada linha, o último commit que a mudou: hash, autor, data e número da linha.
  • -L 5,5 escolhe linhas (também -L 8, -L 5,+2 e -L /texto/,+1); -s, -e e --date=short mudam o que aparece.
  • O ^ marca linhas do primeiro commit; Not Committed Yet, linhas mudadas e ainda não commitadas.
  • O blame diz quem e quando; o git show HASH diz o porquê.
  • git blame HASH -- arquivo mostra o arquivo como estava num commit antigo.
  • Use o blame para achar a pessoa certa para perguntar, não para culpar ninguém.
