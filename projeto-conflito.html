Git Projeto: Resolvendo um Conflito de Verdade

A Ana testou a receita de bolo de cenoura e descobriu que 40 minutos de forno é demais: anotou 35 minutos num branch chamado forno. Ao mesmo tempo, no main, ela trocou a temperatura de 180 para 170 graus, por causa do forno novo. As duas mudanças mexeram na mesma linha da receita. Quando ela tenta juntar os branches, o Git para e diz: CONFLITO. Parece assustador, mas é só o Git pedindo: "eu não sei qual das duas você quer; decida você". Neste projeto você vai ver o conflito acontecer, ler cada mensagem e resolver, primeiro acompanhando a Ana e depois sozinho no terminal do guia.

Você vai aprender (na prática)
  • Por que um conflito acontece, e por que ele é normal (e não um erro seu).
  • Ler o git status durante um conflito: "Caminhos não mesclados" e "ambos modificados".
  • Entender os marcadores <<<<<<<, ======= e >>>>>>> dentro do arquivo.
  • Desistir com segurança com git merge --abort.
  • Resolver: editar o arquivo, git add e git commit; ou ficar inteiro com um dos lados.

Este projeto põe em prática Conflitos de Merge, Resolvendo Conflitos e Desistindo de um Merge. Todas as saídas saíram do Git 2.53 do Ubuntu, na máquina da Ana, com o sistema em português.

A ideia: dois bilhetes na mesma linha do caderno

Imagine que a Ana e a mãe dela têm cópias do mesmo caderno de receitas. A Ana risca "40 minutos" e escreve "35 minutos". A mãe, na cópia dela, risca "180 graus" e escreve "170 graus". Quando elas forem passar tudo a limpo num caderno só, a linha do forno tem duas versões diferentes. Ninguém consegue adivinhar sozinho qual vale: talvez a certa seja uma, talvez a outra, talvez uma mistura das duas ("170 graus por 35 minutos"). Alguém precisa sentar e decidir.

O Git é igual. Se dois branches mudam linhas diferentes (ou arquivos diferentes), ele junta sozinho. Se mudam a mesma linha de jeitos diferentes, ele para o merge no meio, marca o trecho em disputa dentro do arquivo e espera você decidir. Isso é o conflito.

O ponto de partida

A pasta ~/receitas tem a receita bolo.txt e a página index.html. A partir do primeiro commit, a história se dividiu em dois branches:

  • forno: dois commits. Um troca "40 minutos" por "35 minutos"; o outro acrescenta uma linha no index.html.
  • main: um commit, que troca "180 graus" por "170 graus".

Antes de juntar, a Ana olha os galhos e compara a receita nos dois branches:

$ git log --oneline --graph --all
* b93c237 (forno) Avisa que as receitas foram testadas
* 299e5ec Diminui o tempo de forno para 35 minutos
| * fd61241 (HEAD -> main) Baixa o forno para 170 graus
|/
* e89b8c5 Cria a receita de bolo e a página inicial
$ git diff main forno -- bolo.txt
diff --git a/bolo.txt b/bolo.txt
index 6455273..c30a7f9 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -1,3 +1,3 @@

  • O --graph mostra os dois galhos saindo do commit inicial.
  • git diff main forno -- bolo.txt compara a receita no main com a receita no forno. A linha com - é a do main; a com +, a do forno. A mesma linha, duas versões: já dá para prever o conflito.

Etapa 1: o merge e o conflito

Como no projeto anterior, a Ana vai para o branch que recebe (ela já está no main) e pede o merge:

$ git merge forno
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.

Linha por linha:

  • Mesclagem automática de bolo.txt: o Git tentou juntar as duas versões do arquivo sozinho.
  • CONFLITO (conteúdo): …: não conseguiu. "Conteúdo" quer dizer que o problema está dentro do arquivo (há outros tipos, como um lado apagar o arquivo e o outro mudar).
  • Automatic merge failed; fix conflicts and then commit the result.: "o merge automático falhou; corrija os conflitos e depois faça o commit do resultado". O merge parou no meio: ele está "em andamento", esperando você.
  • Repare que o index.html nem aparece: a mudança dele estava só de um lado, e o Git a juntou sem perguntar nada.

O git status durante o conflito

$ git status
No ramo main
Você tem caminhos não mesclados.
  (fixar conflitos e executar "git commit")
  (use "git merge --abort" to abort the merge)

Mudanças a serem submetidas:
        modified:   index.html      « este o Git juntou sozinho

Caminhos não mesclados:
  (usar "git add <arquivo>..." para marcar resolução)
        ambos modificados:   bolo.txt      « este você resolve
  • Você tem caminhos não mesclados.: há arquivos que o Git não conseguiu juntar.
  • As dicas entre parênteses são o roteiro: corrija os conflitos e rode git commit, ou use git merge --abort para desistir.
  • Mudanças a serem submetidas: ("mudanças a serem commitadas"): o que o Git já juntou sozinho (o index.html) está pronto, na área de preparo.
  • Caminhos não mesclados + ambos modificados: bolo.txt: os dois branches mudaram esse arquivo, e é ele que você precisa resolver. A dica diz como avisar que resolveu: git add.

Os marcadores dentro do arquivo

O Git escreveu as duas versões dentro do próprio bolo.txt, separadas por marcadores:

$ cat bolo.txt
Bolo de cenoura
<<<<<<< HEAD      « começa a versão do main (o branch atual)
Forno: 170 graus por 40 minutos
=======      « a divisa
Forno: 180 graus por 35 minutos
>>>>>>> forno      « termina a versão do forno
Cobertura: chocolate
MarcadorSignifica
<<<<<<< HEADComeço do trecho em disputa. Daqui até o ======= está a versão do branch atual (o HEAD, aqui o main): "170 graus por 40 minutos".
=======A divisa entre as duas versões.
>>>>>>> fornoFim do trecho. Entre o ======= e aqui está a versão do branch que está chegando (forno): "180 graus por 35 minutos".

As linhas fora dos marcadores ("Bolo de cenoura", "Cobertura: chocolate") não estavam em disputa e ficaram como são.

Etapa 2: "socorro, quero voltar!" (git merge --abort)

Na primeira vez, a Ana se assusta e tenta fugir para outro branch. O Git não deixa: com um merge pela metade, trocar de branch misturaria tudo. A saída segura é desistir do merge:

$ git switch forno
fatal: cannot switch branch while merging
Consider "git merge --quit" or "git worktree add".
$ git merge --abort
$ git status
No ramo main
nothing to commit, working tree clean      « de volta a antes do merge
$ git log --oneline --graph --all
* b93c237 (forno) Avisa que as receitas foram testadas
* 299e5ec Diminui o tempo de forno para 35 minutos
| * fd61241 (HEAD -> main) Baixa o forno para 170 graus
|/
* e89b8c5 Cria a receita de bolo e a página inicial
  • O git switch recusou: primeiro é preciso resolver (ou desistir de) o merge em andamento.
  • git merge --abort desfaz o merge e deixa tudo exatamente como estava antes do git merge forno: o git status volta a dizer nothing to commit, working tree clean, e o histórico é o mesmo. Nada do forno se perdeu: o branch continua lá.
Abortar não é fracasso. Se o conflito é grande e você não está com tempo (ou não sabe qual versão é a certa), aborte, converse com quem fez a outra mudança e tente de novo depois. O --abort só funciona enquanto o merge está em andamento, isto é, antes do commit final.

Missão 1: o terminal já está no meio do merge com conflito. Rode git status e cat bolo.txt para ver o estado, e então desista do merge com segurança. No fim, o git status tem de dizer nothing to commit.

Etapa 3: resolver de verdade

Com calma, a Ana pensa: o forno novo pede 170 graus, e no teste o bolo ficou pronto em 35 minutos. A versão certa é a mistura: "170 graus por 35 minutos". Ela pede o merge de novo e, antes de mexer, olha o git diff, que durante um conflito mostra os dois lados:

$ git merge forno
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ git diff
diff --cc bolo.txt
index 6455273,c30a7f9..0000000
--- a/bolo.txt
+++ b/bolo.txt
@@@ -1,3 -1,3 +1,7 @@@
  Bolo de cenoura
++<<<<<<< HEAD
 +Forno: 170 graus por 40 minutos
++=======
+ Forno: 180 graus por 35 minutos
++>>>>>>> forno
  Cobertura: chocolate

No git diff de um conflito, há duas colunas de sinais no começo de cada linha: a primeira compara com o main, a segunda com o forno. Não precisa decorar: o importante é ver os marcadores e as duas versões.

A Ana tenta, por pressa, commitar sem resolver. O Git barra:

$ git commit -m 'Junta o forno'
U       bolo.txt
error: Committing is not possible because you have unmerged files.
hint: Fix them up in the work tree, and then use 'git add/rm <file>'
hint: as appropriate to mark resolution and make a commit.
fatal: Exiting because of an unresolved conflict.

Agora, a resolução. Num editor de texto (nano, VS Code…), ela apaga os três marcadores e as duas versões e escreve a linha que vale. Aqui, para mostrar o resultado exato, o arquivo é reescrito com printf; no dia a dia, você edita no editor:

$ printf 'Bolo de cenoura\nForno: 170 graus por 35 minutos\nCobertura: chocolate\n' > bolo.txt
$ cat bolo.txt
Bolo de cenoura
Forno: 170 graus por 35 minutos      « a versão escolhida, sem marcadores
Cobertura: chocolate
$ git status
No ramo main
Você tem caminhos não mesclados.
  (fixar conflitos e executar "git commit")
  (use "git merge --abort" to abort the merge)

Mudanças a serem submetidas:
        modified:   index.html

Caminhos não mesclados:
  (usar "git add <arquivo>..." para marcar resolução)
        ambos modificados:   bolo.txt      « ainda! falta avisar
  • O cat mostra o arquivo limpo, sem nenhum marcador. Confira sempre: um <<<<<<< esquecido vai parar no commit.
  • O git status ainda diz "ambos modificados": o Git não lê o seu arquivo para saber se você terminou. Você avisa com git add.
$ git add bolo.txt
$ git status
No ramo main
Todos os conflitos foram corrigidos mas você continua mesclando.
  (use  "git commit" para concluir a mesclagem)

Mudanças a serem submetidas:
        modified:   bolo.txt
        modified:   index.html

$ git commit --no-edit
[main 4177566] Merge branch 'forno'
  • Depois do git add, o status diz Todos os conflitos foram corrigidos mas você continua mesclando. e pede o git commit para concluir.
  • git commit --no-edit conclui o merge com a mensagem pronta (Merge branch 'forno'). Sem o --no-edit, o Git abre o editor com essa mensagem para você confirmar ou acrescentar uma explicação (por exemplo, "Resolve o conflito do forno: 170 graus por 35 minutos").

O resultado: o commit de merge fecha o galho, e a receita tem as duas mudanças. O git show --stat mostra os dois pais do commit de merge (Merge: fd61241 b93c237) e um detalhe: como a mensagem pronta foi aceita sem editar, ficaram nela as linhas # Conflicts:, que registram quais arquivos tiveram conflito. Missão 2: o merge do forno parou com conflito no bolo.txt. Resolva com a versão "170 graus por 35 minutos": reescreva o arquivo sem os marcadores (por exemplo, printf 'Bolo de cenoura\nForno: 170 graus por 35 minutos\nCobertura: chocolate\n' > bolo.txt), avise o Git com git add e conclua o merge com git commit --no-edit. Confira com git log --oneline --graph.

Formas diferentes de resolver

Nem sempre a resposta é uma mistura. Às vezes você quer uma das versões inteira. O Git chama a versão do branch atual de ours ("a nossa") e a do branch que está chegando de theirs ("a deles"):

$ git merge forno
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ git diff --check
bolo.txt:2: leftover conflict marker      « "marcador de conflito esquecido"
bolo.txt:4: leftover conflict marker
bolo.txt:6: leftover conflict marker
$ git checkout --theirs bolo.txt
Updated 1 path from the index      « "1 caminho atualizado a partir do índice"
$ cat bolo.txt
Bolo de cenoura
Forno: 180 graus por 35 minutos      « a versão do forno
Cobertura: chocolate
$ git checkout --ours bolo.txt
Updated 1 path from the index
$ cat bolo.txt
Bolo de cenoura
Forno: 170 graus por 40 minutos      « a versão do main
Cobertura: chocolate
$ git checkout --merge bolo.txt
Recreated 1 merge conflict      « "1 conflito recriado"
$ cat bolo.txt
Bolo de cenoura
<<<<<<< ours
Forno: 170 graus por 40 minutos
=======
Forno: 180 graus por 35 minutos
>>>>>>> theirs
Cobertura: chocolate
  • git checkout --theirs bolo.txt pôs no arquivo a versão do forno ("180 graus por 35 minutos").
  • git checkout --ours bolo.txt pôs a versão do main ("170 graus por 40 minutos").
  • git checkout --merge bolo.txt traz de volta os marcadores, para você recomeçar a resolução.
  • git diff --check procura marcadores de conflito esquecidos (e espaços sobrando no fim das linhas); git diff --cached --check faz o mesmo no que já está na área de preparo. Sem saída = nada esquecido.
  • git merge --continue conclui o merge, como o git commit.
Cuidado com o "ours" e o "theirs": em um git merge, "ours" é o branch onde você está. Em um git rebase, os papéis se invertem (veja Conflitos no Rebase). Na dúvida, abra o arquivo e confira com cat antes do git add.
SituaçãoComo resolver
A versão certa é uma mistura das duasEdite o arquivo, apague os marcadores, git add, git commit.
Vale inteira a versão do branch atualgit checkout --ours arquivo, git add, git commit.
Vale inteira a versão do branch que chegagit checkout --theirs arquivo, git add, git commit.
Bagunçou a resolução e quer os marcadores de voltagit checkout --merge arquivo.
Não dá para decidir agoragit merge --abort.
Prefere uma ferramenta visualO VS Code mostra botões sobre os marcadores (veja Git no VS Code); git mergetool abre a ferramenta configurada.

Missão 3: de novo o conflito no bolo.txt, mas desta vez a Ana decidiu que vale inteira a versão do branch forno (180 graus por 35 minutos). Fique com a versão "deles" sem editar o arquivo na mão, avise o Git e conclua o merge.

Quando dá errado

"Committing is not possible because you have unmerged files"

Você viu este na etapa 3: git commit com arquivo ainda marcado como "ambos modificados".

O que aconteceu: o Git não deixa concluir o merge enquanto houver arquivo sem resolução. A linha U bolo.txt mostra qual (U de unmerged, "não mesclado").

Como resolver: deixe o arquivo como deve ficar, git add bolo.txt e só então git commit.

"fatal: cannot switch branch while merging"

O que aconteceu: há um merge em andamento (etapa 2). O Git não troca de branch com o trabalho pela metade.

Como resolver: termine o merge (resolver, git add, git commit) ou desista com git merge --abort. A dica fala de git merge --quit, que larga o merge sem desfazer o que já está na pasta: é para quem sabe o que está fazendo. Na dúvida, --abort.

Commitei com os marcadores dentro do arquivo! 
$ git merge forno
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ git add bolo.txt
$ git commit --no-edit
[main 244bd0c] Merge branch 'forno'
$ cat bolo.txt
Bolo de cenoura
<<<<<<< HEAD
Forno: 170 graus por 40 minutos
=======
Forno: 180 graus por 35 minutos
>>>>>>> forno
Cobertura: chocolate

O que aconteceu: o git add só quer dizer "considere resolvido". O Git acredita em você e não confere se os marcadores sumiram. O merge foi concluído com a receita quebrada.

Como confirmar: cat no arquivo, ou git grep -n '<<<<<<<' para procurar marcadores no projeto inteiro. Antes do git add, git diff --check teria avisado (leftover conflict marker); depois do git add e antes do commit, git diff --cached --check.

Como resolver: o merge já está feito; não tente "voltar" para ele. Corrija o arquivo e faça um commit novo: git add bolo.txt e git commit -m 'Remove marcadores de conflito da receita'. Se ainda não enviou para o GitHub, dá também para emendar o commit de merge com git commit --amend.

"Your local changes … would be overwritten by merge" 
$ echo 'Rende 12 fatias' >> bolo.txt
$ git merge forno
error: Your local changes to the following files would be overwritten by merge:
	bolo.txt
Please commit your changes or stash them before you merge.
Aborting
Merge with strategy ort failed.

O que aconteceu: a Ana tinha uma mudança não commitada no bolo.txt, justamente um arquivo que o merge precisa mexer. O Git recusou o merge para não misturar as coisas (nada foi alterado).

Como resolver: commite a mudança antes (e aí o merge pode ou não dar conflito), ou guarde com git stash, faça o merge e depois git stash pop. Regra prática: comece todo merge com o git status limpo.

"There is no merge to abort (MERGE_HEAD missing)" 
$ git merge --abort
fatal: There is no merge to abort (MERGE_HEAD missing).

O que aconteceu: não há merge em andamento: ou ele já foi concluído com o commit, ou nunca começou. ("Não há merge para abortar"; o MERGE_HEAD é o arquivo onde o Git anota o merge em andamento.)

Como resolver: se o merge já foi concluído e você quer desfazê-lo, o caminho é outro: git revert (seguro, se já enviou) ou git reset (só se ainda não enviou). Veja Como Desfazer Qualquer Coisa.

Exercícios

1. Desistir

Complete para desistir de um merge com conflito e voltar ao estado de antes:

git merge

2. Avisar que resolveu

Você editou o bolo.txt e apagou os marcadores. Complete o comando que avisa o Git:

git bolo.txt

3. Ficar com a versão do branch atual

Complete para ficar inteiro com a versão do branch onde você está:

git checkout bolo.txt

4. A Ana está no main e rodou git merge forno. No arquivo apareceu um trecho entre ======= e >>>>>>> forno. De quem é essa versão?

5. Depois de editar o arquivo e apagar os marcadores, o git status ainda diz "ambos modificados". Por quê?

6. Dois branches mudaram arquivos diferentes. O que acontece no merge?

Resumo

  • Conflito = dois branches mudaram a mesma linha de jeitos diferentes. É normal: o Git só não decide por você.
  • O merge para no meio. O git status lista os arquivos "ambos modificados" e mostra o caminho: corrigir e commitar, ou git merge --abort.
  • No arquivo, <<<<<<< HEAD … ======= é a versão do branch atual; ======= … >>>>>>> outro é a que está chegando.
  • Para resolver: deixe o arquivo como deve ficar (sem marcadores), git add, git commit.
  • Uma versão inteira? git checkout --ours ou --theirs. Bagunçou? git checkout --merge traz os marcadores de volta.
  • Antes do commit, cat o arquivo (ou git diff --check) para não deixar marcadores esquecidos.
