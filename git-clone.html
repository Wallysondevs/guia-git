Git clone

O Bruno tem um repositório no GitHub com as sobremesas dele, e a Ana quer uma cópia para estudar as receitas e, quem sabe, ajudar. Ela não precisa baixar arquivo por arquivo nem um .zip: o git clone copia o repositório inteiro (todos os arquivos, todos os commits, todos os branches) para uma pasta nova no computador dela, já ligada ao GitHub. É o primeiro comando que você roda quando vai trabalhar num projeto que já existe.

Você vai aprender
  • A clonar um repositório com git clone URL, e o que cada linha da saída quer dizer.
  • O que o clone cria: a pasta, o remoto origin, o branch main e os branches remotos.
  • A clonar com outro nome de pasta, e a pegar os outros branches com git switch.
  • O clone "raso" (--depth 1) e o clone de uma pasta local.
  • Os erros mais comuns: pasta que já existe, repositório que não existe, repositório vazio.

As saídas desta aula saíram do Git 2.53 do Ubuntu 26.04, num terminal de verdade da máquina da Ana, clonando do "GitHub" do laboratório (uma imitação local, que responde como o de verdade). Os números das linhas remote: e as velocidades mudam de um clone para outro e de um servidor para outro: não se preocupe com eles.

A ideia: xerox do caderno inteiro

A Ana pede o caderno de sobremesas do Bruno emprestado e tira uma cópia completa: todas as páginas, inclusive as anotações de cada mudança. Na capa da cópia, ela anota: "original: casa do Bruno". A partir daí, ela pode ler, riscar e acrescentar receitas na cópia dela sem estragar o original, e sabe onde buscar as novidades.

O git clone faz exatamente isso: a cópia completa é o repositório novo na sua pasta, e a anotação na capa é o remoto origin, que guarda o endereço de onde a cópia veio (veja O que é um Repositório Remoto).

1. O primeiro clone

No GitHub, a página do repositório mostra o endereço para clonar (o botão Code; descrição ilustrativa, baseada na documentação do GitHub em docs.github.com/pt, "Clonar um repositório"). Com o endereço copiado, a Ana vai para a pasta onde quer a cópia (aqui, a pasta pessoal, ~) e roda:

$ git clone https://github.com/bruno-lima/sobremesas.git
Cloning into 'sobremesas'...
remote: Enumerating objects: 12, done.
remote: Counting objects: 100% (12/12), done.
remote: Compressing objects: 100% (7/7), done.
remote: Total 12 (delta 1), reused 0 (delta 0), pack-reused 0 (from 0)
Receiving objects: 100% (12/12), done.
Resolving deltas: 100% (1/1), done.
git clone
"Clone": copie um repositório.
https://github.com/bruno-lima/sobremesas.git
A URL: o usuário dono (bruno-lima) e o nome do repositório (sobremesas). O .git do fim é opcional no GitHub.

A saída, linha por linha (quase toda em inglês, porque vem do servidor ou não tem tradução no Ubuntu):

Cloning into 'sobremesas'...
"Clonando para a pasta sobremesas". O nome da pasta vem do fim da URL, sem o .git.
remote: Enumerating / Counting / Compressing objects
As linhas que começam com remote: são o servidor falando: ele conta os "objetos" (commits, pastas e arquivos guardados) e os comprime para mandar.
remote: Total 12 (delta 1) …
O total de objetos enviados. Os detalhes (delta, reused) são técnicos e mudam de servidor para servidor.
Receiving objects: 100% (12/12), done.
Agora é o seu Git recebendo. Num repositório grande, essa linha mostra a porcentagem subindo e a velocidade do download.
Resolving deltas: 100% (1/1), done.
O Git "descomprime" as partes que vieram como diferença de outra. Terminou: o clone está pronto.

2. O que o clone criou

$ cd sobremesas
$ ls
README.md  mousse.txt  pudim.txt
$ git log --oneline
5b926a9 (HEAD -> main, origin/main, origin/HEAD) Adiciona a receita de mousse
8bf8bfc Adiciona a receita de pudim
419f86c Cria o README

Uma pasta sobremesas com os arquivos, e o histórico inteiro do Bruno: os 3 commits, com os mesmos hashes do GitHub. A Ana não precisa de git init: a pasta já é um repositório. As etiquetas do primeiro commit mostram que o main dela, o origin/main e o origin/HEAD (o branch principal do remoto) estão no mesmo lugar.

$ git status
No ramo main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
$ git remote -v
origin  https://github.com/bruno-lima/sobremesas.git (fetch)
origin  https://github.com/bruno-lima/sobremesas.git (push)

O clone já deixou tudo ligado: o remoto origin aponta para a URL de onde a cópia veio, e o main já acompanha o origin/main ("Your branch is up to date with 'origin/main'", "o seu branch está em dia com o origin/main"). Daqui em diante, git pull traz as novidades do Bruno e git push envia as da Ana (se ela tiver permissão; veja Fork).

Missão: clone o repositório do Bruno, https://github.com/bruno-lima/sobremesas.git, na sua pasta pessoal. Depois entre na pasta e veja o histórico com git log --oneline.

3. Os outros branches

O repositório do Bruno tem um segundo branch, o natal, com a receita de rabanada. Mas o git branch da Ana só mostra um:

$ git branch
* main
$ git branch -a
* main
  remotes/origin/HEAD -> origin/main
  remotes/origin/main
  remotes/origin/natal

O clone trouxe todos os branches, mas como branches remotos (remotes/origin/…, as "fotos" do GitHub). Branch local, para trabalhar, ele cria só um: o principal (main). Para trabalhar no natal, basta ir para ele pelo nome:

$ git switch natal
branch 'natal' set up to track 'origin/natal'.
Switched to a new branch 'natal'
$ git branch
  main
* natal
$ ls
README.md  mousse.txt  pudim.txt  rabanada.txt
branch 'natal' set up to track 'origin/natal'.
Não existia um natal local, mas existia o origin/natal: o Git criou o branch local a partir dele e já o ligou ao remoto ("configurado para acompanhar origin/natal").
Switched to a new branch 'natal'
"Mudou para um branch novo, o natal". A rabanada apareceu na pasta.

Missão: clone https://github.com/bruno-lima/sobremesas.git, entre na pasta e vá para o branch natal, até a receita de rabanada aparecer.

4. Clonando com outro nome

Ponha o nome da pasta depois da URL:

$ git clone https://github.com/bruno-lima/sobremesas.git doces-do-bruno
Cloning into 'doces-do-bruno'...
remote: Enumerating objects: 12, done.
remote: Counting objects: 100% (12/12), done.
remote: Compressing objects: 100% (7/7), done.
remote: Total 12 (delta 1), reused 0 (delta 0), pack-reused 0 (from 0)
Receiving objects: 100% (12/12), done.
Resolving deltas: 100% (1/1), done.
$ ls doces-do-bruno
README.md  mousse.txt  pudim.txt

Mesmo conteúdo, outra pasta. Cada clone é independente: o que você faz em um não aparece no outro (a não ser passando pelo GitHub, com push e pull).

Onde a pasta é criada?

Na pasta em que você está. Se a Ana estiver em ~/Documentos, o clone vira ~/Documentos/sobremesas:

$ git clone https://github.com/bruno-lima/sobremesas.git
Cloning into 'sobremesas'...
remote: Enumerating objects: 12, done.
remote: Counting objects: 100% (12/12), done.
remote: Compressing objects: 100% (7/7), done.
remote: Total 12 (delta 1), reused 0 (delta 0), pack-reused 0 (from 0)
Receiving objects: 100% (12/12), done.
Resolving deltas: 100% (1/1), done.
$ pwd
/home/ana/Documentos
$ ls
sobremesas

Antes de clonar, confira com pwd onde você está. E nunca clone dentro de outro repositório: um repositório dentro do outro confunde o Git (para isso existem os submódulos).

Missão: clone o repositório do Bruno numa pasta chamada doces-do-bruno.

5. Outras formas de clonar

Só o último commit: --depth 1

Num projeto com anos de história, o clone pode demorar. Se você só quer os arquivos de hoje, peça só o último commit (um clone "raso", em inglês shallow):

$ git clone --depth 1 https://github.com/bruno-lima/sobremesas.git raso
Cloning into 'raso'...
remote: Enumerating objects: 5, done.
remote: Counting objects: 100% (5/5), done.
remote: Compressing objects: 100% (2/2), done.
remote: Total 5 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
Receiving objects: 100% (5/5), done.
$ git -C raso log --oneline
5b926a9 (grafted, HEAD -> main, origin/main, origin/HEAD) Adiciona a receita de mousse

Vieram 5 objetos em vez de 12, e o histórico tem um commit só. A etiqueta grafted ("enxertado") avisa que a história foi cortada ali. (O git -C raso roda o comando dentro da pasta raso sem precisar de cd.) Para estudar e contribuir, prefira o clone completo.

De uma pasta do computador

A "URL" também pode ser o caminho de outro repositório no mesmo computador:

$ git clone sobremesas copia-local
Cloning into 'copia-local'...
done.

Sem rede, sem linhas remote:: o Git copia direto. O origin da cópia aponta para a pasta sobremesas.

Com SSH

Quem configurou uma chave SSH no GitHub clona com a URL no formato git@github.com:bruno-lima/sobremesas.git (o GitHub mostra as duas formas). A diferença aparece na hora de enviar: com SSH, o push não pede token. Veja Chaves SSH.

ComandoQuando usar
git clone URLO normal: pasta com o nome do repositório
git clone URL pastaEscolher o nome da pasta
git clone URL .Clonar dentro da pasta atual (ela precisa estar vazia)
git clone -b natal URLComeçar já no branch natal
git clone --depth 1 URLSó o último commit, mais rápido
Botão Code → Download ZIP, no GitHubSó os arquivos, sem o Git: sem histórico e sem origin (não dá para fazer pull nem push)

Quando dá errado

fatal: destination path 'sobremesas' already exists 
$ git clone https://github.com/bruno-lima/sobremesas.git
fatal: destination path 'sobremesas' already exists and is not an empty directory.

O que aconteceu: "a pasta de destino sobremesas já existe e não está vazia". A Ana já tinha clonado antes, e o Git não sobrescreve uma pasta com coisas dentro.

Como resolver: se você só quer as novidades, não clone de novo: entre na pasta e rode git pull. Se quer uma segunda cópia, dê outro nome (git clone URL sobremesas2).

remote: Repository not found. 
$ git clone https://github.com/bruno-lima/sobremesa.git
Cloning into 'sobremesa'...
remote: Repository not found.
fatal: repository 'https://github.com/bruno-lima/sobremesa.git/' not found

O que aconteceu: o GitHub respondeu "repositório não encontrado". Aqui, faltou o s de sobremesas. A mesma resposta aparece para um repositório privado quando você não tem acesso: o GitHub não conta que ele existe.

Como resolver: copie a URL de novo da página do repositório (não digite). Se o repositório é privado, peça acesso ao dono ou configure a autenticação (HTTPS e Token).

warning: You appear to have cloned an empty repository. 
$ git clone https://github.com/ana-souza/tcc.git
Cloning into 'tcc'...
warning: You appear to have cloned an empty repository.
$ cd tcc
$ git status
No ramo main

No commits yet

nada para enviar (crie/copie arquivos e use "git add" para registrar)

O que aconteceu: "parece que você clonou um repositório vazio". É só um aviso: o repositório existe no GitHub, mas ninguém enviou nada ainda. O clone funcionou e já tem o origin.

Como resolver: nada a resolver. Crie os arquivos, faça o primeiro commit e envie com git push -u origin main.

fatal: You must specify a repository to clone. 
$ git clone
fatal: You must specify a repository to clone.

uso: git clone [<options>] [--] <repo> [<dir>]

    -v, --[no-]verbose    be more verbose
    -q, --[no-]quiet      be more quiet
…

O que aconteceu: "você precisa dizer qual repositório clonar". Depois vem o resumo do uso (git clone [<opções>] [--] <repositório> [<pasta>]) e uma lista comprida de opções (cortada aqui, no …).

Como resolver: git clone URL.

Erro com a URL SSH

Clonar com git@github.com:… sem ter uma chave SSH configurada no GitHub falha com Permission denied (publickey) e fatal: Could not read from remote repository. (mensagem ilustrativa: o laboratório da Ana não tem SSH). Como resolver: use a URL HTTPS, ou configure a chave (Chaves SSH).

Resumo

  • git clone URL copia o repositório inteiro (arquivos, histórico e branches) para uma pasta nova, na pasta em que você está.
  • O clone já cria o remoto origin e deixa o main ligado ao origin/main: dá para usar pull e push direto.
  • Os outros branches vêm como origin/NOME; git switch NOME cria o branch local.
  • git clone URL pasta escolhe o nome; --depth 1 traz só o último commit.
  • O clone é para a primeira vez; depois, as novidades chegam com git pull.
