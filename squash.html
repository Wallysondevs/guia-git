Git squash

Enquanto escrevia a receita de pudim, a Ana fez quatro commits: o pudim, o leite, os ovos, e um "corrige a quantidade de leite". Para ela, foi ótimo: cada passo ficou salvo. Mas para quem vai ler o histórico, isso é uma coisa só: "adiciona a receita de pudim". Juntar vários commits em um se chama squash (em inglês, "espremer", "achatar"). Nesta aula você vai ver os jeitos de fazer isso, a começar pelos comandos squash e fixup do rebase interativo.

Você vai aprender
  • O que é juntar commits e quando isso ajuda (e quando atrapalha).
  • Usar squash e fixup na lista do git rebase -i, e a mensagem combinada que abre no editor.
  • Marcar um commit de conserto com git commit --fixup e deixar o Git arrumar com --autosquash.
  • Dois atalhos: git merge --squash e git reset --soft.
  • Os erros reais: cannot 'squash' without a previous commit e a mensagem vazia.

Todos os comandos rodaram no Git 2.53 da máquina da Ana (usuária ana, computador notebook), com o sistema em português. As listas e mensagens do rebase interativo saem em inglês (sem tradução no Git do Ubuntu) e estão traduzidas no texto. Como na aula anterior, o laboratório editou as listas com sed e mostrou o que o editor receberia com GIT_EDITOR=cat (veja Rebase Interativo, seção 7).

A ideia: o rascunho e a versão passada a limpo

Quando você escreve uma redação, o rascunho tem riscos, setas, "ops, era 'receita'". Você entrega ao professor a versão passada a limpo: o mesmo texto final, sem o vaivém. Juntar commits é passar a limpo: o resultado (os arquivos) é exatamente o mesmo; só o caminho até ele fica mais curto.

Antes:   A---P---L---O---C    (pudim, leite, ovos, correção)
Depois:  A---P'                (um commit com tudo)

Por que fazer:

  • O histórico fica fácil de ler: um commit = uma mudança com sentido (aula Boas Práticas).
  • Some o "conserta o commit anterior", que não interessa a ninguém.
  • Desfazer fica mais fácil: um git revert de um commit só tira a receita inteira.

E quando não fazer: quando os commits já estão no GitHub e outras pessoas os usam (aula A Regra de Ouro), e quando cada commit é uma mudança diferente que vale a pena manter separada.

1. A situação

$ git log --oneline
2209ebb Corrige a quantidade de leite
5a86526 Acrescenta os ovos
89d6767 Acrescenta o leite
528c363 Adiciona receita de pudim
8bf5d5b Adiciona receita de bolo          « o main

Os quatro de cima estão no branch pudim; o 8bf5d5b é o main. O objetivo: um commit só, "Adiciona receita de pudim".

2. squash: juntar e escrever a mensagem

A Ana abre o rebase interativo sobre o main e, na lista, deixa o primeiro commit como pick e marca os outros três com squash (ou só s):

pick 528c363 # Adiciona receita de pudim
squash 89d6767 # Acrescenta o leite
squash 5a86526 # Acrescenta os ovos
squash 2209ebb # Corrige a quantidade de leite

O squash quer dizer "use este commit, mas funda no de cima". O primeiro tem de ser pick: é nele que os outros se juntam. Ao salvar a lista, o Git funde os quatro e abre o editor com todas as mensagens, para você escrever a mensagem final. No laboratório, o editor recebeu este texto:

# This is a combination of 4 commits.
# This is the 1st commit message:

Adiciona receita de pudim

# This is the commit message #2:

Acrescenta o leite

# This is the commit message #3:

Acrescenta os ovos

# This is the commit message #4:

Corrige a quantidade de leite

# Please enter the commit message for your changes. Lines starting
# with '#' will be ignored, and an empty message aborts the commit.
#
# Date:      Thu Oct 15 10:30:00 2026 -0300
#
# interactive rebase in progress; onto 8bf5d5b
# Last commands done (4 commands done):
#    squash 5a86526 # Acrescenta os ovos
#    squash 2209ebb # Corrige a quantidade de leite
# No commands remaining.
# You are currently rebasing branch 'pudim' on '8bf5d5b'.
#
# Mudanças a serem submetidas:
#	new file:   pudim.txt
#
  • # This is a combination of 4 commits.: "isto é a combinação de 4 commits". Em seguida, cada mensagem, com um comentário dizendo de qual commit ela veio (1st = 1ª, #2 = 2ª…).
  • As linhas com # serão ignoradas. As que não têm # viram a mensagem. Se você só salvar, a mensagem final terá as quatro frases, uma embaixo da outra.
  • "Uma mensagem vazia cancela o commit": se você apagar tudo, o rebase para (veja Quando dá errado).

A Ana apaga tudo e escreve a mensagem que ela quer: um título e, depois de uma linha em branco, um detalhe (aula Boas Mensagens de Commit):

Adiciona receita de pudim

Leite condensado, leite e ovos.

Ela salva e fecha o editor:

$ git rebase -i main
Rebasing (2/4)Rebasing (3/4)Rebasing (4/4)[detached HEAD 670194f] Adiciona receita de pudim
 Date: Thu Oct 15 10:30:00 2026 -0300
 1 file changed, 4 insertions(+)                 « as 4 linhas do pudim, num commit só

Successfully rebased and updated refs/heads/pudim.
$ git log --oneline

8bf5d5b Adiciona receita de bolo
$ git log -1
commit 670194fc68dafbf730aebea25be8d30f925c1256
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona receita de pudim

    Leite condensado, leite e ovos.
$ cat pudim.txt
Pudim de leite
1 lata de leite condensado
1 lata de leite
3 ovos

Quatro commits viraram um, com a mensagem nova. O arquivo pudim.txt ficou exatamente como estava depois do último commit (com a correção para "1 lata de leite"): juntar commits não muda o resultado, só o caminho. (Os Rebasing (2/4)… são o contador de progresso, que um terminal apaga da tela.)

3. fixup: juntar sem mexer na mensagem

Muitas vezes a mensagem do primeiro commit já é a certa, e as outras são lixo ("conserta", "ops"). Aí o fixup (ou f) é mais rápido: ele funde o commit no de cima e joga fora a mensagem dele, sem abrir o editor:

pick 528c363 # Adiciona receita de pudim
fixup 89d6767 # Acrescenta o leite
fixup 5a86526 # Acrescenta os ovos
fixup 2209ebb # Corrige a quantidade de leite

$ git rebase -i main
Rebasing (2/4)Rebasing (3/4)Rebasing (4/4)Successfully rebased and updated refs/heads/pudim.
$ git log --oneline
dcdac71 Adiciona receita de pudim
8bf5d5b Adiciona receita de bolo

Sem editor, sem pergunta: um commit, com a mensagem do primeiro.

Missão: junte os quatro commits do branch pudim num só, com a mensagem "Adiciona receita de pudim". Use git rebase -i main com fixup nas linhas 2, 3 e 4. Se o editor não abrir no terminal do guia, o jeito sem editor é: GIT_SEQUENCE_EDITOR='sed -i 2,4s/^pick/fixup/' git rebase -i main. Confira com git log --oneline e cat pudim.txt.

Juntando só alguns

Não precisa ser tudo ou nada. Cada squash/fixup se funde no commit logo acima dele na lista. Aqui a Ana junta o leite no pudim (com squash), deixa os ovos separados, e funde a correção nos ovos (com fixup):

pick 528c363 # Adiciona receita de pudim
squash 89d6767 # Acrescenta o leite
pick 5a86526 # Acrescenta os ovos
fixup 2209ebb # Corrige a quantidade de leite

$ git rebase -i main
Rebasing (2/4)# This is a combination of 2 commits.
# This is the 1st commit message:
…                                                  « o editor abre só para juntar pudim + leite
[detached HEAD c8fe594] Adiciona receita de pudim
 Date: Thu Oct 15 10:30:00 2026 -0300
 1 file changed, 3 insertions(+)
 create mode 100644 pudim.txt
Rebasing (3/4)Rebasing (4/4)Successfully rebased and updated refs/heads/pudim.
$ git log --oneline
7bfbb8b Acrescenta os ovos
c8fe594 Adiciona receita de pudim
8bf5d5b Adiciona receita de bolo

(No laboratório, o "editor" foi o cat, que imprime a mensagem combinada no meio da saída; o … marca o trecho cortado, igual ao da seção 2, agora com 2 mensagens. A mensagem ficou a do cat, sem mudanças: o título "Adiciona receita de pudim" e, embaixo, "Acrescenta o leite".) Resultado: dois commits. Repare que a correção do leite foi parar no commit dos ovos, porque o fixup funde no de cima. A ordem das linhas decide onde cada um entra; se precisar, mude a ordem (aula Rebase Interativo, seção 5).

4. git commit --fixup + --autosquash: o Git arruma a lista

A Ana percebe que o título da receita devia ser "Pudim de leite condensado". O erro está no primeiro commit do branch, não no último. Em vez de fazer um commit comum e depois arrastar a linha na lista, ela já diz ao Git, ao commitar, qual commit este conserta:

$ sed -i '1s/.*/Pudim de leite condensado/' pudim.txt
$ git commit -a --fixup=528c363
[pudim 51dce18] fixup! Adiciona receita de pudim       « a mensagem é feita sozinha
 1 file changed, 1 insertion(+), 1 deletion(-)
$ git log --oneline
51dce18 fixup! Adiciona receita de pudim
2209ebb Corrige a quantidade de leite
5a86526 Acrescenta os ovos
89d6767 Acrescenta o leite
528c363 Adiciona receita de pudim
8bf5d5b Adiciona receita de bolo
git commit -a
Commit de tudo o que mudou nos arquivos rastreados (aula git commit).
--fixup=528c363
"Este commit conserta o 528c363". O Git escreve a mensagem sozinho: fixup! + a mensagem do commit consertado.

Na hora de arrumar, o --autosquash lê esses fixup! e já monta a lista com cada conserto embaixo do commit certo, marcado com fixup:

$ git rebase -i --autosquash main

pick 528c363 # Adiciona receita de pudim
fixup 51dce18 # fixup! Adiciona receita de pudim
pick 89d6767 # Acrescenta o leite
pick 5a86526 # Acrescenta os ovos
pick 2209ebb # Corrige a quantidade de leite

A Ana só confere e salva:

Rebasing (2/5)Rebasing (3/5)Rebasing (4/5)Rebasing (5/5)Successfully rebased and updated refs/heads/pudim.
$ git log --oneline
426ad18 Corrige a quantidade de leite
ba2b933 Acrescenta os ovos
678f141 Acrescenta o leite
9735255 Adiciona receita de pudim
8bf5d5b Adiciona receita de bolo
$ git show HEAD~3:pudim.txt
Pudim de leite condensado                 « o conserto entrou no 1º commit
1 lata de leite condensado

O commit fixup! sumiu, e o título já nasce certo no primeiro commit (o git show HEAD~3:pudim.txt mostra o arquivo como ele era naquele commit). Existe também o git commit --squash=HASH, que faz o mesmo com squash (abrindo o editor para juntar as mensagens).

5. Outros jeitos de chegar a um commit só

git merge --squash: o branch inteiro vira um commit no main

Em vez de arrumar o branch, a Ana pode levar o resultado dele para o main como um commit novo:

$ git switch -q main
$ git merge --squash pudim
Updating 8bf5d5b..2209ebb
Fast-forward
Squash commit -- not updating HEAD                « não fez commit: só preparou as mudanças
 pudim.txt | 4 ++++
 1 file changed, 4 insertions(+)
 create mode 100644 pudim.txt
$ git status --short
A  pudim.txt                                      « na área de preparo, esperando o commit
$ git commit -q -m 'Adiciona receita de pudim'
$ git log --oneline --graph --all
* dcdac71 Adiciona receita de pudim
| * 2209ebb Corrige a quantidade de leite
| * 5a86526 Acrescenta os ovos
| * 89d6767 Acrescenta o leite
| * 528c363 Adiciona receita de pudim
|/
* 8bf5d5b Adiciona receita de bolo

"Commit de squash: o HEAD não foi atualizado." O --squash traz todas as mudanças do branch para a área de preparo, mas não faz o commit nem liga os históricos: você faz o commit com a mensagem que quiser. O main ganhou um commit com a receita inteira; o branch pudim continua lá, com os quatro commits (pode apagá-lo depois: aula Apagando Branches). É o que o botão "Squash and merge" do GitHub faz num pull request.

Missão: leve a receita de pudim para o main como um commit só, sem mexer no branch pudim: troque para o main, use git merge --squash pudim, veja o git status e faça o commit com uma mensagem que fale do pudim.

git reset --soft: desfazer os commits e refazer um

Outro jeito, no próprio branch: voltar o branch para o main sem mexer nos arquivos, e commitar tudo de uma vez (aula reset --soft, --mixed e --hard):

$ git reset --soft main
$ git status --short
A  pudim.txt                                      « tudo preparado, como se nunca tivesse sido commitado
$ git commit -q -m 'Adiciona receita de pudim'
$ git log --oneline
dcdac71 Adiciona receita de pudim
8bf5d5b Adiciona receita de bolo

Rápido e sem editor, mas sem a lista: junta todos os commits depois do main, sem escolher. Repare que o hash final (dcdac71) é o mesmo do fixup da seção 3 e do merge --squash: mesmo conteúdo, mesmo pai, mesma mensagem, autor e data (fixa no laboratório) dão o mesmo commit.

Qual usar?

JeitoBom paraCuidado
squash no git rebase -iJuntar commits escolhendo quais, e escrever a mensagem finalAbre o editor para a mensagem
fixup no git rebase -iJuntar consertos no commit certo, mantendo a mensagem deleA mensagem do commit fundido é descartada
git commit --fixup + git rebase -i --autosquashConsertar um commit antigo sem arrastar linhas na listaPrecisa saber o hash do commit consertado

Quando dá errado

cannot 'squash' without a previous commit 
$ git rebase -i main
error: cannot 'squash' without a previous commit
You can fix this with 'git rebase --edit-todo' and then run 'git rebase --continue'.
Or you can abort the rebase with 'git rebase --abort'.

"Não dá para fazer squash sem um commit anterior." A Ana marcou a primeira linha da lista com squash, mas não há nada acima dela para fundir. O rebase fica em andamento, sem ter feito nada (git status mostra No commands done). Como resolver: git rebase --edit-todo, deixe a primeira linha como pick, salve e rode git rebase --continue; ou desista com git rebase --abort.

Apagou toda a mensagem do squash 
$ git rebase -i main
Rebasing (2/4)Rebasing (3/4)Rebasing (4/4)Aborting commit due to empty commit message.
Could not apply 2209ebb... # Corrige a quantidade de leite

"Cancelando o commit por causa da mensagem vazia." No editor da mensagem combinada, só sobraram linhas com # (ou nada). O rebase fica parado no fim da junção, com as mudanças preparadas; o git status diz interactive rebase in progress e a dica execute "git rebase --continue". Como resolver: rode git rebase --continue: o editor abre de novo; escreva a mensagem, salve e feche. No laboratório:

$ git rebase --continue
[detached HEAD dcdac71] Adiciona receita de pudim
 Date: Thu Oct 15 10:30:00 2026 -0300
 1 file changed, 4 insertions(+)
 create mode 100644 pudim.txt
Successfully rebased and updated refs/heads/pudim.

Ou desista com git rebase --abort e comece de novo.

Tentou começar outro rebase com um parado 
$ git rebase -i main
fatal: It seems that there is already a rebase-merge directory, and
I wonder if you are in the middle of another rebase.  If that is the
case, please try
	git rebase (--continue | --abort | --skip)
If that is not the case, please
	rm -fr ".git/rebase-merge"
and run me again.  I am stopping in case you still have something
valuable there.

"Parece que já existe um diretório de rebase; será que você está no meio de outro rebase? Se estiver, use --continue, --abort ou --skip." Um rebase anterior ficou parado (por conflito, por mensagem vazia…). Como resolver: git status mostra o rebase em andamento; termine-o com git rebase --continue ou desista com git rebase --abort. Não apague a pasta .git/rebase-merge à mão: o --abort faz isso do jeito certo.

Juntou demais

Marcou fixup num commit que devia ficar separado? Logo depois do rebase, git reset --hard ORIG_HEAD volta o branch para como estava antes (o ORIG_HEAD guarda essa posição; cuidado, o --hard descarta mudanças não commitadas). Mais tarde, o git reflog ainda mostra o commit de antes do rebase.

Resumo

  • Juntar commits (squash) passa o histórico a limpo: os arquivos ficam iguais, o caminho fica mais curto.
  • No git rebase -i: deixe o primeiro como pick; squash funde no de cima e abre o editor com as mensagens juntas; fixup funde e fica com a mensagem de cima.
  • git commit --fixup=HASH + git rebase -i --autosquash: o Git põe cada conserto no lugar certo da lista.
  • git merge --squash BRANCH leva o branch inteiro ao main como um commit; git reset --soft main junta tudo no próprio branch.
  • Junte só o que ainda não foi compartilhado. Errou? git rebase --abort no meio; git reset --hard ORIG_HEAD logo depois.
