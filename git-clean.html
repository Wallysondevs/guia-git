Git clean

Depois de uma tarde de testes, a pasta do site de receitas da Ana está cheia de arquivos que ela nunca quis guardar: rascunhos, testes, uma pasta de fotos que não deu certo. Nenhum deles foi commitado. O git restore e o git reset --hard não mexem neles, porque o Git não conhece esses arquivos. Para apagar os arquivos não rastreados de uma vez, existe o git clean (em inglês, clean = "limpar"). É um comando útil e perigoso: o que ele apaga não volta. Por isso o Git o protege com uma trava, e esta aula ensina a usá-lo sempre com um ensaio antes.

Você vai aprender
  • O que são arquivos não rastreados, e por que só o git clean os apaga.
  • Por que o git clean sozinho se recusa a trabalhar, e o que é o -f.
  • Como fazer um ensaio com -n antes de apagar de verdade.
  • Como incluir pastas (-d) e arquivos ignorados (-x, -X), e como poupar um arquivo (-e).
  • Como escolher um por um, no modo interativo (-i).

Todas as saídas desta aula vieram do Git real da máquina da Ana (usuária ana, computador notebook), com o sistema em português. A tradução do Git que vem no Ubuntu é parcial: algumas mensagens saem em português, outras em inglês, outras misturadas. Elas estão aqui exatamente como saíram (no Windows, no macOS ou com o sistema em inglês, as frases podem ser diferentes; o sentido é o mesmo).

A ideia: tirar da mesa o que nunca foi arquivado

Imagine a mesa de trabalho da Ana com uma pasta-arquivo de documentos oficiais (os arquivos rastreados, que o Git conhece) e, espalhados em volta, post-its, rascunhos e papéis soltos (os arquivos não rastreados). Os outros comandos de "desfazer" trabalham com a pasta-arquivo: o git restore devolve um documento oficial à última versão arquivada. O git clean faz o contrário: joga no lixo os papéis soltos, os que nunca entraram na pasta-arquivo, e não toca nos documentos oficiais.

E aqui está o perigo: como esses papéis nunca foram arquivados, não existe cópia nenhuma deles. O Git não guardou versão, não há commit, não há reflog. Apagou, acabou (e eles não vão para a lixeira do sistema).

1. A pasta bagunçada

O repositório receitas tem dois arquivos commitados: o README.md e um .gitignore que ignora arquivos *.log (veja .gitignore). Depois da tarde de testes, o git status mostra:

$ git status
No ramo main
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   README.md   « rastreado e modificado: o clean não mexe

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	fotos/           « uma pasta inteira, não rastreada
	rascunho.txt     « arquivos não rastreados
	teste-bolo.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

Há ainda um forno.log na pasta, que o git status nem mostra, porque é ignorado pelo .gitignore. São quatro tipos de arquivo, e o git clean trata cada um de um jeito:

ArquivoTipoQuem apaga
README.md (modificado)rastreadoninguém: o git clean nunca mexe em arquivo rastreado (para descartar a mudança, git restore)
rascunho.txt, teste-bolo.txtnão rastreadosgit clean -f
fotos/pasta não rastreadagit clean -f -d
forno.logignoradogit clean -f -x (ou -X)

2. A trava: git clean sozinho não apaga nada

$ git clean
fatal: clean.requireForce is true and -f not given: refusing to clean

"A configuração clean.requireForce é verdadeira e o -f não foi dado: recusando-me a limpar." É uma trava de segurança, ligada de fábrica: o Git exige que você diga -f (de force, "forçar") para provar que quer mesmo apagar. Antes de forçar, porém, vem o ensaio.

3. O ensaio: -n

A opção -n (ou --dry-run, "ensaio a seco") mostra o que seria apagado, sem apagar nada. Faça sempre o ensaio antes:

$ git clean -n
Would remove rascunho.txt
Would remove teste-bolo.txt

Would remove = "removeria". Só os dois arquivos soltos: a pasta fotos/ e o forno.log não entram sem as opções certas. Acrescentando -d (de directories, "pastas") e -x (inclui os ignorados):

$ git clean -n -d
Would remove fotos/
Would remove rascunho.txt
Would remove teste-bolo.txt
$ git clean -n -d -x
Would remove forno.log
Would remove fotos/
Would remove rascunho.txt
Would remove teste-bolo.txt
git clean
"Apague os arquivos não rastreados…".
-n
"…de mentira: só mostre a lista". Troque por -f para apagar de verdade.
-d
"…incluindo pastas não rastreadas inteiras" (com tudo o que está dentro delas).
-x
"…incluindo os arquivos que o .gitignore manda ignorar".
O hábito que salva

Primeiro git clean -n com as opções que você quer; leia a lista inteira; depois repita o mesmo comando trocando o -n por -f. Assim, o que vai ser apagado é exatamente o que você leu.

4. Apagando de verdade: -f, -fd, -fdx

$ git clean -f
Removing rascunho.txt
Removing teste-bolo.txt
$ git status
No ramo main
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   README.md

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	fotos/   « a pasta ficou: faltou o -d

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

Removing = "removendo": agora foi de verdade. O README.md modificado continua modificado (o clean não mexe em arquivos rastreados), e a pasta fotos/ ficou. As opções curtas podem ser juntadas: -fd é o mesmo que -f -d.

$ git clean -fd
Removing fotos/
$ ls
README.md  forno.log
$ ls -A
.git  .gitignore  README.md  forno.log

Sobrou o forno.log, que é ignorado. O ls -A mostra também os arquivos que começam com ponto: o .gitignore é rastreado (foi commitado), e a pasta .git é o próprio repositório, que o git clean nunca apaga. Para levar o .log junto:

$ git clean -fdx
Removing forno.log
$ ls -A
.git  .gitignore  README.md
Cuidado com o -x

Os arquivos ignorados costumam ser coisas que dá para recriar (logs, programas compilados, a pasta node_modules), mas nem sempre: muita gente guarda no .gitignore o arquivo .env, com senhas e configurações que só existem naquele computador. Um git clean -fdx apaga esse arquivo também, e ele não está no Git para voltar. Só use -x depois de ler a lista do -n.

Missão: limpe a pasta da Ana: apague os arquivos não rastreados e a pasta fotos. Faça o ensaio com -n antes. No fim, o git status deve dizer que não há nada a fazer.

5. Escolhendo o que apagar

Só um arquivo (ou uma pasta)

Com um caminho no fim, o git clean só olha para ele:

$ git clean -n teste-bolo.txt
Would remove teste-bolo.txt
$ git clean -f teste-bolo.txt
Removing teste-bolo.txt

Tudo, menos um: -e

A opção -e (de exclude, "excluir") poupa os arquivos que casam com o padrão. Aqui só sobrava o rascunho.txt, e ele foi poupado, então o ensaio não mostrou nada:

$ git clean -n -e rascunho.txt

Só os ignorados: -X

O -X maiúsculo é o contrário do -x: apaga só os arquivos ignorados, e poupa os não rastreados comuns. Bom para "limpar os restos de compilação, mas não o rascunho que ainda vou commitar":

$ git clean -n -X
$ echo 'erro' > forno.log
$ git clean -n -X
Would remove forno.log

No primeiro ensaio não havia nenhum arquivo ignorado; depois que a Ana criou o forno.log, ele apareceu, e o rascunho.txt (não rastreado, mas não ignorado) ficou de fora.

Um por um: o modo interativo -i

A Ana criou de novo uns arquivos de teste (anotacoes.txt, rascunho.txt e teste-bolo.txt). Com -i, o Git mostra a lista e um pequeno menu (em inglês). A opção 4: ask each ("perguntar para cada um") pergunta arquivo por arquivo:

$ git clean -i
Would remove the following items:
  anotacoes.txt   rascunho.txt    teste-bolo.txt
*** Commands ***
    1: clean                2: filter by pattern    3: select by numbers
    4: ask each             5: quit                 6: help
What now> 4
Remove anotacoes.txt [y/N]? y
Remove rascunho.txt [y/N]? n
Remove teste-bolo.txt [y/N]? y
Removing anotacoes.txt
Removing teste-bolo.txt
$ ls
README.md  forno.log  rascunho.txt
Would remove the following items
"Removeria os seguintes itens": a lista, como no -n.
1: clean
Apagar todos os da lista.
2: filter by pattern
"Filtrar por padrão": tirar da lista os que casam com um padrão (como o -e).
3: select by numbers
"Escolher pelos números" dos itens.
4: ask each
"Perguntar para cada um". Responda y (yes, sim) ou n (no, não). O [y/N] com o N maiúsculo quer dizer que só apertar Enter vale como "não".
5: quit
Sair sem apagar nada.
What now>
"E agora?": o Git espera você digitar o número.

O modo interativo não precisa do -f: as perguntas já são a confirmação. O rascunho.txt, que a Ana respondeu n, ficou; o forno.log, ignorado, nem entrou na lista (faltou o -x).

O terminal do guia não tem o modo interativo: lá, o git clean -i só avisa e sugere o -n e o -f. Experimente o -i no seu computador.

Formas diferentes de limpar

Você quer apagar…Use
Um arquivo não rastreadorm arquivo (o comando do terminal) ou git clean -f arquivo
Todos os arquivos não rastreadosgit clean -n, depois git clean -f
…e as pastas não rastreadasgit clean -n -d, depois git clean -fd
…e os ignorados também (deixar a pasta "como recém-clonada")git clean -n -d -x, depois git clean -fdx
Só os ignoradosgit clean -fX
Escolhendo um por umgit clean -i
As mudanças em arquivos rastreadosNão é com o clean: git restore arquivo ou git reset --hard (veja os modos do reset)
Guardar os não rastreados em vez de apagargit stash -u (veja git stash)

Para deixar tudo exatamente como no último commit, a dupla clássica é git reset --hard (desfaz as mudanças nos rastreados) seguido de git clean -fd (apaga os não rastreados). É o "botão de pânico" do Git, e por isso mesmo merece um git status e um git clean -n antes.

Quando dá errado

refusing to clean 
$ git clean
fatal: clean.requireForce is true and -f not given: refusing to clean

Não é erro de verdade: é a trava. Como resolver: rode git clean -n para ver a lista, e depois git clean -f. (Dá para desligar a trava com git config clean.requireForce false, mas não faça isso: ela existe justamente porque o clean não tem volta.)

A pasta não foi apagada

Você rodou git clean -f e o git status ainda mostra fotos/. Por quê: sem -d, o clean não entra em pastas não rastreadas. Como resolver: git clean -n -d e depois git clean -fd.

O arquivo .log (ou .env) não foi apagado

Arquivos ignorados pelo .gitignore ficam de fora, a menos que você peça com -x (todos) ou -X (só os ignorados). Na maioria das vezes, isso é bom.

Apaguei um arquivo que eu queria

O git clean apaga direto do disco, sem passar pela lixeira, e o Git nunca teve cópia de um arquivo não rastreado. Não há comando do Git que o traga de volta. As únicas esperanças estão fora do Git: o editor de texto ainda aberto, um backup, a sincronização na nuvem. Para não acontecer de novo: -n antes de todo -f, e commite (ou guarde com git stash -u) o que tem valor.

Resumo

  • git clean apaga arquivos não rastreados; nunca mexe em arquivos rastreados nem na pasta .git.
  • Sem -f, ele se recusa (clean.requireForce). Antes do -f, sempre o ensaio com -n.
  • -d inclui pastas; -x inclui os ignorados; -X apaga só os ignorados; -e poupa um padrão; -i pergunta um por um.
  • O que o git clean apaga não volta: nem pelo Git, nem pela lixeira.
  • git reset --hard + git clean -fd deixam a pasta igual ao último commit.
