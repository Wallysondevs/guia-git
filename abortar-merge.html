Git Desistindo de um Merge

Você rodou git merge, apareceram conflitos em dez arquivos, já é tarde e você não sabe o que o colega quis fazer em metade deles. Calma: um merge em andamento não é um caminho sem volta. O git merge --abort ("cancelar", "abortar") desfaz tudo e deixa o repositório exatamente como estava antes do merge. Nesta aula você vai ver o --abort em ação, o que ele leva embora junto, e o que fazer quando o merge já terminou e você se arrependeu.

Você vai aprender
  • Como cancelar um merge com conflito usando git merge --abort, e o git status antes e depois.
  • O que acontece com o que você já tinha resolvido, e com as mudanças que não eram do merge.
  • O erro There is no merge to abort e o que ele quer dizer.
  • Os primos do --abort: git reset --merge e git merge --quit.
  • Como desfazer um merge que já terminou: git reset --hard ORIG_HEAD.

Todas as saídas desta aula vieram do Git 2.53.0 da máquina da Ana (usuária ana, computador notebook), com o sistema em português. A tradução do Git no Ubuntu é incompleta: várias mensagens saem em inglês; elas estão copiadas como saíram e ganham tradução na explicação.

A ideia: o botão "Cancelar" da mudança de móveis

A Ana está juntando os móveis de dois apartamentos num só. No meio da mudança, ela percebe que o sofá não passa na porta e que ninguém sabe onde vai a estante. Ela tem duas saídas: continuar e resolver cada problema, ou desistir hoje, devolver tudo para o lugar e tentar outro dia, com mais calma. O git merge --abort é a segunda saída: tudo volta para onde estava, como se a mudança nunca tivesse começado. Os dois apartamentos (os dois branches) continuam intactos.

Lembre como fica o repositório durante um conflito (aula Conflitos de Merge): o merge está em andamento, o commit de merge ainda não existe, a pasta tem arquivos com marcadores e a área de preparo tem o que o Git já juntou sozinho. Desistir é só desfazer essas três coisas. Os commits não são tocados, porque nenhum commit novo foi criado.

1. git merge --abort no meio de um conflito

O repositório é o das aulas anteriores: o main e o branch forno mudaram a mesma linha do bolo.txt. Antes do merge, o git status está limpo:

$ git status
No ramo main
nothing to commit, working tree clean
$ git merge forno
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ git status
No ramo main
Você tem caminhos não mesclados.
  (fixar conflitos e executar "git commit")
  (use "git merge --abort" to abort the merge)

Mudanças a serem submetidas:
        new file:   cobertura.txt

Caminhos não mesclados:
  (usar "git add <arquivo>..." para marcar resolução)
        ambos modificados:   bolo.txt

A própria dica do git status mostra a saída: (use "git merge --abort" to abort the merge), "use git merge --abort para cancelar o merge". A Ana decide desistir:

git merge
O mesmo comando do merge.
--abort
"Abortar, cancelar": em vez de começar um merge, cancela o que está em andamento. Não leva nome de branch.
$ git merge --abort
$ git status
No ramo main
nothing to commit, working tree clean
$ cat bolo.txt
Bolo de cenoura
- 3 cenouras
- 3 ovos
- 2 xícaras de açúcar
Forno: 180 graus por 45 minutos
$ git log --oneline --graph --all
* 70c15e0 (forno) Assa mais quente e mais rápido
| * aa84752 (HEAD -> main) Aumenta o tempo de forno
|/
* a071866 Adiciona a receita de bolo

O git merge --abort não mostra nada quando dá certo. Confira o resultado peça por peça:

git status
Limpo de novo (nothing to commit, working tree clean): nada de "Caminhos não mesclados", nada de "você continua mesclando". A cobertura.txt, que estava preparada para o commit de merge, também sumiu da pasta, porque ela só existe no forno.
cat bolo.txt
Sem marcadores: o arquivo voltou à versão do main, com 180 graus por 45 minutos.
git log --oneline --graph --all
O mesmo desenho de antes do merge. O forno continua lá, com o commit dele; nada foi perdido. Quando quiser, tente o merge de novo.

Missão: o merge do forno no main parou num conflito. Olhe o git status e o cat bolo.txt, desista do merge e confira de novo: o status deve ficar limpo e o arquivo, sem marcadores.

2. O que o --abort leva embora (e o que ele deixa)

Leva: o que você já tinha resolvido

O --abort volta para antes do merge. Tudo o que você fez durante o merge vai junto. A Ana começou o merge de novo, mexeu no bolo.txt (escreveu só a primeira linha, como quem começa a resolver) e desistiu:

$ git merge forno
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ printf 'Bolo de cenoura\n' > bolo.txt
$ git merge --abort
$ git status
No ramo main
nothing to commit, working tree clean

A edição sumiu sem aviso: o bolo.txt voltou a ser o do main. Se você passou uma hora resolvendo conflitos, pense duas vezes antes do --abort. Se quiser guardar uma resolução, copie o arquivo para fora do repositório antes.

Deixa: mudanças que não tinham nada a ver com o merge

O Git deixa começar um merge com mudanças não commitadas, desde que o merge não mexa nesses arquivos (se mexer, ele recusa antes de começar; veja Merge de Três Vias). Aqui a Ana estava mudando o LEIA.txt, que o forno não toca:

$ git status --short
 M LEIA.txt
$ git merge forno
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ git status --short
 M LEIA.txt
UU bolo.txt
A  cobertura.txt
$ git merge --abort
$ git status --short
 M LEIA.txt
$ cat LEIA.txt
Receitas da Ana e do Bruno

O --abort desfez o merge (sumiram o UU bolo.txt e o A cobertura.txt) e deixou a mudança do LEIA.txt em paz. Mesmo assim, o manual do Git avisa que, em alguns casos, o --abort não consegue reconstruir as mudanças que existiam antes do merge. Por isso a regra de ouro continua: comece o merge com o git status limpo (faça commit ou guarde com git stash).

3. Os primos do --abort

git reset --merge

Em tutoriais antigos, de antes de o --abort existir, você vai ver este comando. Num merge com conflito, ele faz o mesmo:

$ git merge forno
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ git reset --merge
$ git status --short

O git status --short vazio quer dizer "nada mudou": o merge foi cancelado. Prefira o git merge --abort: o nome diz o que ele faz, e ele recusa (com erro) se não houver merge em andamento, em vez de fazer outra coisa. (O git reset tem vários modos e aula própria: git reset.)

git merge --quit: "esquece o merge, mas deixa tudo como está"

O --quit ("sair") também tira o repositório do estado "merge em andamento", mas não desfaz nada na pasta nem na área de preparo:

$ git merge forno
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ git merge --quit
$ git status
No ramo main
Mudanças a serem submetidas:
  (use "git restore --staged <file>..." to unstage)
        new file:   cobertura.txt

Caminhos não mesclados:
  (use "git restore --staged <file>..." to unstage)
  (usar "git add <arquivo>..." para marcar resolução)
        ambos modificados:   bolo.txt

Repare na diferença: sumiram as linhas Você tem caminhos não mesclados e a dica do git merge --abort, e apareceu (use "git restore --staged <file>..." to unstage), "para tirar da área de preparo". O Git esqueceu que havia um merge, mas o bolo.txt continua com os marcadores, e a cobertura.txt continua preparada. Se você fizer um commit agora, ele será um commit comum, com um pai só, e não um commit de merge. É um comando para casos raros (como o git switch sugeriu na aula Conflitos de Merge); para desistir, use o --abort.

4. O merge já terminou e eu me arrependi

O --abort só funciona durante o merge. Se o merge terminou (sem conflito, ou depois do git commit), o commit de merge já existe. A Ana fez um merge com -X theirs (aula Resolvendo Conflitos) e não gostou do resultado:

$ git merge --no-edit -X theirs forno
Mesclagem automática de bolo.txt
Merge made by the 'ort' strategy.
 bolo.txt      | 2 +-
 cobertura.txt | 1 +
 2 files changed, 2 insertions(+), 1 deletion(-)
 create mode 100644 cobertura.txt
$ git log --oneline --graph
*   7877581 (HEAD -> main) Merge branch 'forno'
|\
| * 70c15e0 (forno) Assa mais quente e mais rápido
* | aa84752 Aumenta o tempo de forno
|/
* a071866 Adiciona a receita de bolo
$ git reset --hard ORIG_HEAD
HEAD is now at aa84752 Aumenta o tempo de forno
$ git log --oneline --graph
* aa84752 (HEAD -> main) Aumenta o tempo de forno
* a071866 Adiciona a receita de bolo
git reset --hard
Move o branch atual para outro commit e deixa a pasta e a área de preparo iguais a ele. O --hard joga fora mudanças não commitadas: use com o git status limpo (detalhes em reset --soft, --mixed e --hard).
ORIG_HEAD
Um "marcador" que o Git cria sozinho antes de operações grandes, como o merge: ele guarda onde o HEAD estava antes. Depois do merge, ORIG_HEAD é o aa84752, o main de antes. (Como o primeiro pai do commit de merge é sempre o main de antes, HEAD~1 chegaria ao mesmo lugar.)
HEAD is now at aa84752 Aumenta o tempo de forno
"O HEAD agora está em aa84752". O commit de merge saiu do main; o desenho voltou a ter só o caminho do main. (O git log --graph sem --all mostra só o branch atual; o forno continua existindo.)
Só para merges que ainda não foram enviados

O git reset apaga commits do histórico. Se o commit de merge já foi enviado com git push e outras pessoas já o têm, não use o reset: desfaça com um commit novo, usando git revert -m 1 <commit-de-merge> (o -m 1 diz "o lado certo é o primeiro pai"). Veja git revert e A Regra de Ouro.

Quando dá errado

Não há merge para cancelar: There is no merge to abort (MERGE_HEAD missing) 
$ git merge --abort
fatal: There is no merge to abort (MERGE_HEAD missing).

"Fatal: não há merge para cancelar (falta o MERGE_HEAD)." O MERGE_HEAD é o arquivo, dentro da pasta .git, que marca um merge em andamento (aula Conflitos de Merge). Duas situações comuns: você já cancelou (aqui, a Ana rodou o --abort duas vezes), ou o merge já terminou. Como confirmar: git status: se não aparece "Caminhos não mesclados" nem "você continua mesclando", não há merge em andamento. Como resolver: se o merge terminou e você quer desfazê-lo, veja a seção 4.

"Cancelei e perdi o que tinha resolvido"

Como você viu na seção 2, o --abort descarta as resoluções em andamento sem perguntar. Não há comando do Git que as traga de volta, porque elas nunca entraram num commit. Como evitar: antes de desistir de um merge grande, copie para fora do repositório os arquivos que você já resolveu; na próxima tentativa, aproveite-os.

Apagou a mensagem no editor achando que cancelava o merge

Ao terminar um merge, salvar a mensagem vazia no editor não cancela o merge: o Git responde Not committing merge; use 'git commit' to complete the merge. e o merge continua em andamento (está na aula Merge de Três Vias). Como resolver: para desistir de verdade, git merge --abort.

Resumo

  • Durante um merge com conflito, git merge --abort volta tudo a antes do merge: a pasta, a área de preparo e o estado "merge em andamento". Os branches não são tocados.
  • O --abort descarta as resoluções que você já tinha feito; mudanças em arquivos que o merge não tocou costumam sobreviver, mas o seguro é começar o merge com o git status limpo.
  • fatal: There is no merge to abort (MERGE_HEAD missing): não há merge em andamento (já foi cancelado ou já terminou).
  • git reset --merge é o jeito antigo de cancelar; git merge --quit só esquece o merge, sem desfazer nada.
  • Merge que já terminou: git reset --hard ORIG_HEAD, se ainda não foi enviado; git revert -m 1, se já foi.
