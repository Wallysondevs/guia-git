Git Instalar o Git

Antes de usar o Git no seu computador, é preciso instalá-lo. Ele é gratuito e existe para Windows, macOS e Linux. Nesta aula você vai ver o jeito recomendado em cada sistema, como conferir se deu certo e o que fazer quando o terminal diz que o git não existe. Enquanto isso, o terminal do guia já tem um Git pronto para você praticar.

Você vai aprender
  • Como saber se o Git já está instalado.
  • Como instalar no Windows (Git for Windows e o Git Bash), no macOS e no Linux.
  • Como conferir a instalação com git --version e descobrir onde o programa está.
  • O que fazer quando aparece "comando não encontrado".

Primeiro: será que já está instalado?

Em muitos computadores, o Git já vem instalado ou foi instalado junto com outro programa. Abra o terminal (no Windows, o PowerShell ou o Prompt de Comando; no macOS, o app Terminal; no Linux, o terminal da sua distribuição) e pergunte a versão:

$ git --version
git version 2.53.0

Se aparecer uma linha como essa, o Git está instalado e você pode pular para O Mínimo de Terminal para o Git. Qualquer versão a partir da 2.23 serve para este guia (é a versão que trouxe o git switch e o git restore). Se aparecer uma mensagem dizendo que o comando não existe, siga a seção do seu sistema.

Qual versão é a mais nova?

O Git lança uma versão "2.x" nova a cada poucos meses. A mais recente, segundo o site oficial git-scm.com, é a 2.56.0 (outubro de 2026). Os sistemas costumam trazer uma um pouco mais antiga: o Ubuntu 26.04, usado neste guia, traz a 2.53.0. Para aprender, a diferença não importa.

Windows: Git for Windows

No Windows, o Git oficial se chama Git for Windows. Ele traz, além do git, o Git Bash: um terminal com o Bash e os comandos básicos do Linux (ls, cd, cat…). É o terminal recomendado para seguir este guia no Windows, porque os comandos e o prompt ficam iguais aos das aulas.

Jeito 1: o instalador

  1. Abra git-scm.com/install/windows e baixe o instalador (Setup) para o seu tipo de processador: x64 (a maioria dos computadores) ou ARM64.
  2. Rode o arquivo baixado. O instalador faz várias perguntas; as respostas que já vêm marcadas servem para quem está começando.
  3. Se uma das telas perguntar o nome do ramo inicial dos repositórios novos, você pode escolher main, o nome usado pelo GitHub e por este guia (a aula git init explica por quê).
  4. No fim, abra o Git Bash pelo menu Iniciar e rode git --version.

Jeito 2: o winget, pelo terminal

O Windows 10 e 11 trazem o winget, um instalador de programas pela linha de comando. No PowerShell:

winget install --id Git.Git -e --source winget
winget install
Instala um programa.
--id Git.Git
O identificador do Git for Windows no catálogo do winget.
-e
exact: só aceita o identificador exatamente igual, sem adivinhar.

Busca no catálogo oficial do winget.

Depois, feche e abra de novo o terminal, para ele enxergar o programa novo, e rode git --version.

Ilustrativo

A instalação no Windows não roda no laboratório deste guia. Os passos e o comando do winget foram conferidos na página oficial de instalação (git-scm.com/install/windows), que também cita a versão portátil, que não precisa de instalação, e o choco install git, para quem usa o Chocolatey.

E o WSL?

Se você usa o WSL (o Linux dentro do Windows), ele é um Linux completo e precisa do seu próprio Git: dentro dele, siga a seção do Linux. O Git do Windows e o do WSL são programas separados.

macOS: as Ferramentas de Linha de Comando ou o Homebrew

Jeito 1: as ferramentas da Apple

A Apple distribui o Git junto com as Command Line Tools ("ferramentas de linha de comando") do Xcode. Não é preciso instalar o Xcode inteiro. No app Terminal:

xcode-select --install

Abre-se uma janela pedindo para confirmar a instalação. Muitas vezes, basta digitar git --version num Mac sem as ferramentas: o próprio sistema oferece a instalação.

Jeito 2: o Homebrew

O Homebrew é o gerenciador de pacotes mais usado no macOS. A versão do Git que ele instala costuma ser mais nova que a da Apple. Com o Homebrew já instalado:

brew install git

Feche e abra o Terminal e confira com git --version. A página oficial também cita o MacPorts (sudo port install git).

Ilustrativo

O macOS não roda no laboratório. Os comandos acima são os da página oficial git-scm.com/install/mac.

Linux: o gerenciador de pacotes

No Linux, o Git vem do gerenciador de pacotes da sua distribuição, o mesmo programa que instala qualquer outra coisa. Instalar precisa de permissão de administrador, por isso os comandos começam com sudo (ele vai pedir a sua senha).

Quero um Git mais novo no Ubuntu

O Ubuntu mantém a mesma versão do Git durante a vida de cada lançamento (só com correções de segurança). A página oficial indica um PPA do projeto Git, com a versão estável mais recente: sudo add-apt-repository ppa:git-core/ppa, depois sudo apt update e sudo apt install git. Para seguir este guia, não precisa.

Conferindo, no laboratório

Na máquina da Ana (Ubuntu 26.04, o laboratório deste guia), o Git já está instalado. O apt policy ("política") mostra a versão instalada e a que o apt instalaria hoje:

$ apt policy git
git:
  Instalado: 1:2.53.0-1ubuntu1.1                « a versão instalada
  Candidato: 1:2.53.0-1ubuntu1.1                « a versão que o apt instalaria agora
  Tabela de versão:
 *** 1:2.53.0-1ubuntu1.1 500

O número da versão do pacote tem três partes: 1: (uma "época", detalhe interno do Debian), 2.53.0 (a versão do Git) e -1ubuntu1.1 (a revisão do pacote feita pelo Ubuntu, por exemplo com correções de segurança). Quando o Instalado diz (nenhum), o Git não está instalado.

Conferindo a instalação

Em qualquer sistema, depois de instalar, faça estas duas perguntas ao terminal.

1. Qual é a versão?

$ git --version
git version 2.53.0

2. Onde está o programa?

O comando type (do Bash, inclusive no Git Bash) diz o que é um nome de comando e onde ele está. O which faz algo parecido:

$ type git
git é /usr/bin/git                          « "git é o programa /usr/bin/git"
$ which git
/usr/bin/git

No Linux, o Git fica em /usr/bin/git. No Git Bash, aparece um caminho dentro da pasta de instalação do Git for Windows; no Mac, /usr/bin/git (o da Apple) ou o do Homebrew. Isso ajuda quando há dois Gits instalados e você quer saber qual está respondendo.

Missão: descubra onde está o programa git no terminal do guia, com type git ou which git. Depois rode git --version.

Quando dá errado

"comando não encontrado" 
$ gitk
Comando 'gitk' não encontrado, mas poder ser instalado com:
sudo apt install gitk                       « o comando que instala o que falta
$ echo $?
127                                         « 127 = comando não encontrado

Para mostrar a mensagem real sem desinstalar o Git do laboratório, a Ana digitou gitk, um programa da família do Git (uma janela para ver o histórico) que não vem instalado. Num Ubuntu sem o Git, digitar git dá a mesma mensagem, com git no lugar de gitk. (O "poder ser" com erro de concordância está assim mesmo na tradução do Ubuntu.)

O que aconteceu: o terminal procurou um programa com esse nome nas pastas de programas e não achou. No Ubuntu, um ajudante chamado command-not-found ainda consulta a lista de pacotes e diz qual instalar. Em outros sistemas aparece só algo como bash: git: comando não encontrado. Ou o Git não está instalado, ou o terminal foi aberto antes da instalação.

Como resolver: instale o Git pelo jeito do seu sistema, feche e abra o terminal e tente de novo. No PowerShell do Windows, a mensagem é outra (algo como "O termo 'git' não é reconhecido…"), mas o motivo e a solução são os mesmos.

Instalei, mas a versão continua a antiga

O que aconteceu: há dois Gits no computador (por exemplo, o da Apple e o do Homebrew), e o terminal está achando primeiro o antigo.

Como confirmar: type -a git lista todos os git que o terminal enxerga, na ordem em que ele procura; o primeiro é o que responde. Na máquina da Ana:

$ type -a git
git é /usr/bin/git                          « este é o que responde
git é /bin/git

Aqui não há dois Gits de verdade: no Ubuntu, a pasta /bin é um atalho para /usr/bin, então os dois caminhos levam ao mesmo arquivo. Num Mac com o Git da Apple e o do Homebrew, apareceriam dois caminhos realmente diferentes.

Como resolver: feche e abra o terminal. No Mac com Homebrew, confira se o comando de configuração que o próprio Homebrew mostra no fim da instalação dele foi feito. Detalhes sobre a ordem de busca ficam no Guia Bash: PATH.

"Permissão negada" ao instalar no Linux

O que aconteceu: faltou o sudo. Instalar programas mexe em pastas do sistema, e só o administrador pode.

Como resolver: repita com sudo na frente: sudo apt install git.

Resumo

  • Teste antes: git --version. Se responder, já está instalado (qualquer 2.23 ou mais nova serve).
  • Windows: Git for Windows, pelo instalador ou pelo winget; use o Git Bash.
  • macOS: xcode-select --install ou brew install git.
  • Linux: o gerenciador de pacotes: sudo apt install git, sudo dnf install git, sudo pacman -S git.
  • "comando não encontrado": instale, feche e abra o terminal; type -a git mostra qual Git está respondendo.
