Git stash

A Ana está no meio de uma receita nova, num branch, com arquivos mudados e nada commitado. O telefone toca: o site está com um erro de digitação na página inicial, e ela precisa corrigir agora, no main. Commitar a receita pela metade? Não, ela não está pronta. Jogar fora? Nem pensar. O git stash ("esconderijo", "guardar num canto") resolve: ele guarda as mudanças não commitadas numa gaveta, deixa a pasta limpa para você fazer outra coisa, e depois devolve tudo do jeito que estava.

Você vai aprender
  • Quando o Git não deixa trocar de branch, e como o git stash resolve isso.
  • A mensagem Saved working directory and index state WIP on …, linha por linha, e o git status antes e depois.
  • Como trazer as mudanças de volta com git stash pop.
  • Como guardar também os arquivos novos (-u) e dar um nome ao que foi guardado (-m).
  • O que acontece com a área de preparo (--index e --staged), e os erros mais comuns.

Todas as saídas desta aula vieram do Git 2.53.0 da máquina da Ana (usuária ana, computador notebook), com o sistema em português. A tradução do Git no Ubuntu é incompleta, e quase todas as mensagens do stash saem em inglês: elas estão copiadas como saíram e ganham tradução na explicação.

A ideia: a gaveta da costureira

Uma costureira está fazendo um vestido na mesa quando chega uma cliente com uma calça para fazer a barra, com pressa. Ela não joga o vestido fora, e também não o entrega pela metade: ela guarda o vestido na gaveta, com os alfinetes no lugar, faz a barra da calça na mesa limpa e, quando termina, tira o vestido da gaveta e continua de onde parou.

Na costuraNo Git
O vestido pela metade, na mesaAs mudanças não commitadas na pasta (e na área de preparo)
Guardar na gavetagit stash
A mesa limpaO git status limpo: a pasta igual ao último commit
Tirar da gaveta e continuargit stash pop

O stash não é um commit do seu branch: ele fica guardado à parte, no repositório local, e não aparece no git log nem vai para o GitHub com o git push.

1. O problema: "would be overwritten by checkout"

No branch chocolate, a Ana transformou o bolo de cenoura num bolo de chocolate (já commitado). Agora ela está acrescentando o fermento no bolo.txt e começou uma receita nova, o brigadeiro.txt. Nada disso foi commitado:

$ git status
No ramo chocolate
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   bolo.txt

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	brigadeiro.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

O bolo.txt está modificado (Changes not staged for commit, "mudanças não preparadas para commit") e o brigadeiro.txt é um arquivo novo, que o Git ainda não acompanha (Arquivos não monitorados). Ela tenta ir para o main:

$ git switch main
error: Your local changes to the following files would be overwritten by checkout:
	bolo.txt
Please commit your changes or stash them before you switch branches.
Aborting

"Erro: as suas mudanças locais nos arquivos a seguir seriam sobrescritas pela troca de branch: bolo.txt. Por favor, faça commit das suas mudanças ou guarde-as com stash antes de trocar de branch. Cancelando." O bolo.txt do main é diferente do bolo.txt do chocolate (no main o bolo ainda é de cenoura). Para trocar de branch, o Git teria de pôr na pasta a versão do main, apagando o fermento que a Ana acabou de escrever. Ele se recusa. O próprio Git sugere as duas saídas: commit ou stash.

2. Guardando na gaveta: git stash

$ git stash
Saved working directory and index state WIP on chocolate: ffcf72f Bolo vira de chocolate
git stash
Guarda as mudanças dos arquivos rastreados (os que o Git já conhece), da pasta e da área de preparo, e deixa esses arquivos iguais ao último commit. É a forma curta de git stash push ("empurrar para dentro do stash").
Saved working directory and index state
"Guardei o estado da pasta de trabalho e do índice" (o índice é a área de preparo).
WIP on chocolate
WIP é a sigla de work in progress, "trabalho em andamento", no branch chocolate. É o nome automático do que foi guardado.
ffcf72f Bolo vira de chocolate
O commit em que você estava quando guardou: o hash e a mensagem. Ajuda a lembrar, dias depois, de onde aquilo veio.

E agora? O git status:

$ git status
No ramo chocolate
Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	brigadeiro.txt

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)
$ cat bolo.txt
Bolo de cenoura
- 3 cenouras
- 3 ovos
- 1 xícara de chocolate em pó
$ git stash list
stash@{0}: WIP on chocolate: ffcf72f Bolo vira de chocolate
git status
O bolo.txt saiu da lista de modificados: está igual ao último commit. Mas o brigadeiro.txt continua aí! Por padrão, o stash não guarda arquivos novos, que o Git ainda não acompanha. (Como guardá-los também, na seção 4.)
cat bolo.txt
O bolo de chocolate do último commit, sem o fermento. O fermento está na gaveta.
git stash list
Lista o que está guardado. stash@{0} é o nome do item: o "0" quer dizer "o mais recente". A aula Vários Stashes mostra o que fazer quando há vários.

3. Fazendo a outra tarefa e voltando: git stash pop

Com o bolo.txt limpo, a troca de branch funciona. A Ana corrige o README no main e volta:

$ git switch main
Switched to branch 'main'
$ sed -i 's/recitas/receitas/' README.md
$ git commit -q -am 'Corrige erro de digitação no README'
$ git switch chocolate
Switched to branch 'chocolate'

(O sed trocou recitas por receitas dentro do arquivo, como o "Localizar e substituir" de um editor.) O brigadeiro.txt, que não foi guardado, passeou junto com ela pelos dois branches: arquivos não rastreados não pertencem a branch nenhum. Agora, tirar da gaveta:

$ git stash pop
No ramo chocolate
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   bolo.txt

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	brigadeiro.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")
Dropped refs/stash@{0} (19ca623c5d2a24e6369496b8c8b4b5e529b923ec)
git stash pop
Pop é "tirar o de cima": aplica de volta as mudanças do stash mais recente e, se deu tudo certo, apaga-o da lista.
No ramo chocolate … modified: bolo.txt
Depois de aplicar, o pop mostra um git status: o bolo.txt está modificado de novo, como antes do stash.
Dropped refs/stash@{0} (19ca623…)
"Descartei o stash@{0}": a gaveta foi esvaziada. O número entre parênteses é o hash do stash (sim, por dentro um stash é um tipo de commit). Ele serve para recuperar um stash apagado sem querer, como mostra a aula Vários Stashes.
$ cat bolo.txt
Bolo de cenoura
- 3 cenouras
- 3 ovos
- 1 xícara de chocolate em pó
- 1 colher de fermento
$ git stash list

O fermento voltou, e o git stash list não mostra nada: a gaveta está vazia. A Ana continua o trabalho como se nada tivesse acontecido.

Missão: a Ana está no branch chocolate com o bolo.txt modificado. Tente ir para o main com git switch main e leia o erro. Depois guarde as mudanças na gaveta e vá para o main. Confira com git stash list.

4. Arquivos novos também: -u

Como você viu, o git stash deixa para trás os arquivos não rastreados. Para guardá-los junto, use -u (--include-untracked, "incluir os não rastreados"). E para dar um nome que você vai entender daqui a uma semana, use -m ("mensagem"). Num repositório novo, a Ana acrescentou o fermento ao bolo e criou o brigadeiro.txt:

$ git stash -u -m 'bolo com fermento e brigadeiro'
Saved working directory and index state On main: bolo com fermento e brigadeiro
$ git status
No ramo main
nothing to commit, working tree clean
$ ls
README.md  bolo.txt
$ git stash list
stash@{0}: On main: bolo com fermento e brigadeiro
-u
Guarda também os arquivos novos: o brigadeiro.txt sumiu da pasta (o ls não o mostra) e foi para a gaveta.
-m 'bolo com fermento e brigadeiro'
A mensagem do stash. Repare na lista: com mensagem, o nome fica On main: bolo com fermento e brigadeiro ("no main: …"); sem ela, era WIP on chocolate: ffcf72f Bolo vira de chocolate.
nothing to commit, working tree clean
"Nada a commitar, pasta limpa": agora sim, a mesa ficou totalmente vazia.

O que tem na gaveta? git stash show

$ git stash show
 bolo.txt | 1 +
 1 file changed, 1 insertion(+)
$ git stash show -p --include-untracked
diff --git a/bolo.txt b/bolo.txt
index 92e7eaf..84a5a0b 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -1,3 +1,4 @@

O git stash show mostra um resumo (os arquivos e quantas linhas mudaram), mas, sem opções, não lista os arquivos novos: o brigadeiro.txt não aparece. Com -p (de patch, as mudanças linha a linha, no formato do git diff) e --include-untracked, aparece tudo: o fermento no bolo.txt e o brigadeiro.txt inteiro, como arquivo novo (new file mode).

$ git stash pop
No ramo main
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   bolo.txt

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	brigadeiro.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")
Dropped refs/stash@{0} (c60b7cfbc72befdd5665053dc29cfb73406932c2)

Os dois voltaram: o bolo.txt modificado e o brigadeiro.txt, de novo como arquivo não monitorado.

5. E a área de preparo?

O stash guarda também o que estava na área de preparo (o "index state" da mensagem). Mas, ao trazer de volta, o pop não recoloca as coisas na área de preparo. Num repositório com o bolo.txt já preparado com git add:

$ git status --short
M  bolo.txt
$ git stash
Saved working directory and index state WIP on main: c448d1f Bolo
$ git stash pop
No ramo main
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   bolo.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")
Dropped refs/stash@{0} (0402e8c48127681498527d51a78ca9bd8edb27de)
$ git status --short
 M bolo.txt

Antes: M bolo.txt, com o M na primeira coluna (preparado). Depois: M bolo.txt, com o M na segunda coluna (modificado, mas não preparado). A mudança voltou inteira, só que fora da área de preparo. Normalmente isso não atrapalha: é só um git add de novo. Quando importa, use git stash pop --index, que tenta recolocar também a área de preparo como estava.

Guardando só um pedaço

Duas variações úteis do git stash push (a forma longa, que aceita opções e nomes de arquivos). A Ana tem o README.md preparado, o bolo.txt modificado e o brigadeiro.txt novo:

$ git status --short

 M bolo.txt
?? brigadeiro.txt
$ git stash push --staged -m 'só o README'
Saved working directory and index state On main: só o README
$ git status --short
 M bolo.txt
?? brigadeiro.txt
$ git stash pop --index
No ramo main
Mudanças a serem submetidas:
  (use "git restore --staged <file>..." to unstage)
	modified:   README.md

Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   bolo.txt

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	brigadeiro.txt

Dropped refs/stash@{0} (b3b6d6fde772573b613f19b3ef08064d8493de34)

Saved working directory and index state On main: só o bolo
$ git status --short
M  README.md
?? brigadeiro.txt
git stash push --staged git 2.35+
Guarda só o que está na área de preparo (o README.md); o bolo.txt modificado fica na pasta.

Traz de volta recolocando na área de preparo: o README.md voltou para "Mudanças a serem submetidas".
git stash push -m 'só o bolo' bolo.txt
Com nomes de arquivo no fim, guarda só esses arquivos. O README.md preparado ficou onde estava.

Formas diferentes de fazer a mesma coisa

O stash não é o único jeito de "largar o que está fazendo" por um tempo:

Quando dá errado

Nada para guardar: No local changes to save 
$ git stash
No local changes to save

"Não há mudanças locais para guardar." A pasta já está igual ao último commit, ou as únicas mudanças são arquivos novos, que o git stash sem -u ignora. Nenhum stash foi criado. Como confirmar: git status. Como resolver: se há arquivos novos que você quer guardar, use git stash -u.

Gaveta vazia: No stash entries found. 
$ git stash pop
No stash entries found.

"Nenhum item de stash encontrado." Você já tirou da gaveta (o pop apaga o item), ou guardou em outro repositório. Como confirmar: git stash list não mostra nada. Atenção: o stash é de cada repositório; um stash feito em ~/receitas não aparece em ~/tcc.

Repositório sem nenhum commit: You do not have the initial commit yet 
$ git stash
You do not have the initial commit yet

"Você ainda não tem o commit inicial." O stash guarda a diferença em relação ao último commit; sem nenhum commit, não há com o que comparar. Como resolver: faça o primeiro commit (aula Seu Primeiro Commit).

"Guardei, mas o arquivo novo continua aí"

É o brigadeiro.txt da seção 2: sem -u, arquivos não rastreados ficam na pasta. Se você trocar de branch, eles vão junto; se apagar a pasta achando que estava tudo guardado, eles se perdem. Como evitar: confira o git status depois do stash; para guardar tudo, git stash -u.

O pop deu conflito

Se, enquanto as mudanças estavam na gaveta, o branch ganhou um commit que mexe nas mesmas linhas, o pop dá conflito, como um merge. Nesse caso, o stash não é apagado da lista. Como resolver está na próxima aula, Vários Stashes.

Resumo

  • git stash guarda as mudanças não commitadas (da pasta e da área de preparo) e deixa os arquivos rastreados iguais ao último commit; git stash pop traz de volta e apaga o item da lista.
  • Use quando o Git não deixa trocar de branch (would be overwritten by checkout) ou quando precisa da pasta limpa por um momento.
  • Arquivos novos só entram com -u; um nome ajuda a lembrar: -m "texto".
  • git stash list mostra o que está guardado; git stash show -p, o conteúdo.
  • O pop devolve tudo fora da área de preparo; --index recoloca. git stash push --staged e git stash push arquivo guardam só uma parte.
  • O stash é local e fácil de esquecer: para interrupções longas, prefira um commit provisório.
