Git Novidades

O Git tem mais de 20 anos, mas não parou: sai uma versão nova a cada dois ou três meses, e o próximo grande passo, o Git 3.0, já está anunciado. Esta aula mostra as novidades recentes que você, como iniciante, vai perceber (comandos novos, avisos novos, comandos que vão sumir) e explica por que um tutorial antigo às vezes mostra coisas diferentes do seu terminal.

Você vai aprender
  • Como descobrir a sua versão do Git e onde ler as notas de lançamento oficiais.
  • As novidades das versões 2.50 a 2.53 (a do Ubuntu 26.04, usada neste guia), com saídas reais.
  • O que chegou depois, nas versões 2.54, 2.55 e 2.56.
  • O que muda no Git 3.0: main, SHA-256, reftable, Rust e comandos removidos.
De onde vêm as informações

As novidades foram conferidas nas notas de lançamento oficiais (release notes) do projeto Git, na pasta Documentation/RelNotes, e no documento BreakingChanges, em outubro de 2026. As saídas de terminal vêm do laboratório, com o Git 2.53.0 do Ubuntu 26.04. O que é de versões mais novas que a do laboratório não foi rodado e está marcado como ilustrativo.

A ideia: o Git é como um idioma vivo

O português de hoje não é o dos seus avós: palavras novas aparecem ("printar", "dar um commit"), algumas caem em desuso, mas você ainda entende um livro antigo. O Git é parecido. Ele quase nunca quebra o que já funciona: um comando de 2010 ainda roda hoje. Mas ganha palavras novas (git switch, git config get), passa a dar conselhos diferentes e, raramente, aposenta uma palavra velha. As mudanças que quebram compatibilidade ficam guardadas para uma versão "redonda": o Git 3.0.

Qual é a minha versão?

$ git --version
git version 2.53.0
2
A versão "grande" (major). Só muda quando há mudanças que quebram compatibilidade; o 2.0 é de 2014.
53
A versão "média" (minor): cada uma traz recursos novos. Sai uma a cada dois ou três meses.
0
As correções (patch): 2.53.1, 2.53.2… só consertam problemas. (É o versionamento semântico na prática.)

O Ubuntu (como outras distribuições) congela uma versão do Git em cada lançamento e só aplica correções de segurança. Por isso o Ubuntu 26.04 vem com o 2.53, mesmo depois de o projeto Git lançar versões mais novas. Para quem está aprendendo, isso não faz diferença: tudo o que este guia ensina funciona em qualquer Git dos últimos anos.

Novidades que você já tem (até o Git 2.53)

git switch e git restore deixaram de ser "experimentais" git 2.51

Os dois comandos chegaram no Git 2.23 (2019) para dividir o trabalho do antigo git checkout, que fazia coisas demais: git switch troca de branch e git restore restaura arquivos. Por anos, a documentação os marcou como "experimentais" (podiam mudar). As notas do 2.51 declaram: "git switch" and "git restore" are declared to be no longer experimental, ou seja, agora são oficiais e estáveis. O git checkout continua existindo e, segundo o documento BreakingChanges, vai continuar.

Missão: use só os comandos modernos. Descarte a mudança no bolo.txt com git restore e volte para o branch main com git switch. Confira com git status.

git config get, set e list git 2.46

O git config ganhou subcomandos com nomes claros, no lugar das opções antigas (--get, --list). As notas do 2.46 dizem que as opções antigas foram "deprecated" (desaconselhadas) e substituídas por subcomandos. As formas antigas ainda funcionam, e você vai vê-las muito em tutoriais:

$ git config get user.name                       « forma nova
Ana Souza
$ git config --get user.email                    « forma antiga: ainda funciona
ana@exemplo.com
$ git config set core.editor nano               « forma nova de gravar
$ git config get core.editor
nano
$ git config list --global                       « forma nova de "--list"
user.name=Ana Souza
user.email=ana@exemplo.com
init.defaultbranch=main
core.editor=nano
Forma antiga (ainda funciona)Forma nova
git config --get user.namegit config get user.name
git config user.name "Ana"git config set user.name "Ana"
git config --list ou -lgit config list
git config --unset user.namegit config unset user.name

Missão: descubra qual e-mail o Git vai gravar nos commits da Ana usando a forma nova do comando (git config get …).

O aviso do main e o Git 3.0 git 2.52

Quando ninguém configurou o nome do branch inicial, o git init ainda usa master, mas o aviso agora conta o futuro. Para ver o aviso, a Ana rodou o git init fingindo não ter configuração nenhuma (a variável GIT_CONFIG_GLOBAL=/dev/null faz o Git ignorar o seu ~/.gitconfig só nesse comando):

$ GIT_CONFIG_GLOBAL=/dev/null git init teste
hint: Using 'master' as the name for the initial branch. This default branch name
hint: will change to "main" in Git 3.0. To configure the initial branch name
hint: to use in all of your new repositories, which will suppress this warning,
hint: call:
hint:
hint: 	git config --global init.defaultBranch <name>
hint:
hint: Names commonly chosen instead of 'master' are 'main', 'trunk' and
hint: 'development'. The just-created branch can be renamed via this command:
hint:
hint: 	git branch -m <name>
hint:
hint: Disable this message with "git config set advice.defaultBranchName false"
Repositório vazio Git inicializado em  /home/ana/teste/.git/

A segunda linha é a novidade: "This default branch name will change to "main" in Git 3.0", "este nome padrão vai mudar para main no Git 3.0". As notas do 2.52 registram a decisão e prometem manter o aviso depois da troca, para quem se surpreender. Repare também que a última dica já usa a forma nova, git config set. Como este guia configura init.defaultBranch=main (veja git init), você já vive no futuro.

git repo info: o "RG" do repositório git 2.52

Um comando novo para perguntar características do repositório. No Git 2.53, ganhou a opção --all:

$ git repo info --all
layout.bare=false                               « não é um repositório "bare" (de servidor)
layout.shallow=false                            « tem o histórico completo
object.format=sha1                              « o tipo de hash dos commits
references.format=files                         « como os branches são guardados

Guarde as duas últimas linhas: sha1 e files são exatamente os dois padrões que o Git 3.0 vai trocar (mais abaixo).

O git whatchanged está de saída git 2.51

Se um tutorial antigo mandar usar git whatchanged, veja o que acontece hoje:

$ git whatchanged -1
'git whatchanged' is nominated for removal.

hint: You can replace 'git whatchanged <opts>' with:
hint:	git log <opts> --raw --no-merges
hint: Or make an alias:
hint:	git config set --global alias.whatchanged 'log --raw --no-merges'

If you still use this command, here's what you can do:

- read https://git-scm.com/docs/BreakingChanges.html
- check if anyone has discussed this on the mailing
  list and if they came up with something that can
  help you: https://lore.kernel.org/git/?q=git%20whatchanged
- send an email to <git@vger.kernel.org> to let us
  know that you still use this command and were unable
  to determine a suitable replacement

fatal: refusing to run without --i-still-use-this

Em português: "o git whatchanged foi indicado para remoção"; a dica sugere o substituto (git log --raw --no-merges) ou um alias; e o fatal final diz "me recuso a rodar sem --i-still-use-this" ("eu ainda uso isto"), uma opção que existe só para quem precisa de tempo para se adaptar. A mensagem é em inglês porque é nova e ainda não foi traduzida.

Outras do período (para conhecer)

  • git 2.51 git stash ganhou export e import, para levar stashes de um computador a outro.
  • git 2.51 git merge e git pull ganharam --compact-summary, um resumo mais curto do que chegou.
  • git 2.52 git refs list e git refs exists: uma "caixa de ferramentas" nova para listar e conferir referências (branches, tags).

O documento BreakingChanges lista as mudanças guardadas para o 3.0. Ele diz que ainda não há data para o lançamento, e que versões que quebram compatibilidade costumam sair com intervalos de vários anos. As principais:

Quando dá errado

O tutorial mostra uma mensagem diferente da minha

O que aconteceu: mensagens e dicas do Git mudam de versão para versão (e de idioma para idioma). Um tutorial de 2018 mostra o git status sugerindo git checkout -- arquivo; o Git de hoje sugere git restore.

Como resolver: confira a sua versão com git --version e confie na dica do seu terminal: ela foi escrita para a sua versão.

git: 'last-modified' não é um comando git (ou repo, history…)

O que aconteceu: o comando é mais novo que o seu Git (por exemplo, git history só existe a partir do 2.54).

Como resolver: veja a versão com git --version; use o comando equivalente antigo (o rebase interativo no lugar do git history) ou atualize o Git.

fatal: refusing to run without --i-still-use-this

O que aconteceu: o comando está marcado para remoção no Git 3.0 (como o git whatchanged, acima).

Como resolver: use o substituto que a dica mostra. O --i-still-use-this só adia o problema.

Resumo

  • git --version mostra a sua versão; o Ubuntu 26.04 traz o 2.53.0.
  • Até o 2.53: switch/restore estáveis, git config get/set/list, git repo info, git last-modified, aviso do main, whatchanged de saída.
  • Depois (2.54–2.56): git history, git add --resolved, git branch --delete-merged, dicas novas no git status.
  • Git 3.0 (sem data): main, SHA-256, reftable, Rust obrigatório, comandos velhos removidos; o checkout fica.
  • Na dúvida, confie na dica do seu terminal e no git help da sua versão.
