Git no VS Code e em Outros Programas

Você aprendeu o Git pelo terminal, e isso foi de propósito: no terminal você vê cada passo e cada mensagem. Mas no dia a dia muita gente usa o Git por botões, dentro do editor de código (o VS Code) ou num programa próprio (o GitHub Desktop). A boa notícia: por baixo dos botões é o mesmo Git, com o mesmo .git, a mesma área de preparo e os mesmos commits. Esta aula mostra onde fica cada coisa que você já conhece.

Você vai aprender
  • Que os programas gráficos são "controles remotos" do mesmo Git: dá para misturar botão e terminal.
  • O painel de controle de versão do VS Code: preparar, commitar, enviar e resolver conflitos.
  • O GitHub Desktop: as mesmas ideias, num programa separado.
  • Como fazer o Git do terminal usar o VS Code como editor e como ferramenta de merge.
  • O que fazer quando o programa e o terminal parecem discordar.
O que nesta aula é real e o que é ilustrativo

A máquina da Ana usada no guia é um terminal, sem tela gráfica. As saídas de terminal (seções 4 e "Quando dá errado") são reais, do Git 2.53 do Ubuntu. As descrições das telas do VS Code e do GitHub Desktop são ilustrativas, baseadas na documentação oficial (code.visualstudio.com/docs e docs.github.com/pt). Os nomes de botões aparecem como nos programas, em inglês, que é como eles vêm por padrão; os menus e botões mudam um pouco de uma versão para outra.

A ideia: o controle remoto e os botões da TV

A TV da Ana tem botões no próprio aparelho e um controle remoto. Os dois mudam de canal na mesma TV: se ela troca de canal no controle, o botão da TV não fica "desatualizado". E se o controle quebrar, ela continua conseguindo usar a TV pelos botões.

Com o Git é igual:

  • a "TV" é o repositório, a pasta .git;
  • o terminal (git add, git commit…) e os programas gráficos são formas diferentes de mandar nela;
  • o que você faz num aparece no outro: um commit feito no VS Code aparece no git log do terminal, e um git add no terminal aparece como "preparado" no VS Code.

Por isso quem sabe o terminal entende qualquer programa gráfico: cada botão é um comando que você já conhece. E quando o botão fizer algo estranho, o terminal (git status, git log) conta a verdade.

1. O VS Code: o painel Source Control (ilustrativo)

O VS Code (Visual Studio Code, gratuito, para Windows, macOS e Linux) já vem com o Git embutido: ele usa o Git instalado no computador. Abra a pasta do projeto (um repositório) e procure o painel Source Control ("controle de versão") na barra da esquerda, ou aperte Ctrl+Shift+G (no macOS, ⌃+⇧+G).

Dentro do editor, o VS Code também marca na margem esquerda (a "calha") as linhas que você mudou desde o último commit: verde para linhas novas, azul para linhas modificadas e um triângulo vermelho onde linhas foram apagadas. É um git diff sempre ligado.

Sync Changes = pull + push

O Sync Changes primeiro baixa (pull) e depois envia (push). É prático, mas, se o pull trouxer um conflito, você precisa resolvê-lo antes de o push acontecer. Quando estiver em dúvida, faça os dois passos separados no terminal e leia as mensagens (veja git pull e Push Rejeitado).

Conflitos no VS Code

Quando um merge dá conflito (veja Conflitos de Merge), o arquivo abre com os mesmos marcadores <<<<<<<, ======= e >>>>>>> do terminal, só que coloridos, e com ações clicáveis em cima de cada conflito:

AçãoO que faz
Accept Current ChangeFica com a versão "atual" (a do branch onde você está, o HEAD)
Accept Incoming ChangeFica com a versão "que está chegando" (a do outro branch)
Accept Both ChangesFica com as duas, uma depois da outra
Compare ChangesMostra as duas versões lado a lado

Para conflitos mais difíceis, o botão Resolve in Merge Editor abre o editor de merge de três vias: as duas versões em cima e o resultado embaixo. O Complete Merge prepara aquele arquivo (como um git add); depois de resolver todos, ainda falta o commit do merge. Nenhum botão resolve por você: "aceitar as duas" pode deixar a receita com duas quantidades de açúcar. Leia o resultado antes de commitar, como em Resolvendo Conflitos.

2. O GitHub Desktop (ilustrativo)

O GitHub Desktop é um programa gratuito do GitHub, para Windows e macOS (baixado em desktop.github.com), feito para quem quer usar Git e GitHub sem terminal. Pela documentação (docs.github.com/pt):

  • Entrar na conta: nas configurações do programa (no Windows, menu File → Options; no macOS, GitHub Desktop → Settings), seção Accounts.
  • Repositórios: no menu File ficam New repository… (o git init), Add local repository… (abrir uma pasta que já é repositório) e Clone repository… (o git clone).
  • A aba Changes: a lista de arquivos mudados, cada um com uma caixinha de marcar. Marcado = vai entrar no commit (é a área de preparo).
  • O commit: embaixo da lista, o campo Summary (o título da mensagem), o campo Description (o corpo, opcional) e o botão Commit to main (com o nome do branch atual).
  • Enviar: o botão Push origin, na barra de cima.

Os nomes acima estão em inglês, como no programa; a documentação em português do GitHub traduz alguns deles (por exemplo, "Clonar Repositório…"). O GitHub Desktop é ótimo para tarefas do dia a dia; para as coisas mais avançadas (rebase interativo, reflog, bisect), ele manda você para o terminal.

4. O VS Code trabalhando para o Git do terminal

O caminho contrário também existe: o Git do terminal pode chamar o VS Code. Isso é útil para escrever mensagens longas de commit (veja Configurações Úteis) e para resolver conflitos.

Como editor das mensagens

$ git config --global core.editor "code --wait"
$ git config --global core.editor
code --wait

Agora um git commit sem -m abre uma aba no VS Code; você escreve a mensagem, salva e fecha a aba, e o commit acontece. O --wait ("espere") faz o Git esperar a aba fechar.

Como ferramenta de merge

O Git sabe chamar várias ferramentas de merge; o git mergetool --tool-help lista as que ele conhece. A lista é longa; a linha do VS Code é esta:

$ git mergetool --tool-help
No suitable tool for 'git mergetool --tool=<tool>' found.

The following tools are valid, but not currently available:
		araxis           Use Araxis Merge (requires a graphical session)
		…                « (a Ana cortou aqui 30 linhas da lista)
		vscode           Use Visual Studio Code (requires a graphical session)
		winmerge         Use WinMerge (requires a graphical session)
		xxdiff           Use xxdiff (requires a graphical session)

Some of the tools listed above only work in a windowed
environment. If run in a terminal-only session, they will fail.

"Nenhuma ferramenta adequada encontrada. As seguintes são válidas, mas não estão disponíveis agora" (na máquina da Ana não há tela gráfica nem VS Code). "Requires a graphical session" = "precisa de uma sessão gráfica". Num computador com o VS Code, basta escolher:

$ git config --global merge.tool vscode

e, num conflito, rodar git mergetool: o Git abre cada arquivo em conflito no VS Code, um de cada vez.

Missão: configure o Git para usar o VS Code como editor das mensagens ("code --wait", com as aspas) e como ferramenta de merge (vscode). Confira com git config --global --list.

Quando dá errado

"code: not found" no git commit 
$ git config --global core.editor "code --wait"
$ git add a.txt
$ git commit
code --wait: 1: code: not found
error: there was a problem with the editor 'code --wait'
Please supply the message using either -m or -F option.
$ git status -s
A  a.txt

O que aconteceu: o Git tentou abrir o VS Code para você escrever a mensagem, mas o comando code não existe neste computador ("not found"). "Houve um problema com o editor code --wait. Informe a mensagem com a opção -m ou -F." O commit não foi feito, mas o arquivo continua preparado (A). Como resolver: instale o VS Code (no Windows e no macOS, confira se o comando code funciona num terminal novo; no macOS, a paleta do VS Code tem um comando para instalá-lo no PATH) ou volte para um editor que existe: git config --global core.editor nano. Para não travar agora, use git commit -m "mensagem".

O programa mostra uma coisa e o terminal outra

O que aconteceu: quase sempre, a tela do programa ainda não se atualizou, ou você abriu outra pasta (outro repositório) nele. Como confirmar: no terminal, dentro da pasta, rode git status e git log --oneline -3: essa é a verdade. Confira também se o programa e o terminal estão no mesmo branch. Como resolver: atualize a tela do programa (no VS Code, o painel Source Control tem um botão de atualizar) ou abra a pasta certa.

Cliquei num botão e não sei o que ele fez

Como confirmar: o git reflog mostra os últimos movimentos do HEAD, feitos pelo terminal ou por qualquer programa. No VS Code, a aba Output, escolhendo "Git" na lista, mostra os comandos git … que o editor rodou por você. Como resolver: com o comando em mãos, use o mapa do desfazer.

Resumo

  • Programas gráficos são outra forma de mandar no mesmo repositório: botão e terminal se misturam sem problema.
  • VS Code: painel Source Control (Ctrl+Shift+G), + para preparar, Commit, Sync Changes (pull + push), ações de conflito e o merge editor.
  • GitHub Desktop: aba Changes com caixinhas (a área de preparo), Summary/Description, Commit to main, Push origin.
  • core.editor "code --wait" e merge.tool vscode fazem o Git do terminal usar o VS Code.
  • Na dúvida, o terminal conta a verdade: git status, git log, git reflog.
