Git Terminal do Guia

Este guia tem um terminal que roda dentro da própria página, com um Git de verdade imitado em JavaScript. Ele cria repositórios, commits, branches, conflitos e até um "GitHub" de mentira para você praticar push e pull. Nada do que você digita sai do navegador: pode errar à vontade, e um clique em Reiniciar volta tudo ao começo.

Você vai aprender
  • Como usar as caixas "Experimente": digitar, teclas, missões e botões.
  • Como é a máquina fictícia da Ana e o Git dela, já configurado.
  • O que o Git do simulador faz igual ao Git real e o que ele não faz.
  • Como funcionam as missões com o GitHub de mentira.

Por que um terminal simulado?

Quem está começando no Git costuma ter medo de "estragar o repositório": apagar um commit, perder um arquivo, fazer um merge errado. No terminal do guia esse medo não existe. Ele é um programa da página, não o seu computador. Você pode fazer git reset --hard, apagar a pasta .git ou criar mil branches: ao clicar em Reiniciar, a máquina volta ao estado inicial.

Pense numa maquete: ela não é o prédio, mas tem as mesmas paredes e portas, no mesmo lugar. O Git do simulador guarda os arquivos do mesmo jeito que o Git de verdade (o Como o Git Guarda as Coisas explica), calcula os mesmos códigos de commit (o hash) e responde com as mesmas mensagens, comparadas automaticamente com o Git 2.53 real do laboratório do guia.

O terminal: caixas "Experimente você mesmo"

  1. Clique dentro da janela escura do terminal.
  2. Digite um comando, por exemplo git --version, e aperte Enter.
  3. Leia a resposta. Um prompt novo (ana@notebook:~$) aparece quando o comando termina.
  4. Se a caixa tiver uma missão, um aviso de missão cumprida aparece embaixo da janela quando você chegar ao objetivo.

↑ / ↓Navega pelos comandos já digitados naquela caixa. Ótimo para repetir um git status.
← / →Move o cursor dentro da linha.

Ctrl+LLimpa a tela (o comando clear também).
Ctrl+CDesiste da linha atual.

BotãoFaz

Cada caixa é uma máquina independente: o repositório que você cria numa não aparece nas outras, nem em outra página. Muitas missões começam com um repositório já preparado pela aula (com commits, branches ou até um conflito): é só digitar git status e git log --oneline para descobrir onde você está.

Missão: explore à vontade. Veja a versão do Git com git --version e a configuração da Ana com git config --list. Experimente também ls e git status (fora de um repositório ele reclama: leia a mensagem).

Por que os hashes saem iguais aos do guia

Um commit guarda o nome, o e-mail, a data e o conteúdo; o hash é calculado a partir disso tudo. Como a máquina da Ana tem sempre o mesmo nome, o mesmo e-mail e o relógio parado, o mesmo commit tem o mesmo hash no texto da aula e no simulador:

$ mkdir receitas
$ cd receitas
$ git init
Repositório vazio Git inicializado em  /home/ana/receitas/.git/
$ echo "# Receitas da Ana" > README.md
$ git add README.md
$ git commit -m "Cria o README"
[main (root-commit) 700bbd5] Cria o README          « 700bbd5: o mesmo no seu simulador
 1 file changed, 1 insertion(+)
 create mode 100644 README.md

No seu computador o hash será outro, porque o seu nome, o seu e-mail e a hora são outros. Isso é normal.

Missão: repita os comandos acima, um por linha, e confira que o commit sai com o hash 700bbd5. Depois rode git log --oneline.

As mensagens: português misturado com inglês

O Git do Ubuntu em português é traduzido só em parte. Por isso uma mesma tela mistura as duas línguas, e o simulador imita essa mistura do jeito que ela é:

$ git status
No ramo main                                   « português
nothing to commit, working tree clean          « inglês, na mesma tela

As aulas explicam as duas formas sempre que aparecem. Num computador com o sistema em inglês, tudo sai em inglês; no Windows e no macOS as frases podem ser diferentes.

Quando você tenta algo que o simulador não sabe fazer, ele avisa com uma linha que começa com (simulador): é uma limitação dele, e não um erro do Git. Já um comando que não existe no Git responde como o Git real:

$ git comit -m teste
git: 'comit' não é um comando git. Veja 'git --help'.

The most similar command is
	commit                             « o Git sugere o comando parecido

O GitHub de mentira

Nas aulas de remotos, endereços como https://github.com/ana-souza/receitas.git funcionam dentro do simulador: o repositório "do GitHub" já foi criado pela missão, e às vezes o colega da Ana, o Bruno, também já mandou commits para lá. Você pode fazer git clone, git push, git fetch e git pull como faria com o GitHub de verdade. As mensagens que começam com remote: vêm "do servidor" e ficam em inglês, como no GitHub real.

Uma diferença: no seu computador, o push e o clone mostram linhas de progresso (Enumerating objects…, Writing objects…). O terminal do guia mostra só o resultado:

$ git push -u origin main
To https://github.com/ana-souza/receitas.git
 * [new branch]      main -> main               « o branch main foi criado no GitHub
branch 'main' set up to track 'origin/main'.

Missão: o repositório receitas já tem um commit e já conhece o GitHub (o remoto origin). Envie o branch main com git push -u origin main. Depois rode git status e veja a linha nova sobre origin/main.

Quando não funciona

Digito e nada aparece

O que aconteceu: o terminal não está selecionado.

Como resolver: clique dentro da janela escura antes de digitar.

fatal: not a git repository

O que aconteceu: você está numa pasta que não é um repositório, por exemplo a pasta pessoal logo depois de Reiniciar.

Como resolver: confira com pwd e ls e entre na pasta do repositório (cd receitas). A aula git init explica.

(simulador) aqui não há editor de texto…

O que aconteceu: você rodou git commit sem -m. No seu computador, o Git abriria o editor nano para você escrever a mensagem.

Como resolver: escreva a mensagem no próprio comando: git commit -m "Adiciona receita de bolo".

O hash do meu computador é diferente do guia

O que aconteceu: o seu nome, o seu e-mail e a hora entram no cálculo do hash.

Como resolver: nada: é assim mesmo. Compare a forma da resposta, não os códigos.

Resumo

  • O terminal do guia roda na página, com um Git imitado em JavaScript; nada afeta o seu computador, e Reiniciar volta ao começo.
  • A máquina é sempre a mesma: ana@notebook, Git 2.53 já configurado, 15/10/2026 10:30. Por isso os hashes saem iguais aos do guia.
  • As mensagens misturam português e inglês, como no Git do Ubuntu.
  • Sem editor de tela cheia: use git commit -m. Sem site do GitHub, mas com um GitHub de mentira para push, pull e clone.
  • Quando algo não existe no simulador, a resposta começa com (simulador).
