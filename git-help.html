Git Pedindo Ajuda (git help)

O Git tem mais de cem comandos, e cada um tem dezenas de opções. Ninguém decora tudo: quem usa Git no dia a dia sabe onde perguntar. O próprio Git traz três níveis de ajuda: a lista dos comandos mais comuns, um resumo rápido de cada comando e o manual completo. Nesta aula você vai usar os três.

Você vai aprender
  • Ver os comandos mais comuns com git help (e o que cada um faz, em português).
  • Pedir o resumo de um comando com -h.
  • Abrir o manual completo com git help comando ou git comando --help, e sair dele.
  • Listar todos os comandos e os guias com git help -a e git help -g.

A ideia: o cardápio, a etiqueta e o livro de receitas

Pense numa cozinha. Para saber o que dá para fazer, você olha o cardápio (git help). Para lembrar rapidinho os ingredientes de um prato, lê a etiqueta do pote (git comando -h). E para entender tudo sobre um prato, abre o livro de receitas na página certa (git help comando).

A ajuda do Git está em inglês

Ao contrário das mensagens do dia a dia (o git status, os erros), que saem em português, a ajuda do Git quase não tem tradução: a lista de comandos e o manual estão em inglês. Por isso esta aula traduz as partes importantes. Com um tradutor no navegador, a documentação oficial em git-scm.com/docs também ajuda.

O cardápio: git help

Sem nada depois, git help mostra a forma geral de um comando do Git e os comandos mais usados:

Lendo a primeira parte

As primeiras linhas, depois de usage: ("uso:"), são a forma geral de qualquer comando do Git. Elas usam uma notação que aparece em toda ajuda de terminal:

NotaçãoQuer dizerExemplo
[ … ]Opcional: pode ou não estar.[-v | --version]
< … >Troque por um valor seu.<command> = o nome do comando, como status
a | bUm ou outro.-h | --help: as duas formas fazem o mesmo
…Pode repetir.<pathspec>... = um ou mais arquivos

A última linha da forma geral, <command> [<args>], é a que importa: todo uso do Git é git + um comando + os argumentos dele.

A etiqueta: -h

Quando você já sabe qual comando quer e só não lembra a opção, acrescente -h ao comando. O Git mostra um resumo curto, ali mesmo, sem abrir nada:

$ git status -h
uso: git status [<options>] [--] [<pathspec>...]          « a forma do comando

    -v, --[no-]verbose    detalhado
    -s, --[no-]short      show status concisely             « -s ou --short: mostrar de forma curta
    -b, --[no-]branch     show branch information
    --[no-]show-stash     show stash information
    --[no-]ahead-behind   compute full ahead/behind values
    --[no-]porcelain[=<version>]
                          machine-readable output
    --[no-]long           show status in long format (default)
    -z, --[no-]null       terminate entries with NUL
    -u, --[no-]untracked-files[=<mode>]
                          show untracked files, optional modes: all, normal, no. (Default: all)
    --[no-]ignored[=<mode>]
                          show ignored files, optional modes: traditional, matching, no. (Default: traditional)
    --[no-]ignore-submodules[=<when>]
                          ignore changes to submodules, optional when: all, dirty, untracked. (Default: all)
    --[no-]column[=<style>]
                          list untracked files in columns
    --no-renames          do not detect renames
    --renames             opposite of --no-renames
    -M, --find-renames[=<n>]
                          detect renames, optionally set similarity index

Cada linha é uma opção. À esquerda, as formas de escrever: -s (curta, um tracinho, uma letra) e --short (longa, dois tracinhos, uma palavra), que fazem o mesmo. O [no-] diz que existe também a forma "desligada", como --no-short. À direita, a descrição. Repare que o Git traduziu algumas partes ("uso:", "detalhado") e não outras: a tradução da ajuda ainda está pela metade.

Num comando com muitas opções, como o git commit -h, a lista é longa; o começo mostra a forma do comando:

$ git log -h | head -5
uso: git log [<options>] [<revision-range>] [[--] <path>...]
   ou: git show [<options>] <object>...

    -q, --[no-]quiet      suppress diff output
    --[no-]source         show source

O | head -5 mostra só as 5 primeiras linhas. O "ou:" indica outra forma de uso; aqui, o Git juntou na mesma ajuda o git log e o git show, que têm as mesmas opções.

Missão: leia a "etiqueta" do git status com git status -h e descubra qual é a forma curta da opção --short. Depois experimente o -h de outro comando, como git log -h.

O livro: o manual completo

Para entender um comando a fundo, abra o manual dele. Há duas formas, que dão no mesmo:

git help status
git status --help

No Linux e no macOS, o manual abre no próprio terminal, numa tela de leitura (o man). O começo do manual do git status:

$ git help status
GIT-STATUS(1)                      Git Manual                     GIT-STATUS(1)

NAME
       git-status - Show the working tree status

SYNOPSIS
       git status [<options>] [--] [<pathspec>...]

DESCRIPTION
       Displays paths that have differences between the index file and the
       current HEAD commit, paths that have differences between the working
       tree and the index file, and paths in the working tree that are not
       tracked by Git (and are not ignored by gitignore(5)). The first are what
       you would commit by running git commit; the second and third are what
       you could commit by running git add before running git commit.

OPTIONS
       -s, --short
           Give the output in the short-format.
…

Todo manual tem as mesmas seções: NAME (o nome e uma linha sobre o que faz), SYNOPSIS ("sinopse": a forma do comando), DESCRIPTION (a explicação), OPTIONS (cada opção em detalhe) e, mais para o fim, muitas vezes EXAMPLES (exemplos), a parte mais útil para quem está começando.

No Windows, o manual abre no navegador

No Git for Windows, git help status abre a versão em HTML do mesmo manual no seu navegador. O conteúdo é igual ao das páginas de git-scm.com/docs. Em qualquer sistema, git help -w status pede a versão web (no Linux, isso só funciona se a documentação em HTML estiver instalada).

O terminal do guia não tem o manual

Nas missões, use git help e o -h. Para ler o manual completo, use o terminal do seu computador ou o site git-scm.com/docs.

Todos os comandos e os guias

O git help mostra só os comandos mais comuns. Para a lista completa, use -a (all, "todos"); ela é comprida, por isso aqui vão só as primeiras linhas:

$ git help -a | head -12
See 'git help <command>' to read about a specific subcommand

Main Porcelain Commands                                « os comandos "de uso diário"
   add                     Add file contents to the index
   am                      Apply a series of patches from a mailbox
   archive                 Create an archive of files from a named tree
   backfill                Download missing objects in a partial clone
   bisect                  Use binary search to find the commit that introduced a bug
   branch                  List, create, or delete branches
   bundle                  Move objects and refs by archive
   checkout                Switch branches or restore working tree files
   cherry-pick             Apply the changes introduced by some existing commits

"Porcelain" ("porcelana") é o apelido que o Git dá aos comandos feitos para pessoas, a parte "bonita" do Git, em oposição aos comandos internos, chamados de "encanamento" (plumbing).

Além dos comandos, o Git traz guias sobre conceitos. O -g (guides) lista:

$ git help -g
The Git concept guides are:
   core-tutorial    A Git core tutorial for developers
   credentials      Providing usernames and passwords to Git
   cvs-migration    Git for CVS users
   diffcore         Tweaking diff output
   everyday         A useful minimum set of commands for Everyday Git
   faq              Frequently asked questions about using Git
   glossary         A Git Glossary
   namespaces       Git namespaces
   remote-helpers   Helper programs to interact with remote repositories
   submodules       Mounting one repository inside another
   tutorial         A tutorial introduction to Git
   tutorial-2       A tutorial introduction to Git: part two
   workflows        An overview of recommended workflows with Git

'git help -a' and 'git help -g' list available subcommands and some
concept guides. See 'git help <command>' or 'git help <concept>'
to read about a specific subcommand or concept.
See 'git help git' for an overview of the system.

Para abrir um guia, use o nome dele: git help glossary abre o glossário oficial; git help everyday, o "mínimo do dia a dia". O glossário deste guia, em português, está em Glossário.

Quando dá errado

Ajuda de um comando que não existe 
$ git help stauts
Nenhuma entrada de manual para gitstauts

O que aconteceu: não existe manual para stauts, porque o nome está errado. A mensagem é do man, o leitor de manuais do sistema, e não do Git: por isso está em português e com o nome colado (gitstauts).

Como resolver: use -h com o nome errado; aí quem responde é o Git, que sugere o nome certo:

$ git stauts -h
git: 'stauts' não é um comando git. Veja 'git --help'.

The most similar command is
	status
Abri o manual e não sei sair

O que aconteceu: o manual abriu numa tela de leitura que ocupa o terminal todo. Nada que você digite vira comando enquanto ela estiver aberta.

Como resolver: aperte q. O mesmo vale para outras telas assim que o Git abre, como um git log comprido.

O -h "deu erro"? 
$ git status -h
uso: git status [<options>] [--] [<pathspec>...]
…
$ echo $?
129

O que aconteceu: nada de errado. Por tradição, o Git termina o -h com o código de saída 129 (e não 0), como faz quando um comando é usado de um jeito que ele não entende. Para você, que lê a ajuda, isso não muda nada; só importa em scripts.

Resumo

  • git help é o cardápio: os comandos mais comuns, agrupados por tarefa.
  • git comando -h é a etiqueta: o resumo das opções, no terminal.
  • git help comando (ou git comando --help) é o livro: o manual completo; saia com q.
  • git help -a lista todos os comandos, git help -g os guias.
  • A ajuda do Git está quase toda em inglês; git-scm.com/docs tem o mesmo conteúdo no navegador.
