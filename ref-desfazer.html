Git Como Desfazer Qualquer Coisa

"Fiz besteira, e agora?" Esta página é para esse momento. Encontre a sua situação na tabela, copie o comando e siga o link para a aula, se quiser entender o porquê. Quase tudo no Git tem volta: o que já entrou num commit fica guardado por semanas, mesmo depois de um reset. O que não tem volta é o que nunca foi commitado nem preparado: por isso os comandos marcados com ⚠ perde pedem calma.

Antes de desfazer qualquer coisa
  1. Rode git status. Ele diz em que situação você está e, quase sempre, já mostra o comando para desfazer (as linhas (use "git …")).
  2. Responda: a mudança está só na pasta, na área de preparo, num commit só seu, ou num commit que já foi enviado (push)? Cada caso tem uma linha abaixo.
  3. Na dúvida, faça uma cópia de segurança barata: git branch backup guarda o ponto atual com um nome.

O que o git status já diz

Antes da tabela, olhe o professor que vem de graça. A Ana mudou o bolo.txt e preparou, mudou o README.md sem preparar e criou um rascunho.txt. Saída real:

$ git status
No ramo main

  (use "git restore --staged <file>..." to unstage)          « como tirar daqui (sem perder nada)

  (use "git restore <file>..." to discard changes in working directory)   « como jogar fora (perde!)

Nesta versão do Git, parte das mensagens em português ainda sai em inglês (é a tradução que vem no Ubuntu). As dicas dizem: to unstage = "para tirar da área de preparo"; to discard changes in working directory = "para descartar as mudanças na pasta de trabalho". Para os arquivos novos não há dica de desfazer: o git restore não sabe nada deles (veja o primeiro erro no fim da página); quem os apaga é o git clean.

Quando dá errado

error: pathspec … did not match any file(s) known to git

$ git restore rascunho.txt
error: pathspec 'rascunho.txt' did not match any file(s) known to git

O que aconteceu: o rascunho.txt é um arquivo novo, nunca adicionado: o Git não tem nenhuma versão dele para restaurar ("o caminho não casou com nenhum arquivo conhecido pelo git"). Também aparece com nome digitado errado.

Como resolver: confira o nome com git status. Se é mesmo um arquivo novo que você quer jogar fora, use o git clean (abaixo) ou apague com rm.

fatal: clean.requireForce is true and -f not given

$ git clean
fatal: clean.requireForce is true and -f not given: refusing to clean
$ git clean -n
Would remove rascunho.txt                          « "apagaria rascunho.txt": só mostra
$ git clean -f
Removing rascunho.txt                              « agora apagou de verdade

O que aconteceu: por segurança, o git clean se recusa a apagar sem o -f ("force", forçar). Como resolver: veja antes com -n e depois rode com -f.

fatal: ambiguous argument 'HEAD~1'

$ git reset --soft HEAD~1
fatal: ambiguous argument 'HEAD~1': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

O que aconteceu: não existe "um commit antes" deste: o repositório tem um commit só (ou nenhum). HEAD~1 = o pai do commit atual, e o primeiro commit não tem pai.

Como resolver: para refazer o único commit, use git commit --amend. Para desfazê-lo de vez, mantendo os arquivos: git update-ref -d HEAD (o branch volta a "não ter commits"; os arquivos continuam preparados).

Nada para abortar

$ git merge --abort
fatal: There is no merge to abort (MERGE_HEAD missing).
$ git rebase --abort
fatal: no rebase in progress
$ git revert --abort
error: Nenhum cherry-pick ou revert em progresso
fatal: revert failed

O que aconteceu: não há merge, rebase ou revert pela metade ("não há merge para abortar"; "nenhum rebase em andamento"). Talvez ele já tenha terminado, ou seja outra operação.

Como resolver: rode git status: ele diz qual operação está em andamento (por exemplo, "You have unmerged paths" num merge) e o comando para continuar ou abortar.

error: the branch 'teste' is not fully merged

$ git branch -d teste
error: the branch 'teste' is not fully merged
hint: If you are sure you want to delete it, run 'git branch -D teste'
hint: Disable this message with "git config set advice.forceDeleteBranch false"

O que aconteceu: o branch tem commits que não estão em nenhum outro lugar; apagar faria você "perder" esses commits ("o branch não foi totalmente juntado"). O Git protege você.

Como resolver: junte antes (git merge) ou, se tem certeza, use -D, como a dica (hint) diz. Se se arrepender, o hash está na mensagem do -D (veja acima).
