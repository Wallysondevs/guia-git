Git checkout: o Comando Antigo

Antes de 2019, não existiam o git switch nem o git restore. Um comando só fazia o trabalho dos dois: o git checkout (em inglês, algo como "conferir", "retirar para uso"). Ele continua no Git e funciona muito bem, e você vai encontrá-lo em quase todo tutorial, livro e resposta de fórum escritos antes disso. Esta aula ensina a reconhecer e a traduzir o git checkout para os comandos novos, e mostra por que ele confunde.

Você vai aprender
  • Trocar de branch com git checkout NOME, criar com git checkout -b e voltar com git checkout -.
  • Descartar mudanças com git checkout -- arquivo, e trazer um arquivo de outro branch.
  • Por que um comando que faz tudo é perigoso: a armadilha do branch com nome de arquivo, e o -- que separa os dois.
  • A tabela de tradução: checkout → switch / restore.

As saídas vieram do Git 2.53 do Ubuntu 26.04, na máquina da Ana, com o sistema em português (algumas mensagens do Git ainda não têm tradução e saem em inglês).

A ideia: o canivete suíço e as ferramentas separadas

O git checkout é um canivete suíço: troca de branch, cria branch, descarta mudança de arquivo, traz arquivo de outro commit, visita um commit antigo. É prático, mas fácil de abrir a lâmina errada: git checkout receitas pode querer dizer "vá para o branch receitas" ou "jogue fora as mudanças do arquivo receitas", dependendo do que existe no seu repositório.

No Git 2.23, o canivete foi dividido em duas ferramentas, cada uma com um trabalho só:

  • git switch: tudo o que é trocar de branch;
  • git restore: tudo o que é restaurar arquivos.

O guia usa os comandos novos. Mas o git checkout não vai sumir (o Git leva compatibilidade a sério), então você precisa reconhecê-lo.

1. Trocar de branch: git checkout NOME

O repositório receitas da Ana tem três commits no main. Ela cria o branch sobremesas e vai até ele com o checkout:

$ git branch sobremesas
$ git checkout sobremesas
Switched to branch 'sobremesas'
$ git checkout sobremesas
Already on 'sobremesas'
$ git status
No ramo sobremesas
nothing to commit, working tree clean
git checkout sobremesas
Muda o HEAD para o branch sobremesas e deixa a pasta igual a ele. É exatamente o git switch sobremesas: até as mensagens são as mesmas (Switched to branch …, "mudado para o ramo…"; Already on …, "já em…").
Antes:   A---B---C   ← main ← HEAD
                     ← sobremesas

Depois:  A---B---C   ← main
                     ← sobremesas ← HEAD

A = 700bbd5 (README)   B = 7225e04 (bolo)   C = 0244251 (pão de queijo)

Voltar para o anterior também é igual: git checkout -.

$ echo 'Pudim de leite' > pudim.txt
$ git add pudim.txt && git commit -q -m 'Adiciona receita de pudim'
$ git checkout main
Switched to branch 'main'
$ git checkout -
Switched to branch 'sobremesas'
$ git checkout -
Switched to branch 'main'

2. Criar e trocar: git checkout -b

O equivalente do git switch -c é o -b (de branch):

$ git checkout -b salgados
Switched to a new branch 'salgados'
$ git log --oneline --graph --all
* d6f2336 (sobremesas) Adiciona receita de pudim
* 0244251 (HEAD -> salgados, main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README

Antes:   A---B---C   ← main ← HEAD
                  \
                   D   ← sobremesas

Depois:  A---B---C   ← main
                  \  ← salgados ← HEAD
                   D   ← sobremesas         (D = d6f2336, o pudim)

Como no switch, dá para dar o ponto de partida no fim (git checkout -b bebidas sobremesas), e o -B maiúsculo recria um branch que já existe (o -C do switch):

$ git checkout -B salgados
Switched to and reset branch 'salgados'

Você vai ver muito git checkout -b em tutoriais: é a linha mais famosa do Git antigo.

3. Descartar mudanças: git checkout -- arquivo

Aqui o checkout faz um trabalho completamente diferente: em vez de trocar de branch, ele joga fora as mudanças não commitadas de um arquivo, voltando-o para a versão da área de preparo (que, sem git add, é a do último commit). Hoje, isso é o git restore arquivo (aula própria).

$ echo 'Bolo queimado' > bolo.txt
$ git status --short
 M bolo.txt
$ git checkout -- bolo.txt
$ git status --short                   « nada: a mudança sumiu
$ cat bolo.txt
Bolo de cenoura
--
Dois hifens separados por espaço querem dizer "daqui para frente, só nomes de arquivos". É assim que o checkout sabe que bolo.txt é um arquivo, e não um branch.
bolo.txt
O arquivo a restaurar. Dá para dar vários, ou . para a pasta inteira (git checkout -- .: descarta tudo).
Sem volta

Mudança descartada com git checkout -- arquivo não vai para lixeira nenhuma: nunca foi commitada, então o Git não tem cópia. O git checkout não pergunta "tem certeza?".

Sem o --, também funciona, desde que não exista um branch com o mesmo nome. Repare que o Git até avisa quantos caminhos restaurou:

$ echo 'Bolo queimado' > bolo.txt
$ git checkout bolo.txt
Updated 1 path from the index            « "1 caminho atualizado a partir do índice"
$ cat bolo.txt
Bolo de cenoura

(O índice, ou index, é outro nome da área de preparo.)

4. A armadilha: branch com nome de arquivo

Agora o motivo de o Git ter criado o switch e o restore. A Ana, por engano, criou um branch chamado bolo.txt. Depois, estragou o arquivo bolo.txt e quis desfazer com o comando da seção anterior, sem o --:

$ git branch bolo.txt
$ echo 'Bolo queimado' > bolo.txt
$ git checkout bolo.txt
M       bolo.txt
Switched to branch 'bolo.txt'           « ela queria restaurar o arquivo, e trocou de branch!
$ git status
No ramo bolo.txt
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
        modified:   bolo.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

Quando existe um branch com aquele nome, o git checkout escolhe o branch. O bolo continua queimado, e a Ana foi parar em outro ramo sem perceber. (Repare também no git status: metade das dicas está traduzida e metade não. A segunda dica já ensina o comando novo: git restore <file>.)

Para sair da armadilha, volte ao main, apague o branch que não devia existir (-D: aula Renomeando e Apagando Branches) e restaure com o --:

$ git checkout -q main
$ git branch -D bolo.txt
Deleted branch bolo.txt (was 0244251).
$ git checkout -- bolo.txt
$ git status --short

Com os comandos novos, a confusão não existe: git switch bolo.txt só pode ser um branch, e git restore bolo.txt só pode ser um arquivo.

5. Trazer um arquivo de outro branch

Com um branch e um arquivo, o checkout copia aquele arquivo, na versão daquele branch, para a pasta e para a área de preparo, sem trocar de branch:

$ git checkout sobremesas -- pudim.txt
$ git status --short
A  pudim.txt                    « o pudim veio do sobremesas, já preparado para commit

O equivalente novo é git restore --source=sobremesas --staged --worktree pudim.txt (mais comprido, mas diz exatamente o que faz). A Ana desistiu e desfez com git restore --staged pudim.txt e rm pudim.txt.

6. Visitar um commit antigo: git checkout HASH

Com um commit no lugar do branch, o checkout vai até ele e deixa o HEAD "solto", sem branch. O Git mostra um aviso comprido:

$ git checkout HEAD~1
Note: switching to 'HEAD~1'.

You are in 'detached HEAD' state. You can look around, make experimental
changes and commit them, and you can discard any commits you make in this
state without impacting any branches by switching back to a branch.

If you want to create a new branch to retain commits you create, you may
do so (now or later) by using -c with the switch command. Example:

  git switch -c <new-branch-name>

Or undo this operation with:

  git switch -

Turn off this advice by setting config variable advice.detachedHead to false

HEAD is now at 7225e04 Adiciona receita de bolo
$ git status
HEAD detached at 7225e04
nothing to commit, working tree clean

Esse estado tem nome, HEAD destacado, e aula própria, que traduz esse aviso linha por linha: HEAD Destacado. Com o switch, o mesmo exige pedir explicitamente: git switch --detach HEAD~1.

Experimente

O terminal está na pasta receitas, com três commits no main. Use só o git checkout, para treinar a leitura de tutoriais antigos.

Missão: com o git checkout, crie o branch salgados e vá para ele com um comando só. Depois, volte para o main (dica: git checkout - também serve).

Missão: o bolo.txt está estragado ("Bolo queimado") e ainda não foi commitado. Descarte a mudança com o git checkout, do jeito seguro (com o --). Confira com cat bolo.txt e git status. Depois, para comparar, faça o mesmo com o comando novo: estrague de novo (echo 'Bolo queimado' > bolo.txt) e use git restore bolo.txt.

Qual usar? No seu dia a dia, switch e restore: o nome já diz o que vai acontecer, e não existe a armadilha da seção 4. Use o checkout quando estiver num Git anterior ao 2.23 (servidores antigos, por exemplo; confira com git --version) e saiba lê-lo nos tutoriais.

Quando dá errado

error: pathspec 'bebidas' did not match any file(s) known to git 
$ git checkout bebidas
error: pathspec 'bebidas' did not match any file(s) known to git

"O caminho 'bebidas' não corresponde a nenhum arquivo conhecido pelo Git". A mensagem fala de arquivo porque, como não achou branch nenhum chamado bebidas, o checkout tentou o seu outro trabalho: restaurar um arquivo com esse nome. Também não achou. (Compare com a mensagem do git switch bebidas, que é direta: fatal: invalid reference: bebidas.) Como resolver: confira o nome com git branch; para criar, git checkout -b bebidas.

fatal: a branch named 'salgados' already exists 
$ git checkout -b salgados
fatal: a branch named 'salgados' already exists

O -b só cria branches novos. Como resolver: tire o -b para ir até o que existe: git checkout salgados.

Queria restaurar um arquivo e troquei de branch

A armadilha da seção 4: Switched to branch 'bolo.txt' quando você queria desfazer as mudanças do arquivo. Como confirmar: a primeira linha do git status mostra o branch em que você caiu. Como resolver: volte com git checkout - (suas mudanças vêm junto, como em qualquer troca) e restaure com o --: git checkout -- bolo.txt, ou melhor, git restore bolo.txt.

"You are in 'detached HEAD' state"

Você deu um hash, uma tag ou algo como HEAD~1 para o checkout, e ele foi até o commit sem branch. Não é erro, mas commits feitos ali podem se perder. Tudo sobre isso: HEAD Destacado. Para voltar: git switch - (ou git checkout main).

Resumo

  • O git checkout é o comando antigo que faz o trabalho do git switch e do git restore. Ele continua funcionando, e aparece em quase todo tutorial antigo.
  • git checkout NOME troca de branch; -b cria e troca; - volta para o anterior; um hash leva ao HEAD destacado.
  • git checkout -- arquivo descarta mudanças, sem volta. O -- separa os nomes de arquivos.
  • Se existir um branch com o mesmo nome do arquivo, o checkout sem -- troca de branch em vez de restaurar o arquivo.
  • Prefira switch (branches) e restore (arquivos): git 2.23+.
