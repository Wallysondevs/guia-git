Git Projeto: Seu Primeiro Repositório do Zero

A Ana guarda as receitas da família em arquivos soltos: bolo.txt, bolo-final.txt, bolo-final-AGORA-VAI.txt… Hoje ela decidiu fazer do jeito certo. Neste projeto você acompanha, passo a passo, a criação do repositório do site de receitas, do zero até um histórico com quatro commits, um .gitignore e um susto desfeito. A cada etapa há uma missão: faça você também no terminal do guia.

Neste projeto você vai praticar
  • Conferir a configuração e criar o repositório (git config, git init).
  • O ciclo de todo dia: mudar → git status → git add → git commit.
  • Ver o que mudou antes de commitar (git diff) e ler o histórico (git log, git show).
  • Ignorar um arquivo (.gitignore) e desfazer uma mudança (git restore).
Como funcionam as missões deste projeto

Cada missão começa exatamente onde a etapa anterior terminou: o terminal do guia já prepara a pasta para você. Assim você pode fazer o projeto inteiro de uma vez ou pular direto para a etapa que quiser.

Etapa 1: o Git sabe quem é você?

Todo commit leva um nome e um e-mail. Antes de começar, a Ana confere se já configurou os dois (ela fez isso na aula Configurando Nome e E-mail):

$ git config get user.name
Ana Souza
$ git config get user.email
ana@exemplo.com

Se nada aparecer, configure agora com git config --global user.name "Seu Nome" e git config --global user.email "voce@exemplo.com". Sem isso, o primeiro commit falha com Please tell me who you are.

Etapa 2: criar a pasta e o repositório

Um repositório é só uma pasta comum com uma subpasta escondida, a .git, onde o Git guarda o histórico. A Ana cria a pasta do projeto, entra nela e, de propósito, pergunta o status antes do git init:

$ mkdir receitas
$ cd receitas
$ git status
fatal: not a git repository (or any of the parent directories): .git
$ git init
Repositório vazio Git inicializado em  /home/ana/receitas/.git/
$ ls -a
.  ..  .git
  • fatal: not a git repository: "não é um repositório Git (nem nenhuma das pastas acima)". Até aqui, receitas é uma pasta qualquer, e o Git não tem o que mostrar.
  • Repositório vazio Git inicializado em /home/ana/receitas/.git/: o git init criou a pasta .git. "Vazio" porque ainda não há nenhum commit.
  • O ls -a (com -a, que mostra os ocultos) prova: a única coisa nova é a .git. Nunca mexa nela à mão.

Missão 1: crie a pasta receitas, entre nela e transforme-a num repositório Git. Confira com ls -a e git status.

Etapa 3: o primeiro arquivo e o primeiro commit

A Ana cria o README.md, a "capa" do projeto, e acompanha cada passo com o git status:

$ git status
No ramo main

No commits yet

nada para enviar (crie/copie arquivos e use "git add" para registrar)
$ echo '# Receitas da Ana' > README.md
$ git status
No ramo main

No commits yet

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	README.md                                « o Git viu o arquivo, mas não cuida dele

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)
$ git add README.md
$ git status
No ramo main

No commits yet

Mudanças a serem submetidas:
  (utilize "git rm --cached <arquivo>..." para não apresentar)
	new file:   README.md                    « na área de preparo: vai no próximo commit

$ git commit -m 'Cria o README'
[main (root-commit) 700bbd5] Cria o README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md

Repare como o git status conta a história:

  • No commits yet: "nenhum commit ainda".
  • Arquivos não monitorados: arquivos que o Git vê, mas não rastreia. A dica entre parênteses ensina o próximo passo: git add.
  • Mudanças a serem submetidas: o que está na área de preparo. "Submeter" é como esta tradução chama o commit.
  • [main (root-commit) 700bbd5]: o commit foi para o branch main; root-commit quer dizer "commit raiz", o primeiro de todos; 700bbd5 é o começo do hash dele.
$ git log
commit 700bbd5eb7964a024ce4076aeeb11c490e1bac2e
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Cria o README

O git log mostra o commit inteiro: o hash completo, quem fez (o nome e o e-mail da etapa 1), quando, e a mensagem.

Missão 2: o README.md já está na pasta. Coloque-o na área de preparo e faça o primeiro commit, com a mensagem Cria o README. Use git status antes e depois de cada comando.

Etapa 4: a primeira receita

Agora o conteúdo de verdade. O ciclo é o mesmo; para ir mais rápido, a Ana usa a versão curta do status (--short), em que ?? quer dizer "não rastreado":

Bolo de cenoura

Ingredientes:
- 3 cenouras
- 2 xícaras de farinha
$ git status --short
?? bolo.txt
$ git add bolo.txt
$ git commit -m 'Adiciona a receita de bolo de cenoura'
[main 9795a07] Adiciona a receita de bolo de cenoura
 1 file changed, 5 insertions(+)                « 5 linhas novas
 create mode 100644 bolo.txt

Missão 3: o arquivo bolo.txt já está escrito (veja com cat bolo.txt). Faça o commit dele com uma mensagem clara. Confira com git log --oneline.

Etapa 5: mudar, conferir, commitar

A Ana lembrou dos ovos. Antes de commitar, ela confere o que mudou com o git diff:

$ echo '- 3 ovos' >> bolo.txt
$ git status
No ramo main
Changes not staged for commit:
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   bolo.txt                     « um arquivo rastreado mudou

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")
$ git diff
diff --git a/bolo.txt b/bolo.txt
index 40a62aa..d750d46 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -3,3 +3,4 @@ Bolo de cenoura
 Ingredientes:
 - 3 cenouras
 - 2 xícaras de farinha
+- 3 ovos                                       « o + marca a linha nova
$ git add bolo.txt
$ git commit -m 'Adiciona os ovos ao bolo'
[main c69aa10] Adiciona os ovos ao bolo
 1 file changed, 1 insertion(+)

Changes not staged for commit quer dizer "mudanças fora da área de preparo" (a tradução do Ubuntu deixa algumas frases em inglês). No git diff, as linhas sem sinal são o contexto, e a linha com + é a que entrou.

Missão 4: acrescente a linha - 3 ovos ao fim do bolo.txt (com echo '- 3 ovos' >> bolo.txt; atenção aos dois >, que acrescentam em vez de apagar). Confira com git diff e commite.

Etapa 6: um arquivo que não deve entrar

A Ana anota ideias soltas num rascunho.txt, que não é para ninguém ver. Em vez de tomar cuidado para nunca adicioná-lo, ela avisa o Git com um .gitignore:

$ echo 'testar com açúcar mascavo?' > rascunho.txt
$ git status --short
?? rascunho.txt                                  « o Git oferece o rascunho
$ echo 'rascunho.txt' > .gitignore
$ git status --short
?? .gitignore                                    « o rascunho sumiu da lista
$ git add .gitignore
$ git commit -m 'Ignora o rascunho'
[main e2fc370] Ignora o rascunho
 1 file changed, 1 insertion(+)
 create mode 100644 .gitignore

O .gitignore é um arquivo comum, que vai para o histórico: assim, quem clonar o projeto (o Bruno, por exemplo) também ignora os mesmos arquivos.

Missão 5: o rascunho.txt aparece no git status. Crie um .gitignore que o ignore e commite o .gitignore. No fim, o git status deve dizer que não há nada a commitar.

Etapa 7: o susto (e o Git salvando o dia)

Distraída, a Ana usou > (que apaga) no lugar de >> (que acrescenta) e trocou a receita inteira por uma linha:

$ echo "Bolo de chocolate" > bolo.txt
$ git status --short
 M bolo.txt                                      « M = modificado
$ git diff
diff --git a/bolo.txt b/bolo.txt
index d750d46..8816f39 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -1,6 +1 @@
-Bolo de cenoura                                « tudo isto saiu…
-
-Ingredientes:
-- 3 cenouras
-- 2 xícaras de farinha
-- 3 ovos
+Bolo de chocolate                              « …e só isto entrou
$ git restore bolo.txt                          « volta à versão do último commit
$ cat bolo.txt
Bolo de cenoura

Ingredientes:
- 3 cenouras
- 2 xícaras de farinha
- 3 ovos
$ git status
No ramo main
nothing to commit, working tree clean           « como se nada tivesse acontecido

Como a receita estava commitada, o git restore trouxe de volta a versão do último commit. É para isso que serve commitar cedo: o que foi commitado, o Git devolve. (Cuidado: o git restore joga fora a mudança atual para sempre; use só quando quiser mesmo descartá-la.)

Missão 6: o bolo.txt foi estragado (veja com cat bolo.txt e git diff). Traga de volta a receita do último commit com git restore, sem criar commit novo.

O resultado

$ git log --oneline
e2fc370 (HEAD -> main) Ignora o rascunho
c69aa10 Adiciona os ovos ao bolo
9795a07 Adiciona a receita de bolo de cenoura
700bbd5 Cria o README
$ git show --stat HEAD~1
commit c69aa106233da6b2c7a270202b1dfefb0c481b12
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona os ovos ao bolo

 bolo.txt | 1 +
 1 file changed, 1 insertion(+)

Quatro commits, cada um com um assunto e uma mensagem que explica o que fez. O HEAD~1 quer dizer "um commit antes do atual" (veja O que é HEAD), e o --stat resume quais arquivos o commit mudou. Desenhado, o histórico da Ana é uma linha reta:

700bbd5 ── 9795a07 ── c69aa10 ── e2fc370  ← main ← HEAD
 README     bolo        ovos      .gitignore

Quando dá errado neste projeto

fatal: not a git repository

O que aconteceu: você está fora da pasta do repositório (ou esqueceu o git init).

Como resolver: pwd para ver onde está; cd ~/receitas para entrar. Se a pasta não tem .git (ls -a), rode git init.

nada adicionado ao envio mas arquivos não registrados estão presentes

O que aconteceu: você rodou git commit sem ter feito git add: a área de preparo está vazia.

Como resolver: git add arquivo e depois o commit.

Rodei git init na pasta errada (por exemplo, na pasta pessoal)

O que aconteceu: a pasta inteira virou um repositório, e o git status mostra tudo o que há nela.

Como resolver: se ainda não há commits que você queira, apague só a pasta .git daquele lugar (rm -rf ~/.git, com muito cuidado no caminho) e rode o git init na pasta certa. Veja git init.

Resumo

  • Confira nome e e-mail (git config get); crie a pasta e rode git init.
  • O ciclo: mudar → git status → git add → git commit -m.
  • git diff antes de commitar; git log e git show depois.
  • .gitignore para o que não deve entrar, commitado junto com o projeto.
  • git restore devolve a versão do último commit: commite cedo e com frequência.
