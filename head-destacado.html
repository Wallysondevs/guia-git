Git HEAD destacado (detached HEAD)

Um dia você vai rodar um git checkout com um hash e o Git vai responder com um parágrafo enorme em inglês começando por You are in 'detached HEAD' state. Assusta, mas não é erro: quer dizer que o HEAD está "destacado" (solto) de qualquer branch, parado direto num commit. É o jeito de visitar o passado do projeto. Esta aula mostra quando isso acontece, o que dá para fazer ali, e o único cuidado que importa: não deixar commits para trás.

Você vai aprender
  • A diferença entre o HEAD apontando para um branch e o HEAD apontando direto para um commit.
  • Como entrar no HEAD destacado (git switch --detach, git checkout HASH) e como sair (git switch -).
  • O aviso do Git, traduzido linha por linha.
  • O que acontece com commits feitos sem branch, e como salvá-los com git switch -c ou git branch, mesmo depois de sair.

As saídas vieram do Git 2.53 do Ubuntu 26.04, na máquina da Ana, com o sistema em português. As mensagens desta aula saem todas em inglês: a tradução do Git ainda não as cobre. Por isso cada uma vem traduzida aqui.

A ideia: o marcador de página solto

Lembre da aula O que é HEAD: o HEAD é o marcador "você está aqui". Normalmente ele aponta para um branch, e o branch aponta para um commit. É como um marcador preso na etiqueta "Receitas salgadas" do caderno: quando a Ana escreve uma página nova, a etiqueta anda junto, e o marcador vai junto com ela.

No HEAD destacado, o marcador está solto, enfiado direto numa página antiga, sem etiqueta nenhuma. Dá para ler a página, e até escrever páginas novas a partir dali, mas nenhuma etiqueta aponta para elas. Se a Ana fechar o caderno e abrir em outra etiqueta, essas páginas ficam sem nada que leve até elas.

Normal:     A---B---C   ← main ← HEAD          (HEAD → branch → commit)

Destacado:  A---B---C   ← main
                ↑
               HEAD                            (HEAD → commit, sem branch)

1. Entrando: git switch --detach

A Ana quer ver como o site estava antes da receita de pão de queijo. O repositório tem três commits:

$ git log --oneline
0244251 (HEAD -> main) Adiciona receita de pão de queijo
7225e04 Adiciona receita de bolo
700bbd5 Cria o README
$ cat .git/HEAD
ref: refs/heads/main                      « HEAD aponta para o branch main

O git switch se recusa a ir para um commit sem que você peça:

$ git switch HEAD~1
fatal: a branch is expected, got commit 'HEAD~1'
hint: If you want to detach HEAD at the commit, try again with the --detach option.
$ git switch --detach HEAD~1
HEAD is now at 7225e04 Adiciona receita de bolo
fatal: a branch is expected, got commit 'HEAD~1'
"Era esperado um branch, veio um commit". A proteção do switch.
hint: … try again with the --detach option
"Se você quer destacar o HEAD nesse commit, tente de novo com a opção --detach".
git switch --detach HEAD~1
--detach = "destacar". HEAD~1 = um commit antes do atual; qualquer jeito de apontar um commit serve (o hash 7225e04, uma tag…).
HEAD is now at 7225e04 Adiciona receita de bolo
"O HEAD agora está em 7225e04", com a mensagem desse commit.

Veja como tudo muda de cara:

$ cat .git/HEAD
7225e04b2a5e6944860a305db669f7d0991b1acb       « um hash, e não mais "ref: refs/heads/…"
$ git status
HEAD detached at 7225e04                       « em vez de "No ramo …"
nothing to commit, working tree clean
$ git branch
* (HEAD detached at 7225e04)
  main
$ git log --oneline --graph --all
* 0244251 (main) Adiciona receita de pão de queijo
* 7225e04 (HEAD) Adiciona receita de bolo       « HEAD sem seta: não aponta para branch
* 700bbd5 Cria o README
$ ls
README.md  bolo.txt                            « o pao.txt ainda não existia aqui

Antes:   A---B---C   ← main ← HEAD

Depois:  A---B---C   ← main
             ↑
            HEAD                 (A = 700bbd5, B = 7225e04, C = 0244251)

Três sinais de que o HEAD está destacado: o git status diz HEAD detached at … ("HEAD destacado em…"), o git branch mostra * (HEAD detached at …) em vez de um nome, e o git log mostra (HEAD) sozinho, sem a seta ->.

Para sair, é só ir para um branch:

$ git switch main
Previous HEAD position was 7225e04 Adiciona receita de bolo
Switched to branch 'main'

"A posição anterior do HEAD era 7225e04…; mudado para o ramo 'main'". Como a Ana só olhou, nada se perdeu.

2. O aviso comprido do git checkout

O git checkout (o comando antigo, aula própria) vai para um commit sem precisar de --detach, e por isso mostra um aviso grande:

$ git checkout HEAD~1
Note: switching to 'HEAD~1'.

You are in 'detached HEAD' state. You can look around, make experimental
changes and commit them, and you can discard any commits you make in this
state without impacting any branches by switching back to a branch.

If you want to create a new branch to retain commits you create, you may
do so (now or later) by using -c with the switch command. Example:

  git switch -c <new-branch-name>

Or undo this operation with:

  git switch -

Turn off this advice by setting config variable advice.detachedHead to false

HEAD is now at 7225e04 Adiciona receita de bolo

Em português, parágrafo por parágrafo:

Note: switching to 'HEAD~1'.
"Atenção: mudando para 'HEAD~1'."
You are in 'detached HEAD' state. …
"Você está no estado de HEAD destacado. Você pode olhar à vontade, fazer mudanças experimentais e commitá-las, e pode descartar qualquer commit feito neste estado, sem afetar nenhum branch, voltando para um branch." Ou seja: pode mexer, nada aqui estraga os seus branches.
If you want to create a new branch to retain commits you create …
"Se você quiser criar um branch novo para guardar os commits que fizer, pode fazer isso (agora ou depois) usando -c com o comando switch. Exemplo: git switch -c <nome-do-branch-novo>". É a dica mais importante: a seção 4 mostra.
Or undo this operation with: git switch -
"Ou desfaça esta operação com git switch -" (voltar para onde estava).
Turn off this advice …
"Desligue este conselho pondo a configuração advice.detachedHead em false". Quando você já conhece o aviso, pode desligá-lo (veja a referência).
HEAD is now at 7225e04 …
"O HEAD agora está em 7225e04", a mesma linha do switch --detach.

3. Commitando sem branch, e saindo sem salvar

Ainda destacada no commit do bolo, a Ana testa uma cobertura de chocolate e faz um commit:

$ echo 'Bolo de cenoura com chocolate' > bolo.txt
$ git commit -am 'Testa cobertura de chocolate'
[detached HEAD 7052e9a] Testa cobertura de chocolate     « o "branch" é: nenhum
 1 file changed, 1 insertion(+), 1 deletion(-)
$ git status
HEAD detached from 7225e04                               « "destacado A PARTIR de"
nothing to commit, working tree clean
$ git log --oneline --graph --all
* 0244251 (main) Adiciona receita de pão de queijo
| * 7052e9a (HEAD) Testa cobertura de chocolate
|/
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README

O commit funcionou: o [detached HEAD 7052e9a] diz que ele entrou "em nenhum branch". O git status mudou de detached at ("destacado em") para detached from ("destacado a partir de"): o HEAD já andou para longe do commit onde começou. O HEAD andou junto com o commit, mas nenhuma etiqueta aponta para ele:

A---B---C   ← main
     \
      X   ← HEAD (só ele!)        (X = 7052e9a, o chocolate)

Agora a Ana volta para o main, e o Git avisa:

$ git switch main
Warning: you are leaving 1 commit behind, not connected to
any of your branches:

  7052e9a Testa cobertura de chocolate

If you want to keep it by creating a new branch, this may be a good time
to do so with:

 git branch <new-branch-name> 7052e9a

Switched to branch 'main'
$ git log --oneline --graph --all
* 0244251 (HEAD -> main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README
Warning: you are leaving 1 commit behind, not connected to any of your branches
"Aviso: você está deixando 1 commit para trás, não ligado a nenhum dos seus branches".
7052e9a Testa cobertura de chocolate
Qual commit. Anote o hash.
If you want to keep it … git branch <new-branch-name> 7052e9a
"Se quiser mantê-lo criando um branch novo, esta pode ser uma boa hora, com: git branch <nome-novo> 7052e9a".

Repare no git log --all: o commit do chocolate sumiu do desenho. O --all mostra tudo o que é alcançável a partir de alguma etiqueta (branches, tags, o HEAD), e nenhuma leva mais até ele. Ele ainda existe dentro do .git, mas está "órfão". Se ninguém o resgatar, um dia a limpeza automática do Git (o git gc) apaga commits assim; isso não acontece na hora (por padrão, só depois de semanas), então dá tempo de salvar.

A---B---C   ← main ← HEAD
     \
      X       (sem etiqueta: invisível no git log --all)

4. Salvando o trabalho: dê um nome a ele

Antes de sair: git switch -c

O jeito certo é o da dica do aviso: ainda destacada, crie um branch. O branch nasce onde o HEAD está, e o HEAD passa a apontar para ele:

$ git switch --detach HEAD~1
HEAD is now at 7225e04 Adiciona receita de bolo
$ echo 'Bolo de cenoura com chocolate' > bolo.txt
$ git commit -q -am 'Testa cobertura de chocolate'
$ git switch -c cobertura
Switched to a new branch 'cobertura'
$ git log --oneline --graph --all
* 7052e9a (HEAD -> cobertura) Testa cobertura de chocolate
| * 0244251 (main) Adiciona receita de pão de queijo
|/
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README

Antes:   A---B---C   ← main
              \
               X   ← HEAD

Depois:  A---B---C   ← main
              \
               X   ← cobertura ← HEAD

A seta voltou: (HEAD -> cobertura). O HEAD não está mais destacado, e o commit do chocolate tem nome. Daqui para frente, é um branch como qualquer outro.

Depois de sair: git branch NOME HASH

Se você já saiu, use o hash que o aviso mostrou. Se o aviso já sumiu da tela, o git reflog (o "diário" de onde o HEAD esteve) tem o hash. A Ana testou um bolo de fubá destacada e saiu sem salvar:

$ git switch -q main
$ git switch --detach HEAD~1
HEAD is now at 7225e04 Adiciona receita de bolo
$ echo 'Bolo de fubá' > bolo.txt
$ git commit -q -am 'Testa bolo de fubá'
$ git switch -q main                           « com -q, nem o aviso aparece!
$ git reflog -3
0244251 (HEAD -> main) HEAD@{0}: checkout: moving from 6fb20d2ba5831c9432e3c43cc5aabd39e196a219 to main
6fb20d2 HEAD@{1}: commit: Testa bolo de fubá       « aqui está ele
7225e04 HEAD@{2}: checkout: moving from main to HEAD~1
$ git branch fuba 6fb20d2
$ git log --oneline --graph --all
* 7052e9a (cobertura) Testa cobertura de chocolate
| * 6fb20d2 (fuba) Testa bolo de fubá
|/
| * 0244251 (HEAD -> main) Adiciona receita de pão de queijo
|/
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README

Cada linha do git reflog é um lugar onde o HEAD esteve, do mais recente (HEAD@{0}) para o mais antigo. A linha commit: Testa bolo de fubá tem o hash 6fb20d2; com ele, o git branch fuba 6fb20d2 pôs uma etiqueta no commit, e ele voltou ao desenho. (Também daria para escrever git branch fuba HEAD@{1}, o nome que o reflog dá a essa linha; mas esses números mudam a cada movimento do HEAD, então o hash é mais seguro.)

5. Quando o HEAD destacado é útil

SituaçãoComo
Ver como o projeto estava numa versão antiga (rodar, testar, comparar)git switch --detach HASH, olhar, git switch -
Ver uma versão marcada com tag (git tag)git switch --detach v1.0
Testar uma ideia rápida a partir do passadoDestacar, commitar; se prestar, git switch -c NOME
Achar o commit que trouxe um defeito (git bisect)O próprio bisect destaca o HEAD em cada commit testado

Com uma tag, o switch também pede o --detach, e o git status mostra o nome da tag:

$ git tag v1.0 HEAD~1
$ git switch v1.0
fatal: a branch is expected, got tag 'v1.0'
hint: If you want to detach HEAD at the commit, try again with the --detach option.
$ git switch --detach v1.0
HEAD is now at 7225e04 Adiciona receita de bolo
$ git status
HEAD detached at v1.0
nothing to commit, working tree clean

Por que não dá para "ficar" na tag, como num branch? Porque uma tag é uma etiqueta fixa: ela nunca anda. Se o HEAD apontasse para ela e você commitasse, a tag teria de andar, e ela existe justamente para marcar um ponto que não muda.

Experimente

O terminal está na pasta receitas, com três commits no main. Olhe o git status e o git log --oneline --graph --all a cada passo.

Missão: visite o commit da receita de bolo (um antes do atual), destacando o HEAD. Confira com ls que o pao.txt ainda não existia ali, e com git status que o HEAD está destacado.

Missão: a Ana está com o HEAD destacado e acabou de commitar uma cobertura de chocolate. Antes de sair, salve esse commit num branch chamado cobertura e fique nele.

Missão de resgate: a Ana commitou um bolo de fubá com o HEAD destacado e voltou para o main com -q, sem ver aviso nenhum. Ache o commit perdido no git reflog e crie o branch fuba nele, sem sair do main.

Formas diferentes de entrar e de sair

ParaComando novoComando antigo
Destacar o HEAD num commitgit switch --detach HASHgit checkout HASH
Voltar para onde estavagit switch -git checkout -
Voltar para um branchgit switch maingit checkout main
Salvar os commits, ainda destacadogit switch -c NOMEgit checkout -b NOME
Salvar os commits, ainda destacado, sem sair do HEAD destacadogit branch NOME (cria a etiqueta; o HEAD continua destacado)
Salvar depois de sairgit branch NOME HASH (hash do aviso ou do git reflog)

Qual usar? Prefira o git switch --detach: você só entra no HEAD destacado quando pede. E, se for commitar, crie o branch antes de commitar (git switch -c NOME HASH cria o branch já no commit antigo): assim você nem passa pelo HEAD destacado.

Quando dá errado

"You are in 'detached HEAD' state" e eu não pedi isso

O que aconteceu: você deu ao git checkout um hash, uma tag, um branch remoto (origin/main) ou algo como HEAD~1. Como confirmar: git status começa com HEAD detached at …. Como resolver: se não fez nenhum commit, git switch - ou git switch main, e pronto.

Fiz commits destacada e quero ficar com eles

Como confirmar: git status diz HEAD detached from … e o git log --oneline --graph --all mostra commits com (HEAD) fora de qualquer branch. Como resolver: git switch -c NOME antes de sair. Se quiser levar esse trabalho para o main, depois junte com git merge.

"Warning: you are leaving 1 commit behind"

Você saiu sem salvar. Como resolver: copie o hash do aviso e rode git branch NOME HASH (no exemplo da seção 3, git branch chocolate 7052e9a). Perdeu o aviso? git reflog mostra o hash (seção 4). Se o commit não serve para nada, ignore o aviso: o Git limpa sozinho, um dia.

fatal: a branch is expected, got commit '…' / got tag '…'

É o git switch protegendo você: ele não entra no HEAD destacado sem --detach. Como resolver: se queria visitar o commit, repita com --detach; se queria um branch, confira o nome com git branch.

Resumo

  • Normalmente o HEAD aponta para um branch. No HEAD destacado, ele aponta direto para um commit: .git/HEAD tem um hash.
  • Entra-se com git switch --detach HASH (ou git checkout HASH, com o aviso comprido); sai-se com git switch - ou git switch NOME.
  • Sinais: HEAD detached at/from … no git status, (HEAD) sem seta no git log.
  • Dá para commitar destacado, mas nenhum branch guarda esses commits. Salve com git switch -c NOME antes de sair.
  • Saiu sem salvar? git branch NOME HASH, com o hash do aviso leaving 1 commit behind ou do git reflog.
