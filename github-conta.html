Git GitHub: Criando a Conta

O Git funciona sozinho, no seu computador, sem conta nenhuma. Mas para guardar uma cópia dos seus projetos na internet, mostrar seu trabalho e trabalhar com outras pessoas, você precisa de um serviço de hospedagem de repositórios. O mais usado do mundo é o GitHub. Nesta aula, a Ana cria a conta dela, ana-souza, e deixa tudo pronto para o primeiro repositório.

Você vai aprender
  • O que é a conta do GitHub e o que você ganha com ela (e o que o Git já fazia sem ela).
  • Como criar a conta em github.com/signup e verificar o e-mail.
  • Como escolher um bom nome de usuário.
  • Por que ativar a autenticação de dois fatores (2FA) e manter o e-mail privado.
  • Como a conta se liga ao nome e e-mail que você configurou no Git.
Esta aula é ilustrativa. O site do GitHub não roda no laboratório do guia. Os passos abaixo seguem a documentação oficial em português (Criar uma conta no GitHub). O GitHub muda a aparência das telas com frequência: se algo estiver diferente, siga as instruções que aparecem na tela.

A ideia antes do cadastro

Pense no Git como uma máquina fotográfica e no GitHub como um serviço de álbuns na nuvem. A máquina tira fotos sem precisar de internet nem de cadastro. O serviço de nuvem guarda uma cópia, deixa você compartilhar com quem quiser e permite que outras pessoas colaborem no mesmo álbum. Para usar o serviço, você precisa de uma conta.

Sem conta (só o Git)Com a conta no GitHub
Commits, branches, histórico: tudo funcionaTudo isso continua igual, no seu computador
O histórico mora só no seu computadorUma cópia fica no GitHub (backup)
Para colaborar, só com pastas compartilhadasColegas buscam e enviam commits (git pull, git push)
—Página do projeto, README exibido, issues, pull requests, site grátis

O GitHub é o mais popular, mas não é o único: GitLab, Bitbucket e Codeberg fazem coisas parecidas. Os comandos do Git são os mesmos em todos. A diferença entre o Git e o GitHub está explicada em Git × GitHub.

Antes de começar: o nome de usuário

O nome de usuário (username) aparece no endereço de todos os seus projetos. O da Ana será ana-souza, então o projeto de receitas vai morar em:

https://github.com/ana-souza/receitas

Dicas para escolher:

  • Curto e profissional. Você vai colocá-lo no currículo. ana-souza é melhor que aninha_gamer_2009.
  • Sem acentos e sem espaços. Use letras, números e hífen.
  • Pense no longo prazo. Dá para trocar depois, mas os endereços antigos dos seus projetos mudam junto.

Criando a conta, passo a passo

  1. Abra a página de inscrição: https://github.com/signup. Se preferir, a documentação diz que dá para entrar com uma conta do Google ou da Apple (o botão é Continue with Google); aqui a Ana vai pelo caminho tradicional, com e-mail.
  2. Preencha os dados que o formulário pedir: o e-mail, uma senha e o nome de usuário. Use uma senha que você não usa em nenhum outro site, de preferência guardada num gerenciador de senhas.
  3. Prove que é uma pessoa, se o site pedir um teste de verificação.
  4. Verifique o e-mail. O GitHub manda uma mensagem para o endereço que você informou. Siga as instruções dela. Isso é obrigatório: segundo a documentação, sem o e-mail verificado você não consegue fazer tarefas básicas, como criar um repositório.
  5. Escolha o plano. Para estudar e para projetos pessoais, o plano gratuito basta, com repositórios públicos e privados. Detalhes em Planos do GitHub.

Pronto: a conta existe. No canto superior direito de qualquer página aparece a sua imagem de perfil. Clicando nela, você chega ao seu perfil e às Configurações, que vamos usar já já.

Proteja a conta: autenticação de dois fatores (2FA)

A senha é uma prova de que você é você. A autenticação de dois fatores (two-factor authentication, 2FA) pede uma segunda prova, que só você tem: normalmente um código de 6 dígitos que muda a cada 30 segundos, gerado por um aplicativo no celular. Assim, mesmo que alguém descubra a sua senha, não entra.

O que a documentação do GitHub diz (Sobre a autenticação obrigatória de dois fatores):

  • Para muitas contas que contribuem com código (publicam releases, apps, pacotes, administram projetos importantes), o 2FA é obrigatório: o GitHub avisa por e-mail e dá 45 dias para ativar. Depois do prazo (mais 7 dias de tolerância), a conta fica bloqueada até o 2FA ser ativado.
  • O método recomendado como principal é um aplicativo autenticador (TOTP). Chave de acesso (passkey), chave de segurança e o app GitHub Mobile servem como reserva. SMS é aceito em muitos países, mas é menos seguro.
  • Verificação por e-mail não conta como 2FA.
Ative mesmo que não seja obrigatório para você. E guarde os códigos de recuperação que o GitHub mostra ao ativar: se você perder o celular, são eles que devolvem o acesso à conta.

Seu e-mail nos commits

Lembra do git config? Todo commit leva um nome e um e-mail. O GitHub usa o e-mail do commit para saber que ele é seu e mostrar a sua foto ao lado dele. Por isso, o e-mail configurado no Git deve ser um dos e-mails cadastrados na sua conta.

No notebook, a Ana confere o que o Git dela está usando (o terminal é real; a conta do GitHub é que fica no site):

$ git config --global user.name
Ana Souza                                « o nome que vai em cada commit
$ git config --global user.email
ana@exemplo.com                          « este e-mail precisa estar cadastrado na conta

Ela cadastrou a conta com ana@exemplo.com, o mesmo do Git: o GitHub vai reconhecer os commits dela. Se você usou um e-mail diferente na conta, há duas saídas: cadastrar o e-mail do Git na conta (em Configurações > Emails) ou trocar o do Git com git config --global user.email "outro@email". A troca vale para os commits novos; os antigos continuam com o e-mail antigo.

E se eu não quiser meu e-mail público?

Os commits enviados ao GitHub ficam públicos nos repositórios públicos, com o e-mail dentro. Se você não quer o seu endereço pessoal exposto, a documentação (Configurar o endereço de e-mail de commit) ensina:

  1. Em Configurações > Emails, marque Manter meus endereços de email privados.
  2. A própria página mostra um endereço especial do tipo noreply, criado pelo GitHub só para você.
  3. Use esse endereço no Git: git config --global user.email "ENDEREÇO-NOREPLY-QUE-APARECEU".

Os commits passam a ser seus para o GitHub, sem mostrar o seu e-mail de verdade.

Quando dá errado

"O nome de usuário já existe"

O que aconteceu: outra pessoa já usa esse nome. Nomes de usuário são únicos no GitHub inteiro.

Como resolver: tente variações: ana-souza-dev, anasouza, ana-c-souza. O formulário avisa na hora se o nome está livre.

Não consigo criar repositório: falta verificar o e-mail

O que aconteceu: a mensagem de verificação não foi aberta, ou foi para a caixa de spam.

Como resolver: procure no spam e nas abas "Promoções"/"Atualizações". Se não achar, peça para reenviar nas Configurações > Emails. A documentação tem um guia próprio: "Resolver problemas na verificação de e-mail".

Meus commits aparecem no GitHub sem a minha foto

O que aconteceu: o e-mail dos commits (o do git config user.email) não está cadastrado na sua conta. O GitHub não sabe que eles são seus.

Como confirmar: rode git log -1 --format='%an <%ae>' e compare o e-mail com a lista em Configurações > Emails.

Como resolver: cadastre esse e-mail na conta, ou troque o do Git com git config --global user.email para os próximos commits.

"A senha não funciona no terminal"

O que aconteceu: o GitHub não aceita a senha da conta no git push pelo terminal. Ela só serve para entrar no site.

Como resolver: use uma chave SSH ou um token de acesso.

Resumo

  • O Git funciona sem conta; o GitHub é um serviço que guarda e compartilha repositórios, e para ele você precisa de uma conta.
  • A conta se cria em github.com/signup; verificar o e-mail é obrigatório para criar repositórios.
  • Escolha um nome de usuário curto e profissional: ele vai para o endereço de todos os seus projetos.
  • Ative o 2FA e guarde os códigos de recuperação.
  • O e-mail do git config deve estar cadastrado na conta (ou use o endereço noreply para mantê-lo privado).
  • Para enviar commits pelo terminal, a senha não serve: use SSH ou token.
