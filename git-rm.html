Git rm

A receita de torta da Ana ficou velha e ela quer tirá-la do projeto. Apagar o arquivo da pasta é fácil, mas o Git precisa registrar que ele saiu, num commit, como registra qualquer outra mudança. O git rm (de remove, "remover") faz as duas coisas de uma vez: apaga o arquivo da pasta e prepara a remoção para o próximo commit. E, com --cached, ele faz o contrário do que o nome sugere: tira o arquivo do Git sem apagá-lo do seu computador.

Você vai aprender
  • Como apagar um arquivo e registrar a remoção: git rm arquivo e depois git commit.
  • Que rm arquivo + git add arquivo chega no mesmo lugar.
  • A apagar pastas (-r) e vários arquivos com um padrão ('img/*.png').
  • git rm --cached: parar de rastrear um arquivo sem apagá-lo (o caso da senha).
  • As recusas de segurança do Git, o -f, o -n, e como desfazer um git rm.

Todas as saídas desta aula saíram do Git do Ubuntu 26.04, na máquina da Ana (usuária ana, computador notebook), com o sistema em português. Algumas mensagens do Git ainda não têm tradução e saem em inglês.

A ideia: tirar um item do inventário

Imagine uma loja com um caderno de inventário. Quando um produto sai de linha, não basta tirá-lo da prateleira: é preciso anotar no caderno "a partir de hoje, este produto não existe mais". Senão, na próxima conferência, alguém vai perguntar "cadê a torta?".

No Git, a prateleira é a sua pasta e o caderno é o histórico. O git rm tira o arquivo da prateleira e já deixa a anotação pronta na área de preparo; o git commit grava a anotação. E as versões antigas? Continuam nos commits anteriores: apagar um arquivo nunca apaga o passado dele.

1. O primeiro git rm

O repositório receitas da Ana tem quatro receitas e uma pasta de fotos, tudo commitado:

$ ls
bolo.txt  fotos  lasanha.txt  pudim.txt  torta-velha.txt
$ git rm torta-velha.txt
rm 'torta-velha.txt'
$ ls
bolo.txt  fotos  lasanha.txt  pudim.txt
git rm
O comando: "remova do Git".
torta-velha.txt
O arquivo a remover. Pode ser mais de um (git rm a.txt b.txt).
rm 'torta-velha.txt'
A resposta do Git: uma linha rm '…' para cada arquivo removido. O ls seguinte confirma: o arquivo sumiu da pasta.

E o git status:

$ git status
No ramo main
Mudanças a serem submetidas:
  (use "git restore --staged <file>..." to unstage)
	deleted:    torta-velha.txt

A remoção está em Mudanças a serem submetidas, ou seja, já preparada (deleted = "apagado"). A dica, ainda em inglês, diz: "use git restore --staged para tirar da área de preparo" (é o caminho de volta; veja a seção 7). Falta só o commit:

$ git commit -q -m 'Remove receita de torta antiga'
$ git log --oneline --stat -1
4ed5d57 (HEAD -> main) Remove receita de torta antiga
 torta-velha.txt | 1 -
 1 file changed, 1 deletion(-)

O --stat do git log mostra o que o commit mudou: o torta-velha.txt perdeu a sua única linha (1 -), e o arquivo deixou de existir a partir deste commit. No commit anterior, ele continua lá, inteiro.

Missão: apague a receita torta-velha.txt com git rm, confira com git status e faça o commit da remoção.

2. Apaguei com o rm comum. E agora?

É muito comum apagar o arquivo do jeito de sempre: o rm do terminal, a lixeira do gerenciador de arquivos, o "Excluir" do VS Code. O Git percebe, mas a remoção não fica preparada:

$ rm lasanha.txt
$ git status
No ramo main
Changes not staged for commit:
  (utilize "git add/rm <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	deleted:    lasanha.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

Agora o deleted está em Changes not staged for commit ("mudanças não preparadas"). Repare na dica: utilize "git add/rm <arquivo>...". Ela diz que tanto git add quanto git rm servem para preparar a remoção. Parece estranho "adicionar" um arquivo que não existe, mas o git add prepara a mudança, e aqui a mudança é "o arquivo sumiu":

$ git add lasanha.txt
$ git status
No ramo main
Mudanças a serem submetidas:
  (use "git restore --staged <file>..." to unstage)
	deleted:    lasanha.txt

Mesmo resultado do git rm. Ou seja: git rm arquivo = rm arquivo + git add arquivo. A outra dica, git restore <file>, é o caminho de volta: traz o arquivo apagado de volta à pasta (aula git restore).

O git commit -a também pega remoções

O -a do git commit prepara sozinho tudo o que mudou em arquivos já rastreados, inclusive os apagados. Num outro repositório da Ana, só com o bolo e o pudim, o git commit sem -q mostra a linha delete mode 100644 pudim.txt ("modo apagar"):

$ rm pudim.txt
$ git commit -a -m 'Remove pudim'
[main ae22db1] Remove pudim
 1 file changed, 1 deletion(-)
 delete mode 100644 pudim.txt

3. Pastas: git rm -r

A Ana resolveu tirar a pasta de fotos inteira:

$ git rm fotos
fatal: not removing 'fotos' recursively without -r
$ git rm -r fotos
rm 'fotos/bolo.jpg'
rm 'fotos/pudim.jpg'
$ git status --short
D  fotos/bolo.jpg
D  fotos/pudim.jpg

Sem o -r, o Git recusa: "não vou remover fotos recursivamente (com tudo o que tem dentro) sem -r". É uma trava contra apagar uma pasta inteira por engano. Com o -r (de recursive), ele apaga cada arquivo de dentro e mostra um rm '…' para cada um. No git status --short, o D na primeira coluna quer dizer "apagado e preparado" (o D na segunda coluna, que você vai ver na seção 7, quer dizer "apagado e não preparado").

Vários arquivos com um padrão

Para apagar só os .png da pasta img, use um curinga entre aspas:

$ git rm 'img/*.png'
rm 'img/capa.png'
rm 'img/logo.png'
$ git status --short
D  img/capa.png
D  img/logo.png
$ ls img
leia.txt

Com as aspas, quem expande o * é o próprio Git, olhando os arquivos que ele rastreia (inclusive em subpastas de img). Sem aspas, quem expande é o terminal, com os arquivos que estão na pasta; na maioria das vezes dá no mesmo.

4. Ensaiar antes: -n

O -n (de dry run, "ensaio") mostra o que seria removido, sem remover nada:

$ git rm -n bolo.txt
rm 'bolo.txt'

A saída é igual à de verdade, mas o bolo.txt continua lá, e o git status não muda. É útil antes de um git rm -r ou de um padrão com *.

5. git rm --cached: parar de rastrear, sem apagar

A Ana cometeu um clássico: commitou um senhas.txt. Ela quer que o Git pare de rastreá-lo, mas o arquivo precisa continuar no computador dela. É o --cached (a área de preparo já foi chamada de cache): "remova só da área de preparo, não da pasta".

$ git rm --cached senhas.txt
rm 'senhas.txt'
$ ls
bolo.txt  pudim.txt  senhas.txt
$ git status
No ramo main
Mudanças a serem submetidas:
  (use "git restore --staged <file>..." to unstage)
	deleted:    senhas.txt

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	senhas.txt

O senhas.txt aparece duas vezes, e as duas fazem sentido:

  • em Mudanças a serem submetidas, como deleted: no próximo commit, ele sai do repositório;
  • em Arquivos não monitorados: ele continua na pasta, e agora o Git o vê como um arquivo novo, que ele não rastreia.

Para ele não voltar a aparecer (nem ser adicionado de novo por um git add .), ponha-o no .gitignore e commite tudo junto:

$ echo 'senhas.txt' > .gitignore
$ git add .gitignore
$ git status --short
A  .gitignore
D  senhas.txt
$ git commit -q -m 'Para de rastrear senhas.txt'
O passado continua lá

O commit ops, em que a Ana adicionou o senhas.txt, continua no histórico, com a senha dentro. O git rm --cached só evita que ela vá para os próximos commits. Se o repositório já foi para o GitHub, considere a senha vazada: troque-a e veja Commitei uma Senha! E Agora?.

Missão: o .env, com a senha do site, foi commitado. Faça o Git parar de rastreá-lo sem apagá-lo da pasta, ponha-o no .gitignore e faça o commit. No fim, o .env deve continuar existindo e o git status deve estar limpo.

6. As recusas de segurança e o -f

O git rm apaga o arquivo da pasta. Se esse arquivo tem mudanças que nunca foram commitadas, elas se perderiam para sempre. Por isso o Git recusa:

$ echo 'Pudim de leite condensado' > pudim.txt
$ git rm pudim.txt
error: the following file has local modifications:
    pudim.txt
(use --cached to keep the file, or -f to force removal)

"Erro: o arquivo a seguir tem modificações locais" (mudanças na pasta, não commitadas). A última linha dá as duas saídas: "use --cached para manter o arquivo, ou -f para forçar a remoção". Se as mudanças já estiverem preparadas, a mensagem muda um pouco:

$ git add pudim.txt
$ git rm pudim.txt
error: the following file has changes staged in the index:
    pudim.txt
(use --cached to keep the file, or -f to force removal)

"O arquivo tem mudanças preparadas no index" (o index é outro nome da área de preparo). Se você tem certeza de que quer jogar essas mudanças fora, o -f (de force) obedece:

$ git rm -f pudim.txt
rm 'pudim.txt'
$ git status --short
D  pudim.txt
O -f não tem volta

O que estava commitado volta pelo histórico, mas a linha Pudim de leite condensado, que nunca foi commitada, se perdeu. Antes de um -f, confira o que vai embora com git diff arquivo e git diff --staged arquivo (aulas git diff e git diff --staged).

7. Desfazendo um git rm (antes do commit)

A Ana deu git rm bolo.txt por engano. Como ainda não houve commit, tudo volta em dois passos, seguindo as dicas do próprio git status:

$ git rm bolo.txt
rm 'bolo.txt'
$ git restore --staged bolo.txt
$ git status --short
 D bolo.txt
$ git restore bolo.txt
$ git status --short
$ cat bolo.txt
Bolo de cenoura
  1. git restore --staged bolo.txt tira a remoção da área de preparo. O D pula para a segunda coluna ( D): o arquivo continua apagado da pasta, mas a remoção não está mais preparada. (Aula Tirando da Área de Preparo.)
  2. git restore bolo.txt traz o arquivo de volta à pasta, com o conteúdo do último commit. O git status --short vazio quer dizer: tudo como antes. (Aula git restore.)

Os dois passos também podem ser um só: git restore --staged --worktree bolo.txt ("na área de preparo e na pasta").

E se a remoção já foi commitada? O arquivo está nos commits anteriores e pode ser trazido de volta: veja git restore (opção --source) e git revert. O mapa completo está em Desfazendo: o Mapa.

Quando dá errado

fatal: pathspec 'nada.txt' não encontrou nenhum arquivo 
$ git rm nada.txt
fatal: pathspec 'nada.txt' não encontrou nenhum arquivo
$ echo 'rascunho' > novo.txt
$ git rm novo.txt
fatal: pathspec 'novo.txt' não encontrou nenhum arquivo

Pathspec é como o Git chama o "caminho" que você escreveu. A mensagem diz que nenhum arquivo rastreado corresponde a ele. Duas causas: o nome está errado (confira com ls e git ls-files), ou o arquivo existe mas nunca foi commitado nem preparado, como o novo.txt: o git rm só remove o que o Git conhece. Como resolver: corrija o nome; para um arquivo não rastreado, use o rm comum.

fatal: not removing 'fotos' recursively without -r

Você pediu para remover uma pasta. Como resolver: git rm -r fotos (de preferência, ensaie antes com git rm -r -n fotos).

error: the following file has local modifications

O arquivo tem mudanças que nunca foram commitadas (seção 6). Como resolver: se você quer manter o arquivo no computador e só tirá-lo do Git, git rm --cached; se quer apagar e jogar as mudanças fora, git rm -f; se não tem certeza, faça o commit das mudanças antes.

"Usei git rm querendo só parar de rastrear, e o arquivo sumiu!"

Faltou o --cached. Se ainda não fez commit, recupere com git restore --staged --worktree arquivo (seção 7) e repita com git rm --cached arquivo. Mudanças que nunca foram commitadas não voltam, mas o Git só deixaria apagá-las com -f.

Missão: num só commit, (1) apague a pasta antigas inteira e (2) faça o Git parar de rastrear o config.local, mantendo o arquivo no computador e colocando-o no .gitignore. No fim, o git status deve estar limpo.

Resumo

  • git rm arquivo apaga o arquivo da pasta e prepara a remoção; o git commit a registra. É o mesmo que rm arquivo + git add arquivo.
  • Pastas pedem -r; padrões vão entre aspas (git rm 'img/*.png'); -n ensaia.
  • git rm --cached arquivo para de rastrear sem apagar da pasta; combine com o .gitignore.
  • O Git recusa apagar arquivos com mudanças não commitadas; -f força (e as mudanças se perdem).
  • Antes do commit, git restore --staged --worktree arquivo desfaz um git rm. Depois do commit, o arquivo continua nos commits antigos.
