Git remote

Na aula O que é um Repositório Remoto, você viu que o seu repositório conhece outras cópias dele por nomes, como o origin. O git remote é o comando que cuida dessa lista: mostra quais remotos existem e para onde apontam, acrescenta remotos novos, troca o endereço de um remoto, renomeia e apaga. Ele é a "agenda de contatos" do seu repositório.

Você vai aprender
  • A listar os remotos (git remote, -v) e a ver os detalhes de um deles (get-url, show).
  • A acrescentar um segundo remoto (add) e buscar os branches dele.
  • A renomear (rename), trocar o endereço (set-url) e remover (remove) um remoto.
  • Onde o Git guarda essa lista: o arquivo .git/config.
  • Os erros: remote origin already exists e No such remote.

As saídas desta aula saíram do Git 2.53 do Ubuntu 26.04, num terminal de verdade da máquina da Ana, com o "GitHub" do laboratório (uma imitação local do GitHub).

A ideia: a agenda de contatos

Na agenda do celular, você não decora números: salva "Mãe", "Bruno", "Pizzaria" e liga pelo nome. Se o Bruno troca de número, você edita o contato, e o nome continua o mesmo. Se ele some da sua vida, você apaga o contato, e ninguém fica sabendo.

O git remote é essa agenda: cada remoto é um nome (origin, bruno) ligado a um endereço (a URL). Mexer na agenda não muda nada no GitHub: só muda como o seu repositório chama os outros.

1. Listando: git remote e -v

O repositório de receitas da Ana está ligado ao GitHub dela:

$ git remote
origin
$ git remote -v
origin  https://github.com/ana-souza/receitas.git (fetch)
origin  https://github.com/ana-souza/receitas.git (push)
git remote
Sozinho, lista só os nomes dos remotos, um por linha.
-v
De verbose ("falante"): mostra também a URL de cada um, duas vezes, uma para buscar (fetch) e outra para enviar (push).

Para pegar só o endereço (por exemplo, para colar no navegador ou mandar para alguém):

$ git remote get-url origin
https://github.com/ana-souza/receitas.git

Os detalhes: git remote show

$ git remote show origin
* remote origin
  Fetch URL: https://github.com/ana-souza/receitas.git
  Push  URL: https://github.com/ana-souza/receitas.git
  HEAD branch: main
  Remote branch:
    main tracked
  Local branch configured for 'git pull':
    main merges with remote main
  Local ref configured for 'git push':
    main pushes to main (up to date)

O show conversa com o GitHub (precisa de internet) e conta, em inglês:

Fetch URL / Push URL
Os dois endereços, os mesmos do -v.
HEAD branch: main
O branch principal do remoto é o main.
Remote branch: main tracked
Os branches que existem lá; tracked = o seu repositório acompanha esse branch (tem um origin/main).
main merges with remote main
O seu main, no git pull, junta as novidades do main do remoto.
main pushes to main (up to date)
O seu main, no git push, vai para o main de lá, e os dois estão iguais (up to date, "em dia").

2. Acrescentando um remoto: git remote add

O Bruno fez uma cópia do repositório da Ana no GitHub dele (um fork): https://github.com/bruno-lima/receitas.git. Lá, ele criou um branch pudim com uma receita nova. A Ana quer ver o pudim sem esperar o Bruno mandar para o repositório dela. Ela acrescenta o GitHub do Bruno como um segundo remoto:

$ git remote add bruno https://github.com/bruno-lima/receitas.git
$ git remote -v
bruno   https://github.com/bruno-lima/receitas.git (fetch)
bruno   https://github.com/bruno-lima/receitas.git (push)
origin  https://github.com/ana-souza/receitas.git (fetch)
origin  https://github.com/ana-souza/receitas.git (push)
git remote add
"Acrescente um remoto".
bruno
O nome que a Ana escolheu. Pode ser qualquer um, sem espaços. (Para o repositório "original" de um fork, muita gente usa upstream.)
https://github.com/bruno-lima/receitas.git
O endereço.

O add não baixa nada: só anota na agenda. Para trazer os branches do Bruno, a Ana busca deste remoto pelo nome:

$ git fetch bruno
remote: Enumerating objects: 4, done.
remote: Counting objects: 100% (4/4), done.
remote: Compressing objects: 100% (2/2), done.
remote: Total 3 (delta 1), reused 0 (delta 0), pack-reused 0 (from 0)
Unpacking objects: 100% (3/3), 272 bytes | 272.00 KiB/s, done.
From https://github.com/bruno-lima/receitas
 * [new branch]      main       -> bruno/main
 * [new branch]      pudim      -> bruno/pudim
$ git branch -a
* main
  remotes/bruno/HEAD -> bruno/main
  remotes/bruno/main
  remotes/bruno/pudim
  remotes/origin/HEAD -> origin/main
  remotes/origin/main
$ git log --oneline --graph --all
* f4412ce (bruno/pudim) Adiciona a receita de pudim
* 73a019c (HEAD -> main, origin/main, origin/HEAD, bruno/main, bruno/HEAD) Adiciona a receita de pão de queijo
* c20285a Corrige o tempo de forno do bolo

Os branches do Bruno chegaram com o prefixo do nome do remoto: bruno/main e bruno/pudim, ao lado dos origin/…. No desenho (veja Vendo os Galhos), o bruno/pudim tem um commit a mais que o main da Ana. Ela pode olhar a receita com git show bruno/pudim:pudim.txt, ou juntar o branch com git merge bruno/pudim (veja git fetch e git merge).

Missão: acrescente o GitHub do Bruno, https://github.com/bruno-lima/receitas.git, como um remoto chamado bruno, e busque os branches dele com git fetch. Confira com git branch -a.

3. Renomeando: git remote rename

A Ana prefere que o nome seja igual ao usuário do GitHub:

$ git remote rename bruno bruno-lima
$ git remote -v
bruno-lima      https://github.com/bruno-lima/receitas.git (fetch)
bruno-lima      https://github.com/bruno-lima/receitas.git (push)
origin  https://github.com/ana-souza/receitas.git (fetch)
origin  https://github.com/ana-souza/receitas.git (push)
$ git branch -r
  bruno-lima/HEAD -> bruno-lima/main
  bruno-lima/main
  bruno-lima/pudim
  origin/HEAD -> origin/main
  origin/main

O rename troca o nome e os branches remotos junto: bruno/pudim virou bruno-lima/pudim, sem baixar nada de novo. (O git branch -r, de remote, lista só os branches remotos.)

Missão: a Ana acrescentou um remoto com erro de digitação: gitub. Confira com git remote -v e renomeie esse remoto para github.

4. Trocando o endereço: git remote set-url

Quando um repositório muda de endereço (a Ana renomeou o repositório no GitHub, ou trocou HTTPS por SSH), o nome do remoto continua, e só a URL muda:

$ git remote set-url origin https://github.com/ana-souza/receitas-da-ana.git
$ git remote -v
bruno-lima      https://github.com/bruno-lima/receitas.git (fetch)
bruno-lima      https://github.com/bruno-lima/receitas.git (push)
origin  https://github.com/ana-souza/receitas-da-ana.git (fetch)
origin  https://github.com/ana-souza/receitas-da-ana.git (push)
git remote set-url
"Defina a URL" de um remoto que já existe.
origin
Qual remoto.
https://github.com/ana-souza/receitas-da-ana.git
O endereço novo.

Como o add, o set-url não confere se o endereço existe. Aqui, a Ana só fez um teste: esse repositório não existe no GitHub, e o Git só descobre na próxima conversa:

$ git fetch origin
remote: Repository not found.
fatal: repository 'https://github.com/ana-souza/receitas-da-ana.git/' not found
$ git remote set-url origin https://github.com/ana-souza/receitas.git

Ela voltou o endereço certo com outro set-url. Para trocar para SSH, seria git remote set-url origin git@github.com:ana-souza/receitas.git (veja Chaves SSH).

5. Removendo: git remote remove

A Ana já olhou o pudim e não precisa mais do remoto do Bruno:

$ git remote remove bruno-lima
$ git remote -v
origin  https://github.com/ana-souza/receitas.git (fetch)
origin  https://github.com/ana-souza/receitas.git (push)
$ git branch -r
  origin/HEAD -> origin/main
  origin/main

Os branches remotos dele (bruno-lima/…) também sumiram. Nada mudou no GitHub do Bruno, nem nos branches locais da Ana: só a entrada da agenda. (O nome antigo do remove é rm: git remote rm bruno-lima faz o mesmo.)

6. Onde a agenda fica: .git/config

Todos esses comandos editam um arquivo de texto, o .git/config do repositório:

$ cat .git/config
[core]
        repositoryformatversion = 0
        filemode = true
        bare = false
        logallrefupdates = true
[remote "origin"]
        url = https://github.com/ana-souza/receitas.git
        fetch = +refs/heads/*:refs/remotes/origin/*
[branch "main"]
        remote = origin
        merge = refs/heads/main
[remote "origin"]
A "ficha" do remoto origin.
url = …
O endereço (o que o set-url muda).
fetch = +refs/heads/*:refs/remotes/origin/*
A regra do fetch: "os branches de lá (refs/heads/*) viram origin/… aqui". É daí que vem o prefixo origin/.
[branch "main"]
A ligação do main com o remoto (o "upstream" do git push -u; veja Upstream).

Dá para editar esse arquivo à mão, mas o git remote é mais seguro: ele acerta também os branches remotos e as ligações.

Quando dá errado

error: remote origin already exists. 
$ git remote add origin https://github.com/ana-souza/outro.git
error: remote origin already exists.

O que aconteceu: "o remoto origin já existe". Acontece muito quando se segue as instruções do GitHub num repositório que já tinha origin (por exemplo, um que veio de git clone).

Como confirmar: git remote -v.

Como resolver: se o endereço novo deve substituir o antigo, use git remote set-url origin URL. Se é um remoto a mais, dê outro nome: git remote add outro URL.

error: No such remote: 'gitub' 
$ git remote remove gitub
error: No such remote: 'gitub'
$ git remote rename gitub github
error: No such remote: 'gitub'

O que aconteceu: "não existe o remoto gitub": o nome está errado (ou o remoto já foi removido).

Como resolver: veja os nomes certos com git remote e copie de lá.

remote: Repository not found. depois de um add ou set-url

O que aconteceu: o git remote aceita qualquer endereço sem conferir. O erro só aparece no fetch, pull ou push (como na seção 4).

Como resolver: confira a URL com git remote get-url NOME, compare com a da página do repositório e corrija com set-url.

Resumo

  • git remote cuida da "agenda" de remotos: cada um é um nome ligado a uma URL.
  • -v lista com as URLs; get-url mostra uma; show dá os detalhes (conversando com o servidor).
  • add acrescenta (e o git fetch NOME traz os branches como NOME/branch); rename renomeia; set-url troca o endereço; remove apaga.
  • Nenhum desses comandos muda nada no GitHub; eles editam o .git/config do seu repositório.
  • remote origin already exists → use set-url ou outro nome; No such remote → confira o nome com git remote.
