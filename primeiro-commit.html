Git Primeiro Commit

Na aula anterior, a Ana criou um repositório vazio com o git init. Um repositório vazio é como um álbum de fotos novo, ainda sem nenhuma foto. Nesta aula ela tira a primeira foto do projeto: o primeiro commit (em inglês, "registro"; aqui no guia, pense numa fotografia da pasta naquele momento). São só três comandos (git status, git add e git commit), e você vai ver cada um deles em detalhe nas próximas aulas. Aqui o objetivo é fazer o caminho inteiro uma vez, do começo ao fim, e entender o que o Git respondeu em cada passo.

Você vai aprender
  • O que é um commit e por que o Git pede dois passos (add e depois commit) para guardar uma versão.
  • O caminho completo: criar um arquivo → git status → git add → git commit -m "mensagem" → git log.
  • O que quer dizer cada linha que o Git mostra no caminho, inclusive o (root-commit) e o código do commit.
  • Como fazer o segundo commit (o ciclo que você vai repetir para sempre).
  • Os erros clássicos do primeiro commit: Please tell me who you are, "nada adicionado ao commit" e not a git repository.

Todas as saídas desta aula são reais: saíram do Git da máquina da Ana (usuária ana, computador notebook, Ubuntu 26.04 em português). Se o seu sistema estiver em inglês, o Git fala inglês; a aula mostra a frase em inglês quando ela for importante para você reconhecer.

A ideia: arrumar a mesa e depois tirar a foto

Pense numa confeitaria que fotografa os bolos para o cardápio. O fotógrafo não fotografa a cozinha inteira, com a pia suja e as panelas: ele escolhe o que vai para a mesa da foto, arruma, e só então aperta o botão. A foto vai para o álbum, com data e uma legenda.

O Git trabalha do mesmo jeito, com três lugares:

Na confeitariaNo GitO que é
A cozinha (tudo, bagunçado)Pasta de trabalhoA pasta do projeto, com os arquivos como estão agora no seu computador. É onde você edita.
A mesa da fotoÁrea de preparo (staging area)O que você escolheu para entrar na próxima foto. Você põe coisas lá com git add.
O álbumHistórico (o repositório)As fotos já tiradas, cada uma com autor, data e legenda. Uma foto nova entra com git commit.
pasta de trabalho  ──git add──▶  área de preparo  ──git commit──▶  histórico
   (você edita)                  (a mesa da foto)                  (o álbum)

Por que dois passos, e não um botão "salvar versão"? Porque assim você decide o que entra em cada foto. Se mexeu em três arquivos, mas só dois têm a ver com a receita nova, você prepara só esses dois e tira a foto; o terceiro fica para outra foto, com outra legenda. A aula A Área de Preparo mostra isso com calma.

Antes de começar

Você precisa de duas coisas, das aulas anteriores:

  1. O Git sabe quem você é (git config): todo commit leva o nome e o e-mail do autor. A Ana confere o que configurou: 
    $ git config --global user.name
Ana Souza
$ git config --global user.email
ana@exemplo.com
  2. Uma pasta que é um repositório (git init). A Ana criou a pasta receitas, para o site de receitas dela: 
    $ mkdir receitas
$ cd receitas
$ git init
Repositório vazio Git inicializado em  /home/ana/receitas/.git/

Passo 1: o git status do repositório vazio

Antes de qualquer coisa, pergunte ao Git como as coisas estão. O comando é o git status ("situação"), e ele nunca muda nada: só olha e conta.

$ git status
No ramo main            « você está no ramo "main"

No commits yet          « ainda não há nenhum commit

nada para enviar (crie/copie arquivos e use "git add" para registrar)
No ramo main
"No ramo main". Um ramo (branch) é uma linha do histórico; todo repositório começa com um, o main ("principal"). Os ramos têm um capítulo inteiro, a partir de O que é um Branch. Por enquanto, basta saber que você está nele.
No commits yet
"Nenhum commit ainda": o álbum está vazio.
nada para enviar (crie/copie arquivos e use "git add" para registrar)
Não há nada para commitar (o Git da tradução brasileira diz "enviar" ou "submeter" para commit). E vem a dica: crie ou copie arquivos para a pasta e use git add para o Git começar a cuidar deles. É exatamente o que a Ana vai fazer.
Por que o Git fala metade em inglês?

No Ubuntu, a tradução do Git vem do pacote de idioma do sistema, feita por voluntários, e ela está incompleta: algumas frases saem em português do Brasil, outras em português de Portugal (como "submissão", que você ainda vai ver), outras continuam em inglês, às vezes na mesma linha (use "git add" to registrar). Não é defeito do seu computador: é exatamente isso que aparece no Ubuntu 26.04 (Git 2.53). No Windows, no macOS ou em outra distribuição, as frases podem sair diferentes. Neste guia, as saídas são copiadas como saíram, e cada frase em inglês ganha tradução na explicação. Num sistema todo em inglês, tudo sai em inglês: On branch main, No commits yet, nothing to commit…

Passo 2: criar um arquivo

A Ana cria o primeiro arquivo do site, um README.md (o "leia-me" do projeto; o .md é de Markdown, um formato de texto simples que você vai ver em O README e o Markdown). Ela usa o echo do terminal para escrever uma linha nele, mas poderia usar qualquer editor de texto:

$ echo '# Receitas da Ana' > README.md
$ ls
README.md

O arquivo existe na pasta de trabalho, mas o Git ainda não o conhece. Pergunte de novo:

$ git status
No ramo main

No commits yet

Arquivos não monitorados:                                       « bloco novo
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	README.md                                                       « o arquivo novo

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)
Arquivos não monitorados:
"Arquivos que o Git não está acompanhando" (em inglês, untracked files; neste guia dizemos não rastreados). É a lista de arquivos que estão na pasta, mas nunca entraram no Git.
(utilize "git add <arquivo>..." para incluir o que será submetido)
A dica: use git add seguido do nome do arquivo para incluí-lo no próximo commit. O <arquivo> é um lugar para você pôr o nome (não digite os sinais < >), e os ... dizem que pode ser mais de um.
README.md
O arquivo novo, recuado com uma tabulação.
nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)
O resumo: "nada foi adicionado ao commit, mas existem arquivos não rastreados; use git add para rastreá-los" (o to é o "para" que ficou sem tradução).

"Não rastreado" quer dizer que o Git vê o arquivo, mas não está cuidando dele: se você apagar ou mudar o arquivo, o Git não tem nenhuma cópia para devolver. Ele está na cozinha, longe da mesa da foto.

Passo 3: git add, pôr na mesa da foto

$ git add README.md
git
O programa Git. Todo comando do Git começa assim.
add
O subcomando: "adicionar" à área de preparo.
README.md
O arquivo que vai para a mesa da foto. Pode ser mais de um (git add README.md bolo.txt), ou . para "tudo o que mudou nesta pasta" (aula git add).

O git add não mostra nada quando dá certo: no terminal, silêncio quer dizer "feito". Para ver o efeito, o git status de novo:

$ git status
No ramo main

No commits yet

Mudanças a serem submetidas:                                    « vai entrar no próximo commit
  (utilize "git rm --cached <arquivo>..." para não apresentar)
	new file:   README.md                                       « arquivo novo, preparado
Mudanças a serem submetidas:
"Mudanças que vão entrar no commit" (em inglês, Changes to be committed). É a área de preparo, a mesa da foto. Tudo o que estiver nesta lista entra no próximo git commit.
(utilize "git rm --cached <arquivo>..." para não apresentar)
A dica para voltar atrás: se você preparou o arquivo por engano, git rm --cached README.md o tira da mesa (sem apagar o arquivo da pasta). Ela só aparece assim antes do primeiro commit; depois, a dica muda (você vai ver em git status).
new file: README.md
"Arquivo novo": o README.md nunca esteve num commit e agora está preparado.

O arquivo saiu da cozinha e foi para a mesa. A foto ainda não foi tirada: o histórico continua vazio.

Passo 4: git commit, tirar a foto

$ git commit -m "Adiciona o README"
[main (root-commit) d84dc97] Adiciona o README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
git commit
"Registre": tira a foto de tudo o que está na área de preparo e guarda no histórico.
-m
De message, "mensagem": a legenda da foto vem logo em seguida, na mesma linha.
"Adiciona o README"
A mensagem, entre aspas (porque tem espaços). Ela diz o que este commit faz. O costume é escrever no imperativo ou no presente, curto, como um título: "Adiciona o README", "Corrige o tempo do bolo". A aula Boas Mensagens de Commit é só sobre isso.

A resposta, linha por linha:

[main (root-commit) d84dc97]
Entre colchetes: o commit foi feito no ramo main; root-commit ("commit raiz") avisa que é o primeiro do repositório, a raiz do histórico (só ele tem essa marca); d84dc97 é o começo do código do commit (o hash), o "RG" dessa foto. Você usa esse código para se referir ao commit depois (aula O Hash do Commit). No seu computador ele vai sair diferente, porque depende do nome, da data e do conteúdo.
Adiciona o README
A mensagem que você deu.
1 file changed, 1 insertion(+)
"1 arquivo alterado, 1 inserção": o commit mexeu em 1 arquivo e acrescentou 1 linha (o README.md tem uma linha só).
create mode 100644 README.md
"Criado com o modo 100644": o arquivo é novo no histórico, e 100644 é o jeito do Git anotar "arquivo comum, não executável". Arquivos executáveis (scripts) aparecem como 100755.

E o git status agora:

$ git status
No ramo main
nothing to commit, working tree clean

nothing to commit, working tree clean (esta saiu em inglês) quer dizer "nada a commitar, pasta de trabalho limpa": tudo o que está na pasta é igual à última foto. A linha No commits yet sumiu, porque agora existe um commit.

Passo 5: ver a foto no álbum com git log

$ git log

Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona o README
commit d84dc97…
O código completo do commit, com 40 caracteres. O d84dc97 da saída do git commit é só o começo dele.
Author: Ana Souza <ana@exemplo.com>
"Autor": o nome e o e-mail que a Ana configurou com o git config.
Date: Thu Oct 15 10:30:00 2026 -0300
"Data": quinta-feira (Thu), 15 de outubro (Oct) de 2026, às 10:30, no fuso de Brasília (-0300, três horas a menos que o horário universal). O Git escreve a data em inglês mesmo com o sistema em português.
Adiciona o README
A mensagem, recuada com 4 espaços.

O git log tem uma aula própria (git log). Para ver o que a foto guardou por dentro, existe o git show.

Missão: a pasta receitas já é um repositório e já tem o README.md, que ainda não foi commitado. Rode git status, prepare o arquivo com git add, rode git status de novo e faça o primeiro commit com a mensagem Adiciona o README. No fim, o git status deve dizer que não há nada a commitar.

O segundo commit: o ciclo que se repete

Daqui em diante, o trabalho com o Git é sempre o mesmo ciclo: editar → git status → git add → git commit. A Ana escreve a primeira receita e muda o README:

$ echo 'Bolo de cenoura' > bolo.txt
$ echo 'Site com as receitas da família.' >> README.md
$ git status
No ramo main
Changes not staged for commit:                                  « rastreado e modificado
  (utilize "git add <arquivo>..." para atualizar o que será submetido)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   README.md

Arquivos não monitorados:                                       « novo
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	bolo.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")
$ git add bolo.txt README.md
$ git commit -m "Adiciona a receita de bolo"
[main fa4a0cf] Adiciona a receita de bolo
 2 files changed, 2 insertions(+)
 create mode 100644 bolo.txt
$ git log --oneline
fa4a0cf Adiciona a receita de bolo
d84dc97 Adiciona o README

O que há de novo aqui:

  • O README.md já estava no primeiro commit, então ele não é mais "não monitorado": aparece em Changes not staged for commit ("mudanças não preparadas para o commit") como modified ("modificado"). As dicas mudaram também: git add para preparar a mudança, ou git restore para descartá-la e voltar o arquivo ao que estava no último commit. A aula git status explica cada bloco com calma.
  • O git add recebeu dois arquivos de uma vez, separados por espaço.
  • O commit não tem mais (root-commit): só o primeiro tem. Ele mexeu em 2 arquivos (2 files changed), com 2 linhas novas no total, e só o bolo.txt é arquivo novo (create mode).
  • O git log --oneline mostra o histórico resumido, uma linha por commit: o código curto e a mensagem, o mais novo em cima.

Desenhado, o histórico da Ana agora é uma linha com duas fotos, cada uma apontando para a anterior (a seta mostra de quem cada commit "é filho"):

d84dc97  ◀──  fa4a0cf  ◀── main
(README)      (bolo)

Missão: o repositório já tem um commit. Crie o arquivo bolo.txt (por exemplo, com echo 'Bolo de cenoura' > bolo.txt) e faça o segundo commit com ele. Confira com git log --oneline: devem aparecer duas linhas.

Formas diferentes de fazer

Preparar: um arquivo, vários, ou tudo

Em vez de nomear o arquivo, dá para usar o ponto, que quer dizer "esta pasta, com tudo o que tem dentro":

$ echo 'Pudim de leite' > pudim.txt
$ git add .
$ git status
No ramo main
Mudanças a serem submetidas:
  (use "git restore --staged <file>..." to unstage)
	new file:   pudim.txt

É prático, mas cuidado: o ponto pega tudo, inclusive o que você não queria commitar (um arquivo de senha, um arquivo temporário). Por isso, olhe o git status antes. A aula git add mostra as variações e a .gitignore mostra como fazer o Git ignorar arquivos.

A mensagem: com -m ou no editor

Sem o -m, o Git abre um editor de texto no terminal (no Ubuntu, normalmente o nano; em outros sistemas, o vim) para você escrever a mensagem. Você escreve, salva e fecha, e o commit acontece. Na máquina da Ana, o git commit sozinho abriu o editor nano com este texto:

# Please enter the commit message for your changes. Lines starting
# with '#' will be ignored, and an empty message aborts the commit.
#
# No ramo main
# Mudanças a serem submetidas:
#	new file:   pudim.txt
#

A primeira linha, vazia, é onde você escreve a mensagem. As linhas com # são só um lembrete ("escreva a mensagem; linhas começando com # serão ignoradas, e uma mensagem vazia cancela o commit") e não entram no commit. A Ana fechou o nano com Ctrl+X sem escrever nada, e o Git respondeu:

$ git commit
Aborting commit due to empty commit message.

"Cancelando o commit porque a mensagem está vazia": nenhum commit foi feito, e o arquivo continua na área de preparo, esperando. Para quem está começando, o -m é mais simples. O editor e como escolher outro estão em git commit.

FormaQuando usar
git add arquivoO normal: você escolhe exatamente o que entra na foto.
git add .Quando o git status mostrou que tudo o que mudou deve entrar.
git commit -m "mensagem"Mensagem curta, de uma linha. O mais usado no dia a dia.
git commit (abre o editor)Quando a mensagem precisa de um título e um texto explicando o porquê.

Quando dá errado

"Please tell me who you are" (o Git não sabe quem você é)

Num Git recém-instalado, sem o git config, o git add funciona, mas o commit não:

$ git commit -m "Adiciona o README"
Author identity unknown

*** Please tell me who you are.

Run

  git config --global user.email "you@example.com"
  git config --global user.name "Your Name"

to set your account's default identity.
Omit --global to set the identity only in this repository.

fatal: unable to auto-detect email address (got 'ana@notebook.(none)')

Esta mensagem só existe em inglês. Ela diz: "Identidade do autor desconhecida. Por favor, me diga quem você é. Rode os dois comandos abaixo para definir a identidade padrão da sua conta; sem o --global, a identidade vale só neste repositório." A última linha conta que o Git tentou adivinhar o e-mail juntando o usuário e o nome do computador (ana@notebook.(none)) e desistiu, porque isso não é um e-mail de verdade. Nenhum commit foi feito, mas o arquivo continua preparado. Como resolver: rode os dois comandos com os seus dados (não copie o you@example.com) e repita o commit:

git config --global user.name "Ana Souza"
git config --global user.email "ana@exemplo.com"
git commit -m "Adiciona o README"

Detalhes em git config.

Commit sem git add antes 
$ echo '# Receitas da Ana' > README.md
$ git commit -m "Primeira versão"
No ramo main

Submissão inicial.

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	README.md

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)

O Git não fez o commit e, em vez de um erro, mostrou o git status: "Submissão inicial" (seria o commit inicial), o README.md como não rastreado, e o resumo "nada foi adicionado ao commit". O git commit só fotografa o que está na área de preparo, e ela estava vazia. Como resolver: git add README.md e repita o commit.

Commit quando não mudou nada 
$ git commit -m "Primeira versão"
No ramo main
nothing to commit, working tree clean

"Nada a commitar, pasta de trabalho limpa". Todas as mudanças já estão em commits (talvez você já tenha feito este commit e não percebeu). Confira com git log --oneline. Se você mudou um arquivo e esperava que ele aparecesse, confira se salvou o arquivo no editor.

"not a git repository" (não é um repositório) 
$ cd ~
$ git status
fatal: not a git repository (or any of the parent directories): .git
$ git add receitas/README.md
fatal: not a git repository (or any of the parent directories): .git

"Fatal: não é um repositório Git (nem nenhuma das pastas acima dela): .git". O Git procura a pasta escondida .git na pasta atual e, se não acha, nas de cima. A Ana estava na pasta pessoal (~), que não é um repositório; o repositório é a receitas, que fica dentro dela. Como resolver: entre na pasta do projeto (cd receitas) e confira com pwd. Se a pasta do projeto nunca recebeu um git init, veja git init.

O nome do arquivo errado no git add 
$ git add pudin.txt
fatal: pathspec 'pudin.txt' não encontrou nenhum arquivo

"O caminho pudin.txt não corresponde a nenhum arquivo" (pathspec é o nome que o Git dá ao caminho que você digita). A Ana digitou pudin com n; o arquivo é pudim.txt. Nada foi preparado. Como resolver: confira o nome com ls ou git status e digite de novo (a tecla Tab completa nomes de arquivo e evita esse erro). Maiúsculas contam: Readme.md não é README.md.

Missão: a Ana tentou commitar sem preparar nada. Rode git commit -m "Primeira versão" e leia a resposta do Git. Depois, faça do jeito certo: prepare os dois arquivos da pasta e faça o commit.

Resumo

  • Um commit é uma fotografia do projeto, guardada no histórico com autor, data e mensagem.
  • São dois passos: git add põe o arquivo na área de preparo (a mesa da foto); git commit -m "mensagem" tira a foto do que está preparado.
  • O git status diz a situação a cada passo e, nas linhas entre parênteses, sugere o próximo comando. Rode-o sempre.
  • O primeiro commit aparece como (root-commit): é a raiz do histórico. Cada commit ganha um código (o hash), como d84dc97.
  • O git log mostra as fotos já tiradas; o git log --oneline, uma por linha.
  • Sem nome e e-mail configurados, o Git não deixa commitar (Please tell me who you are); sem nada preparado, não há o que commitar.
