Git log

Você já fez vários commits. Onde eles estão? O git log ("registro", "diário de bordo") abre o álbum: mostra os commits do ramo atual, do mais novo para o mais velho, com o código, o autor, a data e a mensagem de cada um. É o comando para responder "o que aconteceu neste projeto?", "quando isso mudou?" e "qual é o código daquele commit?".

Você vai aprender
  • A ler cada linha do git log, inclusive o (HEAD -> main).
  • A sair do histórico longo (o pager) com a tecla q.
  • As formas mais usadas: --oneline, -n, --stat, -p, --graph e --reverse.
  • A ver o histórico de um arquivo e a procurar por palavra na mensagem (--grep) e por autor (--author).
  • Os erros reais: repositório sem commits, ambiguous argument e not a git repository.

As saídas são reais, do Git 2.53 da máquina da Ana (Ubuntu 26.04), num terminal de verdade. A Ana fez cinco commits no repositório receitas, todos com a data fixa do laboratório do guia (15/10/2026, 10:30); na sua máquina, cada commit terá a data e a hora em que você o fez.

A ideia: o diário de bordo

Navios têm um diário de bordo: cada anotação tem data, quem escreveu e o que aconteceu, e a mais recente fica no fim do caderno. O git log é o diário do projeto, só que de trás para a frente: a anotação mais recente aparece primeiro, porque normalmente é ela que você quer ver.

(END)                                                             « aperte q para sair

Cada commit ocupa um bloco. Linha por linha:

commit e4dc8675c7066aa6015b13725c2d51e94dd0cb02
O hash do commit: o código de 40 caracteres que identifica este commit e nenhum outro (aula O Hash do Commit). Para se referir a ele, bastam os primeiros caracteres: e4dc867.
(HEAD -> main)
Uma etiqueta: o ramo main aponta para este commit, e o HEAD ("cabeça", "onde você está") aponta para o main. Em português: "este é o último commit do ramo em que você está". Ela só aparece no commit onde o ramo está; quando você fizer o próximo commit, ela "anda" para ele (aula O que é HEAD). Depois de ligar o repositório ao GitHub, aparecem outras etiquetas, como origin/main.
Author: Ana Souza <ana@exemplo.com>
"Autor": o nome e o e-mail configurados com o git config de quem fez o commit.
Date: Thu Oct 15 10:30:00 2026 -0300
"Data", sempre em inglês: Thu = quinta-feira (Thursday), Oct = outubro, 15, às 10:30:00, de 2026; -0300 é o fuso horário (3 horas a menos que o horário universal: o horário de Brasília).
a mensagem, recuada
A mensagem inteira, com 4 espaços na frente: título e, se houver, a linha em branco e o corpo (como no commit dos ovos).
(END)
"Fim": você chegou ao fim do histórico dentro do pager (próxima seção). Aperte q para voltar ao terminal.

O pager: como rolar e como sair

Quando o histórico não cabe na tela, o Git não despeja tudo de uma vez: ele abre a saída num pager (um "paginador", o programa less), que mostra uma tela por vez. Você percebe que está nele porque o prompt $ não volta: no rodapé aparece :, ou (END) quando chegou ao fim. Os comandos:

TeclaO que faz
qSai e volta ao terminal (de quit). A mais importante.
Espaço / bDesce / sobe uma tela.
↓ / ↑ (ou j / k)Desce / sobe uma linha.
/palavra EnterProcura a palavra (n vai para a próxima).

Quando a saída cabe na tela, o Git mostra tudo e devolve o prompt direto, sem pager. Para nunca usar o pager num comando, escreva git --no-pager log.

2. Uma linha por commit: --oneline

Na maior parte do tempo, o resumo basta:

$ git log --oneline
e4dc867 (HEAD -> main) Adiciona o e-mail de contato no README
ea0e4fa Corrige a quantidade de ovos do bolo
cce6adb Adiciona a receita de pudim
da810ac Adiciona a receita de bolo de cenoura
d84dc97 Adiciona o README

Cada linha tem o hash curto (7 caracteres), as etiquetas e o título da mensagem (o corpo não aparece). É aqui que um bom título faz diferença (aula Boas Mensagens de Commit).

3. Só os últimos: -n

Num projeto com centenas de commits, você quer ver só os últimos. -2 mostra os 2 mais recentes (qualquer número serve; a forma longa é -n 2 ou --max-count=2):

$ git log -2
commit e4dc8675c7066aa6015b13725c2d51e94dd0cb02 (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona o e-mail de contato no README

commit ea0e4fa83f1c338c65c14e143ca02e2de44b0e68
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Corrige a quantidade de ovos do bolo

    A receita da vó leva 4 ovos, não 3.
$ git log --oneline -3
e4dc867 (HEAD -> main) Adiciona o e-mail de contato no README
ea0e4fa Corrige a quantidade de ovos do bolo
cce6adb Adiciona a receita de pudim

O git log -1 (só o último commit) é muito usado para conferir o commit que você acabou de fazer.

4. Quais arquivos mudaram: --stat

$ git log --stat -2
commit e4dc8675c7066aa6015b13725c2d51e94dd0cb02 (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona o e-mail de contato no README

 README.md | 1 +                              « 1 linha acrescentada no README.md
 1 file changed, 1 insertion(+)

commit ea0e4fa83f1c338c65c14e143ca02e2de44b0e68
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Corrige a quantidade de ovos do bolo

    A receita da vó leva 4 ovos, não 3.

 bolo.txt | 2 +-                              « 1 linha trocada: 1 entrou (+), 1 saiu (-)
 1 file changed, 1 insertion(+), 1 deletion(-)

O --stat (de "estatística") acrescenta, embaixo de cada commit, os arquivos que ele mudou e quantas linhas: + para linhas acrescentadas, - para removidas. Uma linha modificada conta como uma removida e uma acrescentada (o 4 ovos substituiu o 3 ovos).

5. O que mudou, linha por linha: -p

O -p (de patch) mostra, embaixo de cada commit, as linhas exatas que ele mudou:

$ git log -p -1
commit e4dc8675c7066aa6015b13725c2d51e94dd0cb02 (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona o e-mail de contato no README

diff --git a/README.md b/README.md
index 2644316..bd4bba2 100644
--- a/README.md
+++ b/README.md
@@ -1 +1,2 @@
 # Receitas da Ana
+Contato: ana@exemplo.com                     « a linha que entrou

A linha com + é a que o commit acrescentou. Como ler cada linha desse bloco (diff, index, ---, +++, @@) está na aula git diff. Para ver um commit só, com essas mesmas informações, existe o git show. Sem o -1, o git log -p mostra o histórico inteiro com todas as mudanças, e quase sempre abre o pager.

6. Desenhando o histórico: --graph

$ git log --oneline --graph
* e4dc867 (HEAD -> main) Adiciona o e-mail de contato no README
* ea0e4fa Corrige a quantidade de ovos do bolo
* cce6adb Adiciona a receita de pudim
* da810ac Adiciona a receita de bolo de cenoura
* d84dc97 Adiciona o README

Cada * é um commit, ligado ao de baixo (o "pai" dele). Por enquanto o histórico é uma linha reta, e o desenho parece inútil. Quando você começar a usar ramos, aparecem os galhos (|, /, \), e o --graph vira indispensável: aula Vendo os Galhos.

Do mais velho para o mais novo: --reverse

$ git log --oneline --reverse
d84dc97 Adiciona o README
da810ac Adiciona a receita de bolo de cenoura
cce6adb Adiciona a receita de pudim
ea0e4fa Corrige a quantidade de ovos do bolo
e4dc867 (HEAD -> main) Adiciona o e-mail de contato no README

Bom para ler a história do projeto desde o começo, como um livro.

7. Procurando no histórico

O histórico de um arquivo

Ponha -- e o nome do arquivo no fim: só aparecem os commits que mudaram aquele arquivo.

$ git log --oneline -- bolo.txt
ea0e4fa Corrige a quantidade de ovos do bolo
da810ac Adiciona a receita de bolo de cenoura

O -- ("daqui em diante, só nomes de arquivos") é opcional quando o arquivo existe, mas evita confusão (veja Quando dá errado).

Por palavra na mensagem: --grep

$ git log --oneline --grep=pudim
cce6adb Adiciona a receita de pudim

Mostra os commits cuja mensagem contém a palavra (maiúsculas e minúsculas contam: Pudim não acha pudim, a não ser com -i). Mais um motivo para escrever boas mensagens.

Por autor: --author

$ git log --oneline --author=Ana
e4dc867 (HEAD -> main) Adiciona o e-mail de contato no README
ea0e4fa Corrige a quantidade de ovos do bolo
cce6adb Adiciona a receita de pudim
da810ac Adiciona a receita de bolo de cenoura
d84dc97 Adiciona o README

Aqui todos os commits são da Ana. Num projeto em dupla, --author=Bruno mostraria só os do Bruno. Filtros por data (--since), formatos personalizados e outras buscas estão em git log: Filtros e Formatos e Procurando no Histórico.

Formas diferentes

Quero…Comando
ver tudo, com detalhesgit log
uma visão geral rápidagit log --oneline
conferir o commit que acabei de fazergit log -1
saber quais arquivos cada commit mudougit log --stat
ver as linhas que mudaramgit log -p (ou git show para um commit)
ver os galhos dos ramosgit log --oneline --graph (com --all, todos os ramos)

As opções se combinam: git log --oneline --stat -3 -- bolo.txt funciona. Se você usa sempre a mesma combinação, crie um atalho (aula alias).

Quando dá errado

"does not have any commits yet" 
$ git log
fatal: your current branch 'main' does not have any commits yet

"O seu ramo atual, main, ainda não tem nenhum commit". O repositório acabou de ser criado com git init e o álbum está vazio. Como resolver: faça o primeiro commit (Seu Primeiro Commit).

"ambiguous argument" 
$ git log bolo
fatal: ambiguous argument 'bolo': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'
$ git log --oneline 3
fatal: ambiguous argument '3': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

"Argumento ambíguo: bolo não é uma revisão (um commit, ramo ou tag) conhecida nem um caminho que exista na pasta. Use -- para separar caminhos de revisões". No primeiro, faltou o .txt: o arquivo se chama bolo.txt. No segundo, a Ana queria os 3 últimos commits e esqueceu o tracinho: é -3, não 3. Como resolver: confira o nome do arquivo com ls (e use -- arquivo), e o número com o - na frente.

"not a git repository" 
$ cd ~
$ git log
fatal: not a git repository (or any of the parent directories): .git

Você está fora do repositório. Como resolver: cd receitas (a pasta do projeto).

O terminal "travou" depois do git log

Não travou: você está no pager (seção 1), e o rodapé mostra : ou (END). Aperte q. O Ctrl+C não sai do less.

O commit que acabei de fazer não aparece

O git log mostra só o histórico do ramo atual. Se o commit foi feito em outro ramo, ele não aparece aqui; confira o ramo na primeira linha do git status e veja todos os ramos com git log --oneline --graph --all (aula Vendo os Galhos). Confira também se o commit deu certo: um git commit sem nada preparado não cria commit nenhum.

Referência rápida

OpçãoO que faz

Resumo

  • git log mostra os commits do ramo atual, do mais novo para o mais velho: hash, etiquetas, autor, data e mensagem.
  • (HEAD -> main) marca o último commit do ramo em que você está.
  • Histórico longo abre no pager: Espaço desce, q sai.
  • --oneline resume, -N limita, --stat mostra os arquivos, -p mostra as linhas, --graph desenha.
  • -- arquivo, --grep=texto e --author=nome filtram o histórico.
