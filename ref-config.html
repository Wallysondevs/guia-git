Git Configurações (git config)

O Git tem centenas de configurações, mas quem está começando usa umas vinte. Esta página junta as que você vai encontrar nas aulas e em tutoriais: onde elas ficam guardadas, os comandos para ler, gravar e apagar, e as opções mais úteis, cada uma com o comando pronto para copiar. Tudo foi conferido no Git 2.53.0 da máquina da Ana (Ubuntu 26.04).

Como ler esta página
  • Toda configuração tem um nome em duas partes: seção.chave (user.name = a chave name da seção user). Maiúsculas e minúsculas no nome não importam: core.autocrlf e core.autoCRLF são a mesma coisa.
  • Na coluna "Comando", troque --global por nada (só aquele repositório) quando quiser que valha só num projeto.
  • Para entender cada assunto com calma, siga o link da coluna "Aula". A aula principal é Configurando Nome e E-mail; as dicas de dia a dia estão em Configurações Úteis.

Onde as configurações ficam (os níveis)

A mesma configuração pode estar em vários arquivos. O Git lê todos, do mais geral para o mais específico, e o último a falar vence: o que está no repositório passa por cima do que está na sua pasta pessoal, que passa por cima do que vale para o computador inteiro. É como as regras de uma escola: a regra da sala (local) vale mais que a da escola (global), que vale mais que a da prefeitura (sistema).

NívelOpçãoArquivoVale paraPrioridade
Sistema--system/etc/gitconfigTodos os usuários do computador (gravar exige sudo).a mais fraca
Global (do usuário)--global~/.gitconfig (ou ~/.config/git/config)Todos os repositórios da Ana.média
Local (do repositório)--local (o padrão ao gravar).git/config, dentro do projetoSó aquele repositório.forte
Da pasta de trabalho--worktree.git/config.worktreeSó uma pasta de trabalho extra (git worktree); raro.mais forte
Só neste comandogit -c chave=valor …nenhum (não grava)Só aquela execução.a mais forte de todas

Para ver de onde veio cada valor, peça a origem e o nível. Saída real, dentro do repositório receitas da Ana:

$ git config --list --show-origin
file:/home/ana/.gitconfig	user.name=Ana Souza          « do ~/.gitconfig (global)
file:/home/ana/.gitconfig	user.email=ana@exemplo.com
file:/home/ana/.gitconfig	init.defaultbranch=main     « o nome sai todo em minúsculas na lista
file:/home/ana/.gitconfig	core.editor=nano
file:.git/config	core.repositoryformatversion=0  « do .git/config (local): o git init escreveu estas
file:.git/config	core.filemode=true
file:.git/config	core.bare=false
file:.git/config	core.logallrefupdates=true
$ git config --list --show-scope
global	user.name=Ana Souza                       « o nível, em vez do arquivo
global	user.email=ana@exemplo.com
global	init.defaultbranch=main
global	core.editor=nano
local	core.repositoryformatversion=0
local	core.filemode=true
local	core.bare=false
local	core.logallrefupdates=true

Se a mesma chave aparecer duas vezes na lista (uma global, outra local), vale a última. Para perguntar só por uma chave e ver quem venceu: git config --show-scope user.email.

Comandos para ler, gravar e apagar

O git config tem duas formas de escrever. A clássica (opções como --get e --unset) funciona em qualquer Git e é a que você vai ver em quase todo tutorial. A nova, com subcomandos (git config get, git config set…), chegou no Git 2.46 e é mais fácil de ler. As duas fazem a mesma coisa; as aulas do guia usam a clássica.

ParaForma clássicaForma nova git 2.46+
Ler um valorgit config user.emailgit config get user.email
Ler e ver de que arquivo veiogit config --show-origin user.namegit config get --show-origin user.name
Ler e ver de que nível veiogit config --show-scope user.emailgit config get --show-scope user.email
Gravar só neste repositóriogit config user.email "ana@empresa.exemplo"git config set user.email "ana@empresa.exemplo"
Gravar para todos os seus repositóriosgit config --global core.editor nanogit config set --global core.editor nano
Listar tudogit config --list (ou -l)git config list
Listar um nível sógit config --global --listgit config list --global
Listar com arquivo e nívelgit config --list --show-origin --show-scopegit config list --show-origin --show-scope
Procurar pelo nome (expressão regular)git config --get-regexp '^user'git config get --all --show-names --regexp '^user'
Apagargit config --global --unset core.editorgit config unset --global core.editor
Acrescentar mais um valor à mesma chavegit config --global --add safe.directory /srv/sitegit config set --global --append safe.directory /srv/site
Ler todos os valores de uma chave repetidagit config --get-all safe.directorygit config get --all safe.directory
Abrir o arquivo no editorgit config --global --edit (ou -e)git config edit --global
Usar um valor só uma vez, sem gravargit -c core.pager=cat log (o -c vem antes do subcomando)

Saída real das duas formas, lado a lado. Repare que gravar e apagar não mostram nada quando dá certo: o silêncio é o sucesso.

$ git config user.email
ana@exemplo.com
$ git config get user.email                « a forma nova: mesma resposta
ana@exemplo.com
$ git config --show-origin user.name
file:/home/ana/.gitconfig	Ana Souza
$ git config set user.email ana@empresa.exemplo   « grava no .git/config (local)
$ git config user.email
ana@empresa.exemplo                        « o local venceu o global
$ git config --show-scope user.email
local	ana@empresa.exemplo
$ git config --unset user.email            « apaga do local: volta a valer o global
$ git config user.email
ana@exemplo.com
$ git -c user.name="Teste" config user.name
Teste                                      « só nesta execução
$ git config get --all --show-names --regexp '^user'
user.name Ana Souza
user.email ana@exemplo.com

Quando a chave não existe, a leitura não escreve nada e termina com código de saída 1; apagar algo que não existe termina com 5. Isso é útil em scripts ($?):

$ git config pull.rebase
$ echo $?
1                                          « 1 = essa chave não está configurada
$ git config --global --unset core.pager
$ echo $?
5                                          « 5 = não havia o que apagar

Um .gitconfig pronto para começar

Depois de rodar os comandos acima com --global, o arquivo ~/.gitconfig da Ana fica assim (o Git escreve com TAB no começo das linhas). Você pode abrir e editar o arquivo direto, com git config --global --edit: é texto simples.

$ git config --global pull.rebase false
$ git config --global push.autoSetupRemote true
$ git config --global fetch.prune true
$ git config --global merge.conflictStyle zdiff3
$ git config --global core.autocrlf input
$ git config --global alias.st status
$ git config --global alias.arvore "log --oneline --graph --all"
$ git config --global color.ui auto
$ cat ~/.gitconfig
[user]                                     « [seção]
	name = Ana Souza                       « chave = valor
	email = ana@exemplo.com
[init]
	defaultBranch = main
[core]
	editor = nano
	autocrlf = input                       « mesma seção: o Git junta embaixo dela
[pull]
	rebase = false
[push]
	autoSetupRemote = true
[fetch]
	prune = true
[merge]
	conflictStyle = zdiff3
[alias]
	st = status
	arvore = log --oneline --graph --all
[color]
	ui = auto

Uma configuração de três partes, como branch.main.remote, vira uma seção com o nome do meio entre aspas: [branch "main"] e, embaixo, remote = origin.

Cuidado com o que vai para o .gitconfig

Nunca grave senha ou token numa configuração (por exemplo, dentro de remote.origin.url, como https://usuario:token@…): o .git/config e o ~/.gitconfig são texto puro e vão parar em backups e capturas de tela. Use um credential.helper ou SSH. Veja HTTPS e Token e Commitei uma Senha!.

Quando dá errado

O nome ficou só "Ana"

$ git config user.name Ana Souza
$ git config --list --show-scope
…
local	user.name=Ana                      « cadê o "Souza"?

O que aconteceu: sem aspas, o terminal separou Ana e Souza em duas palavras. O Git gravou Ana como valor e entendeu Souza como outra coisa (um filtro de valor antigo, da forma clássica), sem reclamar.

Como resolver: grave de novo, com aspas: git config user.name "Ana Souza". Regra: valor com espaço vai sempre entre aspas.

error: key does not contain a section

$ git config nome
error: key does not contain a section: nome

O que aconteceu: toda chave tem a forma seção.chave; nome não tem o ponto. ("key does not contain a section" = "a chave não contém uma seção".)

Como resolver: use o nome completo: user.name, core.editor… Na dúvida, liste: git config --list.

fatal: bad boolean config value

$ git config core.autocrlf banana
$ git status
fatal: bad boolean config value 'banana' for 'core.autocrlf'

O que aconteceu: o git config grava qualquer valor sem conferir. O erro só aparece depois, quando algum comando precisa ler a configuração ("bad boolean config value" = "valor de configuração verdadeiro/falso inválido"). Até corrigir, o git status, o git log e outros comandos param com a mesma mensagem.

Como resolver: apague a chave com git config --unset core.autocrlf (o git config continua funcionando) ou grave um valor válido (true, false ou input). A mensagem diz o nome da chave; o git config --list --show-origin diz em que arquivo ela está.

error: no action specified

$ git config
error: no action specified

O que aconteceu: faltou dizer o que fazer ("nenhuma ação especificada"). Como resolver: diga a chave, ou --list, ou um subcomando (get, set, list…).
