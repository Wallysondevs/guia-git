Git log: Filtros e Formatos

No começo, o git log cabe numa tela. Depois de um mês de trabalho, a lista tem dezenas de commits; depois de um ano, centenas. Aí as perguntas mudam: "quais commits o Bruno fez?", "quando foi que mexemos na receita do bolo?", "o que entrou desde segunda-feira?". O git log responde a todas elas com filtros (que escolhem quais commits aparecem) e formatos (que escolhem como cada commit aparece).

Você vai aprender
  • A limitar a quantidade de commits: -n 3 ou só -3.
  • A escolher o formato: --oneline, --stat, --name-only e o --format feito sob medida (%h %an %s).
  • A filtrar por pessoa (--author), por palavra na mensagem (--grep) e por arquivo (-- bolo.txt).
  • A filtrar por data com --since e --until, e as pegadinhas das datas.
  • Os erros mais comuns: ambiguous argument, not an integer e o filtro que "não acha nada".

Todas as saídas desta aula saíram do Git do Ubuntu 26.04 (2.53) na máquina da Ana. Repare que a Ana e o Bruno fizeram os commits das receitas todos na mesma manhã (15/10/2026, às 10:30): isso vai importar na parte das datas.

A ideia: a galeria de fotos do celular

Pense na galeria de fotos do seu celular. Com 5 fotos, você rola a tela e acha tudo. Com 5 mil, você usa a busca: "fotos com a vovó", "fotos de dezembro", "fotos da praia". E pode escolher o jeito de ver: miniaturas pequenas (cabe muita coisa) ou uma foto por vez, grande, com todos os detalhes.

O git log funciona igual. Os filtros são a busca (por pessoa, por data, por palavra, por arquivo) e os formatos são as miniaturas ou a foto grande. E dá para combinar: "os commits do Bruno, em miniatura, só do arquivo do pão de queijo".

O histórico desta aula

A Ana e o Bruno estão fazendo juntos o site de receitas. Este é o histórico completo, uma linha por commit (o --oneline que você já viu em git log):

$ git log --oneline
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
b70de85 Corrige erro de digitação no pão de queijo
9d984ae Adiciona a cobertura de chocolate ao bolo
cbe9c2c Cria a página inicial
b97da56 Corrige o tempo de forno do bolo
e2542b6 Adiciona a receita de pão de queijo
906c89d Adiciona a receita de bolo de cenoura
700bbd5 Cria o README

São 8 commits, do mais novo (em cima) para o mais antigo (embaixo). O (HEAD -> main) no primeiro é uma etiqueta que o Git mostra no terminal: "você está no branch main, e este é o último commit dele" (mais sobre ela em Vendo os Galhos). Três deles foram feitos pelo Bruno, mas o --oneline não mostra o autor. Vamos descobrir quais são.

1. Quantos commits mostrar: -n

O jeito mais simples de "filtrar" é pedir só os últimos commits. A opção -n recebe um número:

$ git log --oneline -n 2
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
b70de85 Corrige erro de digitação no pão de queijo
git log
Mostra o histórico, do commit mais novo para o mais antigo.
--oneline
Formato: uma linha por commit (o hash curto e a primeira linha da mensagem).
-n 2
Filtro: só os 2 commits mais recentes. O nome longo é --max-count=2, e o atalho é só -2.

As três formas dão o mesmo resultado: -n 2, -2 e --max-count=2. O atalho com o número grudado no traço é o mais usado. Sem o --oneline, você vê os commits completos, no formato normal:

$ git log -3
commit c0ecf7737a483172e7e6d40cc08e6129be2ef0a6 (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona a receita de brigadeiro

commit b70de8519b13e2413511f72f00cd13f8e7ea76f0
Author: Bruno Lima <bruno@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Corrige erro de digitação no pão de queijo

commit 9d984ae2cac68edfa9180c6a2ac0031461de07b3
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona a cobertura de chocolate ao bolo

Repare que as palavras Author: (autor) e Date: (data) e a data em si (Thu Oct 15 = quinta-feira, 15 de outubro) continuam em inglês, mesmo com o Git em português: essas partes do git log não são traduzidas. Já o segundo commit é do Bruno: achamos o primeiro.

Do mais antigo para o mais novo: --reverse

Para ler a história "como um livro", do primeiro commit para o último, acrescente --reverse (ao contrário):

$ git log --oneline --reverse
700bbd5 Cria o README
906c89d Adiciona a receita de bolo de cenoura
e2542b6 Adiciona a receita de pão de queijo
b97da56 Corrige o tempo de forno do bolo
cbe9c2c Cria a página inicial
9d984ae Adiciona a cobertura de chocolate ao bolo
b70de85 Corrige erro de digitação no pão de queijo
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
O git log que "trava" a tela

No seu terminal, quando o histórico não cabe na tela, o Git o mostra dentro de um paginador (o programa less): use as setas ou o espaço para rolar e aperte q para sair. O -n é uma boa forma de nem precisar dele. As saídas desta aula aparecem inteiras, sem o paginador.

2. Escolhendo o formato

O formato normal (o de cima) é a "foto grande": tudo sobre cada commit. O --oneline é a "miniatura". Entre os dois, há vários outros.

Quais arquivos cada commit mexeu: --stat e --name-only

$ git log --oneline --stat -2
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
 brigadeiro.txt | 2 ++
 1 file changed, 2 insertions(+)
b70de85 Corrige erro de digitação no pão de queijo
 pao-de-queijo.txt | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
--stat
De statistics (estatísticas): depois de cada commit, a lista dos arquivos que ele mudou.
brigadeiro.txt | 2 ++
O arquivo, o número de linhas mexidas e um "gráfico" com um + por linha acrescentada e um - por linha apagada.
1 file changed, 2 insertions(+)
O resumo, em inglês: "1 arquivo mudou, 2 linhas acrescentadas". No segundo commit, 1 insertion(+), 1 deletion(-): uma linha saiu e outra entrou, que é como o Git enxerga uma linha alterada (o Pao virou Pão).

Se você só quer os nomes dos arquivos, sem as contas, use --name-only:

$ git log --name-only --oneline -3
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
brigadeiro.txt
b70de85 Corrige erro de digitação no pão de queijo
pao-de-queijo.txt
9d984ae Adiciona a cobertura de chocolate ao bolo
bolo.txt

O formato sob medida: --format

Quer ver o autor na mesma linha do --oneline? Monte a linha você mesmo com --format (ou --pretty=format:, o nome antigo). Você escreve um "molde" e o Git troca cada código % por uma informação do commit:

$ git log --format='%h %an %s'
c0ecf77 Ana Souza Adiciona a receita de brigadeiro
b70de85 Bruno Lima Corrige erro de digitação no pão de queijo
9d984ae Ana Souza Adiciona a cobertura de chocolate ao bolo
cbe9c2c Bruno Lima Cria a página inicial
b97da56 Ana Souza Corrige o tempo de forno do bolo
e2542b6 Bruno Lima Adiciona a receita de pão de queijo
906c89d Ana Souza Adiciona a receita de bolo de cenoura
700bbd5 Ana Souza Cria o README
--format='…'
O molde de cada linha. As aspas simples são para o terminal entregar o molde inteiro, com os espaços, ao Git.
%h
O hash curto do commit (c0ecf77). Com %H (maiúsculo), o hash completo de 40 caracteres.
%an
O nome do autor (author name): quem escreveu a mudança.
%s
O assunto (subject): a primeira linha da mensagem.

Agora está claro: os commits do Bruno são b70de85, cbe9c2c e e2542b6. O que não é código % sai do jeito que você escreveu, então dá para pôr separadores e a data:

$ git log --format='%h | %ad | %an | %s' -3
c0ecf77 | Thu Oct 15 10:30:00 2026 -0300 | Ana Souza | Adiciona a receita de brigadeiro
b70de85 | Thu Oct 15 10:30:00 2026 -0300 | Bruno Lima | Corrige erro de digitação no pão de queijo
9d984ae | Thu Oct 15 10:30:00 2026 -0300 | Ana Souza | Adiciona a cobertura de chocolate ao bolo
$ git log --format='%h %ad %s' --date=short -3
c0ecf77 2026-10-15 Adiciona a receita de brigadeiro
b70de85 2026-10-15 Corrige erro de digitação no pão de queijo
9d984ae 2026-10-15 Adiciona a cobertura de chocolate ao bolo

O %ad é a data do autor (author date), e o --date=short a deixa curta, no formato ano-mês-dia. Os códigos mais úteis:

CódigoO que viraExemplo (do lab)
%h / %Hhash curto / completoc0ecf77 / c0ecf7737a483172e7e6d40cc08e6129be2ef0a6
%annome do autorAna Souza
%aee-mail do autorana@exemplo.com
%addata do autor (muda com --date=short, --date=iso…)Thu Oct 15 10:30:00 2026 -0300
%ardata relativa ("há quanto tempo")0 seconds ago (no lab, o relógio parou na hora do commit)
%sassunto (primeira linha da mensagem)Adiciona a receita de brigadeiro
%cnnome de quem gravou o commit (committer; quase sempre igual ao autor)Ana Souza

Um exemplo com o e-mail entre parênteses:

$ git log --format='%h %an (%ae) %s' -1
c0ecf77 Ana Souza (ana@exemplo.com) Adiciona a receita de brigadeiro
Por que não sai "há 2 dias"?

Na máquina da Ana, o relógio está parado em 15/10/2026 10:30, a mesma hora dos commits: por isso o %ar mostrou 0 seconds ago ("0 segundos atrás"). No seu computador, com commits de dias diferentes, aparece algo como 3 days ago ou 2 weeks ago (o Git 2.53 do Ubuntu mostrou essas datas relativas em inglês).

Missão: o repositório de receitas da Ana já está pronto. Mostre o histórico com o hash curto, o nome do autor e a mensagem em cada linha (use --format), e descubra quantos commits são do Bruno.

3. Por pessoa: --author

Ler o histórico inteiro procurando o nome do Bruno funciona com 8 commits, mas não com 800. Peça ao Git:

$ git log --oneline --author=Bruno
b70de85 Corrige erro de digitação no pão de queijo
cbe9c2c Cria a página inicial
e2542b6 Adiciona a receita de pão de queijo
--author=Bruno
Só os commits cujo autor contém o texto Bruno. O Git procura no nome e no e-mail juntos (Bruno Lima <bruno@exemplo.com>), então não precisa escrever o nome inteiro.

Como o Git procura também no e-mail, até --author=bruno (minúsculo) achou os mesmos 3 commits: o bruno estava no bruno@exemplo.com. Mas cuidado: a busca diferencia maiúsculas de minúsculas. Para ignorar essa diferença de verdade, use -i (de ignore case):

$ git log --oneline -i --author=bruno
b70de85 Corrige erro de digitação no pão de queijo
cbe9c2c Cria a página inicial
e2542b6 Adiciona a receita de pão de queijo

E dá para juntar com o -n: "os 2 últimos commits da Ana":

$ git log --oneline -2 --author=Ana
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
9d984ae Adiciona a cobertura de chocolate ao bolo

O -2 vale depois do filtro: o Git separa os commits da Ana e mostra os 2 primeiros deles (o commit do Bruno no meio, b70de85, foi pulado).

Missão: mostre, uma linha por commit, só os commits feitos pelo Bruno.

4. Por palavra na mensagem: --grep

A Ana quer tudo o que já foi feito na receita do bolo. Se as mensagens são boas (veja Boas Mensagens de Commit), basta procurar a palavra "bolo" nelas:

$ git log --oneline --grep=bolo
9d984ae Adiciona a cobertura de chocolate ao bolo
b97da56 Corrige o tempo de forno do bolo
906c89d Adiciona a receita de bolo de cenoura
--grep=bolo
Só os commits cuja mensagem contém bolo. O nome vem do comando grep, o "procurador de texto" do terminal. Como no grep, o texto pode ser uma expressão regular (--grep='^Corrige' = mensagens que começam com "Corrige").

Aqui as maiúsculas fazem diferença de verdade: --grep=Bolo não acha nada, porque nenhuma mensagem tem "Bolo" com B maiúsculo. O -i resolve:

$ git log --oneline --grep=Bolo
$ git log --oneline -i --grep=Bolo
9d984ae Adiciona a cobertura de chocolate ao bolo
b97da56 Corrige o tempo de forno do bolo
906c89d Adiciona a receita de bolo de cenoura

Repare que o primeiro comando não mostrou nada, nem um aviso. Para o Git, "nenhum commit combina" não é um erro: é só uma lista vazia.

Várias palavras: "ou" e "e"

Com dois --grep, o Git mostra os commits que têm uma ou outra palavra:

$ git log --oneline --grep=bolo --grep=brigadeiro
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
9d984ae Adiciona a cobertura de chocolate ao bolo
b97da56 Corrige o tempo de forno do bolo
906c89d Adiciona a receita de bolo de cenoura

Para exigir as duas palavras na mesma mensagem, acrescente --all-match ("todas precisam combinar"). "Commits que adicionam algo ao bolo":

$ git log --oneline --grep=Adiciona --grep=bolo --all-match
9d984ae Adiciona a cobertura de chocolate ao bolo
906c89d Adiciona a receita de bolo de cenoura
--grep procura na mensagem, não no arquivo

O --grep só olha o texto que você escreveu no git commit -m. Para achar o commit que acrescentou ou tirou uma palavra de dentro de um arquivo (por exemplo, quando "manteiga" sumiu da receita), o filtro é outro, o -S: veja Procurando no Histórico.

5. Por arquivo: git log -- arquivo

Outra forma de responder "o que aconteceu com o bolo?" é perguntar pelo arquivo, não pela mensagem. Ponha o nome do arquivo no fim, depois de dois traços:

$ git log --oneline -- bolo.txt
9d984ae Adiciona a cobertura de chocolate ao bolo
b97da56 Corrige o tempo de forno do bolo
906c89d Adiciona a receita de bolo de cenoura
--
Dois traços sozinhos querem dizer: "daqui em diante, só vêm nomes de arquivos". Eles evitam que o Git confunda o nome de um arquivo com o nome de um branch ou de um commit.
bolo.txt
Só os commits que mudaram esse arquivo (criaram, alteraram ou apagaram). Dá para pôr mais de um: -- bolo.txt index.html, ou uma pasta inteira.

Funciona mesmo que a mensagem do commit não diga nada sobre o arquivo: o Git olha o que mudou de verdade. Com o arquivo que já existe, o -- é opcional (git log --oneline bolo.txt deu a mesma lista), mas com ele você nunca cai no erro da seção Quando dá errado.

Com dois arquivos, aparecem os commits que mexeram em qualquer um deles:

$ git log --oneline -- bolo.txt index.html
9d984ae Adiciona a cobertura de chocolate ao bolo
cbe9c2c Cria a página inicial
b97da56 Corrige o tempo de forno do bolo
906c89d Adiciona a receita de bolo de cenoura

Missão: mostre só os commits que mexeram no arquivo pao-de-queijo.txt. (Dica: o Tab completa o nome do arquivo.)

6. Por data: --since e --until

"O que entrou desde o dia 1º?" e "o que já existia até o dia 14?" se perguntam com:

  • --since=DATA ("desde"; o sinônimo é --after, "depois de"): commits feitos a partir dessa data;
  • --until=DATA ("até"; o sinônimo é --before, "antes de"): commits feitos até essa data.

Primeiro, no repositório das receitas. Lembre-se: os 8 commits foram feitos em 15/10/2026, às 10:30. Veja o que cada filtro devolve:

$ git log --oneline --since="2026-10-15 00:00" -2
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
b70de85 Corrige erro de digitação no pão de queijo
$ git log --oneline --since="2026-10-15 11:00"
$ git log --oneline --since=2026-10-16
$ git log --oneline --until="2026-10-14 23:59"
$ git log --oneline --after=2026-10-01 --before=2026-10-31 -2
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
b70de85 Corrige erro de digitação no pão de queijo
--since="2026-10-15 00:00"
Desde a meia-noite do dia 15: os commits das 10:30 entram (o -2 mostra só os 2 primeiros).
--since="2026-10-15 11:00"
Desde as 11 horas do dia 15: nada, porque tudo foi feito antes, às 10:30.
--since=2026-10-16
Desde o dia 16: nada, nenhum commit é tão novo.
--until="2026-10-14 23:59"
Até o fim do dia 14: nada, nenhum commit é tão velho.
--after=… --before=…
Os dois juntos fazem um intervalo: "commits de outubro".

O formato mais seguro para a data é ano-mês-dia (2026-10-15), com a hora opcional depois de um espaço. Quando tem espaço, use aspas.

A pegadinha da data sem hora

Quando você escreve só o dia (--since=2026-10-15), o Git completa a hora com a hora atual do relógio, e não com a meia-noite. Na máquina da Ana, o relógio marcava 10:30, então --since=2026-10-15 virou "desde 15/10 às 10:30" e mostrou os 8 commits. Se ela rodasse o mesmo comando às 16h, os commits das 10:30 ficariam de fora. Para não depender do relógio, escreva a hora: --since="2026-10-15 00:00".

Datas relativas: "2 weeks ago", "yesterday"

O Git também entende datas contadas a partir de agora, em inglês: "2 weeks ago" (2 semanas atrás), "3 days ago", "1 hour ago", yesterday (ontem). Na máquina da Ana, com o relógio em 15/10 às 10:30:

$ git log --oneline --since="1 hour ago" -2
c0ecf77 (HEAD -> main) Adiciona a receita de brigadeiro
b70de85 Corrige erro de digitação no pão de queijo
$ git log --oneline --until="1 hour ago"
$ git log --oneline --until=yesterday

"Desde 1 hora atrás" (desde as 9:30) pega os commits das 10:30; "até 1 hora atrás" e "até ontem" não pegam nenhum.

"ontem" não funciona, e o Git não avisa

As palavras das datas são só em inglês. Com uma palavra que não conhece, o Git não dá erro: ele usa a hora atual no lugar. Na máquina da Ana, --until=ontem mostrou os 8 commits (deveria mostrar nenhum, como o --until=yesterday acima). Se um filtro de data "não filtrou nada", confira se a data está em inglês ou no formato 2026-10-15.

Com commits de dias diferentes

No seu repositório, os commits vão ter datas diferentes, e é aí que o --since brilha. A Ana tem um segundo repositório, o do TCC, onde ela fez um commit por noite, de 1º a 8 de outubro:

$ git log --format='%h %ad %s' --date=short
5de2ba1 2026-10-08 Corrige a formatação
d4c1dbc 2026-10-07 Escreve a conclusão
edf9e22 2026-10-06 Adiciona as referências
511c1a3 2026-10-05 Escreve os resultados
f9632c5 2026-10-04 Revisa a introdução
b0e25d9 2026-10-03 Adiciona a metodologia
7320fc7 2026-10-02 Escreve a introdução
abeba2a 2026-10-01 Cria o sumário
$ git log --oneline --since="2026-10-06 00:00"
5de2ba1 (HEAD -> main) Corrige a formatação
d4c1dbc Escreve a conclusão
edf9e22 Adiciona as referências
$ git log --oneline --until="2026-10-03 23:59"
b0e25d9 Adiciona a metodologia
7320fc7 Escreve a introdução
abeba2a Cria o sumário
$ git log --oneline --since="2026-10-03 00:00" --until="2026-10-05 23:59"
511c1a3 Escreve os resultados
f9632c5 Revisa a introdução
b0e25d9 Adiciona a metodologia

"Desde o dia 6" trouxe os 3 últimos; "até o dia 3", os 3 primeiros; e o intervalo "do dia 3 ao dia 5", os 3 do meio. Com datas relativas, contadas a partir do relógio (15/10, 10:30):

$ git log --format='%h %ar %s' -3
5de2ba1 7 days ago Corrige a formatação
d4c1dbc 8 days ago Escreve a conclusão
edf9e22 9 days ago Adiciona as referências
$ git log --oneline --since="1 week ago"
5de2ba1 (HEAD -> main) Corrige a formatação

"1 semana atrás" é 08/10 às 10:30. O commit do dia 8 foi feito à noite, depois disso, e entrou; o do dia 7 ficou de fora. O %ar mostra a idade de cada commit, em inglês (7 days ago = "7 dias atrás").

E no terminal do guia?

No terminal simulado do guia, como no laboratório, todos os commits que você fizer ganham a mesma data e hora (15/10/2026 10:30). Por isso, pratique os filtros de data no Git do seu computador, com um repositório de verdade.

7. Combinando filtros

Filtros de tipos diferentes se somam como um "e": o commit precisa passar em todos. "Os commits do Bruno, desde 1º de outubro, no arquivo do pão de queijo":

$ git log --oneline --author=Bruno --since=2026-10-01 -- pao-de-queijo.txt
b70de85 Corrige erro de digitação no pão de queijo
e2542b6 Adiciona a receita de pão de queijo

E "os commits da Ana que falam de bolo":

$ git log --oneline --author=Ana --grep=bolo
9d984ae Adiciona a cobertura de chocolate ao bolo
b97da56 Corrige o tempo de forno do bolo
906c89d Adiciona a receita de bolo de cenoura

A ordem das opções não importa, com uma exceção: os nomes de arquivos vão sempre no fim, depois do --. A única combinação que vira "ou" é repetir a mesma opção (dois --grep, dois --author), como você viu na seção 4.

Missão: mostre só os commits da Ana que mexeram no arquivo bolo.txt (ou, se preferir, que falam de "bolo" na mensagem).

Formas diferentes de fazer a mesma coisa

A pergunta "o que aconteceu com o bolo?" tem pelo menos três respostas, e cada uma enxerga uma coisa:

ComandoO que ele olhaQuando usar
git log --oneline --grep=boloAs mensagensQuando as mensagens são boas e dizem o assunto
git log --oneline -- bolo.txtOs arquivos mudadosQuando você sabe qual arquivo é (mais confiável: não depende da mensagem)
git log --oneline -S manteigaO conteúdo dos arquivosQuando você procura quem pôs ou tirou um texto (aula Procurando no Histórico)

E para ver quem fez cada commit:

ComandoResultado
git logTudo, em várias linhas por commit (com Author:)
git log --format='%h %an %s'Uma linha por commit, com o nome do autor
git log --oneline --author=BrunoSó os commits de uma pessoa
git shortlog -sUm placar: quantos commits cada pessoa fez (veja Referência: log)
Cansou de digitar o formato?

Um --format que você usa todo dia pode virar um apelido, como git config --global alias.historico "log --format='%h %an %s'". Depois, é só git historico. Veja Apelidos (alias).

Quando dá errado

As mensagens de erro abaixo saíram como no Git do Ubuntu: umas em português, outras em inglês, porque a tradução do Git no Ubuntu é parcial (a aula Seu Primeiro Commit explica).

fatal: ambiguous argument: o arquivo que não existe (mais) 
$ git log --oneline bolo
fatal: ambiguous argument 'bolo': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

O que aconteceu: a Ana esqueceu o .txt. Sem o --, o Git tentou adivinhar o que é bolo: não é um commit nem um branch ("unknown revision", revisão desconhecida) e não é um arquivo da pasta ("path not in the working tree"). As duas linhas de baixo são a dica, em inglês: "use -- para separar commits de arquivos, assim: git <comando> [<commit>...] -- [<arquivo>...]".

Como confirmar: ls mostra os nomes certos dos arquivos.

Como resolver: escreva o nome certo (bolo.txt). E se o arquivo existiu no passado mas foi apagado, aí o -- é obrigatório: git log --oneline -- receita-velha.txt mostra o histórico dele mesmo sem ele estar mais na pasta. Com um nome que nunca existiu, o -- só troca o erro por uma lista vazia (git log --oneline -- bolo não mostrou nada).

O filtro não mostrou nada 
$ git log --oneline --author=Carla
$ echo $?
0

O que aconteceu: nenhum commit combinou com o filtro. Para o Git, isso não é erro (o código de saída é 0, "deu certo"): a resposta é só uma lista vazia.

Como resolver: confira o texto do filtro. Os suspeitos de sempre são: maiúsculas (--grep=Bolo não acha "bolo": use -i), o nome do autor (veja como ele aparece com git log --format='%an'), a data (a pegadinha da hora atual e as palavras em português) e o branch: o git log só olha o branch atual.

error: -n requires an argument e not an integer 
$ git log -n
error: -n requires an argument
$ git log --oneline -n tres
fatal: 'tres': not an integer

O que aconteceu: o -n precisa de um número logo depois. No primeiro, faltou o número ("-n exige um argumento"); no segundo, o número veio por extenso ("'tres': não é um número inteiro").

Como resolver: git log -n 3 ou só git log -3.

fatal: argumento não reconhecido 
$ git log --autor=Bruno
fatal: argumento não reconhecido: --autor=Bruno

O que aconteceu: as opções do Git são em inglês: é --author, com "h". O Git não conhece --autor e para sem mostrar nada.

Como resolver: git log --author=Bruno. Na dúvida sobre o nome de uma opção, git help log mostra o manual (veja git help).

Referência rápida

OpçãoO que faz
-n 5, -5, --max-count=5Só os 5 commits mais recentes
--reverseDo mais antigo para o mais novo
--onelineUma linha por commit

--format='%h %an %s'Formato sob medida (%h hash, %an autor, %ae e-mail, %ad data, %s mensagem)

Exercícios

1. Complete o comando

Mostre, uma linha por commit, só os 4 commits mais recentes:

git log

2. Só os commits da Carla

Complete para mostrar só os commits da Carla:

git log --oneline

3. A Ana quer ver os commits que mudaram o arquivo index.html. Qual comando?

4. git log --oneline --grep=Bolo não mostrou nada, mas há commits com "bolo" na mensagem. Por quê?

5. No formato --format='%h %an %s', o que o %an mostra?

6. São 16h. Os commits foram feitos hoje às 10h. O que mostra git log --since=ontem?

Resumo

  • Filtros escolhem quais commits aparecem; formatos escolhem como cada um aparece. Dá para misturar os dois.
  • -3 (ou -n 3) mostra só os últimos 3; --reverse inverte a ordem.
  • --oneline, --stat, --name-only e --format='%h %an %s' mudam o jeito de ver. As palavras Author: e Date: não são traduzidas.
  • --author=Bruno filtra por pessoa (nome ou e-mail); --grep=bolo filtra pela mensagem; -i ignora maiúsculas; dois --grep = "ou", com --all-match = "e".
  • git log -- arquivo mostra só os commits que mudaram o arquivo. Os nomes de arquivos vão no fim, depois do --.
  • --since/--until filtram por data: prefira "2026-10-15 00:00" (sem hora, o Git usa a hora atual) e palavras em inglês (yesterday, "2 weeks ago").
  • Filtro sem resultado não é erro: o Git só mostra uma lista vazia.
