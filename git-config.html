Git Configurando Nome e E-mail (git config)

Cada commit leva o nome e o e-mail de quem o fez. Por isso, a primeira coisa a fazer num Git recém-instalado é se apresentar a ele. Sem isso, o primeiro commit falha com um "Please tell me who you are" ("por favor, me diga quem você é"). Nesta aula você vai ver esse erro de verdade, configurar o Git uma vez para sempre com git config e saber onde essa configuração fica guardada.

Você vai aprender
  • Configurar o nome (user.name) e o e-mail (user.email) com git config --global.
  • Ler a mensagem "Please tell me who you are" e resolvê-la.
  • Conferir a configuração e saber onde ela fica (~/.gitconfig).
  • A diferença entre a configuração global (sua) e a do repositório.
  • Duas configurações úteis desde o começo: init.defaultBranch e core.editor.

A ideia: assinar o caderno do laboratório

No caderno de um laboratório, cada anotação tem a assinatura de quem a fez. O Git é igual: cada commit guarda um autor, com nome e e-mail. Quando a Ana e o Bruno trabalharem juntos, é assim que se sabe quem fez o quê. O Git não inventa a sua assinatura: você precisa dizê-la uma vez, e ele a usa em todos os commits dali em diante.

Configurando nome e e-mail

A Ana segue a dica do próprio Git:

$ git config --global user.name "Ana Souza"
$ git config --global user.email ana@exemplo.com
git config
O subcomando que lê e grava configurações do Git.
--global
"Para mim, em todos os repositórios": grava no arquivo de configuração da sua usuária.
user.name
O nome da configuração: seção user ("usuário"), chave name ("nome").
"Ana Souza"
O valor. As aspas são obrigatórias quando o valor tem espaço (veja "Quando dá errado").

Nada aparece: no terminal, silêncio quase sempre quer dizer "deu certo". Para conferir, rode o mesmo comando sem o valor: ele mostra o que está gravado.

$ git config --global user.name
Ana Souza
$ git config user.email
ana@exemplo.com

Agora o mesmo commit funciona:

$ git commit -m 'Cria o README'
[master (root-commit) 700bbd5] Cria o README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
$ git log
commit 700bbd5eb7964a024ce4076aeeb11c490e1bac2e
Author: Ana Souza <ana@exemplo.com>          « o nome e o e-mail que ela configurou
Date:   Thu Oct 15 10:30:00 2026 -0300

    Cria o README

O master na primeira linha é o nome do ramo: como este Git ainda não tinha a configuração init.defaultBranch quando o repositório foi criado, ele usou o nome antigo. Você vai configurar isso daqui a pouco.

Que e-mail usar?

O e-mail vai dentro de cada commit, e quem puder ver o repositório pode ler. Se o repositório for público no GitHub, ele fica público. Use o mesmo e-mail da sua conta do GitHub (assim ele liga os commits ao seu perfil) ou o endereço noreply que o GitHub oferece para manter o seu e-mail privado (aula Criando a Conta no GitHub).

Missão: alguém configurou o nome da Ana só como "Ana". Confira com git config --global user.name, corrija para "Ana Souza" (com aspas!) e confira de novo.

Onde a configuração fica guardada

O --global grava num arquivo de texto comum, na sua pasta pessoal: ~/.gitconfig (oculto, porque começa com ponto). Dá para ver com o cat:

$ cat ~/.gitconfig
[user]
	name = Ana Souza
	email = ana@exemplo.com

Entre colchetes fica a seção ([user]); embaixo, as chaves com os valores. Por isso o nome completo da configuração é user.name: seção, ponto, chave. Para ver tudo de uma vez, no formato seção.chave=valor:

$ git config --global --list
user.name=Ana Souza
user.email=ana@exemplo.com

Os três níveis

O Git lê configurações de três lugares. Quando o mesmo nome aparece em mais de um, vale o mais específico (o de baixo na tabela):

NívelOpçãoArquivoVale para
Sistema--system/etc/gitconfigTodos os usuários do computador (raro mexer).
Global--global~/.gitconfigVocê, em todos os seus repositórios. O mais usado.
Repositório--local (ou nada).git/config, dentro do repositórioSó aquele repositório.

Um caso real: a Ana usa o e-mail pessoal em tudo, mas no repositório do trabalho quer o e-mail da empresa. Dentro da pasta desse repositório, ela grava sem --global:

$ git config user.email ana@empresa.exemplo
$ git config user.email
ana@empresa.exemplo                « aqui vale o do repositório
$ cat .git/config
[core]
	repositoryformatversion = 0
	filemode = true
	bare = false
	logallrefupdates = true
[user]
	email = ana@empresa.exemplo        « gravado só neste repositório

A opção --show-origin ("mostrar a origem") diz de que arquivo vem cada valor. (As linhas init.defaultbranch e core.editor vêm de duas configurações que você vai ver mais abaixo.) Repare que user.email aparece duas vezes; vale a última, a do repositório:

$ git config --list --show-origin
file:/home/ana/.gitconfig	user.name=Ana Souza
file:/home/ana/.gitconfig	user.email=ana@exemplo.com
file:/home/ana/.gitconfig	init.defaultbranch=main
file:/home/ana/.gitconfig	core.editor=nano
file:.git/config	core.repositoryformatversion=0
file:.git/config	core.filemode=true
file:.git/config	core.bare=false
file:.git/config	core.logallrefupdates=true
file:.git/config	user.email=ana@empresa.exemplo

As quatro linhas core.… do .git/config foram escritas pelo próprio git init; não mexa nelas. Para desfazer a configuração do repositório e voltar a valer a global, use --unset ("apagar o valor"):

$ git config --unset user.email
$ git config user.email
ana@exemplo.com                    « voltou a valer o global

Missão: o terminal está no repositório trabalho. Configure, só neste repositório, o e-mail ana@empresa.exemplo. Depois confira com git config user.email.

Duas configurações úteis desde o começo

O nome do ramo inicial: init.defaultBranch

Quando você cria um repositório, o Git cria um primeiro ramo (branch). O nome antigo, que o Git ainda usa se você não disser nada, é master; o GitHub e este guia usam main. Para todos os seus repositórios novos começarem com main:

$ git config --global init.defaultBranch main

Sem essa configuração, o git init mostra uma dica comprida a cada repositório novo. A aula git init mostra essa dica e explica a história.

O editor: core.editor

Alguns comandos do Git abrem um editor de texto para você escrever (por exemplo, um git commit sem -m). Se você não disser qual, o Git usa o editor padrão do sistema. No Ubuntu, costuma ser o nano; em outros sistemas, muitas vezes é o Vim, que confunde muita gente na primeira vez. Escolha um editor que você saiba usar:

EditorComando
nano (no terminal, simples)git config --global core.editor nano
VS Code (precisa do comando code no terminal)git config --global core.editor "code --wait"
Vimgit config --global core.editor vim

No VS Code, o --wait ("esperar") é essencial: faz o Git esperar você fechar a aba antes de continuar. Depois das duas configurações, o arquivo da Ana ficou assim:

$ git config --global init.defaultBranch main
$ git config --global core.editor nano
$ cat ~/.gitconfig
[user]
	name = Ana Souza
	email = ana@exemplo.com
[init]
	defaultBranch = main
[core]
	editor = nano

Formas diferentes de fazer a mesma coisa

O Git 2.46 ganhou uma forma nova, com verbos (get, set, list, unset), mais fácil de ler. As duas funcionam; a antiga é a que você vai encontrar na maioria dos tutoriais (e na própria dica do "Please tell me who you are").

Quero…Forma clássicaForma nova git 2.46+
Ler um valorgit config user.namegit config get user.name
Gravar um valorgit config --global user.name "Ana Souza"git config set --global user.name "Ana Souza"
Listargit config --global --listgit config list --global
Apagargit config --global --unset chavegit config unset --global chave
Editar o arquivo inteirogit config --global --edit (abre no editor)git config edit --global
$ git config get user.name
Ana Souza
$ git config list --global
user.name=Ana Souza
user.email=ana@exemplo.com
init.defaultbranch=main
core.editor=nano

Repare que o Git mostrou init.defaultbranch em minúsculas: os nomes de seção e de chave não diferenciam maiúsculas de minúsculas. init.defaultBranch e init.defaultbranch são a mesma configuração.

Quando dá errado

Esqueci as aspas no nome 
$ git config --global user.name Ana Souza
$ git config --global user.name
Ana                                « só o primeiro nome!

O que aconteceu: sem aspas, o terminal separou Ana e Souza em duas palavras. O Git gravou Ana como valor e entendeu Souza como um terceiro argumento, de uso avançado, sem avisar nada.

Como resolver: grave de novo, com aspas: git config --global user.name "Ana Souza". O valor novo substitui o antigo.

Errei o nome da configuração 
$ git config --global nome
error: key does not contain a section: nome

O que aconteceu: "a chave não contém uma seção". Toda configuração tem a forma seção.chave, e nome não tem ponto. Cuidado com o erro silencioso: git config --global user.nome "Ana" (com ponto, mas em português) é aceito sem reclamar, grava uma configuração que o Git nunca vai usar, e o erro do "Please tell me who you are" continua.

Como resolver: confira com git config --global --list, apague a chave errada com git config --global --unset user.nome e grave a certa, user.name.

Ler o arquivo que ainda não existe 
$ git config --global --list
fatal: unable to read config file '/home/ana/.gitconfig': Arquivo ou diretório inexistente

O que aconteceu: num Git recém-instalado, o ~/.gitconfig ainda não existe: ele só é criado na primeira vez que você grava algo com --global. A mensagem mistura inglês ("não consegui ler o arquivo de configuração") com o motivo dado pelo sistema, em português.

Como resolver: nada a consertar: configure o nome e o e-mail, e o arquivo aparece.

Fiz commits com o nome errado

O que aconteceu: o git config vale para os commits daqui para a frente. Os commits já feitos guardam o autor que estava configurado na hora.

Como resolver: se foi só o último commit, dá para corrigir o autor dele (aula Corrigindo o Último Commit). Para os outros, em geral, não vale a pena mexer na história.

2. A Ana tem user.email no ~/.gitconfig e outro no .git/config do repositório do trabalho. Qual vale nesse repositório?

3. O commit falhou com "Please tell me who you are". O que fazer?

4. O e-mail

Complete para gravar o e-mail da Ana em todos os repositórios:

git config user.email ana@exemplo.com

5. O ramo inicial

Complete para os repositórios novos começarem no ramo main:

git config --global main

Resumo

  • Cada commit leva nome e e-mail; configure-os uma vez com git config --global user.name "…" e git config --global user.email ….
  • Sem eles, o commit falha com "Please tell me who you are": a própria mensagem mostra os comandos que resolvem.
  • A configuração global fica em ~/.gitconfig; a do repositório, em .git/config, e vence a global.
  • Para ler um valor, rode o comando sem o valor; --list e --show-origin mostram tudo.
  • Configure também init.defaultBranch main e um core.editor que você saiba usar.
