Git Mensagens de Erro Comuns

Toda pessoa que usa Git vê as mesmas mensagens de erro, e quase todas trazem a solução escrita logo abaixo, nas linhas hint: ou (use "git …"). Esta página reúne as mais comuns, exatamente como saíram no Git 2.53 do Ubuntu 26.04 da Ana, com a tradução, o que aconteceu e o comando que resolve.

Como ler uma mensagem do Git
  • fatal: o comando parou e não fez nada. Seu repositório está como antes.
  • error: algo deu errado; em geral o comando também desistiu (às vezes vem um fatal: logo depois).
  • hint: uma dica ("sugestão") de como sair da situação. Leia sempre.
  • warning: um aviso: o comando funcionou, mas o Git quer que você saiba de algo.
  • Nesta versão do Git, parte das mensagens em português ainda sai em inglês, mesmo com o sistema em português (é a tradução que vem no Ubuntu). Com o sistema em inglês, todas saem em inglês: o começo da mensagem (fatal: not a git repository) é o melhor texto para procurar na internet.

Começando

fatal: not a git repository

$ git status
fatal: not a git repository (or any of the parent directories): .git

Tradução: "não é um repositório git (nem nenhuma das pastas acima): .git".

O que aconteceu: o Git procurou a pasta .git na pasta atual e em todas as de cima, e não achou. Ou você está na pasta errada (o mais comum: esqueceu o cd), ou o projeto ainda não é um repositório.

Como resolver: pwd para ver onde está; cd ~/receitas para ir ao projeto. Se o projeto nunca foi versionado, git init dentro dele. Veja git init e O Mínimo de Terminal.

Missão: a Ana está na pasta pessoal e o git status dá fatal: not a git repository. Entre na pasta receitas, transforme-a num repositório e rode git status de novo.

Please tell me who you are

$ git commit -m 'Adiciona bolo'
Author identity unknown

*** Please tell me who you are.

Run

  git config --global user.email "you@example.com"
  git config --global user.name "Your Name"

to set your account's default identity.
Omit --global to set the identity only in this repository.

fatal: unable to auto-detect email address (got 'ana@notebook.(none)')

Tradução: "Identidade do autor desconhecida. Por favor, me diga quem você é. Rode [os dois comandos] para definir a identidade padrão da sua conta. Omita --global para definir só neste repositório. Fatal: não consegui descobrir o e-mail sozinho."

O que aconteceu: todo commit leva nome e e-mail do autor, e o Git deste computador ainda não sabe os seus. O commit não foi feito.

Como resolver: rode os dois comandos com os seus dados (e as aspas) e repita o commit:

$ git config --global user.name "Ana Souza"
$ git config --global user.email "ana@exemplo.com"

Veja Configurando Nome e E-mail.

Commit

Nada para commitar (três versões)

$ git commit -m 'Teste'
No ramo main

Submissão inicial.

nada para enviar (crie/copie arquivos e use "git add" para registrar)

1. Pasta vazia ("Submissão inicial" = este seria o primeiro commit): não há arquivo nenhum. Crie os arquivos do projeto e dê git add.

$ git commit -m 'Adiciona bolo'
No ramo main

Submissão inicial.

Arquivos não monitorados:
  (utilize "git add <arquivo>..." para incluir o que será submetido)
	bolo.txt

nada adicionado ao envio mas arquivos não registrados estão presentes (use "git add" to registrar)

2. Esqueceu o git add: o arquivo existe, mas não está na área de preparo. O Git só commita o que foi preparado. Resolva com git add bolo.txt e repita o commit. Veja git add.

$ git commit -m 'De novo'
No ramo main
nothing to commit, working tree clean

3. Já está tudo commitado ("nada a commitar, pasta de trabalho limpa"). Não é erro: mude algum arquivo antes do próximo commit. Se o que você queria era corrigir o último commit, veja --amend.

Missão: o git commit -m 'Adiciona bolo' da Ana respondeu "nada adicionado ao envio mas arquivos não registrados estão presentes". Faça o commit do bolo.txt dar certo.

Aborting commit due to empty commit message.

$ git commit -m ''
Aborting commit due to empty commit message.

O que aconteceu: "abortando o commit por causa da mensagem vazia". Acontece com -m '' ou quando o editor abre e você fecha sem escrever nada (ou só com linhas começando por #, que são ignoradas). Como resolver: repita com uma mensagem. Veja Boas Mensagens.

Arquivos e nomes

pathspec … não encontrou / did not match

$ git add boloo.txt
fatal: pathspec 'boloo.txt' não encontrou nenhum arquivo
$ git restore boloo.txt
error: pathspec 'boloo.txt' did not match any file(s) known to git
$ git rm nada.txt
fatal: pathspec 'nada.txt' não encontrou nenhum arquivo
$ git mv nada.txt x.txt
fatal: bad source, source=nada.txt, destination=x.txt

O que aconteceu: pathspec é "o caminho que você digitou". Nenhum arquivo casou com ele: erro de digitação (boloo), pasta errada, ou um arquivo novo que o Git ainda não conhece (o restore e o rm só mexem em arquivos rastreados). No git mv, "bad source" = "origem inválida".

Como resolver: confira com ls e git status; use Tab para completar nomes. Lembre que o Linux diferencia Bolo.txt de bolo.txt.

git: '…' não é um comando git

$ git stauts
git: 'stauts' não é um comando git. Veja 'git --help'.

The most similar command is
	status

O que aconteceu: erro de digitação. "O comando mais parecido é status". Como resolver: digite de novo. Para o Git perguntar se pode rodar o comando certo, veja help.autocorrect em Configurações.

fatal: ambiguous argument … unknown revision or path

$ git diff HEAD
fatal: ambiguous argument 'HEAD': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

Tradução: "argumento ambíguo: revisão desconhecida ou caminho fora da pasta de trabalho. Use -- para separar caminhos de revisões".

O que aconteceu: o Git não achou um commit/branch com esse nome nem um arquivo. Aqui, HEAD ainda não existe porque o repositório não tem commits. Também aparece com HEAD~1 quando só há um commit, ou com um branch digitado errado.

Como resolver: confira os nomes com git log --oneline e git branch. Se for um arquivo que não existe mais, ponha -- antes dele: git log -- receita-antiga.txt.

fatal: your current branch … does not have any commits yet

$ git log
fatal: your current branch 'bolo' does not have any commits yet

O que aconteceu: "o seu branch atual ainda não tem nenhum commit": não há o que mostrar. Parecidos: git tag v1.0 num repositório sem commits dá fatal: Failed to resolve 'HEAD' as a valid ref. Como resolver: faça o primeiro commit (Seu Primeiro Commit).

Branches

fatal: invalid reference / a branch named … already exists

$ git switch receitas
fatal: invalid reference: receitas
$ git switch -c bolo
Switched to a new branch 'bolo'
$ git switch -c bolo
fatal: a branch named 'bolo' already exists

O que aconteceu: "referência inválida": não existe branch receitas (é o nome da pasta, não de um branch). E "já existe um branch chamado bolo": o -c é para criar.

Como resolver: veja os branches com git branch; para ir a um que já existe, git switch bolo (sem -c). Veja git switch.

error: Your local changes … would be overwritten

$ git switch bolo
error: Your local changes to the following files would be overwritten by checkout:
	bolo.txt
Please commit your changes or stash them before you switch branches.
Aborting

Tradução: "As suas mudanças locais nestes arquivos seriam sobrescritas. Faça commit delas ou guarde-as (stash) antes de trocar de branch. Abortando."

O que aconteceu: o bolo.txt tem mudanças não commitadas, e o branch bolo tem outra versão dele. Trocar apagaria o seu trabalho, então o Git não troca. A mesma mensagem aparece no git merge e no git pull ("by merge").

Como resolver: escolha um: git commit (guarda no branch atual), git stash (guarda na gaveta, para trazer depois com git stash pop) ou git restore bolo.txt (joga a mudança fora). Veja git stash.

You are in 'detached HEAD' state

$ git checkout HEAD~1
Note: switching to 'HEAD~1'.

You are in 'detached HEAD' state. You can look around, make experimental
changes and commit them, and you can discard any commits you make in this
state without impacting any branches by switching back to a branch.

If you want to create a new branch to retain commits you create, you may
do so (now or later) by using -c with the switch command. Example:

  git switch -c <new-branch-name>

Or undo this operation with:

  git switch -

Turn off this advice by setting config variable advice.detachedHead to false

HEAD is now at 6ad047c Adiciona bolo

Não é erro, é um aviso. "Você está com o HEAD destacado: pode olhar, fazer mudanças experimentais e commitá-las, e descartar esses commits voltando a um branch. Se quiser guardar os commits, crie um branch com git switch -c nome. Ou desfaça com git switch -."

Como resolver: só olhando? git switch - (ou git switch main). Fez commits que quer guardar? git switch -c novo-branch antes de sair. Veja HEAD Destacado.

error: the branch … is not fully merged

$ git branch -d teste
error: the branch 'teste' is not fully merged
hint: If you are sure you want to delete it, run 'git branch -D teste'
hint: Disable this message with "git config set advice.forceDeleteBranch false"

O que aconteceu: "o branch não foi totalmente juntado": ele tem commits que não estão no branch atual. Apagar com -d é recusado para você não perder trabalho. Como resolver: junte antes (git merge teste) ou, se tem certeza, git branch -D teste. Veja Renomeando e Apagando Branches.

Merge e conflito

CONFLITO e o que vem depois

$ git merge bolo
Mesclagem automática de bolo.txt
CONFLITO (conteúdo): conflito de mesclagem em bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ git status
No ramo main
Você tem caminhos não mesclados.
  (fixar conflitos e executar "git commit")
  (use "git merge --abort" to abort the merge)

Caminhos não mesclados:
  (usar "git add <arquivo>..." para marcar resolução)
	ambos modificados:   bolo.txt

nenhuma modificação adicionada à submissão (utilize "git add" e/ou "git commit -a")

O que aconteceu: o main e o bolo mudaram as mesmas linhas do bolo.txt. "O merge automático falhou; corrija os conflitos e depois faça commit do resultado." O Git deixou o merge pela metade e marcou o trecho no arquivo.

Como resolver: abra o arquivo, escolha o texto final entre <<<<<<< e >>>>>>>, apague as marcas, depois git add bolo.txt e git commit. Para desistir: git merge --abort. Veja Resolvendo Conflitos.

Enquanto o conflito não é resolvido, outros comandos recusam:

$ git commit -m 'Junta'
error: Committing is not possible because you have unmerged files.
hint: Fix them up in the work tree, and then use 'git add/rm <file>'
hint: as appropriate to mark resolution and make a commit.
fatal: Exiting because of an unresolved conflict.
U	bolo.txt
$ git switch bolo
fatal: cannot switch branch while merging
Consider "git merge --quit" or "git worktree add".

"Não é possível commitar porque há arquivos não mesclados (U): corrija-os e marque a resolução com git add." / "Não dá para trocar de branch durante um merge."

Remotos e GitHub

No configured push destination / remote origin already exists

$ git push
fatal: No configured push destination.
Either specify the URL from the command-line or configure a remote repository using

    git remote add <name> <url>

and then push using the remote name

    git push <name>

$ git remote add origin https://github.com/ana-souza/receitas.git
$ git remote add origin https://github.com/ana-souza/receitas.git
error: remote origin already exists.

O que aconteceu: no primeiro, "nenhum destino de push configurado": o repositório nasceu com git init e ninguém disse para onde enviar. No segundo, o origin já existe.

Como resolver: git remote add origin URL uma vez só. Para trocar o endereço: git remote set-url origin URL-NOVA; para conferir: git remote -v. Veja git remote.

fatal: The current branch … has no upstream branch

$ git push
fatal: The current branch main has no upstream branch.
To push the current branch and set the remote as upstream, use

    git push --set-upstream origin main

To have this happen automatically for branches without a tracking
upstream, see 'push.autoSetupRemote' in 'git help config'.

O que aconteceu: "o branch atual não tem branch de rastreamento (upstream)": o Git não sabe para qual branch do servidor mandar. Como resolver: rode o comando sugerido (a forma curta é git push -u origin main); dali em diante, git push sozinho funciona. Para nunca mais ver: git config --global push.autoSetupRemote true. Veja upstream.

error: src refspec main does not match any

$ git push -u origin main
error: src refspec main does not match any
error: failed to push some refs to 'https://github.com/ana-souza/receitas.git'

O que aconteceu: "a origem main não casa com nada": não existe branch main no seu repositório. Ou você ainda não fez nenhum commit (o branch só passa a existir no primeiro commit), ou o seu branch se chama master.

Como resolver: git log (há commits?) e git branch (qual o nome?). Faça o primeiro commit, ou envie o nome certo (git push -u origin master), ou renomeie: git branch -m master main.

! [rejected] … (fetch first)

$ git push
To https://github.com/ana-souza/receitas.git
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/ana-souza/receitas.git'
hint: Updates were rejected because the remote contains work that you do not
hint: have locally. This is usually caused by another repository pushing to
hint: the same ref. If you want to integrate the remote changes, use
hint: 'git pull' before pushing again.
hint: See the 'Note about fast-forwards' in 'git push --help' for details.

Tradução: "rejeitado (busque primeiro). O servidor tem trabalho que você não tem localmente; em geral, outra pessoa enviou para o mesmo branch. Para integrar as mudanças de lá, use git pull antes de enviar de novo."

O que aconteceu: o Bruno enviou um commit depois do seu último pull. O Git nunca apaga o trabalho dele para pôr o seu.

Como resolver: git pull (veja o próximo erro), resolva conflitos se houver, e git push. Não use --force para "resolver": ele apagaria o commit do Bruno. Veja Push Rejeitado.

fatal: Need to specify how to reconcile divergent branches

$ git pull
From https://github.com/ana-souza/receitas
   6ad047c..4cf694c  main       -> origin/main
hint: You have divergent branches and need to specify how to reconcile them.
hint: You can do so by running one of the following commands sometime before
hint: your next pull:
hint:
hint:   git config pull.rebase false  # merge
hint:   git config pull.rebase true   # rebase
hint:   git config pull.ff only       # fast-forward only
hint:
hint: You can replace "git config" with "git config --global" to set a default
hint: preference for all repositories. You can also pass --rebase, --no-rebase,
hint: or --ff-only on the command line to override the configured default per
hint: invocation.
fatal: Need to specify how to reconcile divergent branches.

O que aconteceu: o pull baixou o commit do Bruno (a linha 6ad047c..4cf694c), mas você também tem um commit novo: os branches "divergiram". O Git quer que você escolha como juntar: com merge, com rebase, ou só se der fast-forward. Nada foi juntado ainda.

Como resolver: para esta vez, git pull --no-rebase (merge) ou git pull --rebase. Para não perguntar mais, grave a preferência: git config --global pull.rebase false. Veja git pull e Rebase ou Merge?.

fatal: refusing to merge unrelated histories

$ git pull --no-rebase origin main
From https://github.com/ana-souza/site
 * branch            main       -> FETCH_HEAD
fatal: refusing to merge unrelated histories

O que aconteceu: "recusando juntar históricos sem relação". A Ana criou o repositório no computador (com um commit) e o repositório no GitHub já tinha outro primeiro commit (um README criado pelo site, por exemplo). São duas histórias que não têm nenhum commit em comum.

Como resolver: se é isso mesmo que você quer (juntar as duas), git pull --no-rebase --allow-unrelated-histories origin main, resolva conflitos (o README costuma conflitar) e envie. Para evitar: crie o repositório no GitHub vazio quando o projeto já existe no computador. Veja Criando um Repositório no GitHub.

Repository not found / destination path already exists

$ git clone https://github.com/ana-souza/receita.git
Cloning into 'receita'...
remote: Repository not found.
fatal: repository 'https://github.com/ana-souza/receita.git/' not found
$ git clone https://github.com/ana-souza/receitas.git
fatal: destination path 'receitas' already exists and is not an empty directory.

"Repository not found" ("repositório não encontrado"): o endereço está errado (aqui, faltou o s) ou o repositório é privado e você não está logado com uma conta que tem acesso: o GitHub responde "não encontrado" nos dois casos, para não revelar que um repositório privado existe. Confira a URL no botão de copiar da página do repositório e o seu login (HTTPS e Token).

"destination path … already exists" ("a pasta de destino já existe e não está vazia"): já há uma pasta receitas aqui. Clone com outro nome (git clone URL receitas-2) ou entre na pasta que já existe e use git pull.

Erros de login no GitHub (ilustrativo)

Estes dependem do GitHub de verdade e não rodam no laboratório do guia. As mensagens abaixo seguem a documentação oficial do GitHub (docs.github.com/pt, "Erro: Permissão negada (publickey)" e "Gerenciar seus tokens de acesso pessoal").

  • Permission denied (publickey) com SSH: o GitHub não reconheceu nenhuma chave sua. Confira com ssh -T git@github.com e veja Chave SSH.
  • Authentication failed com HTTPS: o GitHub não aceita a senha da conta no Git; use um token no lugar da senha. Veja HTTPS e Token.
