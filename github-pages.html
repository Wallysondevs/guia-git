Git GitHub Pages

Você fez uma página em HTML, ela abre bonita no seu navegador… mas só no seu computador. Para o mundo ver, ela precisa estar num servidor na internet. O GitHub Pages é esse servidor, de graça: você envia os arquivos do site para um repositório com git push, liga uma opção nas configurações, e o GitHub publica o site num endereço como https://ana-souza.github.io. A cada novo push, o site se atualiza sozinho. Nesta aula, a Ana publica o site de receitas.

Você vai aprender
  • O que o GitHub Pages faz e que tipo de site ele publica (sites estáticos).
  • A diferença entre o site de usuário (ana-souza.github.io) e o site de projeto (ana-souza.github.io/receitas).
  • Como enviar o site com o Git e ligar o Pages nas configurações do repositório.
  • Como atualizar o site: editar, commitar, enviar e esperar.
  • Os problemas mais comuns: a página 404, o site que não muda, o index.html no lugar errado.

Os comandos do Git desta aula rodaram no Git 2.53 da máquina da Ana (usuária ana, computador notebook), enviando para o "GitHub de mentira" do laboratório. As telas do site do GitHub não rodam no laboratório: elas estão descritas com base na documentação oficial (docs.github.com/pt) e são ilustrativas; os nomes podem aparecer em inglês, conforme o idioma da sua conta.

A ideia: a vitrine da loja

O repositório no GitHub é como o estoque de uma loja: tudo guardado, organizado, com o histórico de cada peça. O GitHub Pages é a vitrine: você escolhe uma prateleira do estoque (um branch, e uma pasta dentro dele) e o GitHub expõe o que está lá para quem passa na rua. Quando você troca a peça no estoque (um novo commit enviado com push), a vitrine é rearrumada sozinha, em alguns minutos.

Duas regras da vitrine:

  • Ela só mostra sites estáticos: arquivos prontos (HTML, CSS, JavaScript, imagens), que o navegador abre como estão. Não roda programas no servidor (PHP, banco de dados). Um portfólio, um currículo, a documentação de um projeto, o site de receitas: tudo isso serve.
  • A vitrine é pública: qualquer pessoa vê. Nunca ponha senhas ou dados pessoais nos arquivos; a documentação diz que os sites "não devem ser usados para transações confidenciais, como envio de senhas".

1. Site de usuário ou site de projeto?

TipoNome do repositórioEndereço do siteQuantos
Site de usuárioana-souza.github.io (o seu usuário + .github.io)https://ana-souza.github.ioUm por conta
Site de projetoQualquer um, por exemplo receitashttps://ana-souza.github.io/receitasUm por repositório

O site de usuário é a "página principal" da pessoa (o portfólio). O de projeto fica numa "subpasta" do endereço e serve para cada projeto ter a sua página. O jeito de publicar é o mesmo nos dois. A Ana vai começar pelo site de usuário.

Repositório público

Segundo a documentação, com o GitHub Free (o plano gratuito), o repositório do site precisa ser público. E mesmo nos planos que permitem publicar a partir de repositório privado, o site em si fica público na internet.

2. O site no computador: o index.html

O GitHub Pages procura um arquivo de entrada: index.html, index.md ou README.md, no nível de cima da pasta publicada. É a página que abre quando alguém digita só o endereço. A Ana cria a pasta, o repositório e a página:

$ mkdir ana-souza.github.io && cd ana-souza.github.io && git init -q
$ cat > index.html <<'FIM'
> <!doctype html>
> <html lang="pt-BR">
> <head><meta charset="utf-8"><title>Receitas da Ana</title></head>
> <body>
> <h1>Receitas da Ana</h1>
> <p>Bolo de cenoura, pão de queijo e outras delícias.</p>
> </body>
> </html>
> FIM
$ git add index.html
$ git commit -m 'Primeira versão do site'
[main (root-commit) 78bc0b4] Primeira versão do site
 1 file changed, 8 insertions(+)
 create mode 100644 index.html

Nada de especial até aqui: um repositório comum, com um commit (aula Seu Primeiro Commit). O nome da pasta no computador pode ser qualquer um; quem precisa se chamar ana-souza.github.io é o repositório no GitHub. (No dia a dia, a Ana escreveria o index.html num editor; o cat com <<'FIM' só cria o arquivo pelo terminal.)

Missão: na pasta site (já é um repositório, ainda sem commits), crie o index.html com um título: echo '<h1>Receitas da Ana</h1>' > index.html. Depois, adicione e faça o commit.

3. Enviando para o GitHub

No site do GitHub, a Ana cria um repositório público chamado ana-souza.github.io, vazio (aula Criando um Repositório no GitHub). Depois, liga o repositório local a ele e envia (aulas git remote e git push):

$ git remote add origin https://github.com/ana-souza/ana-souza.github.io.git
$ git push -u origin main
To https://github.com/ana-souza/ana-souza.github.io.git
 * [new branch]      main -> main                      « o branch main foi criado no GitHub
branch 'main' set up to track 'origin/main'.
$ git status
No ramo main
Your branch is up to date with 'origin/main'.          « nada a enviar: o GitHub tem tudo

nothing to commit, working tree clean

Algumas linhas saem em inglês mesmo com o sistema em português: a tradução do Git do Ubuntu não cobre todas as mensagens. Your branch is up to date with 'origin/main' quer dizer "o seu branch está igual ao origin/main", e nothing to commit, working tree clean, "nada a commitar, pasta limpa".

4. Ligando o Pages nas configurações (ilustrativo)

Os arquivos estão no GitHub, mas a vitrine ainda está apagada. Os passos, segundo a documentação:

  1. Na página do repositório, clique em Configurações (Settings). Se não achar, ela está no menu ⋯.
  2. Na barra lateral, na seção "Código, planejamento e automação" (Code and automation), clique em Páginas (Pages).
  3. Em "Build e implantação" (Build and deployment), no campo "Fonte" (Source), escolha Fazer implantação de um branch (Deploy from a branch).
  4. No menu do branch, escolha main. No menu da pasta, escolha a raiz (/ (root)) ou /docs (seção 6).
  5. Clique em Salvar (Save).

Depois de salvar, o GitHub monta e publica o site. A documentação avisa que pode levar até 10 minutos para as mudanças aparecerem. Quando estiver pronto, a mesma tela mostra o endereço do site. A Ana abre https://ana-souza.github.io no navegador e vê o título "Receitas da Ana".

No site de usuário, às vezes nem precisa ligar

O início rápido da documentação cria o repositório ana-souza.github.io já com um README e manda escolher a fonte nas configurações. Se, ao abrir a tela Páginas, a fonte já estiver escolhida, é só conferir que é o branch main e a pasta certa.

5. Atualizando o site: editar, commitar, enviar

A partir de agora, publicar é o ciclo de sempre do Git. A Ana troca uma frase da página:

$ sed -i 's/outras delícias/muito mais/' index.html
$ git commit -am 'Atualiza a frase da página inicial'
[main 64ebfc7] Atualiza a frase da página inicial
 1 file changed, 1 insertion(+), 1 deletion(-)
$ git push
To https://github.com/ana-souza/ana-souza.github.io.git
   78bc0b4..64ebfc7  main -> main                     « o main do GitHub andou de 78bc0b4 para 64ebfc7

O sed -i fez a troca no arquivo (no dia a dia, o editor); o -a do commit adicionou o arquivo alterado e já commitou (aula git commit). Assim que o push chega, o GitHub refaz o site. Em alguns minutos, a frase nova está no ar. Sem push, nada muda no site: o GitHub só publica o que recebeu.

Missão: a Ana já acrescentou uma linha ao index.html, mas o site não mudou. Confira com git status, faça o commit e envie com git push (aqui, o "GitHub" é a pasta ../servidor.git). Depois, git status deve dizer que está tudo em dia.

6. Formas diferentes: de onde o site é publicado

Nas configurações do Pages, você escolhe o branch e a pasta. As combinações mais comuns:

FonteOnde fica o index.htmlQuando usar
Branch main, pasta / (root)Na raiz do repositórioO repositório é só o site (o caso da Ana)
Branch main, pasta /docsNa pasta docs/O repositório tem um programa, e o site (a documentação dele) fica separado na pasta docs
Branch gh-pagesNa raiz desse branchUm branch só para o site; nome tradicional, muito usado por ferramentas que geram o site sozinhas
GitHub ActionsOnde o seu fluxo de trabalho mandarSites que precisam ser "montados" por um programa (aula GitHub Actions)

Para usar a pasta /docs, mova o site para lá (aula git mv), envie, e troque a pasta nas configurações:

$ mkdir docs && git mv index.html docs/
$ git commit -m 'Move o site para a pasta docs'
[main 91f2aa6] Move o site para a pasta docs
 1 file changed, 0 insertions(+), 0 deletions(-)
 rename index.html => docs/index.html (100%)
$ git push
To https://github.com/ana-souza/ana-souza.github.io.git
   64ebfc7..91f2aa6  main -> main

E para o branch gh-pages: dá para criar o branch no GitHub enviando o seu main com outro nome, com git push origin main:gh-pages ("envie o meu main para o branch gh-pages de lá"):

$ git push origin main:gh-pages
remote:
remote: Create a pull request for 'gh-pages' on GitHub by visiting:
remote:      https://github.com/ana-souza/ana-souza.github.io/pull/new/gh-pages
remote:
To https://github.com/ana-souza/ana-souza.github.io.git
 * [new branch]      main -> gh-pages

As linhas remote: vêm do GitHub: ele sempre oferece abrir um pull request para um branch novo (aula Pull Request). Aqui é só ignorar. Depois, nas configurações do Pages, escolha o branch gh-pages.

Quando dá errado

O endereço mostra "404" (ilustrativo)

O navegador mostra uma página de erro 404 do GitHub ("não encontrado"). As causas mais comuns:

  • Ainda não deu tempo: espere até 10 minutos depois do push (ou de salvar as configurações).
  • O Pages não foi ligado, ou a fonte aponta para outro branch ou pasta: confira em Configurações → Páginas.
  • Não há arquivo de entrada no nível de cima da pasta publicada. Um site em docs/index.html com a fonte na raiz (/ (root)) não acha o index.html. Confira com git ls-files, que lista os arquivos do repositório.
  • O nome do arquivo está diferente: Index.html ou index.htm não servem; o servidor do GitHub diferencia maiúsculas de minúsculas.
Mudei o arquivo, mas o site não mudou

Primeiro, a pergunta de sempre: o commit foi enviado? Rode git status:

$ git status
No ramo main
Seu ramo está à frente de 'origin/main' por 1 submissão.      « 1 commit que o GitHub não tem
  (use "git push" to publish your local commits)

nothing to commit, working tree clean

"À frente por 1 submissão" (1 commit) quer dizer: o commit existe no seu computador, mas não no GitHub. A dica diz o que fazer: git push. Se, em vez disso, o arquivo aparecer em Changes not staged for commit ("mudanças fora da área de preparo"), falta até o commit. Se está tudo enviado, espere alguns minutos e recarregue a página sem o cache do navegador (Ctrl+Shift+R).

O repositório se chama ana-souza.github.io, mas o site não aparece nesse endereço

O nome tem de ser exatamente o seu usuário seguido de .github.io. Se a Ana criasse anasouza.github.io (sem o hífen), o GitHub o trataria como um site de projeto comum, em https://ana-souza.github.io/anasouza.github.io. Para consertar, renomeie o repositório nas configurações dele, e atualize o endereço do remoto com git remote set-url (aula git remote).

O CSS e as imagens não carregam no site de projeto

No site de projeto (ana-souza.github.io/receitas), um caminho que começa com /, como /style.css, aponta para a raiz ana-souza.github.io/style.css, fora do projeto. Use caminhos relativos: style.css ou imagens/bolo.jpg.

Resumo

  • O GitHub Pages publica sites estáticos de graça, direto de um repositório; o site é público.
  • Repositório USUARIO.github.io → site de usuário em https://USUARIO.github.io; qualquer outro repositório → site de projeto em https://USUARIO.github.io/REPO.
  • O arquivo de entrada (index.html) fica no topo da pasta publicada: a raiz ou /docs, do branch escolhido.
  • Liga-se em Configurações → Páginas → Fazer implantação de um branch (ilustrativo).
  • Atualizar o site é o ciclo do Git: editar, git commit, git push, e esperar até 10 minutos. Sem push, nada muda. A aula Projeto: Portfólio no GitHub Pages faz tudo isso do zero.
