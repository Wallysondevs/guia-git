Git show

O git log mostra a lista de fotos do álbum. O git show ("mostrar") pega uma foto e mostra tudo sobre ela: quem fez, quando, a mensagem inteira e, principalmente, o que mudou, linha por linha. Ele também abre um arquivo do jeito que ele era num commit antigo, sem mexer na sua pasta. É o comando para responder "o que exatamente esse commit fez?" e "como era esse arquivo antes?".

Você vai aprender
  • A ver o último commit com git show e qualquer outro pelo hash ou por HEAD~1, HEAD~2…
  • A ler a saída: o cabeçalho (igual ao do git log) e o diff (as linhas que saíram e entraram).
  • A resumir com --stat, --name-only e -s.
  • A ver um arquivo como ele era num commit: git show commit:arquivo.
  • Os erros reais: hash que não existe e arquivo que não existe naquele commit.

As saídas são reais, do Git 2.53 da máquina da Ana (Ubuntu 26.04), no mesmo repositório receitas da aula git log, com cinco commits:

$ git log --oneline
e4dc867 (HEAD -> main) Adiciona o e-mail de contato no README
ea0e4fa Corrige a quantidade de ovos do bolo
cce6adb Adiciona a receita de pudim
da810ac Adiciona a receita de bolo de cenoura
d84dc97 Adiciona o README

A ideia: a foto ampliada, com o antes e o depois

Pense numa revista de reforma de casas: a reportagem mostra a sala antes e depois, lado a lado, com uma legenda. O git show faz isso com um commit: a legenda (autor, data, mensagem) e, embaixo, as linhas como eram antes (com -) e como ficaram depois (com +).

1. O último commit: git show

Sem nada depois, o git show mostra o commit onde você está (o HEAD), que normalmente é o último:

$ git show
commit e4dc8675c7066aa6015b13725c2d51e94dd0cb02 (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona o e-mail de contato no README

diff --git a/README.md b/README.md          « daqui para baixo: o que mudou
index 2644316..bd4bba2 100644
--- a/README.md
+++ b/README.md
@@ -1 +1,2 @@
 # Receitas da Ana
+Contato: ana@exemplo.com                   « a linha que entrou

A primeira parte (até a mensagem) é o mesmo cabeçalho do git log: hash, etiquetas, autor, data e mensagem (veja cada linha explicada em git log). A segunda parte é o diff, as diferenças entre este commit e o anterior:

diff --git a/README.md b/README.md
Começa o trecho de um arquivo: o README.md. O a/ é a versão de antes; o b/, a de depois. Um commit que muda três arquivos tem três trechos assim.
index 2644316..bd4bba2 100644
Os códigos internos do conteúdo do arquivo antes e depois, e o modo (100644 = arquivo comum). Você quase nunca precisa olhar esta linha.
--- a/README.md e +++ b/README.md
A legenda das marcas: linhas com - são do arquivo de antes; com +, do arquivo de depois.
@@ -1 +1,2 @@
Onde fica o trecho: no arquivo de antes, a linha 1 (1 linha); no de depois, a partir da linha 1, 2 linhas.
" # Receitas da Ana" (começa com espaço)
Linha que não mudou, mostrada só para você se localizar (o contexto).
+Contato: ana@exemplo.com
Linha acrescentada pelo commit. No terminal, aparece em verde.

A leitura do diff tem uma aula inteira: git diff. O formato é o mesmo.

2. Qualquer commit, pelo hash

Copie o hash do git log --oneline (os 7 caracteres bastam) e dê ao git show. O commit dos ovos tem uma linha que saiu e uma que entrou:

$ git show ea0e4fa
commit ea0e4fa83f1c338c65c14e143ca02e2de44b0e68
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Corrige a quantidade de ovos do bolo

    A receita da vó leva 4 ovos, não 3.          « a mensagem inteira, com o corpo

diff --git a/bolo.txt b/bolo.txt
index 29056e1..10a5c6d 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -1,3 +1,3 @@
 Bolo de cenoura
 3 cenouras
-3 ovos                                         « saiu (vermelho)
+4 ovos                                         « entrou (verde)

Para o Git, uma linha modificada é uma linha que saiu (-3 ovos) e outra que entrou no lugar (+4 ovos). Não existe "linha alterada" no diff. E o corpo da mensagem explica o porquê: é aí que uma boa mensagem paga a conta (Boas Mensagens de Commit).

O primeiro commit: arquivo novo

$ git show d84dc97
commit d84dc9769de7f3c81874872c30843402cbae59f9
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona o README

diff --git a/README.md b/README.md
new file mode 100644                           « o arquivo é novo neste commit
index 0000000..2644316
--- /dev/null                                  « "antes" não existia nada
+++ b/README.md
@@ -0,0 +1 @@
+# Receitas da Ana

Quando o arquivo é novo, o diff mostra new file mode, o "antes" é /dev/null (o "nada" do Linux), o código de antes é só zeros, e todas as linhas têm +.

Missão: use o git log --oneline para achar o commit que corrigiu os ovos do bolo e mostre esse commit com git show e o hash dele. Qual linha saiu e qual entrou?

3. Sem decorar hashes: HEAD~1, HEAD~2…

HEAD é o commit onde você está. HEAD~1 é o anterior a ele (o "pai"), HEAD~2 é o de dois commits atrás, e assim por diante. É um jeito de apontar para commits recentes sem copiar o hash:

d84dc97 ── da810ac ── cce6adb ── ea0e4fa ── e4dc867 ◀── HEAD (main)
HEAD~4     HEAD~3     HEAD~2     HEAD~1     HEAD

$ git show --oneline -s HEAD~3
da810ac Adiciona a receita de bolo de cenoura

(O --oneline -s resume o commit numa linha; veja a próxima seção.) Mais sobre o HEAD e o ~ em O que é HEAD.

4. Resumindo: --stat, --name-only e -s

Num commit grande, o diff inteiro é longo demais. Três opções resumem:

$ git show HEAD~1 --stat
commit ea0e4fa83f1c338c65c14e143ca02e2de44b0e68
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Corrige a quantidade de ovos do bolo

    A receita da vó leva 4 ovos, não 3.

 bolo.txt | 2 +-                               « no lugar do diff: arquivos e contagem
 1 file changed, 1 insertion(+), 1 deletion(-)
$ git show --name-only HEAD~1
commit ea0e4fa83f1c338c65c14e143ca02e2de44b0e68
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Corrige a quantidade de ovos do bolo

    A receita da vó leva 4 ovos, não 3.

bolo.txt                                       « só os nomes dos arquivos
$ git show -s
commit e4dc8675c7066aa6015b13725c2d51e94dd0cb02 (HEAD -> main)
Author: Ana Souza <ana@exemplo.com>
Date:   Thu Oct 15 10:30:00 2026 -0300

    Adiciona o e-mail de contato no README     « só o cabeçalho, sem diff
--stat
No lugar do diff, os arquivos mudados e quantas linhas entraram (+) e saíram (-). A ordem não importa: git show --stat HEAD~1 dá no mesmo.
--name-only
Só os nomes dos arquivos mudados.
-s
De no patch (também se escreve --no-patch): só o cabeçalho, como um git log -1.

Dá para pedir vários commits de uma vez:

$ git show HEAD~1 HEAD~2 --oneline --stat
ea0e4fa Corrige a quantidade de ovos do bolo
 bolo.txt | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
cce6adb Adiciona a receita de pudim
 pudim.txt | 1 +
 1 file changed, 1 insertion(+)

5. Um arquivo como ele era: git show commit:arquivo

Esta é uma das funções mais úteis do git show: ver o conteúdo inteiro de um arquivo do jeito que ele estava num commit, sem mudar nada na pasta. Escreva o commit, dois-pontos e o caminho do arquivo:

$ git show da810ac:bolo.txt
Bolo de cenoura
3 cenouras
3 ovos                          « como era quando a receita entrou
$ git show HEAD:bolo.txt
Bolo de cenoura
3 cenouras
4 ovos                          « como está no último commit
$ git show HEAD~1:README.md
# Receitas da Ana               « o README antes do contato
da810ac
O commit (pode ser o hash, HEAD, HEAD~1, um nome de ramo…).
:
Os dois-pontos, colados, separam o commit do caminho. Sem espaço.
bolo.txt
O caminho do arquivo a partir da pasta principal do repositório (por exemplo, doces/cocada.txt).

A saída é só o conteúdo, como um cat do passado. Para guardar essa versão antiga num arquivo e comparar com calma, use um redirecionamento do terminal: git show da810ac:bolo.txt > bolo-antigo.txt. (Para voltar o arquivo da pasta a uma versão antiga, o comando certo é o git restore.)

Missão: o tempo de forno do pudim mudou num dos commits. Mostre o pudim.txt como ele era no primeiro commit (com git show COMMIT:pudim.txt), para descobrir o tempo original. Dica: veja os hashes com git log --oneline, ou use HEAD~2.

Quando dá errado

"ambiguous argument … unknown revision" 
$ git show abc1234
fatal: ambiguous argument 'abc1234': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'
$ git show HEAD~9
fatal: ambiguous argument 'HEAD~9': unknown revision or path not in the working tree.
Use '--' to separate paths from revisions, like this:
'git <command> [<revision>...] -- [<file>...]'

"Revisão desconhecida". No primeiro, não existe commit com o hash abc1234 neste repositório (erro ao copiar, ou o hash é de outro repositório). No segundo, a Ana pediu 9 commits para trás, mas o repositório só tem 5. Como resolver: copie o hash de novo do git log --oneline, e confira quantos commits existem.

"path … does not exist in 'HEAD'" 
$ git show HEAD:pudin.txt
fatal: path 'pudin.txt' does not exist in 'HEAD'

"O caminho pudin.txt não existe no commit HEAD". Erro de digitação: o arquivo é pudim.txt. Lembre também que o caminho é a partir da pasta principal do repositório, e que maiúsculas contam. Como resolver: confira o nome com git show --name-only ou git ls-files.

"exists on disk, but not in" 
$ git show HEAD~3:pudim.txt
fatal: path 'pudim.txt' exists on disk, but not in 'HEAD~3'

"O pudim.txt existe na pasta, mas não no commit HEAD~3". O nome está certo, mas naquele commit a receita de pudim ainda não tinha sido criada (ela entrou no HEAD~2). Como resolver: veja em quais commits o arquivo existe com git log --oneline -- pudim.txt.

Repositório sem commits 
$ git show
fatal: your current branch 'main' does not have any commits yet

"O ramo atual ainda não tem commits": não há o que mostrar. Faça o primeiro commit (Seu Primeiro Commit).

A saída não acaba e o prompt não volta

Commit grande abre no pager, como o git log: role com Espaço e saia com q (veja git log).

Exercícios

1. No diff do git show, o que quer dizer uma linha que começa com -?

2. O que mostra git show HEAD~1:bolo.txt?

3. Qual comando mostra só os nomes dos arquivos que o último commit mudou?

4. Complete

Complete para ver o README.md como era dois commits atrás:

git show HEADREADME.md

Missão final: o que o commit fez?

Missão: o último commit tem uma mensagem vaga ("Ajusta receitas"). Use o git show para descobrir o que ele fez de verdade: quais arquivos mudaram (--stat) e o que entrou no lugar do açúcar refinado.

Resumo

  • git show mostra um commit por dentro: o cabeçalho (como no git log) e o diff (- saiu, + entrou).
  • Sem argumento, mostra o HEAD; com um hash ou HEAD~N, qualquer commit.
  • --stat, --name-only e -s resumem.
  • git show commit:arquivo mostra o arquivo como ele era naquele commit, sem mexer na pasta.
  • Hash errado ou commit além do começo: unknown revision. Arquivo que não existe no commit: does not exist in (ou exists on disk, but not in).
