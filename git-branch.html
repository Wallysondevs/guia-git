Git branch

Na aula O que é um Branch você viu que um branch (ramo) é uma etiqueta que aponta para um commit. O comando que lista e cria essas etiquetas é o git branch. Ele é o "inventário" dos ramos: mostra quais existem, em qual você está, onde cada um aponta e quais já foram juntados ao main.

Você vai aprender
  • Listar os branches com git branch e reconhecer o atual pelo *.
  • Criar um branch no commit atual (git branch NOME) ou num commit antigo (git branch NOME COMMIT).
  • Ver mais detalhes: -v, --show-current, --merged, --no-merged, --list.
  • Quais nomes o Git aceita, e as mensagens reais quando algo dá errado.

As saídas desta aula vieram do Git real do Ubuntu 26.04, na máquina da Ana, com o sistema em português. Renomear e apagar branches (-m, -d, -D) ficam para a aula Renomeando e Apagando Branches.

A ideia: o quadro de etiquetas da cozinha

Pense numa caixa de fotos (os commits) e num punhado de etiquetas adesivas com nomes. O git branch é o quadro onde você vê todas as etiquetas e cola etiquetas novas:

  • sem nada depois, ele mostra o quadro: quais etiquetas existem, e em qual você está trabalhando;
  • com um nome, ele cola uma etiqueta nova, por padrão na foto em que você está agora.

Colar a etiqueta não leva você até ela. Para mudar de branch, o comando é outro: git switch.

1. Listar os branches

A Ana está na pasta receitas, com três commits (o mesmo repositório da aula anterior):

$ git branch
* main
git
O programa Git.
branch
O subcomando: "ramos". Sem nenhum argumento, ele lista.
* main
O único branch até agora. O * (e, no terminal colorido, a cor verde) marca o branch atual, aquele para onde o HEAD aponta.
A lista não abre um "pager"?

Quando a lista é comprida, o Git pode mostrá-la num paginador (o less), como faz com o git log: role com as setas e saia com q. Com poucos branches, ela aparece direto.

2. Criar um branch

$ git branch sobremesas
$ git branch
* main                « o atual continua sendo o main
  sobremesas          « o branch novo
$ git branch --show-current
main
$ git log --oneline --graph --all
* 0244251 (HEAD -> main, sobremesas) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 Cria o README
git branch sobremesas
Cria o branch sobremesas apontando para o commit em que você está (o mesmo do HEAD). Não mostra nada quando dá certo.
* main / sobremesas
Agora são dois. A lista sai em ordem alfabética, e o * continua no main: criar não muda de branch.
git branch --show-current
Mostra só o nome do branch atual, sem lista e sem *. Útil quando você só quer saber "onde estou".

O antes e o depois:

Antes:   A---B---C   ← main ← HEAD

Depois:  A---B---C   ← main ← HEAD
                     ← sobremesas

A = 700bbd5 (README)   B = 7225e04 (bolo)   C = 0244251 (pão de queijo)

No git log, o (HEAD -> main, sobremesas) mostra as duas etiquetas no mesmo commit; a seta diz que o HEAD está no main.

3. Criar um branch num commit antigo

Por padrão o branch nasce no commit atual, mas dá para escolher outro ponto de partida: basta pôr o commit depois do nome. A Ana quer um ramo versao-antiga que comece no primeiro commit, só com o README:

$ git log --oneline
0244251 (HEAD -> main, sobremesas) Adiciona receita de pão de queijo
7225e04 Adiciona receita de bolo
700bbd5 Cria o README                  « o primeiro commit: HEAD~2
$ git branch versao-antiga HEAD~2
$ git branch
* main
  sobremesas
  versao-antiga
$ git log --oneline --graph --all
* 0244251 (HEAD -> main, sobremesas) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 (versao-antiga) Cria o README     « a etiqueta nova, lá no começo
git branch versao-antiga HEAD~2
O segundo argumento é o ponto de partida: qualquer jeito de apontar um commit serve. HEAD~2 quer dizer "dois commits antes do HEAD"; daria no mesmo usar o hash curto do commit, que aparece no git log --oneline.
Antes:   A---B---C   ← main ← HEAD
                     ← sobremesas

Depois:  A---B---C   ← main ← HEAD
         ↑           ← sobremesas
         versao-antiga

O desenho do git log --graph continua uma linha reta, porque nenhum commit novo foi feito: só apareceu uma etiqueta lá no começo da fila.

4. Mais detalhes: git branch -v

A opção -v (de verbose, "detalhado") mostra, para cada branch, o hash curto e a mensagem do commit para onde ele aponta:

$ git branch -v
* main          0244251 Adiciona receita de pão de queijo
  sobremesas    0244251 Adiciona receita de pão de queijo
  versao-antiga 700bbd5 Cria o README

Três colunas: o nome (com o * no atual), o hash curto do commit para onde a etiqueta aponta e a primeira linha da mensagem desse commit. O main e o sobremesas estão no mesmo lugar.

Depois de a Ana fazer um commit no sobremesas, o -v mostra que cada etiqueta está num lugar:

$ git switch -q sobremesas
$ echo 'Pudim de leite' > pudim.txt
$ git add pudim.txt && git commit -q -m 'Adiciona receita de pudim'
$ git switch -q main
$ git branch -v
* main          0244251 Adiciona receita de pão de queijo
  sobremesas    d6f2336 Adiciona receita de pudim       « andou com o commit
  versao-antiga 700bbd5 Cria o README
$ git log --oneline --graph --all
* d6f2336 (sobremesas) Adiciona receita de pudim
* 0244251 (HEAD -> main) Adiciona receita de pão de queijo
* 7225e04 Adiciona receita de bolo
* 700bbd5 (versao-antiga) Cria o README

(O -q, de quiet, "quieto", só faz o git switch e o git commit não mostrarem mensagens; a troca de branch é assunto da próxima aula.)

A---B---C   ← main ← HEAD
↑        \
│         D   ← sobremesas     (D = d6f2336, o pudim)
versao-antiga

5. Quem já foi juntado: --merged e --no-merged

Com o tempo, um repositório acumula branches. Para faxinar, a pergunta é: o trabalho deste branch já está no meu branch atual?

$ git branch --merged
* main
  versao-antiga
$ git branch --no-merged
  sobremesas
--merged
Lista os branches cujos commits todos já fazem parte do branch atual. Esses podem ser apagados sem perder nada. O versao-antiga aparece porque o commit dele é um antepassado do main.
--no-merged
O contrário: branches com commits que o atual ainda não tem. Aqui, o sobremesas, por causa do commit do pudim. Juntar esse trabalho é assunto do git merge.

6. Filtrar e ordenar

$ git branch --list 's*'
  sobremesas
$ git branch --list 'v*'
  versao-antiga
$ git branch --contains d6f2336
  sobremesas
$ git branch --contains 7225e04
* main
  sobremesas
$ git branch -a
* main
  sobremesas
  versao-antiga
--list 's*'
Só os branches cujo nome casa com o padrão (* = "qualquer coisa"). As aspas impedem que o terminal troque o * por nomes de arquivos antes de o Git ver.
--contains d6f2336
Os branches que têm aquele commit na sua história. O commit do pudim só está no sobremesas; o do bolo (7225e04) está no main e no sobremesas, mas não no versao-antiga, que parou antes dele.
-a
Mostra também os branches de um repositório remoto (o GitHub, por exemplo), que aparecem como remotes/origin/…. Sem remoto, a lista é a mesma do git branch. Veja Repositórios Remotos.

7. Bons nomes de branch

O nome do branch vira um arquivo dentro de .git/refs/heads/, por isso o Git tem regras. As principais:

PodeNão pode
letras, números, -, _, . e barras: sobremesas, receita-bolo, ana/cardapioespaço, ~, ^, :, ?, *, [, \
maiúsculas (mas Sobremesas e sobremesas seriam dois branches diferentes, o que confunde)dois pontos seguidos (..), começar com -, terminar com .lock ou com /

O costume é usar minúsculas e hífen, com um nome que diga o assunto: sobremesas, corrige-foto-bolo. Muitas equipes usam um prefixo com barra: feature/sobremesas, fix/foto-bolo.

Formas diferentes de criar um branch

ComandoO que fazMuda para ele?
git branch NOMECria no commit atualNão
git branch NOME COMMITCria no commit indicadoNão
git switch -c NOMECria e já muda (aula git switch)Sim
git checkout -b NOMEO mesmo, com o comando antigo (aula git checkout)Sim

Qual usar? No dia a dia, quase sempre você cria um branch para trabalhar nele logo em seguida: use git switch -c. O git branch NOME é bom para marcar um ponto e continuar onde está (por exemplo, guardar um "antes de mexer" antes de uma mudança arriscada).

Quando dá errado

fatal: a branch named 'sobremesas' already exists 
$ git branch sobremesas
fatal: a branch named 'sobremesas' already exists

"Um branch chamado 'sobremesas' já existe". O Git nunca cria dois branches com o mesmo nome, nem mexe no que já existe: nada mudou. Como resolver: escolha outro nome, ou, se você queria ir até ele, use git switch sobremesas. (Existe o git branch -f NOME, que força a etiqueta a pular para o commit atual, mas ele pode deixar commits sem etiqueta; só use se souber o que está fazendo.)

fatal: 'receitas doces' is not a valid branch name 
$ git branch 'receitas doces'
fatal: 'receitas doces' is not a valid branch name
hint: See 'git help check-ref-format'
hint: Disable this message with "git config set advice.refSyntax false"
$ git branch receitas..doces
fatal: 'receitas..doces' is not a valid branch name
hint: See 'git help check-ref-format'
hint: Disable this message with "git config set advice.refSyntax false"

"'receitas doces' não é um nome de branch válido". Espaços e dois pontos seguidos são proibidos (a tabela da seção 7 tem as regras). As linhas hint: são dicas: a primeira manda ler a ajuda do git check-ref-format, que lista todas as regras; a segunda ensina a desligar a dica. Como resolver: troque o espaço por hífen: git branch receitas-doces.

fatal: not a valid object name: 'main' (repositório sem commits) 
$ mkdir vazio && cd vazio && git init -q
$ git branch                       « não mostra nada!
$ git branch teste
fatal: not a valid object name: 'main'

Num repositório recém-criado, o git branch não lista nem o main, e criar um branch dá erro: "main não é um nome de objeto válido". O que aconteceu: um branch é uma etiqueta num commit, e ainda não existe nenhum commit para colar a etiqueta. O main só passa a existir de verdade no primeiro commit. Como resolver: faça o primeiro commit (Seu Primeiro Commit) e depois crie o branch.

fatal: not a valid object name: '700bbdx' 
$ git branch versao-nova 700bbdx
fatal: not a valid object name: '700bbdx'

O ponto de partida não existe: aqui, um hash digitado errado (o certo era 700bbd5). Como resolver: copie o hash do git log --oneline.

Dois branches que só diferem na maiúscula 
$ git branch Sobremesas
$ git branch
  Sobremesas
* main
  sobremesas
  versao-antiga

Não é erro para o Git (no Linux), mas é uma armadilha: Sobremesas e sobremesas são branches diferentes, e no Windows e no macOS, onde o sistema de arquivos não diferencia maiúsculas, eles brigam pelo mesmo arquivo. Como resolver: apague o que sobrou com git branch -d Sobremesas (Renomeando e Apagando Branches) e use sempre minúsculas.

Resumo

  • git branch sozinho lista os branches; o * marca o atual. --show-current mostra só o nome dele.
  • git branch NOME cria um branch no commit atual, sem mudar para ele; git branch NOME COMMIT escolhe o ponto de partida.
  • -v mostra para onde cada etiqueta aponta; --merged e --no-merged dizem quais já foram juntados ao branch atual.
  • Nomes: minúsculas e hífen, sem espaço nem ..; o Git recusa nomes inválidos e nomes repetidos.
  • Num repositório sem nenhum commit não dá para criar branch: faça o primeiro commit antes.
